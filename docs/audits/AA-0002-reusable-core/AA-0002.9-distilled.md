# AA-0002.9 — distilled verdict

## Executive summary

**Do nothing structural. The SAF↔SAFE core is a *genuine, correctly-sized* DDD
Shared Kernel — not accidental duplication and not a framework-extraction
candidate.** The one real defect the run found is a *bug*, not an architecture
problem: `ToolCallTrace` is a duplicated type whose sidecar→evals converter
silently drops the `Locations` field, so ghx-sidecar-profile eval episodes
persist empty `Locations` while other profiles keep it — an unregistered
Visibility/Truthfulness asymmetry. It is measurement-touching, so it is routed
to a pre-registered eval ADR ([ADR-0032.2](../../adr/0032.2-tooltrace-unification-locations-flow.md))
and recorded as a TRUST hole now, **not** fixed as a drive-by. Everything else is
watch-list or explicitly deferred. This is the north-star-honest outcome — the
audit did not manufacture a `pkg/saf` refactor to justify itself.

## Tension resolved

The reusable-core lead (H2, "the kernel needs a named boundary") and the YAGNI
skeptic (S1/S2, "do nothing, no split") are **both right and do not conflict**:
the kernel is real and correctly *located* (no physical `pkg/saf` split — YAGNI
+ north-star filter win), while its *findability* can improve without moving code
(naming/doc + a fitness test). The skeptic's caution on the Runner port (one impl)
is noted but overruled *narrowly*: unlike a speculative port, ADR-0036's runner
port has a concrete imminent second implementation (codex-acp) and is the P4
enabler — so it clears the "one implementation forever" bar. Recorded as a decline
of S3-as-High.

## Recommended sequence

1. **Pre-registered eval ADR + fix (ADR-0032.2, the only real action).** Unify
   `ToolCallTrace` via depend-not-copy (evals uses `sidecar.ToolCallTrace`;
   JSON tags identical → the *dedup* is serialization byte-identical) **and** fix
   the `Locations` flow so the sidecar profile captures it. The Locations fix
   changes committed artifacts for that profile, so it is **pre-registered** and
   the effect measured, not a drive-by. Closes the TRUST hole below. Behavior of
   scoring/gates unchanged; the R6 path-scope detector simply stops running on
   silently-empty data for one profile.
2. **Watch-list, non-urgent, trigger-gated:** a contract-surface + marker-value
   fitness test (agent-legibility / anti-drift), a `TurnResult`/`TurnRecord`
   reconciliation — each only when a real trigger fires.
3. **DO NOTHING:** no `pkg/saf` framework extraction, no eval-god-package split
   (frozen), no semantic-OTel merge (frozen-adjacent). These are correct as-is.
