# AA-0002.2 — SAF↔SAFE, through a Go architecture & boundaries lens

The lens: judge the package structure of `internal/sidecar` (SAF runtime) and
`internal/sidecar/evals` (SAFE) with idiomatic-Go eyes — is the dependency
direction between them clean and acyclic, does evals sit correctly as a
*consumer* of the runtime, is the shared substrate (`telemetry`) a proper leaf
both depend on or is it entangled, are there god-packages, and would a
reusable-core split be idiomatic Go or cathedral layering. Grounds: Ben Johnson
*Standard Package Layout*, Go Proverbs ("the bigger the interface, the weaker the
abstraction"; "a little copying is better than a little dependency"), the
consumer-side-interface rule, kit-vs-application, re-priced for our context by
`research/05` (maintainability = agent-legibility / minimal legible edit unit;
compiler-enforced boundaries matter MORE under a fleet; both god-files and
over-fragmentation fail concern-locality).

This audit **builds on and does not repeat** the AA-0001-spirit
`architecture-vision/go-architecture-boundaries-2026-07-07.md` (composition
root, `ghx→codemode` edge, `internal/sidecar` as a 29-file god-package,
singletons-vs-services) or **ADR-0036** (the Runner port; the verified keystone
that `ToolCallTrace`/`TurnResult` import only `time`, so swapping runtimes needs
no measurement-stack change). It cites those and moves on. Its job is the one
seam the charter names: **is the core shared between SAFE and the SAF a genuine
DDD Shared Kernel, or accidental duplication drifting apart — and would lifting
the SAF toward a reusable boundary be idiomatic Go?**

## Executive summary

**The SAF↔SAFE seam is directionally sound — the single most important thing at
this boundary, and it is right.** The import graph is clean, one-directional and
acyclic: `evals → sidecar → {telemetry, tier2}`, `evals → telemetry`,
`hosttask → {sidecar, tier2}`, with `telemetry` a true leaf and — the load-bearing
fact — **nothing in the runtime imports `evals`.** The reusable core (SAF) has
zero knowledge of its consumer (SAFE). `telemetry` is a *genuine* shared kernel,
not two parallel OTel stacks: the runtime and evals call an almost identical set
of policy-free OTLP primitives, and evals *reuses* the leaf rather than
reimplementing it. So the charter's central question resolves in the affirmative
for the capability substrate: this is a Shared Kernel, not duplication drifting
apart.

**The highest-leverage finding is the one asymmetry in the shared-substrate
story.** The OTLP *capability* (`telemetry`) is already a shared leaf both sides
depend on — but the report/trace *vocabulary* it captures (`Report`, `Claim`,
`Evidence`, `RelevantFile`, `ToolCallTrace`, `RawSDKAudit`) is **not** a leaf: it
lives *inside* the runtime package, so the SAFE consumer must import the entire
`internal/sidecar` package — and, transitively, its ACP-SDK/daemon dependency
closure — just to speak the shared vocabulary. The types themselves are
dependency-light (ADR-0036 verified `ToolCallTrace`/`TurnResult` import only
`time`; `Report`/`Claim`/`Evidence` import only stdlib), but their *packaging*
binds them to the runtime. That is the CRP tax that blocks framework-
extractability (charter attribute #3).

**But the correct action is to NAME the seam and WAIT, not extract now.** There
is exactly one non-CLI consumer today (evals). Extracting a shared-vocabulary
leaf before a second consumer proves it would (a) be a speculative framework the
charter and the YAGNI adversary rightly forbid, and (b) move types that *are* the
measurement stack's inputs — a measurement-touching change, ADR-gated by the
frozen-stack rule. So as the Go-boundaries persona I **endorse the skeptic's
guardrail**: the idiomatic reusable-core split is a small shared-kernel leaf
mirroring `telemetry` (not layer packages — that would be the cathedral move to
reject), and it is trigger-gated on a *second consumer*, the P4 protocol swap, or
a deliberate framework lift. Everything below is Medium/Low and mostly
watch-list; there is no genuine High at this seam.

## What is already right (verified, not assumed)

- **Dependency direction is clean, one-way, and acyclic across the whole seam.**
  `go list` (module `github.com/gkoreli/ghx/v2`) resolves the internal edges to:
  `internal/sidecar → {telemetry, tier2}`; `internal/sidecar/evals → {sidecar,
  evals/hosttask, telemetry}`; `internal/sidecar/evals/hosttask → {sidecar,
  tier2}`; `internal/sidecar/telemetry → ∅`; `internal/sidecar/tier2 →
  mapengine`. No cycle exists (Go would refuse to compile one; `go build ./...`
  exits 0). Evals is unambiguously a **consumer of** the runtime, never the
  reverse — the correct direction for a proof machine that measures a product.

- **The reusable core has zero knowledge of its consumer.** Repo-wide, the only
  importers of `internal/sidecar/evals` are `internal/cli`, `evals/cmd/evalreport`,
  and three one-off Go mains under `docs/evals/` — **never the runtime**
  (`go list … {{if eq . ".../internal/sidecar/evals"}}`). This is the property
  that makes the SAF a candidate reusable boundary at all: you could delete SAFE
  and the runtime would still compile. AGENTS.md Engineering Tenets ("decouple
  code whose responsibilities do not belong together; a caller should not inherit
  a dependency it never uses") — met at the package level here.

- **`telemetry` is a genuine shared kernel, not two drifting OTel stacks.** Both
  the runtime and evals import `telemetry` and call the *same* policy-free OTLP
  capability surface — `LogRecord`, `AppendAttrs`, `IntPoint`, `HistogramPoint`,
  `HistogramMetric`, `SumMetric`, `WriteMetrics`, `WriteLogs`,
  `NewTracerProvider`, `MetricFileName`/`LogFileName` — with near-identical call
  profiles (evals: `AppendAttrs`×10, `LogRecord`×5, `IntPoint`×4…; runtime:
  `LogRecord`×9, `AppendAttrs`×5, `IntPoint`×3…). Evals' OTel files
  (`otel_trace.go:13`, `otel_metrics.go:8`, `otel_logs.go:9`,
  `otel_judge_events.go:8`) **import** the leaf; they do not reimplement OTLP.
  This realizes NORTH_STAR "the OTel capture layer is … reused across both",
  ADR-0022's extraction rule, and the Open-Source-Leverage tenet ("official
  formats exactly"). `telemetry` (6 files, 808 LOC) is a properly small,
  policy-free capability provider — kit, not application.

- **The Shared Kernel is expressed as named types, the agentic winner — not a
  shared-policy package.** The seam is coupled through domain *types* (`Report`,
  `ToolCallTrace`, `Claim`, `Evidence`, `RelevantFile`) rather than a
  `common`/shared-behavior package. `research/05 §5.2` ranks exactly this — "name
  the concept as a type" — above both copy and depend, because it gives
  legibility *and* findability without policy coupling. And ADR-0036 verified the
  measurement-facing structs are dependency-light (`turnresult.go` imports only
  `time`; `report.go` only `encoding/json`/`errors`/`fmt`/`regexp`/`strings`), so
  the vocabulary itself is clean POJO-style data.

- **`hosttask` is a cleanly-extracted, cohesive capability subpackage — a
  positive precedent.** The ADR-0032.1 host-task machinery lives in its own
  subpackage (`evals/hosttask/`: `provision.go`, `grader.go`, `attribution.go`,
  `container.go`, `fixture.go`, `scope.go`, `attempt_workspace.go`, plus `doc.go`,
  `corpus/`, `testdata/` — 8 non-test files, 1,348 LOC) with a package doc, while
  the *measurement* wiring that consumes it (`host_episode.go`, `host_anomalies.go`,
  `host_identity.go`) stays in the `evals` root. That split is principled:
  reusable capability vs frozen scoring. It proves the codebase *can* extract a
  bounded concern into an importable subpackage without a cycle — the template
  the flat packages could grow into.

- **No `util`/`common`/`shared`/`models` grab-bag packages at this seam, and no
  role-layer packages.** Every package is named for what it provides
  (`telemetry`, `tier2`, `hosttask`, `evals`, `mockagent`), and `judgeconfig/` is
  not a malformed empty package — it is a `//go:embed` asset directory holding
  one JSON, embedded from `judge_config.go:32` (go:embed cannot reach parent
  dirs, so the sibling dir is the idiomatic placement). Both checks: sound.

## Medium severity

### M1 — The shared report/trace vocabulary is packaged inside the runtime, not a leaf; SAFE imports the whole SAF (and its ACP-SDK closure) to speak it

**What.** `telemetry` completes half of the shared-substrate story — the OTLP
*capability* is a leaf both sides depend on. The other half, the report/trace
*vocabulary* those primitives capture, is **not** a leaf: `Report`, `Claim`,
`Evidence`, `RelevantFile` (`internal/sidecar/report.go:18,24,31,38`),
`ToolCallTrace`/`TurnResult` (`internal/sidecar/turnresult.go:81,…`), and the
`RawSDK*` audit types (`internal/sidecar/rawsdk.go:92`) all live *inside* the
runtime package. So to consume the vocabulary, evals imports the entire
`internal/sidecar` package.

**Evidence.**
- The evals→sidecar coupling surface is **31 distinct `sidecar.X` symbols**, and
  it is dominated by *data types*: `sidecar.Report`×46, `sidecar.ToolCallTrace`×39,
  `sidecar.Claim`×17, `sidecar.RawSDKAudit`×16, `sidecar.RawSDKToolUse`×13,
  `sidecar.RelevantFile`×5, `sidecar.Evidence`×1 — plus a handful of behaviors it
  legitimately drives (`sidecar.Ask`×4, `sidecar.RunPreflightForAgent`×3,
  `sidecar.ShutdownAgent`×3, `sidecar.LoadConfig`×3, `sidecar.BuildPrompt`×2).
  (`grep -hoE '\bsidecar\.[A-Z][A-Za-z0-9]*'` over `evals/*.go`+`hosttask/*.go`,
  non-test.)
- The types are dependency-light, but the *package* is not: `go list -deps
  ./internal/sidecar` includes `github.com/coder/acp-go-sdk`. So an evals file
  that wants only the plain-struct `ToolCallTrace` still pulls the runtime's
  ACP-SDK (and daemon, route engine, session store) into its dependency closure.
  This is the Common-Reuse-Principle tax (`research/05` item 13): "a consumer
  forced to load a component it barely uses pays context tax" — here, both the
  Go compile-time closure and, for a cold agent reading `evals`, the traversal
  into the whole runtime to find where `Report` is defined.
- **No consumer-side interface** narrows this: evals imports the fat concrete
  runtime surface directly (`grep 'interface{' evals/*.go` finds no
  runtime/harness/ask interface defined by the eval consumer). Contrast the good
  taste the same tree shows elsewhere — `graphQLDoer`, `TurnRunner`, `JudgeClient`
  are small consumer-defined seams (AA-0001 go-boundaries audit).

**Why it's debt (which tenet).** NORTH_STAR asserts SAF and SAFE "share one
trace/artifact infrastructure … reused across both" — realized for `telemetry`,
*incomplete* for the vocabulary that rides it. It also blocks the charter's
attribute #3 (framework-extractability) and NORTH_STAR "the framework will
outgrow ghx — later": you cannot lift the SAF, or introduce a second consumer of
the report/trace model, without either dragging the whole runtime (incl. a
protocol the north star plans to replace) or doing this extraction under
pressure. `research/05 §5.2`: judge every shared abstraction by "does it reduce
or increase the tokens an agent must load" — today, reaching the vocabulary
increases them.

**Recommendation (name the seam; DO NOT extract now).** The idiomatic reusable-core
split is a **small shared-kernel leaf** — e.g. `internal/sidecar/report` (or a
`sidecarcontract` leaf) holding `Report`/`Claim`/`Evidence`/`RelevantFile`/
`ToolCallTrace`/`TurnResult`/`RawSDK*` — that **both** the runtime and evals
depend on, mirroring exactly how `telemetry` is already a leaf. That is idiomatic
Go (a dependency-light types leaf, `internal/`-enforced), **not** cathedral
layering (no `domain/`/`models/` role package — reject that). **But gate it on a
trigger, and until then do nothing:** the trigger is a *second consumer* of the
report model, the P4 "below ACP" protocol swap, or a deliberate framework lift.
Extracting before then is a speculative framework (charter binding constraint;
YAGNI adversary) *and* a measurement-touching move (the types are scoring
inputs → pre-registered eval ADR). Add it to the SAF watch-list; it is a two-hour
pure relocation *when* the trigger fires, and near-zero risk of getting worse by
waiting because the types are already clean.

### M2 — `internal/sidecar/evals` is a 42-file / 12.5k-LOC flat god-package (larger than the runtime it measures) — flag, do not refactor

**What.** SAFE is one flat package of 42 non-test files / 12,481 LOC (+42 test
files / 9,087 LOC) — *larger than the SAF runtime it measures* (35 non-test files
/ 9,937 LOC). It mixes at least six concerns in one namespace: the deterministic
measurement stack (`rewards.go`, `gates.go` 35k, `gate_reducers.go`,
`anomalies.go`, `host_anomalies.go`, `union_scoring_test.go`, `closedbook.go`);
the judge layer (12+ `judge_*.go`, four provider clients
`judge_client_{anthropic,openai,cli,http}.go`); run economics (`stopping.go`,
`parallel.go`, `baseline_reuse.go`); OTel emission (`otel_*.go`); episode/store/
runner plumbing; and two ~1k-LOC concerns of their own (`discovery.go` 33k,
`anticipation_predictor.go` 32k). By `research/05 §5.1` a cold agent editing any
one concern loads a package whose minimal legible edit unit is enormous — both
god-files *and* a god-package fail concern-locality.

**Evidence.** `find internal/sidecar/evals -maxdepth 1 -name '*.go' ! -name
'*_test.go' | wc -l` → 42; concatenated LOC → 12,481. `ls -S` surfaces
`discovery.go`, `anticipation_predictor.go`, `gates.go` as the ~1k-LOC files the
AA-0001 tech-debt/cohesion audits already named.

**Why it's debt (which tenet).** AGENTS.md Engineering Tenets: "one authoritative
owner per domain concern … decouple code whose responsibilities do not belong
together." This is the package-scale analogue of the `acp.go` god-*file* the
runtime already split (mainline commit log) — but one altitude up and on the
consumer side.

**Why the recommendation is narrow (frozen-stack + right-sizing).** This scope
is *especially* exposed to the frozen-measurement-stack rule (charter binding
constraint; AGENTS.md "Delegated Workers"): almost every cluster here — rewards,
gates, detectors, the judge (AGENTS.md lists "judges, scores" as measurement),
even OTel event shapes that scorers read — is measurement-identity-bearing, so a
"cohesion" subpackaging is a *measurement-touching* change, not a behavior-
preserving one. **Flag, do not refactor.** The one proven, safe pattern already
in-tree is the `hosttask` extraction (a bounded capability lifted into a
subpackage with its own `doc.go`/`corpus`/`testdata`); *if* an eval ADR ever
opens this package for other reasons, the lowest-risk cohesion win is to mirror
that move for a genuinely non-scoring cluster (e.g. judge *transport* clients,
which are I/O adapters distinct from judge *scoring*) — but even that is
ADR-gated and must prove byte-identical scoring. The honest near-term action is
**watch-list, not a worker task**: naming it keeps the largest cohesion
liability at the seam on the record without inviting a drive-by refactor of the
frozen stack.

## Low severity

### L1 — SAFE is coupled to the ACP protocol directly (6 files import the raw ACP SDK), unlike the CLI frontend (0)

**What.** Six evals files import `github.com/coder/acp-go-sdk` directly:
`host_episode.go`, `runner.go`, `client.go`, `closedbook.go`, `mockagent/main.go`,
and `hosttask/attribution.go`. For contrast, the CLI frontend (`internal/cli`)
imports the raw ACP SDK in **zero** files — it reaches the agent only through the
SAF runtime's abstraction. So the measurement stack sits at the *same* protocol
depth as the runtime itself.

**Why it's a (small) concern.** NORTH_STAR "Protocols are stepping stones, not
identity … the boundary must survive replacing ACP, the brain, or both (P4)."
Today the frozen measurement stack is wired to a protocol the north star has a
pre-registered plan to drop. Part of this is *inherent* — the eval harness must
drive agents at the protocol they speak to compare plain vs ghx vs ghx-sidecar,
so `client.go`/`runner.go`/`mockagent` speaking ACP is not a leak to "fix" — and
`ToolCallTrace` (the measurement-facing view) is *already* protocol-neutral
(ADR-0036). This is a watch-list note, not a defect: the mitigation is the
Runner port (ADR-0036), whose adapter boundary is the place the residual ACP
imports would consolidate when P4 fires. Its trigger is the same P4 "below ACP"
move; no action until then.

### L2 — Four Go `main` packages live under `docs/evals/` and import the frozen measurement package

**What.** `docs/evals/judge-goldset/gen`, `docs/evals/judge-sweep-2026-07-06/sweep`,
and `.../cross-family/runner` are executable Go mains under the docs tree that
import `internal/sidecar/evals`. Executable build-graph code under `docs/` is a
mild placement smell — a cold agent expects `docs/` to be prose, and these are
consumers of the frozen package sitting outside both `internal/` enforcement and
the `evals/cmd/` convention that `evalreport` already follows.

**Why it's Low / recommendation.** They are one-off generators, out of the
charter's core scope (the SAF/SAFE package seam), and harmless to the runtime.
When one is next touched, prefer relocating it under
`internal/sidecar/evals/cmd/` (the existing precedent, `cmd/evalreport/main.go`)
or a top-level `tools/` tree, so all SAFE-consuming executables share one home.
Not a standalone change.

## Recommended sequence (phased, non-rewrite)

The honest shape of this seam is: **it is already sound, so almost every item is
watch-list, not work.** Ordered by leverage; every measurement-touching item is
marked DEFERRED/ADR-gated per the frozen-stack rule.

1. **Posture (zero-cost, now).** Record the shared-substrate rule as a standing
   invariant: the report/trace vocabulary and the OTLP capability are shared
   *substrate*; new eval-only concepts stay in `evals`, new runtime-only concepts
   stay in `sidecar`, and neither grows a dependency on the other's policy. This
   is the discipline that keeps M1 from getting worse while it waits.

2. **Name the shared-kernel leaf on the SAF watch-list (M1) — DEFERRED, trigger-gated.**
   Do *not* extract now. Register the future seam (`internal/sidecar/report` or a
   `sidecarcontract` leaf, mirroring `telemetry`) and its trigger (second consumer
   / P4 protocol swap / framework lift) in the governing ADR so the fleet does not
   re-derive it. When the trigger fires it is a pure relocation of already-clean
   types, pre-registered as an eval ADR because the types are scoring inputs.

3. **Keep the `hosttask` extraction as the cohesion template (M2) — DEFERRED, ADR-gated.**
   No refactor of the flat `evals` package now (frozen stack). If an eval ADR
   opens it for other reasons, the only safe cohesion move is to mirror `hosttask`
   for a genuinely non-scoring cluster, proven byte-identical against the gate
   outputs. Otherwise: watch-list.

4. **Consolidate SAFE-consuming executables (L2) — opportunistic.** Move the
   `docs/evals/**` Go mains under `evals/cmd/` (or `tools/`) the next time one is
   edited. Behavior-preserving; not a standalone task.

## What we deliberately do NOT do (the skeptic's guardrail, adopted)

- **We do not extract a framework, a `sidecarcontract` leaf, or any shared-kernel
  package before a second consumer proves it.** One consumer (evals) + the CLI is
  not a reusable-boundary mandate; it is a shared kernel that already works via
  named types. Extracting now fails the north-star filter and the charter binding
  constraint, and taxes every cold read for a benefit no current caller collects.
- **We do not add `domain/`, `models/`, `core/`, or any role-layer package.** The
  idiomatic reusable split is a *capability/type leaf* (like `telemetry`), never a
  horizontal layer. Layer packages here would be cathedral ceremony, explicitly
  to reject.
- **We do not refactor `internal/sidecar/evals` for cohesion outside a
  pre-registered eval ADR.** Behavior-preserving ≠ measurement-preserving; the
  god-package is flagged, not touched.
- **We do not "fix" evals' ACP imports.** Driving agents at the protocol level is
  what the eval measures; the Runner port (ADR-0036) is the right consolidation
  point, and only when P4 fires.
