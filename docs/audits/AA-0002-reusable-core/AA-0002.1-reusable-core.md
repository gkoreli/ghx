# AA-0002.1 — Reusable-Core Extraction

Read-only audit of the boundary between the SAF runtime (`internal/sidecar`)
and the SAFE eval machinery (`internal/sidecar/evals`), against the charter
question: is the shared core a **genuine DDD Shared Kernel** (small,
deliberately coordinated, context-tax-reducing) or **accidental duplication
drifting apart**? Every finding cites `file:line`, ties to a named tenet /
NORTH_STAR phase, and is priced with the agentic-first lens
(`arch-audit/research/05 §5.2`: *copy vs. depend vs. **name***). Fable
adjudicates; this report finds and ranks.

Tenets / canon audited against:

- NORTH_STAR §"Sidecar Product Capabilities": SAF and SAFE **"share one
  trace/artifact infrastructure — a trace is a trace whether it came from an
  eval episode or a real question; the OTel capture layer is configurable,
  modular, and reused across both"**; the observability tenet's *"never fork
  the visibility stack"*; ADR-0022's extraction rule; ADR-0036's Runner port.
- `AGENTS.md` Engineering Tenets: proper domain models, **one authoritative
  owner per concern**, "no compatibility junk", "refactor cleanly or not at
  all"; the **frozen measurement stack** (evals scoring/detectors change only
  by pre-registered ADR).
- Shared-Kernel canon (`research/02 C2`): *keep it small; make the coupling
  explicit and coordinated*; counter-canon (`research/02 E1–E4`): duplication
  is cheaper than the wrong abstraction; the north-star filter — **do not
  extract a framework before a second consumer proves the boundary**.

## Executive summary

**The verdict is mostly good news, sharpened by one concrete counter-example.
The SAF/SAFE core is a *genuine, deliberately-coordinated Shared Kernel*, not
accidental duplication — the dependency direction is clean and one-way
(evals → runtime, never the reverse, not even in tests), the shared substrate
is single-owner, and the load-bearing shared types are co-designed with the
eval consumer named in their doc comments. But the kernel fails the charter's
*second* attribute — context-tax reduction — on two counts: (1) one pocket of
the kernel (`ToolCallTrace` / `ToolStatusTransition`) is a *verbatim copy* that
has **already drifted** on a freshly-added field, and (2) the kernel as a whole
has **no named boundary** — the real evals↔runtime contract is 31 symbols
diffused across a 456-symbol, un-namespaced `internal/sidecar` package, so a
cold agent cannot tell the deliberate contract from incidental reach-through.**

The single highest-leverage finding is **H1**: `evals.ToolCallTrace` and
`evals.ToolStatusTransition` (`internal/sidecar/evals/episode.go:177-197`) are
field-for-field, doc-comment-for-doc-comment copies of the runtime's
`sidecar.ToolCallTrace` / `sidecar.ToolStatusTransition`
(`internal/sidecar/turnresult.go:73-94`) — and the hand-written converter
between them, `convertSidecarTrace` (`internal/sidecar/evals/trace.go:12-25`),
**silently omits the `Locations` field** that ADR-0032.1 S2 just added to both
structs. This is the charter's "accidental duplication drifting apart" caught
in the act: a new field forced edits at ≥4 sites and one converter was missed.
Because the same file uses `*sidecar.RawSDKAudit` and `*sidecar.Report` *by
reference*, the copy is an inconsistency, not a policy. It is measurement-
adjacent (the type is the durable episode artifact read by scoring), so the
fix is **ADR-gated, not drive-by** — but the serialized JSON is byte-identical
across the two types, making the eventual dedup low-risk.

The important positive result, verified with equal rigor: **the shared
visibility substrate NORTH_STAR calls "reused across both" is genuinely one
owner, not re-implemented.** `internal/sidecar/telemetry` is a clean leaf
(imports nothing under `internal/`), stays policy-free (zero `if eval` branches
in shared code), and *both* the production `Ask` path (`emit.go:120,148,434`)
and the eval path (`evals/otel_trace.go`, `otel_metrics.go`, `otel_logs.go`)
layer their own `ghx.eval.*` / session attributes on top of the *same*
`telemetry.NewTracerProvider` / `WriteLogs` / `WriteMetrics` entrypoints.
ADR-0022's "a trace is a trace" is real and byte-identical, not aspirational.

**On the framework question, the north-star filter binds the recommendation:
do nothing structural.** Exactly one product (ghx) exists, so extracting a
`saf-core` module now would be building generality before a second consumer —
the precise anti-pattern the charter and `research/02 E1` forbid. `telemetry`
is the *one* extraction that has already earned its keep (two real consumers,
byte-identical output, ADR-0022) — it is the template, and it should **not be
grown**. The Runner port (ADR-0036) is a well-formed neutral boundary with
**one** adapter and a pre-registered second (codex/SDK, the P4 exit) — a
watch-list item, not a proven reusable boundary yet. The right moves are all
*small and selective*: fix the one real duplication (H1), and make the existing
kernel *legible* (H2) — by naming, not by a physical package split.

### What is already right (verified, not assumed)

- **Dependency direction is clean and one-directional.** `go list` deps of
  `./internal/sidecar/evals` include `internal/sidecar` and
  `internal/sidecar/telemetry`; the reverse is empty — `go list` Imports of
  `./internal/sidecar` contains no `evals`. The runtime does not know evals
  exists at compile time. This is the SDP-correct shape (`research/02 C4`):
  volatile evals depends on the stabler runtime, never the reverse.
- **The one apparent reverse edge is not a code dependency.** `grep` flagged
  `internal/sidecar/daemon_test.go:25` and `acp_resilience_test.go:32` as
  "importing" evals, but both are `package sidecar_test` (external) and the
  reference is `exec.Command("go build", …, ".../evals/mockagent")` — they
  shell-build the fake-ACP test binary as a fixture. No symbol import, no
  cycle. (A mild coupling — see L1 — but not a direction violation.)
- **The visibility substrate is single-owner and policy-free.**
  `internal/sidecar/telemetry` is a leaf (imports nothing under `internal/`);
  its own package doc (`telemetry/trace.go:1-15`) declares the ADR-0022
  extraction and the neutrality contract: *"Domain-specific attribute shaping
  … is layered on top by the caller; this package stays neutral."* Verified:
  zero `if eval|profile` branches in `telemetry/*.go`, `turnresult.go`, or
  `report.go` — the Sandi-Metz wrong-abstraction signature (`research/02 E2`:
  flags accreting to serve divergent callers) is **absent**.
- **Both halves emit through the same code.** Production `emit.go:120,148,434`
  and eval `otel_trace.go:36,51` / `otel_metrics.go:38` call the identical
  `telemetry.NewTracerProvider` / `WriteLogs` / `WriteMetrics`, and every
  shared JSONL file routes through the single `telemetry.AppendJSONLine`
  primitive with a per-path mutex (`telemetry/jsonl_writer.go:45-67`). One
  authoritative writer per artifact (`AGENTS.md`: "a single telemetry writer").
- **The report contract is single-owner and shared, not copied.** `Report`,
  `Claim`, `RelevantFile`, `Evidence` are defined exactly once
  (`internal/sidecar/report.go:18-45`) and consumed by evals as
  `*sidecar.Report` (46 references) — no parallel eval `Report` type exists.
  This is the NORTH_STAR boundary contract ("compact evidence report out")
  named once and depended upon — the `research/05 §5.2` "name it" winner.
- **`TurnResult` is a co-designed kernel type, the opposite of accidental.**
  `turnresult.go` imports only `time` (deliberately neutral) and its field
  docs name the eval consumer: `ReportRetried` *"so evals can count retries
  honestly"* (`:36`), `WrapUpRecovered` *"counted as the soft anomaly
  turn_cap_wrapup so evals can see how often the net fires"* (`:47`), `RawSDK`
  *"eval-only audit channel"* (`:60`). This is deliberate coordination at
  field granularity — a textbook small, explicit Shared Kernel (`research/02
  C2`).
- **Session vs. Episode are correctly *separate* bounded contexts, not
  duplicated.** Evals uses no runtime session-store or `Ledger` type (only
  `sidecar.SessionOptions`, once); it defines its own `Episode` / `TurnRecord`
  (`evals/episode.go:255,122`). A runtime `Session` (live ACP conversation)
  and an eval `Episode` (one scored trial) are legitimately different models
  of superficially-similar things (`research/02 C1` bounded context) — this is
  right, not a smell.
- **The Runner port is a genuinely neutral boundary, and it protects the
  measurement contract by construction.** `runner.go:27-55` defines the port
  with no ACP types and no subprocess fields; `FailureClass` → marker mapping
  (`runner.go:246-275`) exists precisely *"so evals/anomalies.go never learns
  which runtime ran"* and the markers *"MUST stay byte-identical across
  runtimes."* The runtime author engineered the seam knowing evals reads it —
  the antithesis of drift.

## High severity

### H1 — `ToolCallTrace` / `ToolStatusTransition` are verbatim copies that have already drifted

**What.** The runtime's per-tool-call audit types are duplicated wholesale
into package `evals`, and the hand-written converter between the two copies
has already fallen out of sync on a field added this week.

**Evidence.**
- Runtime owner: `sidecar.ToolStatusTransition` (`internal/sidecar/turnresult.go:73-77`)
  and `sidecar.ToolCallTrace` (`turnresult.go:79-94`), fields
  `ID/Kind/Title/RawInput/Locations/StatusTransitions/OutputSize/OutputExcerpt`.
- Eval copy: `evals.ToolStatusTransition` (`internal/sidecar/evals/episode.go:177-181`)
  and `evals.ToolCallTrace` (`episode.go:183-197`) — **identical fields,
  identical JSON tags, and a word-for-word-identical doc comment**, including
  the `Locations` comment citing "ADR-0032.1 S2" verbatim.
- The converter `convertSidecarTrace` (`internal/sidecar/evals/trace.go:12-25`)
  copies `ID/Kind/Title/RawInput/OutputSize/OutputExcerpt` and
  `StatusTransitions` — but **omits `Locations`**. It is the standard-episode
  path (`evals/runner.go:329,332`), so a sidecar-profile episode's
  `TurnRecord.ToolTraces[].Locations` is always empty via this route.
- Meanwhile a *different* eval path, `client.go:155-156,178-179`, **does**
  populate `evals.ToolCallTrace.Locations` — so the field is filled on the
  raw-ACP path and dropped on the `sidecar.TurnResult` path: an inconsistency
  inside the same package. And `hostLiveTraces` (`host_episode.go:299-311`)
  converts the eval copy *back* into `sidecar.ToolCallTrace` (copying
  `Locations`) *"into the sidecar trace shape the S2 classifier consumes."*
- The same `TurnRecord` struct references `*sidecar.RawSDKAudit`
  (`episode.go:146`) and `*sidecar.Report` (`episode.go:148`) *by name* — so
  the copy of `ToolCallTrace` is an inconsistency, not a deliberate policy.

**Why it violates a tenet.** This is the charter's headline question answered
concretely: a recurring concept living as two hand-synced copies is exactly
`research/05 §5.2`'s penalized case (*"copy a concept"* → should be *named*,
not copied). `AGENTS.md` Engineering Tenets: *"If a concept appears in two
places, it deserves a type."* The Locations omission is the demonstrated cost:
one field forced edits at ≥4 sites (two struct defs, two doc comments, three
converters) and one was missed — the "accidental duplication drifting apart"
failure mode, observed, not hypothesized. It also fails the agent-legibility
lens (`research/05 §5.1`): `evals.ToolCallTrace` advertises a `Locations` field
its own primary constructor never fills, misleading any agent that extends
Locations-based scoring.

**Frozen-measurement flag.** `evals.ToolCallTrace` is the durable episode
artifact type and feeds the host-task S2 classifier — **measurement-adjacent**.
Do **not** refactor drive-by. Because the two types carry identical JSON tags,
switching `TurnRecord.ToolTraces` to `[]sidecar.ToolCallTrace` yields
byte-identical serialized artifacts, making this a low-risk dedup — but it must
be **pre-registered in an eval ADR** (`AGENTS.md` frozen measurement stack),
which should also decide whether the current `Locations`-drop is a latent
host-task scoring gap (flagged for the eval owner; not diagnosed here).

**Recommendation (ADR-gated).** Name it once: make `TurnRecord.ToolTraces`
(and `ReplayedToolTraces`) `[]sidecar.ToolCallTrace`, delete
`evals.ToolCallTrace` / `evals.ToolStatusTransition`, delete
`convertSidecarTrace`, and let `hostLiveTraces` drop its re-conversion. Net:
one named type, zero converters, the whole `Locations`-drift class eliminated —
a context-tax *reduction* (`research/05 §5.2` test passes). If the eval ADR
instead judges the durable artifact must stay schema-frozen independent of the
runtime (a REP argument, `research/02 C3`), then keep the copy but make it an
*explicit* anticorruption layer with a single converter and a doc comment
saying so — the current undocumented verbatim copy reads as accident, and the
lockstep `Locations` edit proves the decoupling is fictional.

### H2 — The real shared kernel has no named boundary: 31 symbols diffused across a 456-symbol package

**What.** The de-facto SAF/SAFE contract — everything evals depends on from the
runtime — is **31 distinct exported `sidecar.*` symbols**, drawn from the
**~456 exported symbols** of the single, un-namespaced `internal/sidecar`
package. There is no marker separating the deliberate boundary contract from
incidental reach-through into runtime internals.

**Evidence** (`grep 'sidecar\.[A-Z]'` over `evals/*.go`, non-test):
- *Deliberate contract* (should be shared): `Report` ×46, `Claim` ×17,
  `RawSDKAudit` ×16, `RawSDKToolUse` ×13, `TurnResult`, `ToolCallTrace`,
  `ReconMCPTool` ×6, `ReconToolName` ×4, the failure markers
  (`LivenessTimeoutMarker`, `SubmitReportToolID`).
- *Driving port* (legitimate — evals is a primary adapter over the runtime):
  `Ask` ×4, `AskRequest`, `Request`, `Config`, `LoadConfig`, `SessionOptions`,
  `ShutdownAgent`, `RunPreflightForAgent`, `FormatPreflight`.
- *Reach-through into runtime internals* (surface widened partly to serve
  evals): `BuildPrompt` (`prompt.go:240`, used at `training_export.go:341`),
  `BuildPersonaSystemPrompt` (`prompt.go:37`), `CanonicalJSONDigest`
  (`rawsdk.go:115`), `ContentSize` (`tooltrace.go:13`). These are internal
  mechanics promoted to `public` so the eval harness can replicate runtime
  behavior — legal (correct direction, no cycle) but boundary-blurring.

**Why it violates a tenet.** `research/02 C2` (Shared Kernel): *"designate with
an explicit boundary … keep this kernel small."* Here the kernel is neither
explicit nor small — it is the entire public face of a 456-symbol god-package,
with the intentional contract (`Report`, `TurnResult`, markers) inseparable
from reach-through internals (`BuildPrompt`, `CanonicalJSONDigest`). This fails
the agent-groundability lens hardest (`research/05 §2c`, §5.1): a cold agent
asked *"what is the SAF/SAFE boundary I must not break?"* has no file, no
package, no named set to load — the answer is scattered across `report.go`,
`turnresult.go`, `rawsdk.go`, `prompt.go`, `reportsink.go`, `acp.go`,
`preflight.go`, `recontool.go`. Under a parallel fleet (`research/05 §2d`), an
un-named boundary is one the fleet erodes silently — precisely how the H1 drift
happened. This is a legibility/context-tax finding, **not** a leak: the
*direction* is clean; the *findability* is not.

**Why not a physical split (the north-star filter).** The fix is **not** a new
`saf-core` package or an extracted framework — one product exists, so that
would violate `research/02 E1` / the charter's YAGNI clause. The fix is
*naming and documentation*: make the boundary a legible, grounded thing without
moving code.

**Recommendation (low-risk, mostly non-code).**
1. Author a short "SAF/SAFE shared contract" section in ADR-0022 (or a thin
   ADR-0022.x) that *enumerates* the intended shared surface (the "deliberate
   contract" + "driving port" lists above) and declares the reach-through set
   (`BuildPrompt`, `CanonicalJSONDigest`, …) as *internal-exported-for-test*,
   not contract. Pure grounding — zero code risk.
2. Graduate the enumeration into a committed fitness test (`research/05 §5.3`:
   fitness functions are the only fleet-proof enforcement) that fails the build
   if evals imports a `sidecar.*` symbol *outside* the declared set — turning
   the boundary from convention into a compiler-adjacent gate. This is the
   durable output that stops H1-class drift recurring.

## Medium severity

### M1 — The frozen eval-anomaly contract lives as bare runtime constants with only a doc comment guarding it

**What.** The measurement contract that evals scores against — the anomaly
marker strings — is owned by the runtime as plain exported constants, protected
only by prose. A runtime refactor of a string silently re-scores every eval.

**Evidence.**
- `LivenessTimeoutMarker = "liveness watchdog timeout"` (`acp.go:58`),
  `maxTurnsErrorMarker` (`acp.go:61`), `peerClosedMarker` (`acp.go:64`),
  `SubmitReportToolID` (`reportsink.go:38`) live in the runtime.
- `runner.go:241-257` documents the coupling — the markers *"are the frozen
  measurement contract read by evals/anomalies.go … they MUST stay
  byte-identical across runtimes"* — and `canonicalTurnError` (`runner.go:266`)
  guards only the `FailureClass` path, not the raw constants a future
  refactor might touch.

**Why it matters.** This is the *good* kind of coordination (deliberate,
documented — it is why the kernel is genuine, not accidental) but it is
enforced by a comment, and `research/05 §5.3` is explicit that under a parallel
fleet only a committed fitness function survives. NORTH_STAR "never fork the
visibility stack" + `AGENTS.md` frozen-measurement stack: the contract deserves
a mechanical guard, not a `MUST` in a doc comment.

**Frozen-measurement flag + recommendation (ADR-gated).** Do not relocate or
rename the markers as drive-by work — they *are* the frozen contract. Instead,
pre-register (eval ADR) a committed test asserting each marker's exact value
and that `evals/anomalies.go` reads them from the runtime constant (not a
re-typed literal), so any future change breaks the build loudly. Optionally the
same ADR names a single "measurement contract" doc location listing these
strings. No behavior change; pure enforcement.

### M2 — The Runner port is a template *by construction* but unproven by a second adapter

**What.** ADR-0036's Runner port (`runner.go`) is the cleanest boundary in the
tree — neutral types, typed `Outcome`, measurement contract protected — but it
has exactly **one** implementation.

**Evidence.** The only type satisfying `Preflight`+`Open`+`Info` is
`claudeACPRunner` (`acprunner.go:117,124,138`); its own doc calls it *"Adapter
1"* with *"codex-acp or an in-process Claude Agents SDK loop later"*
(`acprunner.go:99-105`, `runner.go:10-15`). Evals does **not** consume this
port — it drives the runtime one level up, via `sidecar.Ask`
(`evals/runner.go:215,279`). So the Runner port is orthogonal to the
evals↔runtime seam: it swaps *what runs below `Ask`* (the P4 "below ACP" exit),
not what evals depends on.

**Why it matters (both directions).** Positive: it is the *method template* the
rest of the kernel should imitate — a neutral, named, measurement-safe boundary
(contrast H1/H2). Caution: `research/02 E3` (AHA / Rule of Three) — one
implementer means the neutrality is *asserted, not proven*; the second adapter
may reveal a leak (an ACP assumption baked into the "neutral" types). This
passes the north-star filter *only because* the second adapter is a
pre-registered NORTH_STAR exit trigger (P4/M10), not speculation.

**Recommendation.** **Watch-list, no action.** Do not carve more ports "to
match." Re-audit the port's neutrality claim *when* the codex/SDK adapter lands
(it unblocks NORTH_STAR M10 / the P4 "below ACP" move) — that is the event that
converts it from a well-formed port into a *proven* reusable boundary.

## Low severity

### L1 — Runtime tests reach a shared fixture by package path, not through a neutral home

**What.** Two runtime external tests build the eval-tree `mockagent` binary as
a fixture, coupling runtime tests to an `evals/` path.

**Evidence.** `daemon_test.go:25` and `acp_resilience_test.go:32` both run
`exec.Command("go","build","-o",bin,".../internal/sidecar/evals/mockagent")`.
The fake-ACP agent is genuinely shared (runtime resilience tests *and* eval
`mock_e2e_test.go` both need a scriptable ACP peer), but it lives under
`evals/`, so the runtime's tests know an eval subpath exists.

**Why it's Low.** No production dependency, no cycle, correct direction; it is a
test-fixture-location smell, not an architecture one. A neutral home
(`internal/sidecar/acptest/mockagent` or `internal/testsupport/`) would make
the shared fixture's shared-ness legible and stop the runtime tests pointing
into the eval tree. Defer unless someone is already touching mockagent.

### L2 — Reach-through exports widen the runtime's public surface (flip side of H2)

**What.** `BuildPrompt`, `BuildPersonaSystemPrompt`, `CanonicalJSONDigest`,
`ContentSize`, `RunPreflightForAgent` are exported from the runtime partly so
the eval harness can replicate runtime behavior (`training_export.go:341`
rebuilds the prompt via `sidecar.BuildPrompt`).

**Why it's Low / what to do.** Each is individually defensible, and the
north-star filter forbids a speculative extraction to "clean" them. This is
already covered by H2's recommendation (declare which exports are *contract*
vs. *internal-exported-for-test*). Flagged separately only so the H2 fitness
test explicitly classifies these five rather than silently blessing them.

## Recommended sequence (phased, non-rewrite)

Ordered by leverage × tractability; each step names the frontier work it
unblocks or is marked watch-list. Nothing here is a rewrite; the two structural
items are ADR-gated because the scope is measurement-exposed.

1. **Ground the boundary (H2 step 1) — do first, zero code risk.** Add the
   "SAF/SAFE shared contract" enumeration to ADR-0022.x listing the deliberate
   contract + driving port and declaring the reach-through set. *Unblocks:* the
   framework-half of the north star (a named boundary is the prerequisite for
   NORTH_STAR "the framework outgrows ghx — later" ever being actionable) and
   makes every subsequent step legible.
2. **Pre-register the dedup + drift-guard eval ADR (H1 + M1).** One eval ADR
   covering: (a) collapse `evals.ToolCallTrace`/`ToolStatusTransition` to the
   shared `sidecar.*` types (byte-identical serialization), resolving the
   `Locations` drift; (b) decide whether the current `Locations`-drop is a
   host-task scoring gap; (c) add the marker-value fitness test (M1).
   *Unblocks:* trust-ledger work (NORTH_STAR C7 / `docs/evals/TRUST.md`) — a
   drifted artifact type is a latent H3 trace-completeness hole.
3. **Land the import-boundary fitness test (H2 step 2).** After step 1 names
   the set, commit the test that fails if evals imports an undeclared
   `sidecar.*` symbol. *Unblocks:* fleet-proof enforcement (`research/05 §5.3`)
   so H1/H2-class drift cannot silently recur under parallel workers.
4. **(Watch-list) Re-audit the Runner port's neutrality when adapter #2 lands
   (M2).** No action until the codex/SDK adapter exists; that event
   (NORTH_STAR M10 / P4) converts the port from well-formed to proven and is
   the moment to check the "neutral" types didn't smuggle an ACP assumption.
5. **(Watch-list) Relocate the shared `mockagent` fixture to a neutral home
   (L1)** — only when someone is already editing it. Not worth a dedicated
   touch.

**Explicitly rejected (north-star filter):** creating a `saf-core` / framework
package, extracting the Runner port to a leaf package now, or growing
`telemetry` to absorb more shared logic. One product exists; generality ahead
of a second consumer is the anti-pattern the charter names.

## Method / auditability

- Dependency edges from `go list -deps` / `go list -f '{{.Imports}}'` over
  `./internal/sidecar` and `./internal/sidecar/evals`; reverse-edge confirmed
  by `grep -l 'internal/sidecar/evals' internal/sidecar/*.go` then inspecting
  the two hits (both `package sidecar_test`, both `exec.Command "go build"`).
- Shared-symbol surface from `grep -rhoE '\bsidecar\.[A-Z][A-Za-z0-9_]*'` over
  `evals/*.go` (non-test), `sort -u` → 31; runtime exported-symbol count from
  `grep -E '^(func|type|const|var) [A-Z]…'` over `internal/sidecar/*.go`
  (non-test) → ~456 (a proxy count, not exact — the point is order-of-magnitude
  diffusion, not a precise ratio).
- Duplication + drift confirmed by reading `turnresult.go:73-94`,
  `evals/episode.go:177-197`, and `evals/trace.go:12-25` side by side, and by
  locating the two divergent `Locations` paths (`trace.go` omits;
  `client.go:155-156` populates; `host_episode.go:305` round-trips).
- Telemetry ownership from `telemetry/*.go` package doc + a leaf-import check
  (`go list` Imports ∩ `internal/` = ∅) and the shared-entrypoint greps in
  `emit.go` and `evals/otel_*.go`.
- Sole Runner impl confirmed by enumerating `Preflight`/`Open`/`Info` receivers
  (`acprunner.go` only).
- `go build ./...` succeeds at audit time; **no code was modified** — this
  audit produced only this artifact. The audit worktree was fast-forwarded to
  `mainline` (cf39223) before reading, so every `file:line` matches the current
  tip.

**Least-confident call.** H1's *recommended resolution* (share the type vs.
keep an explicit ACL), not the finding itself. The duplication and the
`Locations` drift are verified fact; whether the durable episode artifact
*should* depend on the runtime's `ToolCallTrace` turns on a REP/artifact-freeze
judgment (`research/02 C3`) that belongs to the eval owner inside the
pre-registered ADR — the observed lockstep sync argues the decoupling is
fictional and sharing is right, but I did not trace whether any host-task
scorer's output changes if `Locations` starts flowing on the sidecar-profile
path, and that is a measurement question I deliberately did not answer.
