# AA-0002.5 — Duplication & Coupling Metrics: SAF ↔ SAFE

Read-only, quantitative audit of the boundary between the **SAF runtime**
(`internal/sidecar`), **SAFE** (`internal/sidecar/evals`), and the shared
`internal/sidecar/telemetry` substrate. Every number below is reproducible with
the commands in **Method / auditability**; every finding cites `file:line`
verified against the working tree at audit time. No code was modified.
`go list ./internal/sidecar/...` resolves and the tree builds.

This persona answers the charter's mechanical question: **where do the eval
machinery and the runtime re-implement the same thing, how tightly are they
coupled, and is the "one trace/artifact infrastructure … reused across both"
claim (NORTH_STAR §"Sidecar Product Capabilities") true or aspirational?**

Companion audits (`docs/audits/architecture-2026-07-07.md`,
`coupling-cohesion-testability-2026-07-07.md`) already flagged the eval
god-files and the (now-split) `acp.go` god-file. **This audit does not
re-litigate file-size god-files**; it measures the *cross-boundary* duplication
and coupling that those single-lens audits did not quantify, and it reaches a
different flagship finding: a **git-provable, already-realized data-loss drift**
caused by a duplicated boundary type.

---

## Executive summary

- **The coupling structure is clean and textbook.** The dependency graph is
  **acyclic** — `evals → sidecar → {telemetry, tier2}`, and `sidecar` does
  **not** import `evals` (verified: `go list -deps ./internal/sidecar | grep
  evals` → empty). Martin **instability** rises monotonically toward the
  consumer and falls toward the substrate: `telemetry` I=**0.00** (leaf,
  Ce=0) ← `tier2` I=**0.25** ← `sidecar` I=**0.40** ← `evals` I=**0.75**.
  Dependencies point from unstable to stable. This is what a healthy
  shared-kernel-plus-consumer looks like.

- **The telemetry substrate IS genuinely shared with one owner — the
  NORTH_STAR claim holds.** `internal/sidecar/telemetry` (808 non-test LOC,
  6 files) has **zero** internal dependencies (pure leaf) and is imported by
  **both** `sidecar` and `evals` (afferent Ca=2). Both halves consume the same
  low-level primitives (`WriteLogs`, `NewTracerProvider`, `HistogramMetric`,
  `SumMetric`, `HistogramPoint`, `AppendAttrs`, `LogRecord`, the `*FileName`
  constants). A trace writer really is a trace writer for both. **Verified,
  not aspirational.**

- **But the flagship finding is a duplicated boundary type that has ALREADY
  drifted into a silent data-loss bug.** `ToolCallTrace` and
  `ToolStatusTransition` are defined **byte-for-byte twice** — SAF
  (`turnresult.go:73-94`) and SAFE (`evals/episode.go:177-197`) — identical
  fields, identical JSON tags, identical doc comments citing the same
  ADR-0032.1 S2. Because they are two copies, they need two hand-written
  mappers, and the two mappers **already disagree**: `convertSidecarTrace`
  (`evals/trace.go:12`) **silently drops the `Locations` field** while
  `hostLiveTraces` (`evals/host_episode.go:299`) preserves it. Git proves the
  drift: `Locations` was added to both *type copies* (SAFE in `3cf0e0d`, SAF in
  `1d32948`), but the converter in `trace.go` has **never been touched since
  before the field existed** (its last three commits all predate ADR-0032.1).
  This is the charter's "two copies silently diverging" attribute materializing
  as a concrete defect. **This is measurement-reachable → flagged, not fixed**
  (see H1).

- **A second-order duplication:** the *semantic OTel-emission layer* is written
  twice on top of the shared toolkit — SAF's `emit.go` (556 LOC) vs SAFE's
  `otel_trace.go`+`otel_logs.go`+`otel_metrics.go` (625 LOC). The low-level
  *writer* is shared; the *domain→span/attribute mapping* is not, so the OTel
  attribute vocabulary can drift between the runtime's traces and the eval's
  traces even though NORTH_STAR wants "a trace is a trace." Softer than H1
  (genuinely different domain objects, partial overlap) — **M2**.

**Verdict for this lens:** the boundary is a *real* shared kernel at the
telemetry layer (one owner, deliberately coordinated, context-tax-reducing) and
a *partially accidental* duplication one layer up (the ACP tool-call trace
shape). The fix for the accidental part is **collapse-to-depend, not
extract-a-framework**: `evals` already imports `sidecar`, so it can *use*
`sidecar.ToolCallTrace` instead of *copying* it — YAGNI-safe, no new
abstraction, no second consumer required. The only caveat is that the copies
sit on the measurement-frozen path, so the collapse must go through a
pre-registered eval ADR proving artifact byte-identity (it will be identical —
the JSON tags already match).

## Coupling metrics (the evidence for "already right")

Internal (our-module) dependency edges, from
`go list -f '{{range .Imports}}…' <pkg>` filtered to `gkoreli/ghx`:

| Package | LOC¹ | files¹ | Ce (internal out) | Ca (internal in) | **Instability I=Ce/(Ce+Ca)** |
|---|---:|---:|---|---|---:|
| `sidecar/telemetry` | 808 | 6 | **0** (leaf) | 2 — `sidecar`, `evals` | **0.00** — maximally stable substrate |
| `sidecar/tier2` | 2 249 | 9 | 1 — `mapengine` | 3 — `cli`, `sidecar`, `evals/hosttask` | **0.25** |
| `sidecar` (SAF root) | 9 937 | 35 | 2 — `telemetry`, `tier2` | 3 — `cli`, `evals`, `evals/hosttask` | **0.40** |
| `sidecar/evals` (SAFE) | 14 520 | 52 | 3 — `sidecar`, `evals/hosttask`, `telemetry` | 1 — `evals/cmd/evalreport` | **0.75** — unstable top consumer |

¹ non-test LOC / non-test `.go` files. Totals: internal/sidecar non-test tree ≈
**27 514 LOC**; `evals` alone is **52.8%** of it.

**Reading it:** every arrow points from higher instability to lower — the
Stable-Dependencies Principle holds exactly. `telemetry` is the anchor (I=0.00);
`evals` is the volatile leaf that everything else is protected from (only
`evalreport`, a `cmd/`, depends on it). There is **no cycle** and **no
back-edge** from runtime to evals. Nothing here needs fixing; it is cited as the
verified baseline the findings below sit against.

Cross-boundary import direction (the seam itself):

- `evals` → imports `sidecar` (SAF root), `evals/hosttask`, `telemetry`
  (`evals/episode.go:14` imports `internal/sidecar`).
- `evals/hosttask` → imports `sidecar`, `tier2`.
- `sidecar` → imports `telemetry`, `tier2` only. **Never `evals`.**

So SAFE depends on SAF, one direction, deliberately. The kernel candidates that
cross the seam are exactly: `sidecar.Report`, `sidecar.RawSDKAudit`,
`sidecar.ToolCallTrace`, and the `telemetry` primitives. Three of those four are
shared by *dependency* (one owner). One — `ToolCallTrace` — is shared by *copy*.
That single exception is the whole story.

## What is already right (verified)

1. **`telemetry` is a genuine DDD Shared Kernel.** One owner
   (`internal/sidecar/telemetry`, Ce=0), two deliberate consumers (Ca=2),
   small (808 LOC / 6 files), tight public surface (1 exported type
   `LogRecord` + ~12 functions/constants). Both `emit.go` and
   `evals/otel_*.go` build their OTel output on the *same* writer primitives.
   NORTH_STAR's "OTel capture layer … reused across both" is **true**.
   Evidence: symbol-usage counts — `telemetry.LogRecord` (SAF 9×, evals 5×),
   `telemetry.AppendAttrs` (SAF 5×, evals 10×), `telemetry.HistogramMetric`,
   `telemetry.NewTracerProvider`, `telemetry.WriteLogs/WriteMetrics` used from
   both. This is copy-avoidance done correctly (depend, don't copy).

2. **`Report` has exactly one owner and is shared by dependency.** Defined once
   at `internal/sidecar/report.go:38`; `evals` references `sidecar.Report` in
   ≥8 sites (`episode.go:148,273`, `rewards.go:88-122`, `judge_bundle.go:142`,
   `anticipation_predictor.go:253`) and never redefines it. The report-parsing
   / extraction / coercion logic (`submit_report`, `<ghx-report>` fallback)
   lives entirely in `internal/sidecar/*` (report.go, reportsink.go, emit.go,
   prompt.go); `evals` consumes flags (`ReportCoerced`, `ReportRetried`) rather
   than re-implementing extraction. **No report-parsing duplication.**

3. **`RawSDKAudit` is shared by dependency too.** `evals/episode.go:146`
   holds `*sidecar.RawSDKAudit`; no parallel definition in evals.

4. **No `~/.ghx` path-layout duplication.** SAF owns the session/artifact path
   layout (`session.go:65 sessionDir`, `session.go:74 SessionWorkspace`);
   `evals` *consumes* produced dirs (`anticipation_predictor.go:308
   loadSessionReports(reportsDir)`) rather than re-deriving the layout.

5. **Acyclic, one-directional coupling.** `go list -deps ./internal/sidecar`
   contains no `evals` package. The runtime can be built, tested, and reasoned
   about with zero knowledge of the eval machinery.

The shared-kernel thesis is therefore **mostly proven** — the boundary is a
real kernel, not accidental duplication drifting apart, *except* for the one
type family in H1.

## Findings by severity

### H1 — `ToolCallTrace`/`ToolStatusTransition` are duplicated across the boundary and have already drifted into silent `Locations` data-loss
**Charter attribute:** Real-shared-kernel-vs-duplication (highest weight).
**Tenet tie:** AGENTS.md Engineering Tenets — *"One authoritative owner per
domain concern"* and *"If a concept appears in two places, it deserves a
type"*; NORTH_STAR *Visibility and Truthfulness* (the eval turn path must
faithfully mirror the product turn path; every persisted artifact honest).

**The duplication (byte-identical, two owners):**
- SAF: `internal/sidecar/turnresult.go:73-77` (`ToolStatusTransition`) and
  `:79-94` (`ToolCallTrace`).
- SAFE: `internal/sidecar/evals/episode.go:177-181` (`ToolStatusTransition`)
  and `:183-197` (`ToolCallTrace`).

Both `ToolCallTrace` copies have the identical field set — `ID, Kind, Title,
RawInput, Locations, StatusTransitions, OutputSize, OutputExcerpt` — the
identical JSON tags, and *the same doc comment* citing "ADR-0032.1 S2". Both
`ToolStatusTransition` copies are `Status string \`json:"status"\`` +
`At time.Time \`json:"at"\``. This is copy-paste, not convergent evolution —
the comments were copied verbatim.

**The realized drift (git-provable):** because there are two copies, the
boundary needs hand-written mappers, and they disagree on `Locations`:
- `convertSidecarTrace` (`evals/trace.go:12-25`) maps
  `sidecar.ToolCallTrace → evals.ToolCallTrace` copying `ID, Kind, Title,
  RawInput, OutputSize, OutputExcerpt, StatusTransitions` — **and omits
  `Locations`.** Used on the ghx-sidecar profile recon path
  (`evals/runner.go:329,332`).
- `hostLiveTraces` (`evals/host_episode.go:299-316`) maps the *reverse*
  direction and **does** copy `Locations` (`:305`).

Git blame proves the drop is stale duplication, not intent:
`Locations` was added to the SAFE type copy in `3cf0e0d` (ADR-0032.1 S2) and
to the SAF type copy in `1d32948`; the mainline HEAD commit `5aec071` then
*populated* it on the SAF capture side. But `evals/trace.go` — the converter —
has **never been touched since before `Locations` existed** (its three most
recent commits, `afd6e99`/`9e870c7`/`9e76f39`, all predate ADR-0032.1). The
field was threaded through every *type* but the *mapper between the two types
was forgotten* — exactly the failure mode a single owner makes structurally
impossible.

**Consequence:** for the **ghx-sidecar profile**, recon `TurnRecord.ToolTraces`
are built via `convertSidecarTrace`, so their persisted `Locations` are silently
empty; for the **plain/ghx profiles** the eval's own ACP client
(`evals/client.go:155-156,178-179`) populates `Locations` directly, so they
are present. The audit trail is **asymmetric by profile** — a
Visibility-and-Truthfulness gap nobody registered.

**Measurement-stack flag (why I flag, not fix):** `Locations` feeds the
host-arm write policy and the exploration/engineering attribution classifier
(`evals/hosttask/attribution.go:178 classifyLocations`), and the converter is
on an evals-reachable path, so **any change to what it copies is
measurement-touching** per the charter and AGENTS.md frozen-stack rule. The
host-task class is *not* currently harmed (host episodes capture via
`client.go` and flatten via `hostLiveTraces`, both of which keep `Locations`),
which is why no gate has failed — but the recon-side artifact asymmetry is
real. **Do not drive-by-fix the converter.**

**Recommendation (pre-registered, YAGNI-safe):** collapse to *one owner*.
`evals` already imports `sidecar`, so replace `evals.ToolCallTrace` /
`evals.ToolStatusTransition` with `sidecar.ToolCallTrace` /
`sidecar.ToolStatusTransition` and delete `convertSidecarTrace` entirely
(the reverse mapper `hostLiveTraces` also disappears — no cross-type copy
needed). This is *depend, not copy* (charter §2 "copy vs depend vs name"),
adds no framework, needs no second consumer. **Because both copies carry
identical JSON tags, the serialized artifacts are byte-identical**, so this is
a strong candidate for a *no-op-artifact* pre-registered eval ADR (verify
episode-JSON byte-identity across the change, then land). The collapse
simultaneously eliminates the `Locations` asymmetry as a side effect — but that
correctness delta is precisely why it must be pre-registered rather than
slipped in.

### M1 — Parallel turn shapes (`TurnResult` vs `TurnRecord`) hand-copied field-by-field across the boundary
**Charter attribute:** Context-tax reduction.
**Tenet tie:** *"If a concept appears in two places, it deserves a type"*;
*"Refactor cleanly or not at all"* (two shapes of one concept double the
surface every future agent must reconcile).

`sidecar.TurnResult` (`turnresult.go:6-64`, the runtime turn) and
`evals.TurnRecord` (`evals/episode.go:122-175`, the eval turn) are two shapes
of one concept. ~12 fields are conceptually identical and copied by hand:
`FullText`↔`Text`, `Thinking`, `ToolCalls`, `ToolTraces`, `ReplayedText`,
`ReplayedThinking`, `ReplayedToolTraces`, `ReportRetried`, `ReportCoerced`,
`WrapUpRecovered`, `SessionRecreated`, `ToolOutputChars`. The copy happens at
`evals/runner.go:317-332` (`rec.Text = turn.FullText`, `rec.ReportCoerced =
turn.ReportCoerced`, … per-field), i.e. the same manual-mapping tax as H1 but
across a *larger* field set.

Unlike H1 this is **not** byte-identical: `TurnRecord` legitimately adds
eval-only fields (`Turn`, `Question`, `DurationMs`, `Error`, `Resumed`) and
*embeds* the shared owners correctly (`*sidecar.Report`, `*sidecar.RawSDKAudit`).
So it is a genuine projection, not a pure copy — but the **overlap block** is
copy-prone (the same class of "field added to one, forgotten in the mapper" as
H1). Lower severity because the drift here would surface as a compile error or
an obviously-missing field, and because merging the two structs would fight the
runtime-vs-artifact boundary (one is a live streaming result, one is a
serialized record).

**Recommendation (watch-list, not now):** do **not** merge the structs. Once H1
lands (shared `ToolCallTrace`), the remaining overlap is small enough that a
single `func (r TurnResult) Record(turn int, q string) TurnRecord` on the
*owner* side (SAF) would centralize the mapping so a new runtime field can only
be added in one place. Measurement-reachable (it produces episode artifacts) →
pre-register if pursued. Fine to leave as-is under YAGNI until a field-drift
bug actually bites.

### M2 — The semantic OTel-emission layer is written twice on top of the shared telemetry toolkit
**Charter attribute:** Context-tax reduction / Replaceability.
**Tenet tie:** NORTH_STAR *"a trace is a trace whether it came from an eval
episode or a real question"*; Open-Source-Leverage (*"our own metrics ride
alongside … never as a fork"* — implies one attribute vocabulary).

The *writer* is shared (see "already right" #1), but the *mapping from domain
object → OTel span + attribute keys* is duplicated:
- SAF: `internal/sidecar/emit.go` (556 LOC) emits spans/logs/metrics for a
  production `Ask`/session.
- SAFE: `internal/sidecar/evals/otel_trace.go` (333) + `otel_logs.go` (116) +
  `otel_metrics.go` (176) = **625 LOC** emit spans/logs/metrics for an
  `Episode`.

Both hand-build attribute sets (`ghx.eval.tool_call_count` at
`otel_trace.go:193`, tool-call spans at `emit.go` and `otel_trace.go:115,250`).
Because the **attribute-key vocabulary is not a shared constant set**, a runtime
tool-call span and an eval tool-call span can label "the same thing" with
different keys and nobody would notice — the precise drift NORTH_STAR's
"a trace is a trace" is meant to prevent.

This is **softer than H1**: an `Episode` and a production `Ask` are genuinely
different domain objects with substantial non-overlapping attributes (rewards,
gates, contamination on the eval side; route, tier on the runtime side), so
full unification would be over-coupling. The tractable, YAGNI-safe slice is only
the **shared span/attribute-key names**, not the emission logic.

**Recommendation (watch-list):** if/when this is touched, extract only the
*shared OTel attribute-key constants and the tool-call-span shape* into
`telemetry` (or a sibling `telemetry/semconv`-style file), leaving both
emission call sites in place. **Heavily measurement-touching** — eval OTel
attributes are consumed by the trace-capture comparator (`anomalies.go:171
CompareTraceCapture`) and any trace-based analysis — so this is *only* a
pre-registered eval-ADR move, never a refactor-in-passing. Default outcome:
**watch**; the shared toolkit already prevents the *worst* fork (the writer),
and no second framework consumer exists to force the issue.

## Recommended sequence (phased; mostly watch-list)

The boundary is healthy enough that most of this is **watch**, not **do**. In
priority order:

1. **H1 — collapse `ToolCallTrace`/`ToolStatusTransition` to one owner
   (`sidecar`).** The only finding with a *realized* defect (`Locations`
   asymmetry) and the only one that is both high-value and low-risk (identical
   JSON tags → byte-identical artifacts). Path: pre-register a no-op-artifact
   eval ADR asserting episode-JSON byte-identity → delete
   `evals.ToolCallTrace`/`evals.ToolStatusTransition`/`convertSidecarTrace` and
   point evals at `sidecar.ToolCallTrace` → verify artifact identity + that the
   `Locations` recon-side change is the *intended* delta → land ff-only.
   This is *depend-not-copy* within an existing edge; adds no abstraction and
   needs no second consumer, so it passes the YAGNI/north-star filter cleanly.

2. **M1 — after H1, add a single `TurnResult.Record(...)` mapper on the SAF
   side** to centralize the turn-shape projection so runtime fields can only be
   added in one place. Watch-list; do only if a field-drift bug surfaces.
   Pre-register (artifact-producing).

3. **M2 — watch.** Do not unify the two OTel emitters. If the eval-trace and
   runtime-trace attribute vocabularies are ever edited together, extract *only*
   the shared attribute-key constants + tool-call-span shape into `telemetry`.
   Pre-registered eval ADR mandatory (trace-capture comparator consumes these).

4. **L1 — watch.** Narrow the `evals` exported surface (99 types) *before* any
   future kernel-extraction, not before.

5. **L3 — do nothing.** The complexity frontier is the frozen measurement
   stack; it is on the record here so the distillation persona and Fable can
   weigh it, but it is out of bounds for consolidation absent a Goga-triggered
   pre-registered run.

**Explicit YAGNI position (the charter's mandatory adversary line):** do **not**
extract a SAF framework or a standalone telemetry module. There is exactly one
runtime consumer and one eval consumer; the shared kernel that exists
(`telemetry`, `Report`, `RawSDKAudit`) is already correctly shared by
dependency. The single accidental copy (H1) is fixed by *using the existing
dependency*, not by building new infrastructure. "Do nothing beyond H1 + a
watch-list" is a defensible outcome for this lens.

## Method / auditability

All commands run from the repo root at audit commit; reproducible offline.

```sh
# Package inventory
go list ./internal/sidecar/...

# Internal dependency edges (per package), filtered to our module
go list -f '{{range .Imports}}{{.}}{{"\n"}}{{end}}' ./internal/sidecar        | grep gkoreli/ghx
go list -f '{{range .Imports}}{{.}}{{"\n"}}{{end}}' ./internal/sidecar/evals  | grep gkoreli/ghx

# Afferent coupling (Ca): who imports X
for p in $(go list ./...); do \
  go list -f '{{range .Imports}}{{.}}{{"\n"}}{{end}}' "$p" \
  | grep -q 'internal/sidecar/telemetry$' && echo "$p"; done

# Cycle check: does the runtime transitively import the evals?
go list -deps ./internal/sidecar | grep 'internal/sidecar/evals' \
  || echo "NO CYCLE"

# Duplicate / parallel type declarations of shared concepts
grep -rn --include='*.go' -E \
  'type +[A-Z][A-Za-z0-9]*(Report|TurnResult|Turn|Episode|Session|Trace|Artifact|Reward|Result|Record) ' \
  internal/sidecar | grep -v _test.go

# The realized drift: converter never updated for Locations
sed -n '12,25p' internal/sidecar/evals/trace.go          # convertSidecarTrace: no Locations
git log --oneline -- internal/sidecar/evals/trace.go     # last touch predates ADR-0032.1
git log --oneline -S 'Locations         []string' -- \
  internal/sidecar/turnresult.go internal/sidecar/evals/episode.go

# Telemetry reuse (symbol usage from both halves)
grep -rn 'telemetry\.' internal/sidecar/*.go       | grep -v _test.go
grep -rn 'telemetry\.' internal/sidecar/evals/*.go | grep -v _test.go

# Sizes / complexity proxy (gocyclo unavailable offline)
find internal/sidecar -name '*.go' ! -name '*_test.go' | xargs wc -l | sort -rn | head -25
# branch-density proxy per file: grep -cE '\b(if|for|case|switch)\b|&&|\|\|' <file>
```

**Instability** I = Ce/(Ce+Ca) computed from the internal (our-module) import
edges above. **LOC** = `wc -l` on non-test `.go` files. **Complexity** is a
branch-keyword proxy (`if|for|case|switch|&&|||`), not true cyclomatic
complexity — `gocyclo` is not installed in this environment; the proxy is used
only for *relative* hotspot ranking, never as an absolute metric.

**Frozen-measurement-stack discipline:** every recommendation that touches an
evals-reachable path (H1, M1, M2, L3) is explicitly flagged as requiring a
**pre-registered eval ADR** before implementation; this audit **proposes no
change to any scorer, gate, reward, or detector**, and no code was modified.
