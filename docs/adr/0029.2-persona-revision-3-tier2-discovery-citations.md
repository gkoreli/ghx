# 0029.2. Sidecar Persona Revision 3 — Tier-2 Doctrine + Discovery Citation Discipline

## Status

Pre-registered before implementation; accepted on merge.

Like ADR-0029 and ADR-0029.1, this ADR is **pre-registered before the next
run; never mid-run**. Persona wording changes the subject under measurement,
so it may land only between runs, must never be introduced while a gate run
is in progress, and must never be used to rescore existing episodes. After
merge, a **sidecar-only spot check** (live asks, anomaly read) gives
direction; any citable number comes only from a later pre-registered run.

This ADR does **not** change eval scoring, detectors, rewards, gates,
thresholds, episode definitions, or ground truth. It changes only sidecar
persona doctrine in `internal/sidecar/prompt.go`.

## Context

Two independent evidence streams say the persona is behind the product and
behind the scorer.

**Tier 2 exists but the persona has never heard of it.** ADR-0024.1 shipped
local structural analysis in two slices (2026-07-06): `ghx tier2 codemap`
(backend `local:codemap`), `ghx tier2 astgrep` (`local:ast-grep`), and
`ghx tier2 repomap` (`local:repomap`), all live-verified against honojs/hono.
The report contract already carries the canonical `local:*` backend IDs and
an optional validated `tierUsed` field, and ADR-0024.1's implementation notes
explicitly deferred "persona emission of these fields … to the pre-registered
persona revision" — this one. Today the persona's only escalation text is
operating-loop step 7 ("name the deeper backend needed but do not perform it
unless allowed"), which predates the tools existing: a persona-driven sidecar
cannot escalate to a backend it cannot name.

**The first live discovery episodes scored verifiedRecall 0.000 across all
three profiles, and the sidecar scored inferenceHonesty 0.000**
(`docs/evals/spot-instrumented-2026-07-06/README.md`, Q3; n=1 per cell,
PRELIMINARY by construction, but the defect mechanism is unambiguous):

- All three subjects named 2/3 target repos, but **none emitted a single
  `owner/repo:path` citation** — grep over all answer text found zero colon
  citations. The ghx profile actually read target evidence (8×
  `ghx read … README.md`, 1× `ghx explore Portkey-AI/gateway`) yet earned no
  verified credit because the read was never cited (ADR-0019.2 D2 condition
  2). Names were recalled; verification was performed but not evidenced.
- The sidecar report listed 4 repos under `verified` whose evidence was only
  `ghx repos` search listings — its own uncertainty section admitted "ranking
  based on repo/search metadata only". Search-only is inferred (ADR-0019.1
  D3); labeling it verified is exactly the dishonesty D-G3 penalizes, hence
  inferenceHonesty 0.000.
- The spot check's explicit subject-behavior implication: "the binding
  constraint on D-G1 is citation discipline + read-then-cite behavior, not
  repo discovery. The sidecar discovery persona may need a stronger 'verify
  by reading files and cite owner/repo:path' push before a gate run is worth
  its ~60 episodes."

The current discovery doctrine (`discoveryDoctrine` in prompt.go) states the
rule abstractly ("only repos you actually read into may back verified
claims") and mentions the citation form once, parenthetically, at the bottom
("owner/repo (or owner/repo:path for a specific file)") — with the bare
`owner/repo` form listed first, which is the exact form that earns zero
verified credit under the frozen scorer.

## Decision

Two surgical persona edits. Everything else in the persona is untouched
(ADR-0029 non-goal: no broad prompt rewrite).

### D1. Teach Tier-2 escalation in the operating loop

Current persona text being changed (rendered persona bytes, operating-loop
step 7 — the final step):

```text
7. If remote evidence is insufficient, name the deeper backend needed but do not
   perform it unless allowed.
```

Replacement text (steps 7–8):

```text
7. Escalate to Tier 2 for cross-file STRUCTURE questions that remote evidence
   cannot answer — what imports/calls/depends on X, blast radius, whole-repo
   "which files matter" ranking. Tier 2 is never the first move: reach for it
   only AFTER remote evidence (inspect/search/maps) falls short, and only when
   your allowed backends include local. One example each:
     ghx tier2 codemap owner/repo --importers src/file.ts    (backend local:codemap)
     ghx tier2 astgrep owner/repo --pattern 'compose($$$ARGS)' --lang ts    (backend local:ast-grep)
     ghx tier2 repomap owner/repo --query concern    (backend local:repomap)
   Every Tier-2 claim must cite the exact ghx tier2 command in its evidence,
   list the local:* backend in backendsUsed, and set tierUsed to "tier2".
8. If a deeper backend is needed but not allowed, name it in
   uncertainty/nextReads and do not fake the answer.
```

Rationale: this is deliberately doctrine-level, not a policy engine. The
declarative `EscalationPolicy` from ADR-0024.1 remains future runtime work;
until it lands, the persona carries the same escalation shape in words:
hard-signal question classes (cross-file dependency / structure questions)
plus remote-insufficiency ("AFTER remote evidence falls short"), gated on
`local` in allowed backends, with the blocked-backend honesty rule preserved
as its own step. The three example invocations are lifted from the live
`ghx tier2` CLI (`internal/cli/tier2.go` Examples), and each names its
canonical backend ID inline so the report ledger (`backendsUsed`,
`tierUsed`) cannot drift from the command used — satisfying ADR-0024.1's
visibility contract ("Every Tier-2 answer has `tierUsed: "tier2"` and at
least one `local:*` backend") from the persona side.

### D2. Discovery mode: read-then-cite with a worked example

Current persona text being changed (rendered `discoveryDoctrine` bytes,
items 3–4 and the closing citation paragraph):

```text
3. Verify before claiming: only repos you actually read into (ghx explore,
   ghx read) may back verified claims. A repo seen only in search results
   is an inferred candidate, never a verified one.
4. Report a ranked comparison of the top candidates, and be honest about
   the unverified tail: name the candidates you did not read into in
   inferred/uncertainty instead of silently dropping them.

Cite repo-level evidence as owner/repo (or owner/repo:path for a specific
file) in relevantFiles paths and evidence sources. The depth budget bounds
the sweep exactly as it bounds repo-scoped exploration.
```

Replacement text:

```text
3. Verify before claiming — read, then cite: a claim may enter "verified"
   ONLY if you actually read a file in that repo this session (ghx read,
   or ghx explore for its README) AND the claim's evidence cites that
   exact file in owner/repo:path form. A repo you only saw in search
   results (ghx search, ghx repos) is INFERRED — never claim it as
   verified, no matter how confident you are; put it in
   inferred/unverified instead.
4. Worked example — after running: ghx read acme/rate-limiter README.md
   a verified claim looks like:
     summary:  "acme/rate-limiter implements token-bucket rate limiting"
     evidence: "acme/rate-limiter:README.md — usage section shows the
                TokenBucket middleware"
   The owner/repo:path citation is mandatory in the evidence of EVERY
   verified claim; a verified claim without one counts as unverified.
5. Report a ranked comparison of the top candidates, and be honest about
   the unverified tail: name the candidates you did not read into in
   inferred/uncertainty instead of silently dropping them.

Cite evidence as owner/repo:path — a bare owner/repo name in evidence
never earns verified credit. Use owner/repo:path in relevantFiles paths
and evidence sources. The depth budget bounds the sweep exactly as it
bounds repo-scoped exploration.
```

Rationale: the spot check showed the abstract rule does not transfer — a
subject can obey "read before claiming" and still score 0.000 because the
citation form never appears. The replacement makes the mechanical contract
explicit (read AND cite, in one sentence, capitalized), demotes the bare
`owner/repo` form from "the default" to "never earns verified credit", and
adds one worked example because the repo-scoped persona's biggest doctrine
wins (ADR-0029 D2, ADR-0029.1 D2) came from copyable examples, not rules.
The example repo `acme/rate-limiter` is deliberately fictional: using any
real repo risks contaminating discovery ground truth (litellm, Helicone, and
Portkey are live target-set members; see Considered and rejected).

## Eval-measurement rule

- These persona changes are pre-registered here **before the next run** and
  must never land or change **mid-run**.
- After merge, verification is a **sidecar-only spot check for direction**:
  live `ghx sidecar ask` episodes (one tier2-shaped repo-scoped ask, one
  discovery ask), checked for whether the trail/report actually shows the
  new doctrine (a `ghx tier2` command or an honest blocked-backend note; an
  `owner/repo:path` citation on verified discovery claims). A spot check
  where the agent ignores the doctrine is a negative finding and gets
  committed as such — it does not get retried until it looks good.
- No existing episodes are rescored. The baseline defect signatures this
  revision targets — discovery verifiedRecall 0.000 / sidecar
  inferenceHonesty 0.000 (`docs/evals/spot-instrumented-2026-07-06`, n=1
  per cell) — get citable successors only from the next pre-registered
  run on Goga's trigger.

## Considered and rejected

- **Adding `ghx tier2 …` to the "How to run ghx" example list.** Rejected.
  That list is the persona's canonical first-reach command surface
  (ADR-0029.1 D1 rationale); tier2 must never be a first move and is gated
  on allowed backends. The example invocations live inside the escalation
  step instead, so they carry their precondition with them.
- **Using a real repo in the discovery worked example.** Rejected as
  contamination: the live discovery target sets include BerriAI/litellm,
  Helicone/helicone, and Portkey-AI/gateway; a persona that names a target
  (or any real gateway-adjacent repo) would leak ground truth into the
  subject prompt and poison every future discovery measurement. The example
  is fictional (`acme/rate-limiter`) and shaped only to teach the citation
  form.
- **Implementing the ADR-0024.1 `EscalationPolicy` engine now and letting
  the runtime decide escalation.** Out of scope for a persona revision; the
  policy engine is its own pre-registered runtime slice. Persona doctrine
  and the declarative policy are designed to agree (same signals, same
  allowed-backends gate) so the later slice replaces judgment with policy
  without re-teaching the persona.
- **Report-sink validation rejecting verified discovery claims without
  `owner/repo:path` evidence.** Deferred, not rejected. The report sink is
  shared by repo-scoped turns, where repo-relative paths (no owner/repo:
  prefix) are the correct citation form; a discovery-aware validator needs
  the sink to know the ask's scope. Revisit with spot-check evidence after
  this doctrine lands.
- **Changing the discovery scorer to give partial credit for uncited
  reads.** Rejected outright: that is a measurement change, and the scorer
  is right — an uncited read is unauditable from the report alone. The
  subject must cite, not the scorer forgive.
