# 0016.3. Eval Observability, Profile Isolation, and Subject-Model Economics

## Status

Proposed 2026-07-04, after the first formal gate-run attempt was aborted twice
in one day. Blocks the ADR-0016.1 gate run: no gate data is valid until this
lands.

## Context

The first gate-run attempt (2026-07-04, `gate-run-2026-07-04`, quarantined as
`-INVALID-unauditable`) surfaced five holes. None of them are hypothetical —
each was observed live:

1. **Tool calls are opaque.** `client.go` records only `Title (Status)` at
   `tool_call` creation time — every captured entry reads `Terminal (pending)`.
   The `tool_call_update` that carries the resolved command and output is used
   solely for character counting (`ToolOutputChars`). The episode schema's
   `Actions`/`Observations` arrays (ADR-0016) exist but are always empty.
   Consequence: commands cannot be audited, and the episodes are worthless as
   training trajectories — which violates the ADR-0016 north star ("accumulate
   a gold mine of high-quality agent trajectories").

2. **The plain baseline can silently use ghx.** `ghx` is on the engineer's
   PATH (`/Users/goga/Library/pnpm/ghx`), the plain persona permits "your
   shell and the gh CLI" without forbidding ghx, and (1) makes actual usage
   invisible. A plain agent that discovers ghx corrupts G1/G3 — the
   comparison becomes unfalsifiable exactly where it must be airtight,
   including for future public/marketing use of the results (NORTH_STAR
   tenet: evals are how we know).

3. **Subject agents run inside the ghx repo.** `runner.go` sets the ACP
   session cwd to `os.Getwd()` — the eval package directory. Claude-backed
   adapters auto-load repository context (CLAUDE.md/AGENTS.md), so subject
   agents inherit this project's instructions and file tree. Episodes are not
   environment-neutral.

4. **No agent identity in artifacts.** Episodes record neither the subject
   model, nor the adapter package/version, nor the agent command. ADR-0016.2
   checklist item 4 ("identical agent command/model for all profiles") is
   currently unverifiable from artifacts. It also went unnoticed that the
   subject model was whatever the engineer's Claude Code default happened to
   be — observed: `claude-fable-5[1m]`, the most expensive available model,
   silently powering all three profiles.

5. **No live run visibility.** Runner stdout was piped through `tail`; run
   health was only observable via artifact mtimes. The first bad round burned
   20 minutes of all-zero episodes (bare `claude` fallback, no ACP handshake)
   before inspection of artifact *contents* caught it.

## Decision

### 1. Full tool-call trace capture (audit + training data)

Capture per tool call: ACP tool-call id, `kind`, title, raw input (the
command/arguments from `tool_call`/`tool_call_update` raw input), status
transitions, output size, and a bounded output excerpt (first 2 KB per call;
sizes always exact). Populate the episode's `Actions` (tool invocations) and
`Observations` (outputs) arrays that ADR-0016 specified. `Turn.ToolCalls`
keeps a human-readable summary, now with the resolved command instead of
`Terminal (pending)`.

### 2. Trace completeness now; OTel emission is its own architecture decision

The requirement that must land now is **capture completeness**: episode JSON
must record everything a trace format would need (tool-call ids, kinds, raw
inputs, status transitions, timestamps, outputs). That makes every token
spent on a live episode reusable — for audit, for training data, and for any
later trace export — regardless of how OTel emission is architected.

OTel emission itself (ADR-0016's plan) requires a real architectural
decision and is **deferred to ADR-0016.4**, which must weigh at least:

- **In-process OTel SDK** (`go.opentelemetry.io/otel` + file exporter):
  standard semantics, live spans, but a heavyweight dependency tree inside
  the ghx binary's module and a second source of truth next to episode JSON.
- **Hand-rolled OTLP JSON writer**: no dependency, but reimplements a spec
  and risks divergence from the "respect the open format" goal.
- **Offline exporter**: a converter that renders stored episode JSON into
  OTLP `traces.jsonl` after the fact. Zero runtime coupling, zero extra
  live-run cost, works retroactively on every episode captured after this
  ADR — but spans are reconstructed, not emitted live.

ADR-0016 already ruled that "the local artifact is the durable source of
truth; OTel traces are diagnostics, replay data, and future exporter input" —
so capture-first does not prejudge the emission architecture. Span/attribute
content must never contain secrets, whichever option wins.

### 3. Profile isolation (falsifiable baseline)

- Every episode runs in a fresh empty temp directory as cwd — no repository
  context leaks into any profile.
- The plain profile must run with `ghx` unreachable: the eval constructs a
  scrubbed PATH (standard system dirs plus required tools: shell, `gh`,
  `node`/`npx` for the adapter) or otherwise verifies `ghx` cannot resolve.
- Deterministic compliance checks over the captured commands (enabled by 1):
  a plain episode that invokes `ghx` is **invalid** (excluded from gates,
  rerun); a `ghx`-profile episode with zero `ghx` invocations is flagged; the
  verdict's data-sufficiency notes must list compliance results.

### 4. Agent identity metadata (checklist 4 made executable)

Record in each episode and in the run manifest: subject model, adapter
package and version, agent command (`GHX_EVAL_AGENT` value), and wrapper
script content hash. `EvaluateGates` refuses to mix identities in one run
(or labels the verdict invalid), turning ADR-0016.2 checklist item 4 from
prose into a check.

### 5. Subject-model economics (explicit, cheap, identical)

The wrapper (`scripts/eval-agent-acp.sh`) pins an explicit, token-efficient
subject model (sonnet-class) via environment for **all three profiles**.
Rationale: the sidecar thesis targets cheap specialized brains (ADR-0014.1);
benchmarking on a fable-class model both burns engineering quota (~90
episodes per gate run) and measures the wrong regime. Subject-agent model
choice is a benchmark design parameter owned by this ADR; it is unrelated to
CLAUDE.md's engineering model routing. Changing the subject model
mid-gate-run invalidates the run (identity check, 4).

### 6. Live progress and a read-only reporter

- The runner logs one line per completed episode to stderr (unbuffered):
  task, profile, turns, overall reward, main-agent chars, duration.
- A read-only reporter (`go run ./internal/sidecar/evals/cmd/evalreport
  <run-dir>`) prints: episode count vs expected, per-profile aggregates,
  per-task × profile matrix, running G1–G5 status with thresholds, and the
  PRELIMINARY/valid label. It only reads artifacts; it can run while a round
  is in flight and after it, and is the tool for humans asking "who is
  winning and is it valid yet."

## Run Economics Protocol (token stinginess as a rule)

Live episodes spend real agent-subscription tokens. Preliminary results —
however promising — never justify a full run. The spend ladder is:

| Stage | Cost | Purpose | Gate to next stage |
|-------|------|---------|--------------------|
| **V0 mock** | 0 tokens | Prove the framework itself: capture completeness, compliance checks, identity checks, reward math, gate logic — all against the mock agent | All `go test ./internal/sidecar/evals` green, including new capture/compliance/identity coverage |
| **V1 live smoke** | ~3 episodes, cheap model | Prove capture/isolation/identity end-to-end against a real adapter: commands visible, plain provably ghx-free, model recorded | Artifacts inspected by hand; no framework bug found |
| **V2 spot checks** | 1 task × profiles, on demand | Guide engineering iterations step by step; catch regressions cheaply | Engineer judgment |
| **V3 full gate run** | ~90 episodes | The pre-registered ADR-0016.1 verdict | **Explicit engineer trigger only** — never autonomous, and only when V0–V2 give no reason to distrust the framework |

The 2026-07-04 aborts are the cautionary tale for this table: episodes were
burned on a fable-class model before the framework could prove it wasn't
lying to us. False positives are worse than no data — a wrong "THESIS
SUPPORTED" would steer product and marketing; the framework must be shown
correct before results are believed, and engineering progress between spends
happens at V0–V2 prices.

## Consequences

- The `gate-run-2026-07-04` artifacts are invalid for gate purposes
  (unauditable compliance, unknown-cost fable-class subject model, repo-cwd
  contamination). Quarantined as `-INVALID-unauditable`; useful only as
  calibration. There is **no immediate gate-run restart**: the framework
  re-earns trust through V0–V2 above, and V3 waits for an explicit engineer
  trigger (restoring ADR-0016.1's original "not run autonomously" rule).
- Scoring semantics (rewards.go, gate thresholds) are intentionally
  untouched: this ADR adds capture, isolation, identity, and reporting.
  Correctness/evidence/compression math does not change, so no measured
  result is re-interpreted — there are no valid prior results.
- Episode JSON grows (bounded excerpts); traces.jsonl adds a second artifact
  stream. Both remain local-first and gitignored; curated evidence still goes
  to `docs/evals/`.
- Cheap-subject-model results will differ from any fable-class smoke
  intuition; that is the point — the measured regime now matches the product
  thesis.

## Implementation Notes

*(V0 mock-verified slice implemented 2026-07-04.)*

### Built and verified

- Full ACP tool-call capture now lands in episode JSON: per-turn
  `toolTraces`, episode-level `actions`, and episode-level `observations`.
  Traces record ACP tool-call ID, kind, title, raw input, status transitions
  with timestamps, exact output sizes, and bounded output excerpts (2048
  bytes). `Turn.ToolCalls` remains a human-readable summary, now resolved from
  raw command input when available.
- Direct and sidecar profiles both use the same trace contract. The sidecar
  path required a small runtime-only extension to `internal/sidecar`:
  `TurnResult` now carries `ToolTraces` and ACP initialize `AgentInfo`, and
  `sidecar.Config` has JSON-ignored `Cwd`/`Env` overrides for eval isolation.
  Public CLI configuration and behavior are unchanged.
- Every eval episode gets a fresh temp cwd. The plain profile inherits the
  full process environment for a fair baseline, but its `PATH` drops every
  directory that contains an executable `ghx` or `ghx.exe`. This keeps normal
  auth/keychain/toolbox behavior while making `ghx` unreachable by PATH. ghx
  and ghx-sidecar profiles inherit the normal environment unchanged.
- Gate evaluation now performs compliance and identity checks around the
  existing reward math and thresholds. Plain episodes that invoke `ghx` are
  marked invalid, excluded from aggregates, and noted in the verdict. ghx
  episodes with zero ghx invocations are noted but retained. Mixed agent
  identities mark the verdict invalid.
- Episode and run manifest identity now record agent command, ACP adapter
  name/version, subject model, best-effort adapter-exposed model metadata, and
  the sha256 of wrapper script paths. Subject model is read from
  `GHX_EVAL_SUBJECT_MODEL` in the eval process when present, otherwise
  best-effort parsed from the readable wrapper script defaults, otherwise
  recorded as `unknown` and noted as unverified by gate evaluation.
- `scripts/eval-agent-acp.sh` pins `ANTHROPIC_MODEL` to
  `claude-sonnet-5` unless already set, and mirrors that value into
  `GHX_EVAL_SUBJECT_MODEL`.
- The runner emits one unbuffered stderr progress line per completed episode:
  task, profile, turns, overall reward, main-agent chars, and duration.
- `internal/sidecar/evals/cmd/evalreport` is a read-only artifact reporter
  that works mid-run or post-run. It loads `manifest.json` when present,
  prints episode count vs expected, per-profile aggregates, task/profile
  matrix, G1-G5 status via the existing gate evaluator, validity/preliminary
  label, and compliance/identity notes.

### Evidence and test strategy

- V0 proof is entirely mock-backed: the mock ACP agent now emits real
  `tool_call` pending events plus `tool_call_update` completed events with raw
  `{command: ...}` input and tool output content. Tests assert trace fields,
  actions, observations, resolved summaries, identity capture, compliance
  exclusion, identity mixing, PATH isolation, and reporter rendering.
- `go test ./...` and `go vet ./internal/sidecar/evals/...` pass after the
  implementation. No live agent or eval episode was run.
- The adapter model-selection source was inspected with
  `npm pack @agentclientprotocol/claude-agent-acp@0.55.0`; the published
  `dist/acp-agent.js` chooses the current model from `ANTHROPIC_MODEL` before
  settings/default model fallback in `getAvailableModels`, so wrapper pinning
  is supported by package source rather than a live run.

### V1 live-smoke findings and V1.1 fixes

- V1 live smoke run
  `internal/sidecar/evals/.ghx-evals/runs/v1-smoke-2026-07-04` found that the
  symlink-minimal plain baseline broke Claude ACP authentication
  (`Authentication required`) and was an unfair baseline because it removed the
  normal Unix toolbox. V1.1 replaces it with full env inheritance plus
  path-directory filtering for executable `ghx`/`ghx.exe` only. Compliance
  detection was tightened to flag indirect invocations such as `npx ghx` and
  `npx -y @gkoreli/ghx`.
- V1 also showed `subjectModel` was missing from manifest identity because the
  wrapper-exported `GHX_EVAL_SUBJECT_MODEL` existed only inside the wrapper
  process. V1.1 resolves subject model in the Go runner from eval env, then
  wrapper defaults (`GHX_EVAL_SUBJECT_MODEL=...` or `ANTHROPIC_MODEL=...`),
  then `unknown`; unknown subject model now produces an identity note.
- Pending tool-call rendering showed `execute: {} (pending)` when adapters sent
  empty raw input before the update event. V1.1 falls back to the ACP title or
  tool-call ID in both eval and sidecar summaries.

### Deviations, schema notes, and uncertainty

- ADR text mentions `traces.jsonl` in consequences, but this V0 intentionally
  writes only enriched episode JSON plus `manifest.json`; OTel/trace export is
  still deferred to ADR-0016.4.
- Episode JSON changes are additive (`toolTraces`, `actions`,
  `observations`, `identity`, `invalid`, `exclusionReasons`), so old artifacts
  remain readable. New verdict JSON adds `valid`.
- Adapter subject-model recording is best effort: `GHX_EVAL_SUBJECT_MODEL` is
  authoritative for the harness, while ACP `AgentInfo.Meta` is only inspected
  for common model keys if an adapter exposes them. The Claude ACP adapter
  source confirms environment-based selection, but no live handshake was run
  to prove which model ID the backend ultimately resolved for an account.

### V1 closed (2026-07-04, live smoke ×2)

The first V1 smoke (`v1-smoke-2026-07-04`) caught three defects for ~3
episodes of spend: plain-profile boot failure (`Authentication required` —
the symlink-minimal PATH broke Keychain credential lookup, and was judged a
handicapped-baseline validity flaw besides), missing `subjectModel` in
identity (wrapper env never crosses the process boundary), and pending
summaries rendering as `execute: {}`. Fixes landed in `9e870c7` (plain now
inherits the full environment with only ghx-providing PATH dirs dropped;
subjectModel from eval env → wrapper parse → "unknown"+verdict warning;
`npx …ghx` compliance detection).

The verification smoke (`v1-smoke-2026-07-04.1`, hono-middleware × 3
profiles, sonnet subject) closed all V1 criteria: plain boots and produces a
genuine `gh api … | base64 -d` baseline (2 turns, 53,927 main-agent chars,
zero ghx invocations in captured commands — now provable); manifest records
`subjectModel: claude-sonnet-5`; every command visible with status
transitions and excerpts. PRELIMINARY n=1 gates: G1/G2/G3/G5 pass — G3
sidecar 3,962 vs ghx 77,603 chars (ratio 0.051 vs 0.35 threshold); the
sidecar also beat the *plain* baseline's context burden 13.6×. G4 fails on
repeat-read ratio (0.5 vs ghx 0.0) — consistent across both smokes:
the sidecar re-reads files across turns instead of reusing session memory.
That is the ADR-0014.1 evidence-ledger gap, tracked as the product follow-up
that blocks ADR-0017; it does not block V2/OTel framework work.

### Compliance detector refinement (2026-07-04, pre-registered pre-verdict)

Mid-gate-run, the new SPT report surfaced a compliance exclusion of
`ghx-mapengine_plain`: hand-inspection proved a **false positive** — every
"ghx" match was the `gkoreli/ghx` repo path inside legitimate `gh api`
commands; the plain agent never invoked the ghx binary. The detector
matches "ghx" as a substring anywhere in a command instead of as an
invoked binary, so any task targeting the ghx repository wrongly excludes
valid plain baselines (silently unbalancing G1/G3 in the sidecar's favor —
the exact bias class 0016.2 forbids). Refinement, pre-registered before
any verdict: a command is ghx usage only when `ghx` appears in command
position (start, or after a pipe/`;`/`&&`/`||`/`$(`/backtick) or as an
npx package invocation (`npx …ghx`); substrings inside arguments, URLs,
and repo paths do not count. Exclusion is verdict-time classification over
stored raw commands, so collected episodes are unaffected and the verdict
is recomputed over the same artifacts — no data discarded, no rerun.
