# 0023.1. Judge Scorer Decision

## Status

Accepted as architecture; **build gated behind the ADR-0022 merge** (the
judge emits through the shared visibility substrate) and **scores gated
behind calibration** (D5). Required before M9 per the eval-truthfulness
tenet (AGENTS.md; NORTH_STAR milestone note). Grounded in ADR-0023
(research memo, 25 sources); constraint numbers below reference it.

## The frame

The deterministic gates measure pre-registered fact recall; they decide
verdicts and always will (constraint 1). The judge answers the question
gates cannot: *was this good reconnaissance* — exploration quality,
evidence-groundedness, uncertainty honesty — for benchmark episodes and,
per the observability-as-substrate tenet (NORTH_STAR 2026-07-05), for
production sessions the same way. Real-world quality claims to customers
require both layers.

## Decisions

### D1. Two layers, one decider

Gates decide; the judge informs. Judge scores never flip a verdict.
Gate/judge disagreement is a first-class recorded signal: every verdict
gains a disagreement section (episodes where gates passed but the judge
scored below its calibrated "poor" threshold, and the reverse), and a
disagreement rate above a pre-registered bound (initially 15%) marks the
run's judge layer INVESTIGATE — quoted only with that label until the
disagreements are hand-reviewed (resolves ADR-0023 OQ-5).

### D2. Judge input: blind, structured, from committed artifacts

The judge reads an evidence bundle assembled from the episode artifacts —
question, accepted report JSON, tool-call titles + summaries, ledger,
turn thinking when captured — never the raw session transcript (TRAIL
evidence, constraint 2), and never full tool outputs. The bundle is
**profile-blind**: no `plain`/`ghx`/`ghx-sidecar` label, no agent
command, no model name reaches the judge, so it cannot brand-favor the
architecture we are selling. The bundle builder is deterministic and
unit-tested; the bundle is stored next to the score so every judgment is
reproducible from committed artifacts.

### D3. Rubrics: task-adaptive by authorship, not by LLM

Each task file gains an optional `judge` block: 2–5 task-specific
criteria written by the task author (seeded from `checks.expectedFiles` /
`checks.requiredClaims` plus what a correct exploration of that repo
looks like). These combine with a fixed core rubric of three dimensions:
evidence-groundedness (claims cite commands/files that support them),
exploration efficiency (no flailing, no redundant reads), and uncertainty
honesty (unverified things labeled unverified). LLM-generated rubrics at
eval time are rejected for now — a second nondeterministic call inside
the measurement stack (revisit after first calibration; ADR-0023 OQ-4).

### D4. Judge models: cross-family primary, committed versions

- Primary judge: a **non-Anthropic** frontier model (GPT-5.5-class via
  the OpenAI API already available in this setup) — the subject is
  Anthropic, so self-preference is structurally broken (constraint 6).
- Secondary judge: an Anthropic opus-class model on a 20% sample plus
  every episode the primary scores below threshold; family disagreement
  is reported, never averaged away.
- Per-episode absolute scoring uses rubric + k=3 self-consistency
  (cost-effective baseline per ADR-0023 Q6); profile A/B comparisons use
  swap-augmented pairwise on matched task pairs.
- Judge prompt, model ID, and parameters are committed artifacts; any
  change re-triggers calibration before scores are citable (same frozen
  measurement stack rule as the gates).

### D5. Calibration is the gate on the judge itself (binding)

No judge score is citable before: a hand-labeled gold set drawn from the
two committed gate runs (anomaly-filtered episodes; the founder labels
with written instructions committed alongside), agreement κ ≥ 0.6
against the labels, and the calibration run's artifacts committed under
`docs/evals/`. Below 200 labeled episodes the judge layer self-labels
PRELIMINARY regardless of κ (constraint 5, verdict-is-a-floor
discipline). Recalibration: on any prompt/model change, and scheduled
monthly while the judge is in active use.

### D6. Emission: extend the existing events, ride the shared substrate

Judge results extend `gen_ai.evaluation.result` events in the existing
reward-event emitter (never a new format — constraint 3), with
`gen_ai.evaluation.explanation` carrying the judge's reasoning summary
and the full reasoning as a content-log record. Judge invocations are
spans in the same session/run directory as the episodes they judge
(ADR-0022 substrate, constraint 10) — one viewer, one replay recipe.
Verify the exact v1.39.0 attribute YAML against the semconv repo at
implementation time (memo flag).

### D7. Scope guards

- Anomaly pre-filter: BLOCKED / WARN-noreport episodes are excluded
  (nothing to judge); safety remains a gate, never a judgment.
- Continuous mode (production sessions under `~/.ghx`): same judge, same
  rubric core, sampled cadence configurable — **default off until D5
  calibration passes**; it then becomes the first concrete step of the
  self-improving-sidecar tenet.
- Local-first: no hosted eval platform, no eval-service key; model APIs
  the setup already holds are acceptable. Steal rubric/prompt patterns
  from autoevals/promptfoo/DeepEval with attribution; adopt none as a
  runner.

## Considered and rejected

- **Judge as a gate or auto-blocker** — breaks pre-registration and
  invites optimizing to an uncalibrated critic. Rejected permanently.
- **Agent-as-a-Judge with tool access** (judge re-runs `ghx read` to
  verify claims): promising but costly; deferred as a pre-registered
  experiment after first calibration, comparing κ uplift vs cost on the
  gold set (ADR-0023 OQ-2).
- **LLM-generated rubrics at eval time** — see D3.
- **Dual-format emission for Phoenix's judge UI** — wait for Phoenix to
  adopt the official semconv (open-source-leverage tenet; ADR-0023 OQ-7).
- **Single same-family judge** — self-preference; rejected by D4.

## Sequencing

1. ADR-0022 merges (substrate).
2. Gold-set labeling protocol + founder labeling session (can start
   immediately after; independent of code).
3. Bundle builder + rubric blocks + judge runner + emission (delegable).
4. Calibration run → κ report committed → judge layer goes live.
5. Then M9 exports may use judge labels as trajectory quality signals.
