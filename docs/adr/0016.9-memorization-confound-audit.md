# 0016.9. Memorization Confound Audit

## Status

Proposed. Pre-registration draft for a measurement-only audit. This ADR
must land before any closed-book scores are run, inspected, summarized, or
used to revise the task corpus.

## Context

The ADR-0016 eval corpus currently targets famous repositories:

- `gin-gonic/gin` (`gin-routing`)
- `pallets/flask` (`flask-routing`)
- `expressjs/express` (`express-router-location`)
- `honojs/hono` (`hono-middleware`)
- `openai/openai-node` (`openai-node-streaming`)
- `gkoreli/ghx` (`ghx-mapengine`)

The fixtures live at `internal/sidecar/evals/testdata/tasks/*.json`.
Their checks are deterministic file/symbol/claim matches loaded through
`LoadTasks` and scored by `ComputeRewards` / `correctnessReward` in
`internal/sidecar/evals/rewards.go`.

Threat: the subject model (`claude-sonnet-5`) may answer some
pre-registered checks from training data without performing repository
exploration. If so, open-book scores overstate reconnaissance quality.
The inflation risk is broad, but it especially affects the `plain`
baseline because the observed plain correctness is already high
(~0.90). A plain agent that can recall common framework internals from
model weights is not proving that ordinary tool-based exploration matched
the sidecar.

This is not a failure of deterministic scoring by itself. It is a
construct-validity risk: the gate may be measuring "does the model already
know Flask/Gin/Express/Hono/OpenAI Node internals?" instead of "does this
workflow explore a repository better?"

## Decision

Add a closed-book memorization probe for every task in the current eval
corpus.

For each task, invoke the same subject model with:

- no tools
- no repository access
- no ghx, gh, shell, web, read, or MCP tools
- no sidecar persona
- no direct-profile preamble
- no task metadata except the exact eval question text

The model's answer is persisted as a normal audit artifact and scored
using the same deterministic checks path as open-book episodes: construct
an `evals.Episode` whose `TurnRecord.Text` is the model answer, then call
`ComputeRewards(task, ep)`. The primary reported metric is
`rewards.correctness`, because memorization confounds the answer checks.
Other reward components may be stored for recomputability, but they must
not be interpreted as closed-book exploration quality.

## Probe Harness

Implement a small harness under `internal/sidecar/evals` with the
`agent_e2e` build tag, or an equivalent script that imports the same Go
package and calls the same exported functions. The preferred form is a
Go test because it can reuse the existing eval runner identity and ACP
client plumbing without creating a second measurement stack.

Required behavior:

1. Load tasks with `LoadTasks("testdata/tasks")`.
2. For every task, run `n = 5` closed-book trials.
3. For single-turn tasks, send exactly `task.Turns[0]`.
4. For multi-turn tasks, send each `task.Turns[i]` as its own prompt in
   the same no-tool session, with no synthetic recap or added
   instructions. This preserves the original turn wording while still
   testing whether the model can answer the eval sequence from memory.
5. Capture only assistant text. Tool calls are a harness failure.
6. Build an episode with profile value `"closed-book"`, `TaskID`, `Repo`,
   snapshotted `Checks`, one `TurnRecord` per task turn, no actions, no
   observations, no report, and no tool calls.
7. Score with `ComputeRewards(task, ep)`.
8. Persist the raw episode JSON and a run summary.

The harness must not call `runDirectEpisode` unchanged, because current
direct-profile sessions are created without `_meta.claudeCode.options`.
Closed-book requires explicit session steering.

## Subject Invocation

Use the existing ACP wrapper path and subject model identity, pinned the
same way as live evals (`GHX_EVAL_SUBJECT_MODEL=claude-sonnet-5` or the
current wrapper equivalent).

Create the ACP session with `_meta.claudeCode.options.tools` set to the
empty array:

```json
{
  "claudeCode": {
    "options": {
      "settingSources": [],
      "strictMcpConfig": true,
      "tools": [],
      "allowedTools": [],
      "model": "claude-sonnet-5",
      "thinking": { "type": "disabled" }
    },
    "emitRawSDKMessages": true
  }
}
```

Important implementation note: `sidecar.SessionOptions.Tools` currently
has `json:"tools,omitempty"`. Marshaling `Tools: []string{}` through that
struct omits the field, and omitted tools means "all tools" per
`internal/sidecar/session_options.go`. The closed-book harness must either
build the `_meta` options as a raw map that preserves `tools: []`, or first
change the steering type in a separately reviewed implementation so an
empty tools list serializes as an explicit empty array. A closed-book run
where `tools` is omitted is invalid.

`allowedTools` must also be an explicit empty list. The report-sink
`submit_report` tool is not available in this probe; answers are plain
assistant text.

## Artifacts

Committed audit results land under:

```text
docs/evals/memorization-audit/
  README.md
  manifest.json
  closed-book-summary.json
  episodes/
    <task-id>_closed-book_trial-<n>.json
```

The manifest records:

- ADR id: `ADR-0016.9`
- run id and timestamp
- git commit
- task corpus hash
- wrapper SHA256
- adapter name/version
- subject model requested and adapter-reported subject model
- number of trials per task (`n = 5`)
- exact session options, including proof that `tools: []` and
  `allowedTools: []` were sent
- scoring code commit

The summary records, per task:

- mean closed-book correctness
- median closed-book correctness
- max closed-book correctness
- standard deviation
- all trial episode ids
- open-book reference means used for comparison, with source run id
- `exploration_signal = open_book_correctness_mean - closed_book_correctness_mean`

Open-book reference means must come from a named committed run, not from
memory or an uncommitted local scratch directory.

## Interpretation Rules

Closed-book correctness is a contamination probe, not a new leaderboard.

For each task:

- If closed-book correctness is near open-book correctness, the task is
  flagged as primarily measuring recall rather than exploration.
- If the open-book minus closed-book gap is large, that gap is the
  exploration signal the task actually measures.
- If closed-book correctness is high for all profiles' open-book scores,
  the task cannot support claims about workflow advantage without a
  replacement or a harder variant.
- If closed-book correctness is high but open-book sidecar still beats
  direct profiles on evidence, compression, memory, or judge trajectory
  quality, that can be reported only as a non-correctness advantage. Do
  not cite the task's correctness as exploration evidence.
- If closed-book answers hallucinate stale paths that deterministic checks
  reject, the task remains useful as a freshness/honesty check, but the
  audit should record that usefulness explicitly.

Pre-registered thresholds:

| Closed-book result | Label | Required action |
|---|---|---|
| mean closed-book correctness >= 0.80 | recall-dominated | replace task before using it in future citable correctness gates |
| mean closed-book correctness within 0.10 absolute of open-book mean | low exploration signal | replace or rewrite task; do not cite it as exploration evidence |
| max closed-book correctness = 1.00 and mean >= 0.60 | memorization-risk | keep only with explicit caveat or replace in the next corpus revision |
| mean closed-book correctness < 0.40 and open-book gap >= 0.30 | exploration-bearing | acceptable for future task corpus, subject to normal ground-truth checks |

The corpus-level report must include both raw open-book correctness and
memorization-adjusted correctness:

```text
memorization_adjusted_correctness = open_book_correctness - closed_book_correctness
```

This adjusted score is diagnostic only. It does not retroactively rescore
ADR-0016.1 gate verdicts unless a future ADR explicitly changes the gate.

## Future Task Authoring Rule

Every new or replacement eval task must pass a closed-book acceptance check
before it enters a citable gate corpus.

Acceptance bar:

- `n = 3` minimum for task authoring smoke
- mean closed-book correctness < 0.40
- max closed-book correctness < 1.00 unless the task is explicitly labeled
  as a hallucination/freshness trap
- no required deterministic check may be satisfied by generic framework
  lore alone

Preferred replacement tasks should target less-famous repositories, recent
commits, project-specific internal names, or cross-file relationships that
require inspecting the current default branch. Popular repos are still
allowed, but only when the check asks for details unlikely to be stable
training-data recall.

## Considered and Rejected

- **Relying on the plain baseline as the memorization detector.** Rejected.
  Plain is an open-book profile with tools available; high plain
  correctness cannot separate exploration from recall.
- **Asking the model whether it used memory.** Rejected. Self-report is
  not evidence, and it invites the exact truthfulness problem this audit
  is meant to avoid.
- **Changing deterministic correctness thresholds immediately.** Rejected.
  The audit measures a confound first. Gate changes require a separate
  pre-registered ADR.
- **Using a judge to decide whether an answer was memorized.** Rejected for
  the primary audit. The deterministic closed-book score is reproducible
  from committed artifacts. A judge may later explain qualitative patterns,
  but it is not the gate for this confound.
- **One closed-book trial per task.** Rejected. Closed-book answers are
  stochastic; `n = 5` matches the current gate-run trial count and gives
  a small but useful distribution.
- **Adding a "do not use prior knowledge" instruction.** Rejected. The
  probe is explicitly measuring what the model can answer from its
  weights. Extra instruction text changes the prompt and creates another
  compliance variable.
- **Disabling only Bash/Read while leaving MCP/report tools available.**
  Rejected. The probe is closed-book, not "reduced tool." `tools: []` and
  `allowedTools: []` are mandatory.

## Verification Plan

- Unit test that the closed-book session metadata serializes with explicit
  `tools: []` and `allowedTools: []`.
- Harness test with the mock ACP agent proving any tool-call notification
  fails the closed-book episode.
- Offline scorer test constructing a closed-book episode from fixed text
  and verifying `ComputeRewards` matches the same answerText/checks path
  used by normal episodes.
- Live audit run with `agent_e2e`, committed under
  `docs/evals/memorization-audit/`.
- README includes the exact command used, environment variables, wrapper
  identity, and per-task interpretation labels.
