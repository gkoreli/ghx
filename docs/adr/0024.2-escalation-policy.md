# 0024.2. Escalation Policy Engine — Declarative Tier Decisions, Recorded

## Status

Pre-registered before implementation; accepted on merge.

This is the M7 slice-3 ADR under `docs/adr/0024.1-escalation-tiers-decision.md`
("Escalation Policy", "Visibility Contract", "Implementation Shape"). Slices
1–2 landed the Tier-2 substrate (snapshot/cache, codemap, ast-grep, repomap)
and the `ghx tier2 ...` CLI surface. This slice lands the **policy engine and
the recorded decision**: a sidecar turn's tier escalation must be explainable
from a recorded rule evaluation over named observables — never from vibes
(AGENTS.md "Visibility and Truthfulness"; NORTH_STAR capability 1: "which tier
answered is always visible in the report and traces"; capability 3: "every
escalation decision ... captured as OTel traces and reports").

This ADR does **not** change eval scoring, detectors, rewards, gates,
thresholds, episode definitions, or ground truth. It does not change the
sidecar persona (`prompt.go`) — the persona revision that teaches the agent
`ghx tier2` is pre-registered separately as ADR-0029.2 and sequenced by the
orchestrator between runs.

## Context

ADR-0024.1 chose the escalation surface implicitly by its evidence contract:
Tier-2 evidence cites `ghx tier2 codemap ...` commands, and the persona
"already has `AllowedBackends` ... and says to name deeper backends when
remote evidence is insufficient". The sidecar agent reaches Tier 2 the same
way it reaches Tier 1 — by running a ghx command with its shell tool. There
is no runtime interception point inside a single ACP prompt turn: the runtime
sees the turn's tool activity only when the turn ends, and all production
telemetry is assembled post-hoc from turn structures (`emit.go`, ADR-0022 D2).

That shapes what "the runtime MAY escalate" honestly means in v1:

- The **hard gate** is `AllowedBackends`: Tier 2 is available to the agent
  only when `local` is allowed (and the persona, once ADR-0029.2 lands, only
  teaches the escalation move under that gate).
- The **declarative policy** is evaluated by the runtime from recorded
  observables and the decision is persisted in three places (span, jsonl,
  report provenance). The policy evaluation is deterministic and recomputable
  from committed artifacts, so any auditor can re-derive the decision.
- **Reconciliation, not silent correction**: the record states both what the
  policy decided and what the agent actually did (`escalationUsed`). An agent
  that used Tier 2 when the policy did not allow it is a *visible anomaly* in
  `tier-decisions.jsonl`, not something the runtime hides or rewrites.

## Decisions

### D1. Policy model v1 — pure, table-driven, versioned

`internal/sidecar/tier2/policy.go` ships the ADR-0024.1 model verbatim:
`EscalationPolicy{Version, Signals, Rules}`, `EscalationSignal`,
`EscalationObservations`, `EscalationDecision`. `DefaultPolicy()` returns
policy **`v1`** with the seven pre-registered signals and two rules:

| Rule | Fires when |
|---|---|
| `hard-signal` | ≥ 1 of `question.cross_file_dependency`, `question.precise_reference` |
| `soft-pair` | ≥ 2 of `remote.search_exhausted`, `remote.symbol_absent_after_maps`, `remote.candidate_ambiguous`, `remote.import_chain_invisible`, `answer.low_confidence_remote_only` |

`Evaluate(obs)` is a pure function: it fires signals from observations,
applies the rules, and returns an `EscalationDecision` with
`FromTier: "tier1"`, `ToTier: "tier2"`, the fired signal/rule IDs, the full
observations, and a human-readable reason. `Allowed` is true only when a rule
fired **and** the `local` backend is allowed. When a rule fires but `local`
is absent, `Allowed` is false and the reason names the blocked backend — the
report must surface it in `uncertainty`/`nextReads` and must not fake a
Tier-2 answer (ADR-0024.1 "Initial rule").

`AllowedBackends` spelling (resolving the ADR-0024.1 open question): the
grant is **`local`** — one entry that permits all `local:*` structural
backends. Canonical per-tool IDs (`local:codemap`, `local:ast-grep`,
`local:repomap`) remain the report/ledger vocabulary. Any `local:*` entry in
`AllowedBackends` is also accepted as a narrower grant.

Later policy changes bump the version and must be ADR'd before a citable run
(ADR-0024.1).

### D2. Observation derivation v1 — deterministic, from recorded artifacts

The v1 runtime derives `EscalationObservations` from artifacts it already
records, so every fired signal is recomputable:

- `question.cross_file_dependency` / `question.precise_reference` — fired by
  case-insensitive, word-boundary phrase tables over the question text,
  pre-registered here and mirrored exactly in `policy.go`:
  - cross-file dependency: `imports`, `imported by`, `import graph`,
    `depends on`, `dependency`, `dependencies`, `dependents`,
    `blast radius`, `what breaks`, `breaks if`, `would break`, `fan-in`,
    `fan-out`, `who calls`, `what calls`.
  - precise reference: `call path`, `call chain`, `call sites`,
    `callers of`, `callees`, `implementors`, `implementers`,
    `who implements`, `what implements`, `implementations of`,
    `definition of`, `where defined`, `references to`, `referenced by`,
    `all references`.
- `remote.search_exhausted` — fired when ≥ 2 observed `ghx search` commands
  were not followed by any `ghx read` or `ghx inspect` command before the
  next `ghx search` (or turn end). Commands come from the turn's tool traces
  (the same `RawInput` extraction the evidence ledger uses), so the count is
  recomputable from `traces.jsonl` / the saved `actualCommandLedger`.
- `answer.low_confidence_remote_only` — fired when the accepted report has a
  non-empty `uncertainty` AND neither its `backendsUsed` nor the observed
  commands show any `local:*`/`ghx tier2` evidence.
- `remote.symbol_absent_after_maps`, `remote.candidate_ambiguous`,
  `remote.import_chain_invisible` — **not runtime-derivable in v1**: they
  require semantic judgment about search/read outcomes the runtime cannot
  recompute deterministically. The evaluator supports them (they are policy
  signals with unit-tested predicates over explicit observation fields), but
  the v1 runtime never sets them; they fire only when a future surface
  supplies agent-declared observations. Recording a signal the runtime
  guessed at would be a fake observable — worse than an honest gap.

### D3. Every turn records a tier decision, in three places

One decision record per Ask turn — **including negative decisions** (no
signals fired, or fired-but-blocked) and **including failed turns**: negative
results are committed evidence, and failed explorations need auditing most
(ADR-0022, ADR-0027 D3).

1. **Trace**: a `ghx.tier.decision` span, child of `sidecar.turn`, emitted
   through the shared post-hoc emit path (`emit.go`), timestamped at turn
   start so it precedes tool spans in the timeline. Attributes (ADR-0024.1
   "Visibility Contract" plus reconciliation):

   ```text
   ghx.tier.policy.version   ghx.tier.from        ghx.tier.to
   ghx.tier.allowed          ghx.tier.signals     ghx.tier.reason
   ghx.tier.used             ghx.tier.used_source ghx.tier.escalation_used
   ghx.repo.full_name
   ghx.repo.ref  ghx.repo.sha  ghx.clone.strategy  ghx.clone.cache_hit
   ghx.clone.sparse_paths.count      (clone attrs: see D5)
   ```

2. **Session artifact**: one JSON line appended to
   `~/.ghx/sessions/<session>/tier-decisions.jsonl` per turn:
   `{time, session, repo, turn, decision{policyVersion, fromTier, toTier,
   allowed, firedSignals, firedRules, observations, reason}, tierUsed,
   tierUsedSource, runtimeDerivedTierUsed, escalationUsed, clone?}`.
   Append failures degrade to a stderr warning and never fail the ask
   (ADR-0022 emission contract).

3. **Report provenance**: `tierUsed` on the report (D4).

Honest deviation from ADR-0024.1's "emit ... before Tier 2 runs": with the
shell surface, Tier-2 commands run *inside* the ACP turn, so v1 evaluates and
records the decision when the turn's artifacts are assembled — post-hoc,
deterministic, recomputable. Inline pre-gating (runtime intercepting the
escalation before the tool runs) belongs to the daemon-owned orchestration
slice, where the runtime owns warm tool lifecycles (ADR-0030). The span's
position (turn start) preserves trace readability; the ADR trail preserves
the truth about when evaluation actually happens.

### D4. `tierUsed` provenance — agent value preserved, runtime backfill labeled

- The runtime always derives `runtimeDerivedTierUsed` from observed commands:
  `tier2` if any `ghx tier2 ...` command ran; else `tier1` if any other
  `ghx ...` command ran; else `tier0` (answered from session memory alone).
- An agent-declared `report.tierUsed` is **never overwritten**
  (`tierUsedSource: "agent"`); disagreement with the derived value stays
  visible in the jsonl record as an anomaly.
- When the report omits `tierUsed` (every report until ADR-0029.2 lands), the
  runtime backfills it with the derived value and records
  `tierUsedSource: "runtime"`. This keeps NORTH_STAR's "which tier answered
  is always visible in the report" true now, without pretending the agent
  declared it. `ValidateReport`'s canonical-tier check (slice 1) already
  covers the backfilled values.
- `escalationUsed` (whether any `ghx tier2` command was observed) is recorded
  alongside; `escalationUsed && !decision.allowed` is the loud anomaly shape.

### D5. Clone provenance on the decision — parsed, best-effort

The Tier-2 CLI prints its pre-tool provenance block to stderr
(`tier2 snapshot: repo=… ref=… sha=…`, `tier2 clone: strategy=… cache=… path=…`,
`tier2 sparse: …` — slice 1). When Tier 2 ran via shell, the runtime parses
the first such block out of the turn's recorded tool output
(`tier2.FindProvenance`, the exact inverse of `Provenance.Lines`, living next
to it so the format has one owner) and attaches it to the decision record and
the `ghx.repo.ref/sha` + `ghx.clone.*` span attributes. This is best-effort:
tool output excerpts are bounded and adapter-dependent, so the clone attrs
are omitted when the block is not visible — an honest gap, never a guessed
value. The authoritative provenance remains the snapshot metadata and the
recomputable `ghx tier2` command itself.

## Not in this slice

- **Persona revision** — pre-registered as ADR-0029.2 with exact text; not
  applied to `prompt.go` here. Until it lands, agents do not know `ghx tier2`
  exists, so live `escalationUsed` stays false and decisions are
  policy-evaluation records only. That is the correct sequencing: the
  measurement surface lands before the behavior change.
- **Agent-declared observations** (the three v1-underivable soft signals).
- **Inline pre-gating / daemon orchestration** of Tier-2 tool runs.
- **Eval scoring of tier decisions** — any detector or reward reading
  `tier-decisions.jsonl` needs its own pre-registered ADR.

## Considered and Rejected

- **Evaluate the policy inside the `ghx tier2` CLI subprocess**: rejected.
  The subprocess cannot see the turn's remote-insufficiency observables
  (failed searches, report confidence); it would gate on question shape only
  and the decision record would be split across processes.
- **Let the runtime guess the three semantic soft signals from trace
  heuristics**: rejected — fake observables poison the audit surface.
- **Overwrite an agent-declared `tierUsed` with the derived value**:
  rejected. Runtime metadata may correct the record around the report
  (precedent: `actualCommandLedger`, ADR-0029 D5), but the agent's claim is
  itself evidence; divergence is recorded, not erased.
- **Record decisions only when escalation fires**: rejected — negative
  decisions are the baseline that makes positive ones measurable, and the
  visibility tenet commits negative results.
- **Block the ask when `escalationUsed && !allowed`**: rejected for v1. The
  evidence already exists; destroying the answer punishes the user, not the
  policy violation. The anomaly is recorded loudly instead.

## Verification Plan

- Policy matrix unit tests: each hard signal alone escalates; each soft
  signal alone does not; every soft pair escalates; hard signal with `local`
  absent → `Allowed=false`, reason names the blocked backend; decision JSON
  round-trips with `policyVersion` intact (ADR-0024.1 "policy-version
  serialization").
- Phrase-table tests including word-boundary negatives ("important" must not
  fire `imports`).
- Derivation tests: search-without-accepted-read counting, low-confidence
  remote-only, tier derivation (`tier0`/`tier1`/`tier2`), provenance parsing
  round-trip against `Provenance.Lines`.
- Emission tests through the real Ask path: `ghx.tier.decision` span with
  required attributes in `traces.jsonl`; `tier-decisions.jsonl` appended;
  failed-turn path still records a decision.
- `tierUsed` round-trip: agent-declared preserved end-to-end; empty →
  runtime backfill visible in the returned report, saved report artifact,
  jsonl, and span.
- `go vet ./...`, `go test ./...` (real exit codes), `-race` on
  `internal/sidecar` and `internal/sidecar/tier2`.

Live-eval verification follows the spot-check default (CLAUDE.md "Eval
Verification Routing"); no full gate run is triggered by this slice.
