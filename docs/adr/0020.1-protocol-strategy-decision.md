# 0020.1. Protocol Strategy Decision

## Status

Accepted. Architecture decision built on ADR-0020 (landscape research +
source-level steering recon, both 2026-07-05), the north star (P1–P4 path,
"Protocols are stepping stones" tenet with its four pre-registered exit
triggers, commit 1620b2e), and the founder's direction: adopt whatever
serves; never reinvent the wheel; the boundary and the brain are ours.

## The frame

The durable asset is the **boundary contract** — English question in,
compact evidence report out, specialist opacity, full traceability — plus
the brain behind it. Every wire underneath is an adopted stepping stone.
ADR-0020 confirms the industry is converging on exactly this layering
(MCP for tools, A2A for agent delegation, harness SDKs below), and that
nothing out there ships our contract: the evidence-shaped report schema
and SPT measurement discipline have no found equivalent. So the strategy
question is never "which protocol is our identity" but "which adopted
layers serve the contract cheapest right now."

## Decisions

### D1. Stay on ACP for the sidecar runtime; no protocol migration

M4 proved the thesis over ACP (all five gates, 25× compression). None of
the four exit triggers has fired — and ADR-0020's addendum shows Triggers
2 and 3 were *overestimated*: the shipped adapter grants session-level
steering we simply never used. Migration now would be a rewrite itch, not
evidence. ACP stays until a trigger fires; Trigger 4 (custom-model
serving, M10) remains the expected forcing function.

### D2. Exploit the full ACP session steering surface (the immediate build)

Rewire `internal/sidecar` session creation to use what
`claude-agent-acp@0.55.0` already forwards (evidence: ADR-0020 addendum,
file:line-cited):

1. **Persona → system prompt.** The sidecar persona/doctrine moves from
   per-turn user prompt text to `_meta.claudeCode.options.systemPrompt`
   (custom string). `BuildPrompt` splits into stable system persona vs
   per-turn question + ledger delta. Direct SPT gain: cacheable, stable
   position, out of the user-message stream.
2. **Isolation by default.** `settingSources: []` (no host settings
   inheritance), `strictMcpConfig: true`, `tools` allowlist scoped to
   what the persona actually needs (shell for ghx, read; no editor
   tools). This closes the ADR-0016.3 leak at the source instead of at
   runner workarounds. `permissionMode` via `SetSessionMode` post-create
   (creation-time value is overwritten by the adapter — recon caveat).
3. **Mechanical budgets.** `--depth cheap|normal|deep` maps to
   `maxTurns`/`thinking`/`effort` options instead of prompt-text
   honor-system phrasing.
4. **Model pinning.** `options.model` set per session from sidecar
   config/eval wrapper — the silent-wrong-subject-model failure mode
   becomes structurally impossible.
5. **Audit channel.** `emitRawSDKMessages` on for eval runs (labeled
   adapter-specific in artifacts), off by default in production.

Accepted cost: this steering is adapter-specific, not portable ACP. That
is acceptable because the adapter is already our compatibility layer and
the portable asset is the boundary contract (D1 frame). If we ever swap
adapters, we re-derive steering from that adapter's surface; the spec-level
fallback (prompt text) always works.

**Measurement rule (binding):** D2 changes the sidecar product, therefore
measurement conditions. It lands on a branch, is smoke-validated, and gets
a pre-registered re-run of the ADR-0016.1 gate suite before any of its
numbers are quoted. Expectation (recorded per the verdict-is-a-floor
tenet, never citable until measured): correctness and SPT floors rise.
Sequencing: after the ADR-0018 observability merge, so the re-run's traces
carry thinking + content and the comparison is fully auditable.

### D3. A2A is the anticipated third surface — demand-gated, not now

ADR-0020's OQ-4 asked whether M5 should ship an A2A AgentCard. Decision:
not yet. The north-star filter fails today: no agent in our adoption loop
(Claude Code dogfooding, MCP-speaking mains) consumes A2A, so an AgentCard
removes nothing from any real main agent's context. But A2A is
architecturally the industry home of our delegation pattern (150+ orgs,
LF governance, task lifecycle + artifacts + discovery), so it is the
*expected* external surface once an orchestrator-shaped demand signal
appears (a dogfood friction entry, a user request, or an integration
partner). Pre-registered trigger: first concrete A2A-speaking consumer.
The recon-service boundary (ADR-0019) maps cleanly when it fires:
question → A2A Task, report → typed Artifact, AgentCard = the one small
skill. Watch item: the rumored Q3 2026 MCP/A2A joint spec (unverified,
ADR-0020) — reassess on publication.

### D4. P4 harness: criteria now, choice later

Choosing between Claude Agent SDK and OpenAI Agents SDK today would
decide a fast-moving space years early on stale facts. Instead, the
binding evaluation criteria for the M9/M10-era harness ADR:

1. serves custom-trained weights first-class (vLLM behind an
   Anthropic-Messages or OpenAI-compatible facade is the verified
   serving pattern either way — ADR-0020 Q4);
2. full context-assembly and tool-registry control;
3. official OTel GenAI conventions emission (ours per ADR-0018, or
   native + our schema riding along);
4. does not invert the Go-native product architecture — a harness may be
   a subprocess or a thin service beside the Go core, never a rewrite of
   it (ADR-0010 rule).

M9 training exports stay harness-neutral (official formats only), so this
deferral costs nothing.

### D5. ADR-0018 continues on the ACP path, unchanged

OQ-5 resolved: the custom Go OTLP-file exporters (traces/logs/metrics,
spec-exact) remain the emission path — SDK-native telemetry is not
reachable through the ACP boundary today, and because our emission is
official GenAI semconv, a future harness swap changes the producer, not
the schema. Steal naming/shape ideas from the community Claude-SDK GenAI
instrumentor (ADR-0020 Q3) where useful, with attribution.

### D6. Deferred with pointers

- **AgentGateway** (LF, Apache 2.0): evaluate for M7 tool consolidation
  (ghx CLI + codemap + local tools behind one MCP endpoint) before
  building any aggregator — open-source-leverage tenet applied forward.
- **acp-go-sdk v0.13.0 → v0.13.5**: routine bump alongside the D2 work
  (verify changelog, run suite); not urgent, pinned versions are healthy.
- **Devin's Critic pattern**: feeds the judge-scorer ADR (adversarial
  review of the sidecar's own reports), noted for that thread.

## Considered and rejected

- **Migrate the boundary to A2A now**: fails the north-star filter (no
  consumer), abandons a working, measured runtime for governance
  aesthetics. Rejected; revisit on the D3 trigger.
- **Author a ghx sidecar protocol**: prohibited by the stepping-stones
  tenet and open-source-leverage tenet. Rejected permanently.
- **Jump to an agent-SDK harness today (pre-empt P4)**: none of the four
  exit triggers has fired; D2 dissolves most of the pressure that made
  the jump tempting; the M4-proven runtime would be discarded mid-stream.
  Rejected until a trigger fires.
- **Treat `allowedTools` as the isolation mechanism**: recon-verified to
  be auto-approve, not an allowlist — using it would *widen* the surface
  while appearing to narrow it. `tools` + `disallowedTools` are the real
  controls.

### Captured _meta JSON (depth=normal, eval-mode=false)

```json
{
  "claudeCode": {
    "options": {
      "systemPrompt": "<persona text — BuildPersonaSystemPrompt() output>",
      "settingSources": [],
      "strictMcpConfig": true,
      "tools": ["Bash", "Read"],
      "maxTurns": 8,
      "thinking": { "type": "enabled", "budgetTokens": 2048 },
      "effort": "medium",
      "model": "<empty omitted / value from Config.Model>"
    }
  }
}
```

In eval mode `"emitRawSDKMessages": true` is added at the `claudeCode`
level — a **sibling** of `options`, matching the adapter's read path
(`sessionMeta?.claudeCode?.emitRawSDKMessages`), not inside `options`.

Shape corrections found in Fable's audit against the shipped
`claude-agent-acp@0.55.0` + `claude-agent-sdk` sources (2026-07-05):
`thinking` is the SDK ThinkingConfig object (`{"type":"disabled"}` /
`{"type":"enabled","budgetTokens":N}`), never a bare number; the effort
enum is `low|medium|high|xhigh|max` — `"normal"` does not exist;
`emitRawSDKMessages` placement as above. The worker's initial cut had
all three wrong, which the exact-shape unit tests now pin.

### Depth → budget mapping

| depth | maxTurns | thinking | effort |
|---|---|---|---|
| cheap | 12 | disabled | "low" |
| normal (default) | 24 | enabled, 2048 | "medium" |
| deep | 48 | enabled, 4096 | "high" |

Rationale: the persona's command budget (4/8/extended) is the operative
budget; `maxTurns` is a hard safety net at ~3× it. It cannot sit near the
command count: an SDK turn is every assistant/tool cycle, and hitting the
cap is a hard adapter error ("Reached maximum number of turns") that
destroys the exploration before the report — observed live 2026-07-05 in
spot-2026-07-05-d2-adr21 (flask-routing and openai-node-streaming died at
the original maxTurns=8; hono-middleware survived). Corrected same day.
Thinking tokens are conservative. Adjust after confirmatory re-run.

Open live finding (three runs consistent): the adapter emits zero
agent_thought_chunk even with thinking {"type":"enabled"} — debug via the
emitRawSDKMessages channel during the confirmatory re-run.

### Implementation decisions

1. **settingSources serialization**: `SessionOptions.SettingSources` is
   `[]string` with no `omitempty` tag so it serializes as `[]` not absent.
   This is required — absent means "use adapter default [user,project,local]".

2. **allowedTools not used**: Per ADR-0020.1 "Considered and rejected":
   `allowedTools` is auto-approve, not an allowlist. `tools` is the real
   allowlist. Only `Bash` and `Read` are in the allowlist.

3. **permissionMode not set at creation**: Per the ADR addendum, the adapter
   overwrites `permissionMode` at creation time. If a mode is needed post-create,
   use `SetSessionMode` (acp-go-sdk `client_gen.go:304`). Current code does
   not call `SetSessionMode` post-create — the `denyClient` handles permission
   logic at the ACP protocol layer.

4. **EvalMode vs GHX_EVAL_SUBJECT_MODEL**: The eval runner sets `EvalMode:true`
   on `sidecar.Config` and reads `GHX_EVAL_SUBJECT_MODEL` via `resolveSubjectModel`
   to populate `Config.Model`. The identity label (`ep.Identity.SubjectModel`)
   continues to be set from the initialize response and the env var separately —
   they are independent signals.

5. **acp-go-sdk v0.13.5 changelog**: No breaking changes to our call sites.
   `Logout` promoted from unstable to stable in `Agent` interface — only
   required mockagent update. `UnstableSetSessionModel` removed (unused).
   `UnstableSetProviders` renamed to `UnstableSetProvider` (unused).
