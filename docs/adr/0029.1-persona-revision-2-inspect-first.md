# 0029.1. Sidecar Persona Revision 2 — Inspect-First Exploration

## Status

Pre-registered before implementation; accepted on merge.

Like ADR-0029, this ADR is **pre-registered before the next run; never
mid-run**. Persona wording changes the subject under measurement, so it may
land only between runs, must never be introduced while a gate run is in
progress, and must never be used to rescore existing episodes. After merge, a
**sidecar-only spot check** (live asks, anomaly read) gives direction; any
citable number comes only from a later pre-registered run.

This ADR does **not** change eval scoring, detectors, rewards, gates,
thresholds, episode definitions, or ground truth. It changes only sidecar
persona doctrine in `internal/sidecar/prompt.go`.

## Context

ADR-0028.2 shipped `ghx inspect <owner/repo> <query>` (merged 2026-07-06,
commit 333b0b6): a one-shot budgeted concern inspection that returns ranked
files, structural maps, bounded snippets, and `next` read hints inside one
`--budget`. Its design intent is explicit ("Sidecar Relationship" section):

> The sidecar may call `inspect` as its first Tier-1 concern-localization tool.

But the sidecar persona predates the command. `BuildPersonaSystemPrompt` in
`internal/sidecar/prompt.go` teaches `explore`, `read --map`, and repo-scoped
`search` — it never mentions `inspect`. A persona-driven sidecar therefore
still runs exactly the multi-command chains `inspect` was built to replace
(CLI-FINDINGS defect 4: `map -> line reads` in 77 runs,
`explore -> tree -> read` in 63, `search -> read result files` in 46).

The actual command surface, from a fresh build (`go build -o ghx ./cmd/ghx &&
./ghx inspect --help`):

```text
Usage:
  ghx inspect <owner/repo> <query> [flags]

Examples:
  ghx inspect gkoreli/ghx "flag error suggestions"
  ghx inspect gin-gonic/gin "routing middleware" --lang go
  ghx inspect openai/openai-node "streaming responses" --glob "src/**/*.ts"

Flags:
      --budget int    Approximate total output budget in characters (default 12000)
      --glob string   Limit candidates by path glob
      --lang string   Limit search candidates by language
  -l, --limit int     Candidate search limit before ranking (max 100) (default 30)
      --path string   Prefer or constrain candidates to a subtree
```

This ADR extends the ADR-0029 read-ladder doctrine: the ladder stays, but for
concern-shaped questions the preferred first rung becomes one `inspect` call
instead of assembling the same evidence from map/search chains.

## Decision

Two surgical persona edits. Everything else in the persona is untouched
(ADR-0029 non-goal: no broad prompt rewrite).

### D1. Add `inspect` to the "How to run ghx" example list

Current persona text being changed (rendered persona bytes):

```text
  ghx explore owner/repo
  ghx read owner/repo path/to/file --map
  ghx read owner/repo file1 file2 --map
  ghx search "repo:owner/repo symbolName"
  ghx search "repo:owner/repo exact phrase"
```

Replacement text:

```text
  ghx inspect owner/repo "concern phrase"
  ghx explore owner/repo
  ghx read owner/repo path/to/file --map
  ghx read owner/repo file1 file2 --map
  ghx search "repo:owner/repo symbolName"
  ghx search "repo:owner/repo exact phrase"
```

Rationale: the example list is the persona's canonical command surface
(ADR-0029 D2 made it the substitute for live `--help` detours, which are
banned during evals). A command absent from this list effectively does not
exist for the sidecar.

### D2. Make `inspect` the preferred first move for concern-shaped questions

Current persona text being changed (rendered persona bytes):

```text
## Operating loop

1. Separate verified / inferred / unverified claims explicitly.
2. Calibrate confidence: high / medium / low.
3. Stop when you can identify the 1–5 most relevant files.
4. Use the read ladder for each file: map once, then read one targeted range.
   Do not read the same file again unless you first name the new symbol or line
   gap the prior read did not answer. Prefer one `ghx read owner/repo file1 file2 --map` over serial map calls.
5. Every search must end in one of three outcomes: read the top relevant hit,
   record the hit as rejected, or cite it as an inferred candidate. If two
   searches fail to produce useful next reads, stop searching and use maps/tree.
6. If remote evidence is insufficient, name the deeper backend needed but do not
   perform it unless allowed.
```

Replacement text:

```text
## Operating loop

1. Separate verified / inferred / unverified claims explicitly.
2. Calibrate confidence: high / medium / low.
3. Stop when you can identify the 1–5 most relevant files.
4. For concern-shaped questions ("where/how is X implemented"), PREFER one
   `ghx inspect owner/repo "concern"` as your first command: a single budgeted
   call that returns ranked files, structural maps, bounded snippets, and next
   reads. Examples: `ghx inspect gin-gonic/gin "routing middleware" --lang go`,
   `ghx inspect owner/repo "streaming responses" --glob "src/**/*.ts"`. Follow
   its next hints with one targeted `ghx read owner/repo path --lines A-B`
   instead of starting a map/search chain. Fall back to explore/search/maps
   only when inspect returns no ranked files or the question is not
   concern-shaped.
5. Use the read ladder for each file: map once, then read one targeted range.
   Do not read the same file again unless you first name the new symbol or line
   gap the prior read did not answer. Prefer one `ghx read owner/repo file1 file2 --map` over serial map calls.
6. Every search must end in one of three outcomes: read the top relevant hit,
   record the hit as rejected, or cite it as an inferred candidate. If two
   searches fail to produce useful next reads, stop searching and use maps/tree.
7. If remote evidence is insufficient, name the deeper backend needed but do not
   perform it unless allowed.
```

Rationale: the new step 4 sits above the read ladder because `inspect`
replaces the chain that *feeds* the ladder — candidate discovery plus map plus
first snippet — not the ladder itself. The two example invocations are lifted
from `ghx inspect --help` so persona doctrine and CLI examples cannot drift
apart silently. The fallback clause keeps explore/search/maps legitimate for
non-concern questions (inventory questions, "what does this file do", config
lookups) and for the exit-code-1 no-ranked-files case (ADR-0028.2 semantic
exits).

## Eval-measurement rule

- These persona changes are pre-registered here **before the next run** and
  must never land or change **mid-run**.
- After merge, verification is a **sidecar-only spot check for direction**:
  live `ghx sidecar ask` episodes, checked for whether the trail actually
  used `ghx inspect` (grep session traces for `ghx inspect`). A spot check
  where the agent ignores `inspect` is a negative finding and gets committed
  as such — it does not get retried until it looks good.
- No existing episodes are rescored. Citable effect numbers (defect-4 chain
  shrinkage: `map -> line reads` baseline 77, `explore -> tree -> read`
  baseline 63, `search -> read result files` baseline 46) come only from the
  next pre-registered full-rigor run on Goga's trigger.

## Considered and rejected

- **Also rewriting the "During evals" search-fallback sentence to name
  inspect.** Rejected for this revision: the sentence governs what to do after
  failed searches; making it point back to `inspect` risks a loop
  (inspect -> search fallback -> inspect). Keep the fallback as explore/tree/
  mapped reads; revisit with mining evidence.
- **Replacing the read ladder with inspect.** Rejected. `inspect` localizes a
  concern; targeted follow-up reads still need the ladder's reread
  accountability. ADR-0028.2 explicitly emits `ghx read ... --lines A-B` next
  hints that the ladder governs.
- **Making inspect mandatory ("always run inspect first").** Rejected. Not all
  sidecar questions are concern-shaped; discovery mode, inventory questions,
  and single-file questions are better served by repos/explore/read. "PREFER"
  plus a concrete question shape keeps the doctrine honest.
- **Waiting for `--json` before teaching the persona.** Rejected. The text
  output contract is agent-optimized by design (ADR-0028.2 Output Contract);
  deferring adoption would leave the highest-value command unused for another
  eval cycle.
