# ADR-0016.13. Eval Corpus Discrimination Refresh R1–R4

## Status

Proposed. Research grounding:
`docs/research/h7-corpus-discrimination.md` (§2 per-task evidence table,
§3 replacement designs, §4 pre-registration requirements, §8 evidence
appendix). Executes the proposal in
`docs/evals/corpus-discrimination-2026-07-07.md`; advances TRUST rows **H7**
(ceiling effects) and **H2** (memorization bar), workstream C7.

## Context

The corpus's discrimination power rests on **2 of 6 tasks**
(`corpus-discrimination-2026-07-07.md`): only `express-router-location`
(profile spread 0.500) and `openai-node-streaming` (the sole sidecar−ghx
regression signal, −0.200) can reveal a correctness change. `gin-routing`,
`hono-middleware`, `flask-routing` sit at min-profile 1.000 / spread 0.000;
`flask-routing` also fails the H2 exploration bar (closed-book 0.400, not
< 0.40 — memorization-dominated per `docs/evals/memorization-audit/`);
`ghx-mapengine` is contamination-confounded (self-referential, its nominal
0.178 spread an exclusion artifact with inverted anti-thesis ordering).
Consequence: every correctness gate (G1/G2) is effectively a 2-task
measurement wearing a 6-task costume.

## Decision

Replace the four dead/confounded tasks with pre-registered harder variants:

- **R1 — Werkzeug delegation matching** (replaces flask-routing): which
  component owns URL matching; requires tracing delegation Flask→Werkzeug.
  Kills the partial-recall channel (`add_url_rule` from weights).
- **R2 — gin route-conflict detection** (replaces gin-routing): identify the
  conflicting-route panic condition across registration order and wildcard
  semantics.
- **R3 — hono SmartRouter selection/fallback** (replaces hono-middleware):
  when SmartRouter regresses to RegExpRouter/trie, and what degrades.
- **R4 — Non-self-referential engine-selection task** (replaces
  ghx-mapengine): same skill shape (map-driven engine choice) on an external
  repo, removing the self-referential contamination channel.

Constraints carried from prior ADRs:

- **Per-task closed-book canary before commit**: each new task's closed-book
  mean must be `< 0.40` (ADR-0016.9 acceptance bar), artifacts committed under
  `docs/evals/`.
- **Gates unchanged** — no scorer/detector edits; this is fixture work only
  (frozen-stack rule respected; measurement stack changes land via their own
  ADRs, e.g. ADR-0032.2's Locations fix stays separate).
- **D-G style run plan**: after fixtures land, one discovery-style formal run
  re-establishes citable numbers under `docs/evals/`.

Rejected alternatives: judge-only rescue (gates stay deterministic per
ADR-0023.1); corpus expansion instead of replacement (keeps paying four dead
cells per run).

## Consequences

- Projected 6/6 tasks clearing both the H7 ceiling bar (nonzero spread) and
  the H2 closed-book gap bar — the path to closing H7.
- Risks: fixture authoring cost (mitigated by the ADR-0019.2 fixture-family
  precedent); contamination discipline for repos reused elsewhere in evals
  (R4 explicitly external); old tasks retained in git history so past verdicts
  stay recomputable.
- Verification: `Task.Validate` unit tests per fixture, committed canary
  artifacts, golden recompute of the §2 table from committed episodes.
