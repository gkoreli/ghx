# 0031.2. nextReads contract revision — concrete paths, then re-measure

## Status

Accepted (orchestrator review 2026-07-06: persona-hash-same-commit discipline verified, frozen predictor snapshot untouched, normalizer lenient/visible, miner comparability unaffected — it strips line refs itself). Nothing here is rescored.
Pre-registered follow-up (a) from ADR-0031.1's implementation note: the D1
predictor gate FAILED (committed-evals recall 0.071, dogfood 0.000,
`docs/evals/anticipation-predictor-2026-07/`) because `nextReads` is sparse
(4/30 eval pairs seeded) and prose-shaped ("tree.go lines 135-400 for
insertion logic", "docs") where the miner needs concrete paths.

## Decision — report-contract revision

`nextReads` entries MUST be concrete repo-relative file paths —
`owner/repo:path/to/file.go` or plain `path/to/file.go`; exactly one path
per entry, no prose, no descriptions, no line ranges, no directory areas;
an empty list when the agent genuinely anticipates nothing.

Persona doctrine line (base persona, submit_report section): `nextReads`
means **"the files the NEXT turn will most likely need read"**. The
operating-loop instruction to park disallowed-backend needs in
"uncertainty/nextReads" now names `uncertainty` only — backend names are
not file paths.

## Validation stays lenient — the contract steers, validation never breaks asks

A lenient normalizer (`Report.NormalizeNextReads`, `internal/sidecar/report.go`)
runs on both accepted-report paths (strict `submit_report` decode and the
`<ghx-report>` fallback): single path tokens are cleaned (wrapping
quotes/backticks trimmed, trailing `:N` / `:N-M` / `#LN` line suffixes
stripped); prose entries pass through trimmed; blanks are dropped. **No
report is ever rejected over nextReads shape** — production asks must not
break while agents converge on the contract. Persona golden hash updated in
the same commit as the persona change, per repo precedent.

## Re-measurement plan (pre-registered)

Re-run the ADR-0031.1 D1 miner (`internal/sidecar/evals/anticipation_predictor.go`,
unchanged) over the NEXT full eval run's artifacts. The gate stays exactly as
pre-registered in 0031.1 D1: **predictor recall ≥ 0.30** unlocks the D4
prefetch build. `docs/evals/anticipation-predictor-2026-07/` is a frozen
snapshot and is never rewritten; regeneration follows the protocol documented
by `TestWriteAnticipationPredictorArtifacts`.

## First sighting (spot check, 2 sidecar-only episodes, 2026-07-06)

Live spot per the eval-cadence hard cap (2 sidecar-only cells, randomly
drawn; claude-sonnet-5 via pinned `scripts/eval-agent-acp.sh`,
`GHX_REPORT_SINK_EXE` = fresh build of this tree, `GHX_EVAL_STRICT=1`;
artifacts in gitignored `.ghx-evals/runs/spot-0031.2-nextreads/`; scored
only by the frozen deterministic scorers). Verbatim `nextReads`:

- `hono-middleware/ghx-sidecar` (2 turns, zero anomalies): turn-1
  `["src/hono-base.ts"]`; turn-2 `["src/http-exception.ts"]`. Turn 2
  actually read `src/hono-base.ts` (map + 6 line-range reads) — turn-1's
  prediction is a real recall hit under the miner's exact-file rule.
- `ghx-mapengine/ghx-sidecar` (1 turn, zero anomalies):
  `["internal/mapengine/goast.go", "internal/mapengine/regex.go"]`.

All entries are concrete repo-relative paths, one per entry, no prose; raw
submit_report payloads match the persisted values byte-for-byte, so the
normalizer had nothing to clean. n=2, PRELIMINARY by construction — the
citable re-measurement waits for the next full run's miner pass.
