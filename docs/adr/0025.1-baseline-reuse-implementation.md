# 0025.1. Baseline Reuse Implementation

## Status

Proposed 2026-07-06. This is the concrete implementation registration for
ADR-0025 D2: reuse plain/ghx baseline episodes from a prior committed run iff
the baseline identity is identical and recent. It must land before any run
claims `BASELINE-REUSED`.

This ADR touches eval artifact identity and provenance only. It does not change
reward scoring, gates, anomaly detectors, or thresholds in
`internal/sidecar/evals/rewards.go` / `gates.go`.

## Context

ADR-0025 D2 accepts baseline reuse to reduce a full confirmatory run from 90
live episodes to 30 live episodes when the plain and direct-ghx baselines have
not changed. The accepted rule is deliberately strict:

> identical wrapper script hash, identical adapter version, identical subject
> model ID, identical task corpus hash, identical direct-profile preamble, and
> the prior run <= 7 days old. Any mismatch -> fresh baselines.

The current artifact model already has the pieces that make this auditable:

- `internal/sidecar/evals/store.go` records `RunManifest`, `PlannedRound`, and
  run identity.
- `internal/sidecar/evals/episode.go` records per-episode `AgentIdentity`,
  including `agentCommand`, `adapterName`, `adapterVersion`, `subjectModel`,
  `adapterSubjectModel`, and `wrapperSha256`.
- `internal/sidecar/evals/profiles.go` owns `directPreamble`, the prompt text
  used by the plain and ghx direct profiles.
- `internal/sidecar/evals/tasks.go` loads task definitions from sorted
  `*.json` files.
- ADR-0016.5 established the precedent that eval identity boundaries must be
  explicit when transport/runtime mechanics can contaminate measurement.

Baseline reuse is only valid if a human can recompute every score from committed
artifacts and can see exactly why the old baseline episodes were admitted into
the new run. References alone are too implicit for the visibility tenet.

## Decisions

### D1. Hash inventory is explicit and byte-defined

A run eligible for baseline reuse records a `baselineReuse.hashes` inventory in
`manifest.json`. Each record has:

```json
{
  "name": "wrapperScript",
  "algorithm": "sha256",
  "value": "<hex>",
  "source": "<human-readable source>",
  "sourceKind": "<file|value|generated>"
}
```

The required hashes and values are:

1. **Wrapper script hash**
   - Name: `wrapperScript`
   - Source kind: `file`
   - Source: `RunConfig.AgentCmd`
   - Computation: `sha256` of the exact bytes returned by
     `os.ReadFile(RunConfig.AgentCmd)`.
   - Eligibility rule: `RunConfig.AgentCmd` must be a readable filesystem path
     (`filepath.IsAbs(cmd)` or contains an OS path separator), matching the
     existing `wrapperHash` identity behavior in `internal/sidecar/evals/env.go`.
     If the command is not a readable path, baseline reuse is disabled and all
     profiles run fresh.
   - Rationale: environment changes embedded in the wrapper, such as
     `MAX_THINKING_TOKENS`, are runtime identity and must invalidate reuse.

2. **Adapter version**
   - Name: `adapterVersion`
   - Source kind: `value`
   - Source: ACP `InitializeResponse.AgentInfo.Version`, recorded as
     `AgentIdentity.AdapterVersion`.
   - Computation: `sha256` of the UTF-8 bytes of the adapter version string.
   - Eligibility rule: the current run obtains this value through a startup
     identity probe using the same `RunConfig.AgentCmd` before deciding whether
     to skip baselines. The candidate prior run's `manifest.identity.adapterVersion`
     and every copied plain/ghx episode's `identity.adapterVersion` must equal
     the probed value before hashing. Blank adapter versions are ineligible.
   - Rationale: `AgentIdentity.AdapterVersion` is already the artifact-level
     identity field; hashing the value gives the manifest one uniform inventory.

3. **Subject model ID**
   - Name: `subjectModel`
   - Source kind: `value`
   - Source: `resolveSubjectModel(RunConfig.AgentCmd)` in
     `internal/sidecar/evals/env.go`: `GHX_EVAL_SUBJECT_MODEL` in the eval
     process, else wrapper-default parsing, else `unknown`.
   - Computation: `sha256` of the UTF-8 bytes of the resolved model string.
   - Eligibility rule: `unknown` is not reusable, even against another
     `unknown`. A missing model ID means identity was not proven.
   - Rationale: ADR-0025 D4 requires same-arm comparisons. Reusing sonnet
     baselines for a haiku subject, or for an unverified subject, invalidates
     the comparison.

4. **Task corpus hash**
   - Name: `taskCorpus`
   - Source kind: `file`
   - Source: canonical eval task directory
     `internal/sidecar/evals/testdata/tasks/*.json` for gate runs, or the
     explicit task directory passed to `LoadTasks` for tests.
   - Computation: build a canonical byte stream from non-directory `*.json`
     entries sorted by base filename, exactly matching `LoadTasks` ordering:
     for each file, append:
     - the literal bytes `file\0`
     - the UTF-8 base filename
     - the literal byte `\0`
     - the decimal byte length of the raw file content in ASCII
     - the literal byte `\0`
     - the raw file bytes returned by `os.ReadFile`
     - the literal byte `\n`

     The `taskCorpus` value is `sha256` of that canonical stream.
   - Eligibility rule: every task file byte and filename must match. JSON is not
     parsed or reserialized for hashing.
   - Rationale: raw-byte hashing detects task text, checks, contamination paths,
     judge criteria, filenames, and formatting drift without inventing a second
     task canonicalization format.

5. **Direct-profile preamble hash**
   - Name: `directProfilePreamble`
   - Source kind: `generated`
   - Source: `directPreamble(ProfilePlain, repo)` and
     `directPreamble(ProfileGhx, repo)` in `internal/sidecar/evals/profiles.go`,
     evaluated for every task in the planned task corpus.
   - Computation: after loading tasks in canonical order, build a canonical byte
     stream. For each task, append records for `plain` then `ghx`:
     - the literal bytes `profile\0`
     - the profile string (`plain` or `ghx`)
     - the literal bytes `\0task\0`
     - the task ID
     - the literal bytes `\0repo\0`
     - the repo string
     - the literal bytes `\0len\0`
     - the decimal byte length of the generated preamble in ASCII
     - the literal byte `\0`
     - the generated preamble UTF-8 bytes
     - the literal byte `\n`

     The `directProfilePreamble` value is `sha256` of that stream.
   - Eligibility rule: any change to the direct-profile instruction text,
     profile-specific ghx guidance, task repo interpolation, or task membership
     invalidates reuse.
   - Rationale: the sidecar profile may change between runs; reused baselines
     are only valid when the direct-profile prompt contract is identical.

The prior run age is not hashed. It is checked directly from
`manifest.createdAt` in UTC. If the prior manifest has no `createdAt`, or if
`currentRunStart.Sub(prior.CreatedAt) > 7*24*time.Hour`, reuse is disabled.

### D2. Manifest schema records provenance, hashes, and copied episodes

`RunManifest` gains an optional `BaselineReuse` field:

```go
type BaselineReuse struct {
    ReusedFromRunID string                  `json:"reusedFromRunId,omitempty"`
    ReusedFromRunDir string                 `json:"reusedFromRunDir,omitempty"`
    ReusedAt time.Time                      `json:"reusedAt,omitempty"`
    MaxAgeDays int                          `json:"maxAgeDays"`
    VerdictLabel string                     `json:"verdictLabel,omitempty"`
    Hashes []BaselineReuseHashRecord        `json:"hashes,omitempty"`
    Episodes []BaselineReusedEpisodeRecord  `json:"episodes,omitempty"`
}

type BaselineReuseHashRecord struct {
    Name string       `json:"name"`
    Algorithm string  `json:"algorithm"`
    Value string      `json:"value"`
    Source string     `json:"source"`
    SourceKind string `json:"sourceKind"`
}

type BaselineReusedEpisodeRecord struct {
    Profile Profile `json:"profile"`
    TaskID string   `json:"taskId"`
    SourceFile string `json:"sourceFile"`
    TargetFile string `json:"targetFile"`
    SHA256 string `json:"sha256"`
}
```

Manifest requirements:

- `reusedFromRunId` is the stable run ID, normally the basename of the committed
  run directory under `docs/evals/<run-id>/`.
- `reusedFromRunDir` is the source run path used during execution. Committed
  artifacts may move, so `reusedFromRunId` is the durable identity and
  `reusedFromRunDir` is audit context.
- `maxAgeDays` is always `7` for ADR-0025 D2.
- `verdictLabel` is exactly `BASELINE-REUSED` when reuse occurs.
- `hashes` records the five records from D1.
- `episodes` records every copied plain and ghx episode JSON with source path,
  target path, and target-file raw-byte `sha256`.

The manifest field is omitted when no reuse occurred. A run with a
`BaselineReuse` block but missing copied episode files is invalid.

### D3. Verdict schema and markdown label reused baselines explicitly

`Verdict` gains:

```go
Labels []string `json:"labels,omitempty"`
```

When baselines are reused, `Labels` includes exactly `BASELINE-REUSED`.
`FormatVerdict` renders the label in the verdict line prefix, alongside
`PRELIMINARY` and `INVALID` labels, for example:

```text
**BASELINE-REUSED** **THESIS SUPPORTED** — G1, G2, G3, G5 pass.
```

The verdict notes also include:

```text
BASELINE-REUSED: plain and ghx episodes copied from <run-id>; manifest.json records hash inventory and copied episode provenance.
```

The label is descriptive, not a weaker verdict class. A sufficient, valid run
with reused baselines is citable if every ADR-0025 D2 condition was met and the
new run's artifacts are committed.

### D4. Reuse copies episode JSONs byte-for-byte into the new run

Baseline reuse copies prior plain and ghx episode JSON files into the new run
directory before gate evaluation. It does not reference them in place, symlink
them, or reserialize them.

Copy procedure:

1. Load the candidate prior `manifest.json`.
2. Load prior episodes with `LoadRunEpisodes`.
3. Require the prior run to contain a complete baseline matrix for every planned
   task and trial: profiles `plain` and `ghx`, same task IDs, same task count,
   and the same per-task trial count intended for the new run.
4. Validate every prior baseline episode:
   - profile is `plain` or `ghx`
   - `taskId` exists in the current task corpus
   - `repo` equals the current task repo for that task ID
   - episode identity matches wrapper hash, adapter version, and subject model
   - episode was not invalid and has no exclusion reasons
   - episode JSON filename does not collide with a new-run file
5. Copy the raw source episode JSON bytes to the target run directory with the
   same basename.
6. Record each copied file under `manifest.baselineReuse.episodes`.
7. Run only `ghx-sidecar` live episodes for the new run.
8. Run `EvaluateGates` over the union of copied baseline episode JSONs and new
   sidecar episode JSONs.
9. Save `verdict.json` and `verdict.md` with `BASELINE-REUSED`.

Rationale for copying:

- The visibility tenet says every score must be recomputable by a human from
  committed artifacts. If the new run commits its own copied baseline episode
  JSONs, `go run internal/sidecar/evals/cmd/evalreport <run-dir>` can recompute
  from that directory alone.
- Byte-for-byte copying preserves the original canonical episode artifact,
  including `startedAt`, `endedAt`, identity, checks snapshot, tool traces,
  actions, observations, context accounting, rewards, and anomalies.
- Reserializing would create a new artifact that looks freshly produced and may
  silently alter JSON field ordering, omitted fields, timestamps, or anomaly
  derivation.
- References would make the verdict depend on another directory being present
  and unchanged, which is weaker than a self-contained committed run.

Copied baseline episodes keep their original episode IDs and timestamps. The
manifest provenance, not edited episode JSON, explains why those old episodes
belong to the new run.

### D5. Any mismatch means fresh baselines; no partial reuse

Baseline reuse is all-or-nothing. Any mismatch or missing proof in D1-D4 causes
the runner to execute fresh `plain`, `ghx`, and `ghx-sidecar` episodes.

No partial reuse is allowed:

- plain matches but ghx mismatches -> fresh baselines
- ghx matches but plain mismatches -> fresh baselines
- some tasks match but one task changed -> fresh baselines
- subject model is `unknown` -> fresh baselines
- adapter version is blank -> fresh baselines
- prior run is older than 7 days -> fresh baselines
- prior run lacks a manifest or hash inventory -> fresh baselines
- copied baseline matrix is incomplete -> fresh baselines
- any copied episode fails identity/provenance validation -> fresh baselines

The implementation reports the first mismatch reason to stderr and records no
`baselineReuse` block in the manifest for the fresh run. It must not silently
reuse the matching subset.

Rationale: partial reuse creates asymmetric noise in the exact arms that the
eval is comparing. Fresh baselines are cheaper than explaining a mixed
provenance matrix.

### D6. Verification is unit-test first

The implementation must add focused unit tests before any reused-baseline run is
claimed.

Required tests:

1. **Hash inventory stability**
   - Same wrapper bytes, task files, subject model, adapter version, and
     generated preambles produce the same inventory.
   - Changing one byte in the wrapper changes only `wrapperScript`.
   - Changing one task JSON byte or filename changes `taskCorpus`.
   - Changing direct preamble text through a test hook or generated fixture
     changes `directProfilePreamble`.
   - `unknown` subject model is marked ineligible.

2. **Task corpus hash ordering**
   - Files are hashed in sorted basename order.
   - Directory entries and non-`.json` files are ignored, matching `LoadTasks`.
   - Raw JSON formatting changes affect the hash.

3. **Manifest roundtrip**
   - `SaveRunManifest` / `LoadRunManifest` preserve `baselineReuse`,
     `hashes`, and copied episode records.
   - `RecordManifestRound` and `UpdateManifestIdentity` do not drop an existing
     `baselineReuse` block.

4. **Eligibility mismatch table**
   - Table-driven test where each ADR-0025 D2 condition mismatches one at a
     time and reuse is rejected.
   - A fully identical candidate is accepted.
   - A prior run older than 7 days is rejected by `createdAt`.

5. **Copy semantics**
   - Reused baseline episode files in the target run are byte-identical to the
     source files.
   - `LoadRunEpisodes(targetRunDir)` loads copied baselines plus new sidecar
     episodes without needing the source directory.
   - The manifest records target-file `sha256` matching copied bytes.

6. **No partial reuse**
   - Candidate prior run missing one plain task, one ghx task, or one trial
     causes fresh-baseline mode.
   - Candidate prior run with only one matching baseline profile causes
     fresh-baseline mode.

7. **Verdict labeling**
   - `verdict.json.labels` includes `BASELINE-REUSED` when reuse occurs.
   - `verdict.md` renders `BASELINE-REUSED`.
   - Runs without reuse have no label.

The live gate runner may use the feature only after these tests pass under
`go test ./internal/sidecar/evals/...`.

## Considered and Rejected

### References to prior episode JSONs instead of copying

Rejected. References are compact, but they make the new verdict non-local: a
human cannot recompute the new run from its committed directory alone. This
violates the visibility tenet and makes artifact retention part of score
validity. Copying costs disk space and saves auditability.

### Symlinks to prior episode JSONs

Rejected. Symlinks look local but are path-dependent, fragile across artifact
moves, and easy to commit incorrectly. They also make the target directory's
raw contents insufficient for recomputation.

### Reserializing reused episodes with new IDs or timestamps

Rejected. Rewriting old baseline episodes makes them look like new live
episodes and risks changing the canonical JSON bytes. The correct provenance
belongs in `manifest.baselineReuse`, not inside mutated episode artifacts.

### Partial reuse by profile or task

Rejected. It saves a few more episodes in edge cases but creates a mixed
baseline surface where one arm is old and another is fresh. The eval runner
should be boring: either the baseline contract is identical or the baselines
run again.

### Treating `unknown` subject model as a comparable value

Rejected. `unknown == unknown` proves only that both runs failed to identify the
subject. ADR-0025 D2 requires identical subject model ID, not identical absence
of evidence.

### Hashing Go source files instead of generated preamble text

Rejected. The comparison needs the actual prompt bytes the direct profiles see,
including repo interpolation and task membership. Source-file hashing would miss
runtime-generated differences and over-trigger on unrelated edits in
`profiles.go`.

### JSON-canonicalizing task files before hashing

Rejected. The task loader consumes raw files and `encoding/json`, but the eval
artifact contract should not depend on a second canonical JSON format. Raw-byte
hashing is simpler, stricter, and fully reproducible.

### Reusing baselines from uncommitted local runs

Rejected for citable runs. ADR-0025 D2 says previous committed run. Local
experiments may copy artifacts manually for debugging, but a verdict labeled
`BASELINE-REUSED` must point to a committed `docs/evals/<run-id>/` source.

## Consequences

- A reused-baseline run is self-contained: copied baseline episodes, new
  sidecar episodes, manifest provenance, and verdict labels live in one
  committed directory.
- The common confirmatory case can run only the sidecar profile live while
  preserving deterministic recomputation from JSON artifacts.
- Strict hash and age checks intentionally make reuse unavailable after wrapper,
  adapter, subject, corpus, or prompt drift. That is a feature, not friction.
- The implementation creates one new eval identity surface
  (`manifest.baselineReuse`) but does not alter scoring math.

## Cross-references

- ADR-0025 D2 — accepted baseline reuse policy and 7-day identity rule.
- ADR-0025 D1/D3 — sequential stopping and bounded parallelism remain
  orthogonal; reused baseline episodes still count as planned episodes for gate
  aggregation and stopping math.
- ADR-0016.5 — identity/decontamination precedent: measurement artifacts must
  distinguish runtime transport mechanics from live episode activity.
- ADR-0016.8 D5/D6 — manifest round accumulation and persistence-time anomaly
  completeness; baseline reuse must preserve both.
- `internal/sidecar/evals/store.go` — `RunManifest`, `PlannedRound`, and

```text
BASELINE-REUSED: plain and ghx episodes copied from <run-id>; manifest.json records hash inventory and copied episode provenance.
```

The label is descriptive, not a weaker verdict class. A sufficient, valid run
with reused baselines is citable if every ADR-0025 D2 condition was met and the
new run's artifacts are committed.

### D4. Reuse copies episode JSONs byte-for-byte into the new run

Baseline reuse copies prior plain and ghx episode JSON files into the new run
directory before gate evaluation. It does not reference them in place, symlink
them, or reserialize them.

Copy procedure:

1. Load the candidate prior `manifest.json`.
2. Load prior episodes with `LoadRunEpisodes`.
3. Require the prior run to contain a complete baseline matrix for every planned
   task and trial: profiles `plain` and `ghx`, same task IDs, same task count,
   and the same per-task trial count intended for the new run.
4. Validate every prior baseline episode:
   - profile is `plain` or `ghx`
   - `taskId` exists in the current task corpus
   - `repo` equals the current task repo for that task ID
   - episode identity matches wrapper hash, adapter version, and subject model
   - episode was not invalid and has no exclusion reasons
   - episode JSON filename does not collide with a new-run file
5. Copy the raw source episode JSON bytes to the target run directory with the
   same basename.
6. Record each copied file under `manifest.baselineReuse.episodes`.
7. Run only `ghx-sidecar` live episodes for the new run.
8. Run `EvaluateGates` over the union of copied baseline episode JSONs and new
   sidecar episode JSONs.
9. Save `verdict.json` and `verdict.md` with `BASELINE-REUSED`.

Rationale for copying:

- The visibility tenet says every score must be recomputable by a human from
  committed artifacts. If the new run commits its own copied baseline episode
  JSONs, `go run internal/sidecar/evals/cmd/evalreport <run-dir>` can recompute
  from that directory alone.
- Byte-for-byte copying preserves the original canonical episode artifact,
  including `startedAt`, `endedAt`, identity, checks snapshot, tool traces,
  actions, observations, context accounting, rewards, and anomalies.
- Reserializing would create a new artifact that looks freshly produced and may
  silently alter JSON field ordering, omitted fields, timestamps, or anomaly
  derivation.
- References would make the verdict depend on another directory being present
  and unchanged, which is weaker than a self-contained committed run.

Copied baseline episodes keep their original episode IDs and timestamps. The
manifest provenance, not edited episode JSON, explains why those old episodes
belong to the new run.

### D5. Any mismatch means fresh baselines; no partial reuse

Baseline reuse is all-or-nothing. Any mismatch or missing proof in D1-D4 causes
the runner to execute fresh `plain`, `ghx`, and `ghx-sidecar` episodes.

No partial reuse is allowed:

- plain matches but ghx mismatches -> fresh baselines
- ghx matches but plain mismatches -> fresh baselines
- some tasks match but one task changed -> fresh baselines
- subject model is `unknown` -> fresh baselines
- adapter version is blank -> fresh baselines
- prior run is older than 7 days -> fresh baselines
- prior run lacks a manifest or hash inventory -> fresh baselines
- copied baseline matrix is incomplete -> fresh baselines
- any copied episode fails identity/provenance validation -> fresh baselines

The implementation reports the first mismatch reason to stderr and records no
`baselineReuse` block in the manifest for the fresh run. It must not silently
reuse the matching subset.

Rationale: partial reuse creates asymmetric noise in the exact arms that the
eval is comparing. Fresh baselines are cheaper than explaining a mixed
provenance matrix.

### D6. Verification is unit-test first

The implementation must add focused unit tests before any reused-baseline run is
claimed.

Required tests:

1. **Hash inventory stability**
   - Same wrapper bytes, task files, subject model, adapter version, and
     generated preambles produce the same inventory.
   - Changing one byte in the wrapper changes only `wrapperScript`.
   - Changing one task JSON byte or filename changes `taskCorpus`.
   - Changing direct preamble text through a test hook or generated fixture
     changes `directProfilePreamble`.
   - `unknown` subject model is marked ineligible.

2. **Task corpus hash ordering**
   - Files are hashed in sorted basename order.
   - Directory entries and non-`.json` files are ignored, matching `LoadTasks`.
   - Raw JSON formatting changes affect the hash.

3. **Manifest roundtrip**
   - `SaveRunManifest` / `LoadRunManifest` preserve `baselineReuse`,
     `hashes`, and copied episode records.
   - `RecordManifestRound` and `UpdateManifestIdentity` do not drop an existing
     `baselineReuse` block.

4. **Eligibility mismatch table**
   - Table-driven test where each ADR-0025 D2 condition mismatches one at a
     time and reuse is rejected.
   - A fully identical candidate is accepted.
   - A prior run older than 7 days is rejected by `createdAt`.

5. **Copy semantics**
   - Reused baseline episode files in the target run are byte-identical to the
     source files.
   - `LoadRunEpisodes(targetRunDir)` loads copied baselines plus new sidecar
     episodes without needing the source directory.
   - The manifest records target-file `sha256` matching copied bytes.

6. **No partial reuse**
   - Candidate prior run missing one plain task, one ghx task, or one trial
     causes fresh-baseline mode.
   - Candidate prior run with only one matching baseline profile causes
     fresh-baseline mode.

7. **Verdict labeling**
   - `verdict.json.labels` includes `BASELINE-REUSED` when reuse occurs.
   - `verdict.md` renders `BASELINE-REUSED`.
   - Runs without reuse have no label.

The live gate runner may use the feature only after these tests pass under
`go test ./internal/sidecar/evals/...`.

## Considered and Rejected

### References to prior episode JSONs instead of copying

Rejected. References are compact, but they make the new verdict non-local: a
human cannot recompute the new run from its committed directory alone. This
violates the visibility tenet and makes artifact retention part of score
validity. Copying costs disk space and saves auditability.

### Symlinks to prior episode JSONs

Rejected. Symlinks look local but are path-dependent, fragile across artifact
moves, and easy to commit incorrectly. They also make the target directory's
raw contents insufficient for recomputation.

### Reserializing reused episodes with new IDs or timestamps

Rejected. Rewriting old baseline episodes makes them look like new live
episodes and risks changing the canonical JSON bytes. The correct provenance
belongs in `manifest.baselineReuse`, not inside mutated episode artifacts.

### Partial reuse by profile or task

Rejected. It saves a few more episodes in edge cases but creates a mixed
baseline surface where one arm is old and another is fresh. The eval runner
should be boring: either the baseline contract is identical or the baselines
run again.

### Treating `unknown` subject model as a comparable value

Rejected. `unknown == unknown` proves only that both runs failed to identify the
subject. ADR-0025 D2 requires identical subject model ID, not identical absence
of evidence.

### Hashing Go source files instead of generated preamble text

Rejected. The comparison needs the actual prompt bytes the direct profiles see,
including repo interpolation and task membership. Source-file hashing would miss
runtime-generated differences and over-trigger on unrelated edits in
`profiles.go`.

### JSON-canonicalizing task files before hashing

Rejected. The task loader consumes raw files and `encoding/json`, but the eval
artifact contract should not depend on a second canonical JSON format. Raw-byte
hashing is simpler, stricter, and fully reproducible.

### Reusing baselines from uncommitted local runs

Rejected for citable runs. ADR-0025 D2 says previous committed run. Local
experiments may copy artifacts manually for debugging, but a verdict labeled
`BASELINE-REUSED` must point to a committed `docs/evals/<run-id>/` source.

## Consequences

- A reused-baseline run is self-contained: copied baseline episodes, new
  sidecar episodes, manifest provenance, and verdict labels live in one
  committed directory.
- The common confirmatory case can run only the sidecar profile live while
  preserving deterministic recomputation from JSON artifacts.
- Strict hash and age checks intentionally make reuse unavailable after wrapper,
  adapter, subject, corpus, or prompt drift. That is a feature, not friction.
- The implementation creates one new eval identity surface
  (`manifest.baselineReuse`) but does not alter scoring math.

Amended 2026-07-06 on branch `codex-reuse-fix` after the dogfood diagnosis in
`docs/dogfood/FRICTION.md` ("2026-07-06 baseline-reuse refusal is silent and
falls back to the expensive path"). Evidence from that diagnostic run showed a
reuse request could be refused without a manifest block or log line, then run
fresh plain+ghx+sidecar episodes. Code inspection found the deeper eligibility
bug at `internal/sidecar/evals/baseline_reuse.go`: source identity hashes were
read from `prior.BaselineReuse.Hashes`, so only reuse-consuming runs could seed
future reuse.

- Every run now writes the five-hash identity inventory to
  `manifest.identityHashes` at run start, immediately after the planned round
  and ACP identity probe. `baselineReuse.hashes` remains accepted-copy
  provenance, but source eligibility reads the top-level inventory so a normal
  completed run can become a later reuse source.
- Trial-count semantics now compare each source plain/ghx task/profile cell
  against the new run's accumulated planned trial count from
  `manifest.rounds`, not the current invocation's `Trials: 1`. The source must
  contain at least that many valid episodes (`invalid=false` and no
  `exclusionReasons`); the copier selects exactly the planned count by earliest
  `episode.startedAt`, with filename as the deterministic tie-breaker. Existing
  matching target files are accepted idempotently so repeated `-count`
  invocations can accumulate.
- Reuse refusal is loud. When `GHX_EVAL_BASELINE_REUSE_RUN_DIR` is set and any
  eligibility check refuses the source, the run fails with the exact refusing
  check and remediation. The only permitted fresh-baseline fallback is explicit:
  `GHX_EVAL_BASELINE_FALLBACK=fresh`, recorded in
  `manifest.baselineFallback` with the refused source, reason, remediation, and
  controlling env value.
