# 0024.3. `local:cbm` — Absorb the codebase-memory-mcp *engine* (gated, stateless), gated on a pre-registered bake-off

## Status

**Pre-registered before any build. Not accepted.** This ADR registers (a) the
shape of a new Tier-2 backend `local:cbm` that shells out to the
`codebase-memory-mcp` engine, and (b) the **pre-registered bake-off** that must
pass before that backend is ever wired into the production persona, policy
router, or default `AllowedBackends`. It is the operational execution of the
product-audit decision **PA-0002** ("absorb the ENGINE, gated — not the product;
today's action is the EVAL, not the integration").

The one blocking obligation before this can move to *accepted*:

1. **The bake-off has not run.** The gate below (D3) is UNMET. No production
   wiring lands until it passes on ghx's own numbers.

**Cross-family adjudication — DONE (`PA-0002.10`).** The self-preference guard
(arXiv:2404.13076; skill-forge Round 3) required an independent cross-family check
of the decision and this gate design before *accepted* status. Codex/gpt-5.5 ran
it read-only (2026-07-07, session `019f3f73`) and **CONFIRMED the net
recommendation** — "absorb only the engine narrowly as an optional, brain-gated,
stateless tier2 backend, and only after a governing ADR plus a ghx-native bake-off;
not the whole product/installer/watcher/persistent-index/UI/hook." Three precision
corrections were accepted and are folded into D1/D3 below (license terms stated
precisely; not a "clean drop-in" — registry updates required; vendor headline is
120× not 99%). So the remaining bar to *accepted* is the bake-off gate itself.

This ADR does **not** change eval scoring, detectors, rewards, thresholds,
episode definitions, ground truth, or the production persona. It adds no
runtime dependency to the default build: `local:cbm` is discovered on PATH
exactly like `local:codemap`, and its absence is a graceful fallback, never a
failure (ADR-0024.1 "Escalation Policy").

## Context

ADR-0024.1/.2 landed the Tier-2 substrate: a snapshot/cache, the
`subprocessAdapter` seam (`internal/sidecar/tier2/toolrun.go:53`), three
absorbed structural backends (`local:codemap`, `local:ast-grep`,
`local:repomap` — `service.go:186,188`, `RunRepomap`), the escalation policy
engine, and the recorded tier decision. The escalation move is: when the brain
hits a **cross-file dependency** or **precise-reference / call-path** question
that remote Tier-1 evidence cannot settle, it invokes a Tier-2 structural
backend the runtime records (ADR-0024.2 D1 hard signals).

`DeusData/codebase-memory-mcp` (MIT, 27.9k★) is a persistent SQLite
knowledge-graph engine (tree-sitter + LSP-derived call/reference graph, Cypher
queries, semantic search) fronted by an MCP server **and a one-shot CLI**
(`src/main.c:9`, `cbm cli <tool> <json>`). Its own README states it *"does not
include an LLM… relies on your MCP client to be the intelligence layer"* — it is
a **brain-less tool**, which is exactly the P3 "swallow the tools" target
(NORTH_STAR *The Moat*): absorbing it removes the strongest OSS code-recon
competitor's only differentiator and folds it under ghx's one brain.

PA-0002 established, with a cross-validated evidence ledger:

- **License GO** — MIT ("Copyright (c) 2025 DeusData"); all deps usable under
  permissive terms (`THIRD_PARTY.md`: MIT/Apache/BSD/ISC/0BSD/Unlicense; zstd is
  dual BSD/GPLv2 with **BSD selected**, Java JDT is EPL-2.0 **reference-only**) —
  not literally "zero GPL", but no copyleft obligation attaches to a shell-out
  (AGENTS.md *Open Source Leverage*: "MIT in, MIT out"; cross-family-checked,
  `PA-0002.10`).
- **The engine's additive value over ghx's existing backends is only ~20%** (a
  persistent Cypher call-graph + semantic search); codemap + ast-grep + repomap
  already cover ~80%.
- **That additive value is a token-efficiency *trade*, not a quality *win*** —
  the vendor's own arXiv:2603.27277 reports **83% answer quality vs 92%
  baseline** at ~10× fewer tokens, winning **19/31 languages**; the headline
  "99% fewer tokens" is a 5-query microbenchmark (README:240). Its "sub-ms"
  latency and persistent-index advantages are **structurally unavailable** to
  ghx's stateless, remote-first snapshot model — we would pay per-snapshot index
  cost the vendor amortizes across a warm daemon.

So the value is real but *conditional*, and the vendor's numbers are the wrong
baseline/tasks/judge to settle it. It must be measured on **ghx's** harness
before we buy it. This ADR is that measurement, pre-registered.

## Decisions

### D1. Absorb the ENGINE as `local:cbm`, stateless, one-shot — reject the product

`local:cbm` follows the `codemap`/`ast-grep` pattern **verbatim**
(`internal/sidecar/tier2/cbm.go`, new): a domain request type → `args()` → the
embedded `subprocessAdapter` doing PATH discovery + evidence-capturing execution
inside the snapshot dir. Concretely, mirroring `codemap.go`:

```go
const BackendCbm = "local:cbm"          // canonical backend ID on reports/traces
const cbmBinary  = "cbm"                 // discovered on PATH; absorbed, credited
var  ErrCbmNotInstalled = errors.New("cbm binary not installed: backend local:cbm unavailable")
// CbmInstallHint names the upstream install + credits DeusData/codebase-memory-mcp (MIT);
// on discovery failure the ask falls back to remote Tier-1 / the other local:* backends.
type Cbm struct{ subprocessAdapter }     // NewCbm() → PATH lookup, per-call timeout
```

Each ask is a **fresh, stateless, one-shot** invocation over the current
snapshot: `cbm cli <tool> <json>`, `--stateless` / no-persist, watcher and
auto-index **off**, no daemon, index materialized into the snapshot's tool
artifacts and discarded with it. Exactly like `local:codemap`, the backend
disappears from the operational surface but **never from attribution**: every
invocation is a recorded `ToolRun` stamped `local:cbm`, recomputable from the
committed command.

**Explicitly rejected — the product's soul (each inverts a founding tenet):**

- **Source-fork** (~40k lines of C) — rejected; we shell out to the upstream
  binary and credit it (ADR-0026.1 precedent: "it stays an upstream tool we
  spawn, credited openly"). No vendoring, no auto-install.
- **Persistent local index by default** — rejected; inverts NORTH_STAR:207
  ("Remote-first… **No clone, no local index by default**"). `local:cbm` is a
  Tier-2 escalation the brain *decides* to invoke, stateless per ask.
- **Background watcher / daemon** — rejected; not our lifecycle. (If a future
  daemon slice (ADR-0030) ever warms Tier-2 tools, a persistent cbm index is a
  *separate* ADR with its own gate, not smuggled in here.)
- **The 11-agent auto-installer** — rejected; ghx installs nothing into other
  agents.
- **The in-context injection hook (`hook_augment.c`)** — **hard rejected**; it
  writes into the host agent's prompt, directly violating "the main agent's
  **context is sacred**" (NORTH_STAR; Non-Goal:268). ghx surfaces evidence the
  brain *pulls*; it never *pushes* into the host's context.

The one non-engine thing worth stealing is the **host-wiring *pattern*** (how it
makes itself available to many agents) — routed to the M5/B2 discovery gap
(below), not the hook itself.

### D2. Build order — the *measurement harness* first, the *product integration* never (until the gate passes)

This is how "the EVAL, not the integration" is made real without a chicken-and-egg:

1. **S1 — minimal gated adapter (eval-only).** `internal/sidecar/tier2/cbm.go`
   + a narrow request surface for the query class under test (call-path /
   references / cross-file deps / semantic lookup). The adapter *body* mirrors
   `codemap.go`, but "clean drop-in" is the wrong phrase (cross-family finding,
   `PA-0002.10`): the tier-2 surface is deliberately explicit, so S1 also touches
   the backend-enumeration lists — `status.go:41` (backend status),
   `tool_registry.go:132` (tool registry), `report.go:45` (canonical local
   backend IDs) — plus tests. **Effort M**, not trivial. Wired **only** into the
   bake-off's arm B (below). **Not** taught to the production persona
   (`prompt.go`), **not** in default `AllowedBackends`, **not** in the policy
   router's default grant. It is a throwaway measurement surface: if the gate
   fails, `cbm.go` and its registry entries are reverted, not shipped.
2. **S2 — pre-register + run the bake-off (D3).** Goga-triggered; a citable run
   (~episodes past spot-check scale — eval cadence: event-driven, not a
   treadmill).
3. **S3 — promote *only if the gate passes*.** Then and only then: a persona
   revision teaching the escalation move (its own ADR, ADR-0029-series pattern),
   `local:cbm` added to the grant, policy-router wiring, README. If the gate
   fails, this slice never exists and the ADR closes as *measured and declined*
   (a committed negative result — visibility tenet).

This mirrors ADR-0024.2/0032.1 discipline exactly: **the measurement surface
lands before the behavior change, and nothing runs until Goga triggers.**

### D3. The pre-registered bake-off gate — vector verdict, ghx's numbers, non-inferiority on quality

Two arms, identical except for one backend:

- **Arm A — `ghx-sidecar`**: the current sidecar (codemap + ast-grep + repomap).
- **Arm B — `ghx-sidecar+cbm`**: the same, plus `local:cbm` in the grant and a
  minimal persona note teaching only its escalation move.

**Scope (registered):** the **cross-file dependency / precise-reference /
call-path** query class only — the sub-slice where a persistent call/reference
graph could plausibly beat codemap+ast-grep. **Exclude** single-file / local
lookups (grep/read suffice there; including them dilutes the signal toward zero).
This scope is chosen *before* any run and frozen with the stack.

**Gate (vector verdict, never a blend — ADR-0032.1 D2 forms):** absorb **only if
all three** hold; else **reject** and delete the adapter.

| Gate | Claim | Registered form |
|------|-------|-----------------|
| **CBM-quality (non-inferiority)** | cbm does NOT buy tokens at a correctness cost | Paired per-task: arm-B correctness ≥ arm-A correctness − **δ = 0.10** in ≥ **5 of 6** query-class tasks (`at_least(n)`, ADR-0025.2; FRAGILE annotation applies). This is the gate that **directly tests against the vendor's own 83-vs-92 regression** — reproduce that regression on ghx tasks and cbm is rejected outright. Never quoted as a quality *win*. |
| **CBM-efficiency (superiority)** | the token trade actually pays off on ghx's *stateless* numbers | Paired per-task: arm B wins BOTH host-task SPT (higher signals-per-token) AND dead-weight fraction (lower) in ≥ **5 of 6** tasks, using **real `gen_ai.usage.*` counts** (ADR-0016.11), **with the per-snapshot index/materialization cost charged to arm B** (no warm-daemon amortization — the vendor's advantage that ghx structurally cannot have). Wall time informational only. |
| **CBM-additive (necessity)** | the win comes from the ENGINE, not from noise | On the same tasks, arm B's advantage must be attributable to the call-graph/semantic queries (traces show `local:cbm` evidence carrying the answer), not to tasks codemap/ast-grep already solved. If ~80% overlap means arm B rarely escalates to cbm, the additive value is empirically ~0 and the backend is not worth its dependency surface. |

**Corpus:** query-class tasks authored/selected under ADR-0032.1 D3 rules
(memorization canary, pinned SHA, F2P/P2P where applicable), or the recon
suite's cross-file/precise-reference cells if sufficient. Minimum sample and
sequential stopping per ADR-0025 D1 / ADR-0016.8 sufficiency; a cell below
threshold ⇒ PRELIMINARY.

**Measure on ghx's harness, tasks, baseline, and judge — never the vendor's
numbers.** The vendor evidence *bounds* expectations (mildly discouraging on
quality) but cannot *settle* the ghx question (wrong baseline/tasks/judge).

## Considered and Rejected

- **Absorb "entirely" (the whole product).** Rejected — PA-0002's core
  correction. codemap/repomap are pure tools; this is a *product* whose posture
  (persistent-index-by-default, daemon, installer, injection hook) inverts
  ghx's founding tenets. You can gate a *subprocess* behind Tier-2; you cannot
  gate a *product's soul*. Swallow the engine, reject the posture.
- **Wire `local:cbm` in on the strength of the vendor's benchmarks.** Rejected —
  they are the wrong baseline/tasks/judge, and their own quality number (83 vs
  92) is a regression hidden behind a token-savings headline. Evidence-not-vibes:
  measure on ghx's harness first.
- **Skip cbm entirely (the additive value is only ~20%).** Not chosen — the
  ~20% (persistent call-graph + semantic search) is precisely the Tier-2
  escalation target (cross-file / precise-reference), so it is worth *one bounded
  measurement*. But the CBM-additive gate exists exactly so that if the overlap
  swamps the additive value in practice, we reject rather than carry dead weight.
- **Build the full production integration now, measure later.** Rejected —
  inverts the pre-registration discipline (ADR-0032.1) and risks shipping a
  quality regression. Harness before behavior; gate before wiring.
