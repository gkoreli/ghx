# 0016.7. Sidecar Report Reliability — Fixing the Gate-Run Negative

## Status

Proposed. Written immediately after the M4 gate run's futility stop
(ADR-0016.1 "Gate-run outcome", evidence in `docs/evals/gate-run-2026-07/`).
This ADR records the verdict-driven product decision: what exactly failed,
why, and the fixes that must land before the confirmatory rerun.

## Context: what the gate run measured

The 2026-07 gate run returned **THESIS NOT SUPPORTED** on the current
build: G1 correctness FAIL (sidecar 0.580 vs ghx 0.851), G2 evidence FAIL
(0.463 vs 0.70), with G3/G4/G5 passing. The instructed framing when this
ADR was commissioned was "fix the thin-report defect — make the sidecar's
reports carry citations and enough evidence density to clear G2."

Hand-verification of all 22 sidecar episodes **corrected that diagnosis**.
Healthy reports already carry citations and clear both failed gates:

| mode | n / 22 | correctness | evidence |
|------|--------|-------------|----------|
| healthy report (2.2k–5.5k chars) | 10 | 0.95 | 0.94 |
| BLOCKED escape hatch (~300 chars) | 8 | 0.00 | 0.00 |
| WARN: no report extracted | 4 | 0.56 | 0.20 |

The defect is **reliability, not evidence density**: 12 of 22 episodes
produced no usable report at all. The gates fail because zeros are
averaged in, not because good reports are too thin. Signal-per-token
(ADR-0016.6) confirms the architecture delivers when it completes:
sidecar main-agent SPT 0.921 vs ghx 0.048 (~19×) *including* the failures.

## Root causes (artifact-verified)

### RC1 — the persona never says how to run ghx, but scripts giving up

`internal/sidecar/prompt.go` tells the agent to "gather evidence with ghx"
and then provides a verbatim escape hatch:

> If ghx is unavailable, call submit_report immediately with:
> answer: "BLOCKED: ghx is unavailable in this sidecar session."

Nothing states that ghx is a **CLI binary on PATH executed via the shell
tool**. In `gin-routing_ghx-sidecar_1783287778632.json` the action log
shows the downstream agent searching its *registered tool list* for a tool
named "ghx" ("No matching deferred tools found") and taking the escape
hatch two tool-calls in. The downstream session also inherits the host
user's full Claude Code tool surface (MCP servers, deferred-tool search),
which makes the tool-list detour attractive and the failure intermittent —
8/22 episodes (36%), spread across both run days and five of six tasks.

### RC2 — strict typed unmarshal discards near-conformant reports

`sidecar.ExtractReport` (`internal/sidecar/report.go`) unmarshals the
`<ghx-report>` JSON into the typed `Report` struct and returns nil on
*any* mismatch. In `hono-middleware_ghx-sidecar_1783285987325.json` turn 1
the raw text ends with a single well-formed block whose JSON parses — but
`unverified`, `commandsRun`, `uncertainty`, `backendsUsed`, `nextReads`
are bare strings and `verified`/`relevantFiles`/`evidence` are single
objects where arrays are expected. The whole report — correct answer,
citations, commands — is thrown away and replaced by the WARN placeholder
in `runtime.go`, scoring ~0 on evidence for work that was done and
recorded. 4/22 episodes (18%). Under the 2,000-char compactness pressure
(the ADR-0016.1 pre-gate-run contract), models drop array brackets on
single-element fields often enough that strictness is a self-inflicted
wound.

### RC3 — no recovery path when extraction fails

`runtime.go` falls back to the WARN placeholder immediately. The ACP
session is still alive at that point; a one-shot corrective follow-up
("emit the <ghx-report> block now, JSON only") would recover most RC2
cases even without lenient parsing, and would also catch genuinely
missing blocks.

## Decision

Three product fixes, in order of expected impact:

1. **Persona CLI-invocation contract** (`prompt.go`): add an explicit
   "How to run ghx" section — ghx is a command-line binary already on
   PATH; run it with the shell/terminal/Bash tool; it is *not* an MCP
   tool or registered tool, do not search the tool list for it. Replace
   the blind escape hatch with a verify-first rule: before reporting
   BLOCKED, the agent must actually attempt `ghx --version` via the
   shell and may report BLOCKED only if that execution itself fails.
2. **Lenient report parsing** (`report.go`): coerce near-conformant
   shapes during unmarshal — a bare string where a string array is
   expected becomes a one-element array; a bare string in a claim array
   becomes `Claim{Summary: s}`; a single object where an array is
   expected becomes a one-element array. The `answer`-required rule
   stays. Every coercion is unit-tested against the exact JSON from the
   failed episode artifact.
3. **One-shot report retry** (`runtime.go`): when extraction still
   yields nil, send one corrective follow-up in the same ACP session
   before falling back to the WARN placeholder. The retry is recorded
   on the turn result so evals can count retries honestly rather than
   hiding them.

4. **BLOCKED is an alarm, not a data point to discover later** (Goga,
   2026-07-05): the eval runner preflight already verifies ghx is
   installed, so a sidecar episode whose report answer starts with
   `BLOCKED` contradicts a verified precondition. Harness-side guard
   (alarming, not scoring — the measurement stack is untouched): the
   runner prints a prominent per-episode ANOMALY line when a sidecar
   report is BLOCKED or the WARN placeholder; smoke/ladder runs (V1)
   **fail the test** on any such episode; gate runs keep scoring them
   honestly (they are real production behavior) but the operator must
   inspect the first anomaly before launching further rounds. The
   2026-07 run spent ~3 rounds of live tokens before the surrender
   pattern was characterized; this guard makes that impossible to miss
   after round 1.

### Non-goals

- **No scoring, threshold, or task changes.** The measurement stack
  stays frozen; the gates re-run exactly as pre-registered in
  ADR-0016.1. Fixing the subject, not the ruler.
- The unequal-cell weighting noted in the run's DATA QUALITY caveat is
  eval-stack follow-up; if addressed, it must be pre-registered before
  the rerun, separately from this ADR.
- Downstream-agent environment isolation (the inherited user tool
  surface in RC1) is a real contributing factor but architecturally
  belongs with ADR-0016.3's isolation work; recorded there as follow-up.
  The persona contract fix must be sufficient regardless of tool-surface
  noise — that is part of the point of the sidecar owning its doctrine.
- ~~`otel_exporter.go` OTLP/JSON hex-ID spec violation~~ **Fixed
  2026-07-05, same day it was found**: the exporter marshaled through
  vanilla protojson, base64-encoding `traceId`/`spanId`/`parentSpanId`
  where the OTLP/JSON spec requires lowercase hex — standard receivers
  rejected every span, which contradicted ADR-0016.4's "spec-compliant
  open format" decision and the visibility tenet (official industry
  tooling must consume our traces as-is). `hexEncodeSpanIDs` in the
  exporter now applies the spec deviation, pinned by
  `TestOTLPJSONFileExporterEmitsSpecHexIDs`; the gate run's local
  traces.jsonl was migrated in place (lossless ID transcode) and a
  hand-rolled replay script that papered over the violation was deleted
  the same day it was written.

## Acceptance (pre-registered before the fixes are built)

- Unit tests: coercion cases from the actual failed artifacts parse into
  the expected `Report`; escape-hatch prompt text asserts the
  verify-first rule.
- Ladder before spending tokens (ADR-0016.3): mock e2e stays green, then
  a ~3-episode V1 smoke on the fixed build with **zero BLOCKED and zero
  WARN-noreport** episodes.
- Confirmatory full gate run (6 tasks × 5 trials × 3 profiles, fresh run
  directory, same frozen identity discipline): all five ADR-0016.1 gates
  evaluated unchanged. Target: G1 and G2 flip to PASS; G3 must stay PASS
  (the persona compactness contract is untouched, so report size should
  not regress).
- `docs/evals/gate-run-2026-07/` remains committed as the honest
  negative regardless of the rerun's outcome.

## Consequences

- ADR-0017 remains paused until the confirmatory rerun passes.
- The eval framework did its job: a pre-registered negative verdict
  localized two one-line-diagnosable product bugs (a missing sentence in
  a prompt; an over-strict unmarshal) that manual demos never surfaced.
  This is the strongest evidence yet for the benchmark investment thesis
  in `docs/NORTH_STAR.md`.
- Scorer visibility note (Goga, 2026-07-05): scoring in this framework is
  deterministic Go (`rewards.go`) over committed artifacts — there is no
  LLM judge in the gate path. The visibility/truthfulness tenet (full
  auditability of scoring for humans and agents; any future LLM judge
  must emit full OTel reasoning traces and calibration metrics) is
  recorded in `AGENTS.md` and binds this thread's future work.
