# 0016.5. Resume-Replay Decontamination and Repeat-Read Metric Refinement

## Status

Proposed 2026-07-04, pre-registered **before any gate run** (all existing
runs are PRELIMINARY smokes; no gate data exists to be re-scored). This is
the metric change that ADR-0015.1's honesty clause reserved: "refining it
becomes its own pre-registered change landed before any gate run — never
after." The evidence demanded by that clause now exists.

## Context (V2 spot check, `v2-ledger-spot-2026-07-04`)

After the evidence ledger shipped (ADR-0015.1, `d3da07a`), the sidecar's
true turn-1 behavior was correct — two narrowed follow-ups
(`--lines 395-475`, `--grep "errorHandler"` on an already-inspected file),
zero unnarrowed re-reads. G4 still reported repeat-read 1.0 for two
distinct measurement reasons:

1. **Resume replay contamination.** ACP `loadSession` replays session
   history as `session/update` notifications. The turn capture records them
   as if the resumed turn executed them: turn 1's trace contained turn 0's
   eight commands byte-identical, all timestamped within 1 ms
   (`18:42:08.434`) — a replay burst — versus the two genuine commands with
   real ~1 s durations. This contaminates tool traces, repeat-read, ledger
   derivation inputs, and `sidecarInternalChars` accounting.
2. **Mention-based repeat detection.** The metric counts any path token
   seen in turn 0 and mentioned again later (`rewards.go` path-token
   overlap). A narrowed follow-up on the same file — precisely the behavior
   the ledger instructs — scores as a repeat. With replay fixed, the spot
   check's two legitimate commands would still score 1.0.

## Decision

1. **Replay decontamination (capture correctness, all consumers).** Tool
   calls and updates received before the turn's `session/prompt` request is
   sent (i.e., during `loadSession` history replay) are recorded separately
   as `replayed` and excluded from: turn tool traces, repeat-read inputs,
   ledger derivation, and char accounting. Replayed entries may be kept
   under a distinct field for audit but must never count as turn activity.
2. **Repeat-read metric refinement (pre-registered).** A later-turn tool
   call counts as a repeat read only when it re-reads an already-inspected
   path **without narrowing**: an identical command string, or a
   `read`-shaped command on the same path with no `--lines`, no `--grep`,
   and no new pattern relative to prior inspections of that path. Narrowed
   follow-ups (`--lines`, `--grep` with a new pattern, `--map` after plain
   read) are legitimate evidence-driven refinement and do not count.
   Mention-in-command alone never counts. The G4 threshold and resume-rate
   check are unchanged.
3. **Comparability note.** Both changes apply symmetrically to all three
   profiles. Committed smoke/spot artifacts keep their recorded scores as
   historical calibration (same policy as ADR-0016.2); nothing valid is
   re-scored because nothing valid exists yet.

## Consequences

- G4 measures what it claims: failure to reuse session memory, not session
  transport mechanics or healthy narrowing behavior.
- Accounting for resumed sidecar turns becomes honest (no replayed output
  double-count in `sidecarInternalChars`).
- One more V2 spot check (~2 episodes) validates both fixes before the
  gate run; the pre-gate-run checklist gains: "no replay contamination in
  resumed-turn traces."
