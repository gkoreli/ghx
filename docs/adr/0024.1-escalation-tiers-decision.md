# 0024.1. Escalation Tiers Decision — Tier-2 Local Structural Analysis

## Status

Proposed.

This is the M7 decision ADR following `docs/adr/0024-escalation-tiers-research.md`.
It governs NORTH_STAR **P3** ("Swallow the tools"), milestone **M7**, workstream
**A3** (Tier-2 structural tools absorbed under the CLI), and workstream **B9**
(sidecar-decided escalation tiers).

North-star filter: this removes structural reconnaissance from the main agent's
context, keeps the sidecar as the decision-making product, and makes escalation
auditable rather than magical. The moat remains the sidecar brain: codemap,
ast-grep, and repomap-style ranking are tools swallowed under that brain.

This ADR does not change eval scoring, detectors, reward code, gates, or
pre-registered measurement artifacts.

## Evidence Reviewed

- `docs/adr/0024-escalation-tiers-research.md` in full: codemap, ast-grep,
  repomap, stack-graphs, SCIP, ctags, clone economics, escalation signals, and
  OTel visibility.
- `docs/NORTH_STAR.md` P3, The Moat, M7, workstream A3, and workstream B9.
- `docs/adr/0026-prior-art-landscape.md`: absorption watchlist:
  codemap HIGH/MED, ast-grep MED/LOW, aider repomap PageRank MED/LOW,
  stack-graphs HIGH/HIGH behind codemap.
- `docs/adr/0026.1-sidecar-view-absorption.md`: absorb tools by making them
  disappear under ghx while preserving attribution and open formats.
- `docs/adr/0028.2-ghx-inspect.md`: `inspect` is remote Tier 1 and must not
  overlap with local Tier 2 importers, blast radius, call/reference graphs, or
  local clone indexes.
- `internal/mapengine/`: current mapengine is file-scoped. It extracts package,
  import, function, type, const, var, and other symbols through Go AST,
  tree-sitter, and regex fallback. It does not build repo-wide import,
  dependency, reference, definition, call, or PageRank graphs.
- `internal/sidecar/prompt.go`: the persona already has
  `AllowedBackends`, defaults to `["remote"]`, and says to name deeper
  backends when remote evidence is insufficient.
- `internal/sidecar/report.go` and `reportsink.go`: reports already carry
  `backendsUsed`, commands, evidence, and strict validation.

## Decision

Tier 2 means **local structural analysis over a cloned repo snapshot**. It is
not "more remote ghx"; it is not `inspect`; it is not a replacement for
`mapengine`.

The first M7 implementation lands in this order:

1. **Local snapshot and cache substrate**
   - Resolve repo/ref to a commit SHA.
   - Materialize a local, read-only working snapshot under `~/.ghx`.
   - Emit clone/cache provenance before any structural tool runs.
   - This lands first because every Tier-2 tool depends on the same local
     snapshot contract.

2. **codemap as the primary Tier-2 tool**
   - Absorb codemap as an internal subprocess tool, not as a user-facing
     dependency in the sidecar contract.
   - First surfaces: JSON/context output, importers, dependency flow, and blast
     radius when available.
   - Backend ID: `local:codemap`.
   - codemap is first because ADR-0024 found it HIGH impact / MED effort and it
     fills the biggest current gap: cross-file import/dependency structure that
     `mapengine` cannot provide.

3. **ast-grep as the structural pattern tool**
   - Absorb ast-grep as a direct subprocess tool for AST pattern searches and
     as the dependency that enables codemap `--deps` flows where codemap needs
     it.
   - Backend ID: `local:ast-grep`.
   - This lands after codemap because it is cheaper and useful, but it answers
     "where does this structural pattern occur?", not "which files matter?"

4. **repomap-style ranking as an algorithm, not a dependency**
   - Steal the idea: definitions/references/import graph features ranked with a
     PageRank-like centrality boost under a strict token budget.
   - Do not vendor or shell out to aider.
   - Backend ID: `local:repomap`.
   - This lands after codemap/ast-grep because it should rank from artifacts ghx
     already owns: local tree, mapengine symbols, codemap import/dependency
     outputs, and visible query terms.

Stack-graphs stays out of the first Tier-2 build. It remains a watchlist item
behind codemap for precise reference/definition and implementor questions, but
the first implementation must measure where codemap + ast-grep + repomap-style
ranking fail before absorbing a HIGH effort / language-maturity-risk backend.

## Tier Boundaries

Tier 0/1 remains remote evidence:

- `ghx explore`
- `ghx tree`
- `ghx search`
- `ghx read`
- `ghx read --map`
- `ghx inspect`

Tier 1 can rank candidate files and show per-file maps. It may not claim
whole-repo importers, blast radius, call graph, definition/reference graph, or
PageRank over a local index.

Tier 2 begins only after a local snapshot exists. Tier-2 tools may use
`internal/mapengine` over local files, but that use is subordinate to the
local structural workflow. `mapengine` remains the Tier-1 file map primitive;
codemap and repomap do not replace it.

Tier 3 remains handoff to the main agent when local structural evidence is still
insufficient or the question asks for implementation, refactoring, mutation,
build execution, or long-running debugging beyond reconnaissance.

## Clone and Cache Strategy

Tier 2 uses shallow, filtered, cached snapshots because M7 structural analysis
does not need repository history.

Default clone plan:

```text
git clone --depth=1 --filter=blob:none --no-tags --sparse <url> <worktree>
git -C <worktree> sparse-checkout set <candidate paths or dirs>
git -C <worktree> rev-parse HEAD
```

Rules:

- Cache root: `~/.ghx/cache/tier2/repos/github.com/<owner>/<repo>/`.
- Snapshot key: resolved commit SHA.
- Snapshot path:
  `~/.ghx/cache/tier2/repos/github.com/<owner>/<repo>/snapshots/<sha>/`.
- Metadata path:
  `~/.ghx/cache/tier2/repos/github.com/<owner>/<repo>/snapshots/<sha>/ghx-cache.json`.
- Metadata records: repo, remote URL, requested ref, resolved SHA, clone
  strategy, sparse paths, createdAt, lastAccessedAt, byte size, ghx version,
  and tool artifact hashes.
- If Tier 1 already found candidate paths, start sparse. If the question is
  repo-wide or codemap needs broader context, expand sparse checkout
  deliberately and emit that expansion as a Tier-2 decision event.
- For explicit diff/blast-radius questions, fetch the comparison ref
  shallowly on demand and record both SHAs.
- Private repos require an explicit clone preflight with `contents: read`
  credentials. API read permission is not assumed to imply clone permission.

Eviction:

- Default cache budget: 5 GiB under `~/.ghx/cache/tier2`.
- Default TTL: 30 days since `lastAccessedAt`.
- Eviction policy: LRU by snapshot metadata, never evict the active snapshot
  for the running turn.
- Eviction runs before creating a new snapshot and may also be exposed later as
  `ghx cache ls` / `ghx cache clean`.
- Cache eviction emits a local runtime log/event, not a report claim.

Rejected clone defaults:

- Full-history clone: unnecessary for M7 and too expensive.
- Uncached temporary clones: wastes bandwidth and makes multi-turn evidence
  less reproducible.
- Treeless clone as default: faster first contact, but worse for reusable
  cached structural analysis that repeatedly needs trees.
- Silent auto-expansion from sparse to full checkout: allowed only when recorded
  as an observable Tier-2 decision.

## Escalation Policy

Escalation is a deterministic policy plus agent judgment over explicit
observables. The LLM does not get to silently decide "try local"; it asks the
runtime for escalation through a declarative policy.

Add a versioned policy model:

```go
type EscalationPolicy struct {
    Version string
    Signals []EscalationSignal
    Rules   []EscalationRule
}

type EscalationSignal struct {
    ID          string
    Kind        string
    Description string
    Weight      int
}

type EscalationDecision struct {
    PolicyVersion string
    FromTier       string
    ToTier         string
    Allowed        bool
    FiredSignals   []string
    Observations   EscalationObservations
    Reason         string
}
```

Initial signal IDs:

| Signal | Trigger |
|---|---|
| `question.cross_file_dependency` | Question asks what imports/calls/depends on something, blast radius, what breaks, or dependency flow. |
| `question.precise_reference` | Question asks for call path, implementors, definition/reference, or exact symbol relationship. In v1 this may escalate to Tier 2 but can still end with Tier-3 handoff if codemap/ast-grep cannot answer. |
| `remote.search_exhausted` | At least two repo-scoped searches produced no accepted next read. |
| `remote.symbol_absent_after_maps` | Target symbol/path term is absent after mapped reads of candidate files. |
| `remote.candidate_ambiguous` | Tier 1 finds several plausible files but cannot rank the top 1-5 with evidence. |
| `remote.import_chain_invisible` | A mapped import/reference points to a file or package not visible in the remote evidence already fetched. |
| `answer.low_confidence_remote_only` | The sidecar is about to report low confidence with only `remote` evidence. |

Initial rule:

- Escalate from Tier 1 to Tier 2 only when `local` is present in
  `AllowedBackends`.
- Escalate immediately on either hard signal:
  `question.cross_file_dependency` or `question.precise_reference`.
- Escalate on any two soft remote-insufficiency signals:
  `remote.search_exhausted`, `remote.symbol_absent_after_maps`,
  `remote.candidate_ambiguous`, `remote.import_chain_invisible`,
  `answer.low_confidence_remote_only`.
- If Tier 2 is not allowed, the report must name the blocked backend in
  `uncertainty` / `nextReads` and must not fake a Tier-2 answer.

This policy is intentionally simple. It is pre-registered, inspectable, and
measurable. Later policy changes must be ADR'd before being used in a citable
run.

## Visibility Contract

Every Tier-2 decision must be visible in three places.

### Report

Extend the sidecar report contract with:

```json
{
  "tierUsed": "tier2",
  "backendsUsed": ["remote", "local:codemap"]
}
```

Rules:

- `tierUsed` is the highest tier used to answer the question:
  `tier0`, `tier1`, `tier2`, or `tier3`.
- `backendsUsed` remains the tool/backend ledger and uses canonical IDs:
  `remote`, `local:codemap`, `local:ast-grep`, `local:repomap`.
- Evidence entries cite recomputable commands or artifacts:
  `ghx tier2 codemap ...`, `codemap --json ...`, `ast-grep ...`, or a
  committed/local artifact path under the session directory.
- The answer must not cite `~/.ghx/cache` paths as primary evidence. Cache paths
  are provenance. Session artifacts and commands are evidence.

### Traces

Emit a `ghx.tier.decision` span or event before Tier 2 runs. Required
attributes:

```text
ghx.tier.policy.version
ghx.tier.from
ghx.tier.to
ghx.tier.allowed
ghx.tier.signals
ghx.tier.reason
ghx.repo.full_name
ghx.repo.ref
ghx.repo.sha
ghx.clone.strategy
ghx.clone.cache_hit
ghx.clone.sparse_paths.count
```

Each structural tool invocation is a child tool span with standard GenAI tool
semantics where applicable:

```text
gen_ai.operation.name=execute_tool
gen_ai.tool.name=codemap | ast-grep | repomap
ghx.tier=tier2
ghx.backend=local:codemap | local:ast-grep | local:repomap
```

### Session Artifacts

Persist Tier-2 artifacts under the session, not only under the cache:

```text
~/.ghx/sessions/<session>/
  tier-decisions.jsonl
  tier2/
    <turn>/
      clone.json
      codemap.json
      ast-grep.json
      repomap.json
```

The cache is an implementation detail. The session directory is the audit
surface.

Emission failures remain best-effort and must not fail the ask, matching
ADR-0022. Tool failures are different: a failed codemap/ast-grep invocation is
evidence and must be reported as uncertainty or a blocked Tier-2 path.

## Absorb vs Steal

| Tool / idea | Decision | Rationale |
|---|---|---|
| codemap | Absorb as subprocess first | HIGH/MED; active; JSON/context/importers/blast-radius directly fill Tier-2 gaps. |
| ast-grep | Absorb as subprocess | MED/LOW; useful direct structural search and codemap dependency for `--deps`. |
| aider repomap | Steal algorithm, not dependency | The useful part is budgeted graph ranking; ghx should own the model over its own artifacts. |
| stack-graphs | Keep out of v1; revisit behind codemap | HIGH/HIGH; precision value is real, but language maturity and integration cost should be justified by measured codemap failures. |
| SCIP | Do not absorb for M7 | Build/typecheck-heavy and not aligned with fast sidecar escalation. |
| universal-ctags | Do not absorb now | `internal/mapengine` already owns cheap symbol inventory; use ctags only if a measured language gap appears. |

Credit upstream projects in docs when their workflows or algorithms influence
ghx. Absorption means they disappear from the user's operational surface, not
from attribution.

## Implementation Shape

Add a Tier-2 domain package rather than scattering clone/tool logic through
the sidecar runtime:

```text
internal/sidecar/tier2/
  policy.go        # declarative escalation policy and decisions
  cache.go         # ~/.ghx cache layout, metadata, eviction
  clone.go         # clone/fetch/sparse materialization
  codemap.go       # codemap subprocess adapter
  astgrep.go       # ast-grep subprocess adapter
  repomap.go       # local ranking service
  artifacts.go     # session artifact writes
```

The sidecar runtime owns orchestration:

```text
sidecar turn
  -> remote Tier 1 evidence
  -> EscalationPolicy.Evaluate(observations)
  -> if allowed, tier2.Service.Analyze(...)
  -> report + traces + artifacts
```

Do not pass anonymous maps around as the Tier-2 API. The domain types are part
of the design: `Snapshot`, `CloneStrategy`, `ToolRun`, `StructuralFinding`,
`RankedFile`, `EscalationDecision`, and `Tier2Result`.

## Considered and Rejected

- **Let the LLM decide escalation implicitly**: rejected. It violates the
  visibility tenet and makes cost/correctness tradeoffs impossible to audit.
  The policy must emit fired signals and observations.

- **Make `inspect` do Tier-2 work**: rejected. ADR-0028.2 defines `inspect` as
  remote Tier 1. Blurring it with local import graphs would make tier boundaries
  overlap and hide cost.

- **Replace `internal/mapengine` with codemap**: rejected. `mapengine` is the
  shipped Tier-1 file map primitive and works without a clone. Tier 2 layers
  cross-file structure on top.

- **Start with stack-graphs**: rejected for v1. It is the right candidate for
  precise syntactic reference resolution, but codemap/ast-grep/repomap cover
  the first M7 use cases with lower effort and clearer integration.

- **Start with SCIP**: rejected. SCIP-class precision usually requires
  language indexers and build/typecheck context. That is too heavy for
  escalation-on-demand reconnaissance.

- **Use codemap MCP or HTTP mode first**: rejected for the first slice.
  Subprocess JSON is easiest to test, trace, sandbox, and attribute. MCP/HTTP
  can be reconsidered after the always-on daemon owns warm tool lifecycles.

- **Vendor upstream code immediately**: rejected. Shell out to codemap and
  ast-grep first; steal repomap's algorithmic shape without pulling aider in.
  Absorption under ghx does not require source vendoring.

- **No cache / temp clone every time**: rejected. It wastes time and bandwidth,
  and makes multi-turn session evidence less reproducible.

- **Full clone with history**: rejected. Tier-2 structural analysis needs a
  snapshot, not history. Fetch comparison refs only for explicit diff/blast
  radius questions.

- **Hide cache paths in evidence as if they were source citations**: rejected.
  Cache paths are provenance; session artifacts and tool commands are the
  auditable evidence surface.

Success criteria for the first engineering slice:

- Tier 2 never runs unless `AllowedBackends` includes local structural analysis.

- Cache hits reuse the same resolved SHA snapshot.
- `inspect` remains remote-only.

Full gate runs do not block this work. A later citable M7 verdict requires a
pre-registered eval run after the policy and tool stack are frozen.

## Open Questions

- Exact `AllowedBackends` spelling for local structural analysis:
  recommended first spelling is `local`, with canonical report backends
  distinguishing `local:codemap`, `local:ast-grep`, and `local:repomap`.
- Whether `ghx cache ls/clean` lands in the first implementation or after the
  automatic eviction path is proven.
- Whether codemap's own remote-clone mode should ever be used. Current decision:
  no for v1, because ghx must own clone strategy, cache location, and
  provenance.
- Which measured failure classes justify stack-graphs. Candidate threshold:
  repeated Tier-2 uncertainty on implementor/reference/call-path questions
  where codemap and ast-grep found files but could not prove symbol relations.

## Implementation Notes (items 1-2, 2026-07-06)

First engineering slice landed: the snapshot/cache substrate and codemap as
`local:codemap`. ast-grep (item 3), repomap ranking (item 4), the escalation
policy engine, sidecar-runtime orchestration, session tier artifacts, and
persona wiring are NOT in this slice.

What was built:

- `internal/sidecar/tier2/` per the Implementation Shape, with `service.go`
  added as the single owner (`Service`) that both the CLI and the future
  sidecar runtime call; `cache.go`, `clone.go`, `codemap.go` as planned.
  Domain types shipped: `Snapshot`, `CloneStrategy`, `ToolRun`,
  `SnapshotMetadata`, `Provenance`, `EvictionEvent`, `CodemapRequest`.
- Cache layout, metadata fields, 5 GiB budget, 30-day TTL, LRU order, and
  "never evict the active snapshot" implemented exactly as pre-registered.
  The active set is tracked per Service instance (the running turn).
- Clone plan implemented as pre-registered (`--depth=1 --filter=blob:none
  --no-tags [--sparse]`), with `git ls-remote` resolving repo/ref to the SHA
  before any clone so cache hits skip the network. Exact-SHA refs use an
  equivalent `init + fetch --depth=1 --filter=blob:none <sha> + checkout
  FETCH_HEAD` plan because `git clone --branch` cannot take a SHA; GitHub
  serves reachable-SHA fetches. Materialization is atomic (temp dir + rename
  keyed by SHA), so concurrent same-SHA clones converge.
- "Read-only snapshot" is enforced at the domain level: `Service` exposes no
  mutating operations and tools run as read-only subprocesses in the snapshot
  dir. File-mode enforcement (chmod) was rejected — it complicates eviction
  and adds no auditability.
- CLI surface: `ghx tier2 codemap <owner/repo> [--ref] [--sparse] [--context
  [--compact] | --importers <file> | --deps]`, matching this ADR's evidence
  command naming (`ghx tier2 codemap ...`). Provenance and eviction events
  print to stderr before any tool output; tool stdout stays clean for piping.
- Missing binary → typed `ErrCodemapNotInstalled` + install hint + exit 3,
  checked before any clone work; the domain error is the graceful-fallback
  signal the sidecar wiring will consume. A non-zero codemap exit returns the
  populated `ToolRun` plus an error naming the recomputable command (failure
  is evidence).
- Report contract: `Report.TierUsed` added (optional; canonical
  `tier0..tier3` enforced in `ValidateReport`), canonical backend IDs
  documented in the submit_report schema. Persona emission of these fields is
  deferred to the pre-registered persona revision.

Deviations and findings:

- Live verification against codemap built from source (`JordanCoin/codemap`
  main @ 2026-07-06; `go install` fails upstream — module declares path
  `codemap`): `--json .`, `context`, `--deps --json`, `--importers` all
  exist. `--importers` and `--deps` need ast-grep even for fan-in, so those
  two surfaces return honest tool-failure evidence until item 3 lands.
  `codemap context` emits JSON by default; no `--json` needed there.
- Live smoke on honojs/hono: miss → shallow-blobless clone at
  `626b185d0e80f…` (6.2 MB snapshot), provenance emitted, `context` and

- Trace emission (`ghx.tier.decision` span) is deferred to the
  sidecar-runtime wiring slice: sidecar telemetry is emitted post-hoc from
  turn structures (`emit.go`), so tier spans belong where the turn is
  assembled, not in the substrate. Session `tier-decisions.jsonl` follows the
  same slice.
- `ghx cache ls/clean` not built (open question resolved: after the
  automatic eviction path is proven).

Verification: `go vet ./...` clean; `go test ./...` all green;

## Implementation Notes (items 3-4, 2026-07-06)

Second engineering slice landed: ast-grep absorbed as `local:ast-grep`
(item 3) and repomap-style ranking as `local:repomap` (item 4). The
escalation policy engine, sidecar-runtime orchestration, session tier
artifacts (`tier-decisions.jsonl`), tier trace spans, and persona wiring
remain deferred to the sidecar-runtime wiring slice, as in slice 1.

What was built:

- **Shared subprocess base** (`toolrun.go`): `ToolRun` moved out of
  `codemap.go` and gained a `Tool` field so every absorbed binary renders
  its own recomputable `Command()`. A package-private `subprocessAdapter`
  now owns PATH discovery (typed not-installed error), timeout, and
  evidence capture; `Codemap` and `AstGrep` embed it. One owner for the
  concern, no duplicated exec plumbing (AGENTS.md Engineering Tenets).
- **ast-grep adapter** (`astgrep.go`): `local:ast-grep` runs
  `ast-grep run --pattern <p> [--lang <l>] --json=compact [paths...]`
  (surface verified live on ast-grep 0.44.1). Missing binary →
  `ErrAstGrepNotInstalled` + install hint + exit 3 BEFORE any clone
  (proven by a CLI test that empties `PATH`, and live: no cache dir is
  created). Artifact key `ast-grep:run:<lang>:<digest12>` — patterns are
  arbitrary multi-line text, so keys carry a bounded digest of
  pattern+lang+paths rather than the raw pattern.
- **Grep-parity exit semantics** (live finding, 0.44.1): ast-grep exits 1
  with clean stderr and `[]` stdout when the search ran but matched
  nothing. The adapter treats that as a finding, not a failure
  (`err == nil`, `ToolRun.Matched() == false`); the CLI prints the empty
  JSON and exits with ghx's semantic no-results code 1. Exit 1 WITH
  stderr, and exit ≥2, stay real failures naming the recomputable command.
- **repomap as a stolen algorithm** (`repomap.go`): backend
  `local:repomap`, no aider dependency, no external binary — the
  recomputable evidence command is the ghx invocation itself. Inputs are
  artifacts ghx already owns: the snapshot tree walk, `mapengine` symbols
  (which stays the single symbol owner per Tier Boundaries), heuristic
  import extraction, and query terms. `RankFiles` is a pure function:
  file graph with reference edges (identifier mentions of names defined
  elsewhere, diluted by definer count, min ident length 3) and import
  edges (weight 5 split across resolved targets), personalized PageRank
  (damping 0.85, fixed 30 iterations, query-matching files boosted 10x),
  budget fill at ~4 chars/token with aider-style degradation (full entry
  → path-only → stop). Scores round to 1e-9 before sort/output so equal
  inputs render byte-identical bytes on any platform (Go may fuse
  float ops into FMA on arm64).
- **Determinism proven at three levels**: unit (shuffled input order →
  byte-identical JSON), fixture repo (rerun → identical artifact hash),
  live (two `ghx tier2 repomap honojs/hono --query compose --budget 512`
  runs → identical sha256 `cfd144c8…` over 367 ranked files).
- **CLI surfaces**: `ghx tier2 astgrep <owner/repo> [paths...] --pattern
  --lang [--ref --sparse]` and `ghx tier2 repomap <owner/repo> [--query
  --budget --ref --sparse]`, matching this ADR's backend naming. The
  snapshot/provenance/eviction stderr flow was extracted into one shared
  CLI helper (`tier2Snapshot`) used by all three subcommands; provenance
  still always precedes tool output.
- Both new backends record stdout/canonical-JSON sha256 in the snapshot
  `toolArtifactHashes` ledger like slice 1.

Live verification (2026-07-06, hono @ `626b185d0e80f…`, cache hit from the
slice-1 snapshot key):

- `astgrep --pattern 'compose($$$ARGS)' --lang ts` → JSON matches in
  `src/hono-base.ts` with meta-variables; exit 0.
- Zero-match pattern → `[]`, exit 1, "no ast-grep matches" naming the
  pattern.
- `repomap --query compose --budget 512` → 367 files ranked, 8 in
  budget, 511/512 tokens used; hubs (`src/jsx/base.ts`, `src/types.ts`,
  `src/utils/html.ts`, `src/context.ts`) surface.
- **codemap `--importers`/`--deps` unblocked**: with ast-grep on PATH,

  `src/compose.test.ts`, `src/middleware/combine/index.ts`,
  `src/hono-base.ts`) and `--deps` renders the dependency flow — the

Deviations and open v1 characteristics:

- Test files rank high in repomap output (e.g. `src/request.test.ts`
  second on hono): tests reference many definitions, so they accrue
  centrality — same characteristic as aider's map. Not filtered in v1;
  a future slice can down-weight path patterns if the sidecar's usage
  shows it matters. Query personalization already counteracts it.
- Import extraction is deliberately heuristic (Go blocks, ES
  from/side-effect/require, Python dotted modules; Rust/Java/Kotlin/Ruby
  fall back to reference edges only). Precise resolution is stack-graphs
  territory, which stays out of this build by decision.
- ast-grep pattern quality is the caller's concern: on 0.44.1, bare Go
  expression patterns like `fmt.Println($A)` can fail to parse as a Go
  translation unit and match nothing (verified live); statement/function
  shaped patterns match fine. The adapter passes patterns through
  verbatim — no rewriting.
