# 0016.2. Benchmark Validity Hardening Before the Gate Run

## Status

Proposed. Phase 3 implementation notes appended at the bottom.

## Context

ADR-0016.1 built the eval kernel and pre-registered gates G1–G5. Before
spending the formal gate run (~90 live episodes), an audit (2026-07-03) of
`internal/sidecar/evals/` asked: **is the instrument itself trustworthy?**
The north star is unchanged — prove or disprove whether the sidecar
architecture improves code reconnaissance enough to justify a
sidecar/delegation framework (ADR-0017 go/no-go). This ADR exists only to
make that verdict trustworthy; any hardening that would not change the
go/no-go reading is explicitly out of scope.

The audit found real validity gaps, ordered by decision impact:

1. **G1 is parrotable (HIGH).** Correctness matches expected symbols and
   claims as raw case-insensitive substrings over all episode text. Two
   fixtures leak their own answers: `flask-routing` expects symbol
   `route` while the question says "the route() decorator";
   `express-router-location` expects symbol `Router` while the question
   says "is the router itself implemented". Since agents echo questions,
   an episode can score symbol hits without exploring. Substring matching
   also self-inflicts false positives (`route` ⊂ "routes"). If G1 parity
   can be reached by parroting, the gate cannot distinguish a sidecar
   that answers from one that summarizes the question.
2. **G2 accepts junk evidence (HIGH).** The evidence reward counts a
   verified claim as evidenced when its evidence string is any non-empty
   text. A report claiming `"evidence": "trust me"` scores the same as
   `"src/compose.ts:32"`. G2 gates exactly the property that makes the
   sidecar report worth trusting instead of the transcript; a
   non-citation floor makes it vacuous.
3. **The verdict does not know its own sample size (HIGH).** The smoke
   runs printed **THESIS SUPPORTED** at n=1 with only a small
   INSUFFICIENT-DATA note when a profile was entirely absent. Nothing
   checks the pre-registered minimum (≥ 6 tasks, ≥ 5 trials per
   task × profile, ≥ 2 multi-turn tasks, all 3 profiles). A preliminary
   verdict that looks final is the most likely way this benchmark
   misleads the ADR-0017 decision.
4. **G3 has two known bias channels (MED).** (a) Direct-profile
   tool-output accounting depends on the ACP adapter attaching content to
   `tool_call`/`tool_call_update`; an adapter that omits it silently
   undercounts the baseline and hands the sidecar an unearned G3 pass.
   (b) Sidecar episodes that fail and produce empty/no reports deflate
   the sidecar's mean main-agent chars, again helping G3 while G1 might
   still pass on the surviving episodes.
5. **Ground truth can rot silently (MED).** Expected files were verified
   against default branches on 2026-07-03, but repos move (ADR-0016.1
   already rejected one fixture for exactly this). A gate run against a
   drifted fixture wastes the spend or, worse, produces a false G1
   failure blamed on the sidecar.
6. **Coverage is stylistically narrow (LOW, recorded not fixed).** All
   six tasks are "where is X implemented / how does X work" reconnaissance
   on popular open-source repos, 2 of 6 multi-turn, one evidence-honesty
   task. That satisfies the pre-registered minimum and is representative
   of the sidecar's target workload, but the verdict generalizes only to
   this task family — stated as a standing caveat, not fixed here.

## Decision

Adopt **task validity rules**, a **citation floor for evidence**, and
**verdict self-awareness** — the minimal set that protects G1, G2, and G3
— plus an executable pre-run fixture check. Everything is tests and
validation rules; no architecture changes, no new metrics, no threshold
changes (thresholds stay as pre-registered in ADR-0016.1).

### Task validity rules (enforced by `Task.Validate`, i.e. at load time)

A task fixture is **disqualified** when:

- **Leakage**: any `expectedFiles`, `expectedSymbols`, `requiredClaims`,
  or `unacceptableClaims` entry appears as a case-insensitive substring
  of any question turn. Checks must be *discoverable*, never *given* —
  if the question names it, it cannot be scored. (Unacceptable claims are
  included because a leaked one would zero every honest echo of the
  question.)
- **Emptiness**: no positive check at all (pre-existing rule), empty
  id/repo/turns (pre-existing), or any blank check string (new — a blank
  substring matches everything).

### Scoring hardening (rewards.go)

- **Symbols match on word boundaries**, not raw substrings: `route` no
  longer matches "routes". Files and claims stay substring-matched (paths
  and phrases don't have useful word boundaries), protected by the
  leakage rule instead.
- **Evidence must cite**: a verified claim's evidence string counts only
  if it contains a path-like token or a `:<line>` reference. Presence of
  a command trail and reasons on relevant files stay as-is.

### Verdict self-awareness (gates.go)

- `Verdict` gains `DataSufficient` plus counters (distinct tasks,
  min trials per task × profile, multi-turn tasks, profiles present)
  checked against the pre-registered minimums. When below minimum, the
  markdown verdict line is prefixed **PRELIMINARY** and the reason is a
  note. Gate math is unchanged — a preliminary run still computes gates.
- **Data-quality notes** (warnings, not gate failures): direct-profile
  episodes with tool calls but zero `toolOutputChars` (adapter not
  reporting outputs → G3 biased pro-sidecar); sidecar episodes with a
  missing/empty report answer (deflates G3 denominator); per-task episode
  counts unbalanced across profiles (unweighted means skew G1/G3); ghx
  baseline mean correctness below the G1 absolute floor (the "≥ 0.9 ×
  ghx" relative comparison is vacuous against a collapsed baseline — a
  G1 pass in that state says nothing about parity).
- **Verdict footnote**: the rendered verdict states that `Overall` is not
  cross-profile comparable (compression is 0 by construction for direct
  profiles) and that G3 is meaningful only jointly with G1/G2 — a tiny
  useless report maximizes compression, so compression alone never
  supports the thesis.

### Fixture repairs (this ADR's rules applied to the current set)

- `flask-routing`: drop leaked symbol `route`; keep `add_url_rule`,
  files unchanged.
- `express-router-location`: drop leaked symbol `Router`; add
  `unacceptableClaims: ["lib/router/index.js"]` — verified live
  2026-07-03 that Express 5 has no `lib/router` and
  `lib/application.js:26` does `var Router = require('router')`; an
  agent answering from stale Express-4 training data cites exactly
  `lib/router/index.js`. The full stale path (not the bare `lib/router`
  directory) is used deliberately: an honest answer may truthfully say
  "there is no lib/router here", and an unacceptable-claim substring must
  never fire on an honest negation. This *strengthens* the task's
  evidence-honesty purpose after losing the weak symbol check.
- All other fixtures pass the new rules unchanged.

### Executable pre-run sanity check

`TestTaskGroundTruth` (build tag `agent_e2e`, no LLM, network + token
only) asserts every `expectedFiles` entry of every fixture exists on the
repo's default branch via raw.githubusercontent. Required green before a
formal gate run; also re-run when a fixture is edited.

### Pre-gate-run checklist (the operational contract)

1. `go test ./internal/sidecar/evals` — validity rules and reward tests.
2. `go test -tags=agent_e2e -run TestTaskGroundTruth` — fixtures fresh.
3. Adapter reports tool outputs: any smoke episode of a direct profile
   must show `toolOutputChars > 0`; a gate run with the warning note
   present is invalid for G3.
4. Identical agent command/model for all profiles (already in RunConfig).
5. Verdict must print without the PRELIMINARY prefix, or it is not the
   gate run.

## Considered and rejected (north-star filter)

- **Precision penalty on correctness** (punish path-spraying): direct
  profiles legitimately narrate many paths while exploring; a precision
  term would penalize the baseline asymmetrically and *manufacture* a G1
  edge for the sidecar. Rejected as verdict-distorting.
- **Multi-phrasing claim schema (anyOf)**: richer, but no current gate
  depends on it; adds fixture complexity before we know the simple form
  fails. Deferred.
- **Task-weighted aggregates**: with balanced runs (enforced by the
  unbalance warning) plain means are equivalent. Deferred.
- **LLM-as-judge**: pre-registered as out of scope in ADR-0016.1;
  deterministic rewards remain the gate.
- **Ref/SHA pinning for fixtures**: pinning would make scores reproducible
  over time, but the product explores the live default branch — pinning
  the eval to an old ref would measure something users never run. The
  freshness preflight (detect drift, fix fixtures) protects the verdict
  at lower cost. Rejected for now.
- **Precision on file matching** (suffix match on bare names like
  `tree.go` can hit same-named files elsewhere): real but low-impact on
  these fixtures; recorded as a standing caveat rather than complicating
  the matcher before evidence it distorts a gate.

## Consequences

- Correctness scores may drop slightly across *all* profiles (word
  boundaries remove false hits); this lands before the gate run, so no
  measured result is invalidated. Thresholds are untouched.
- The committed smoke snapshots (`docs/evals/2026-07-03-smoke*/`) retain
  rewards computed under the old rules; they are historical calibration
  artifacts, not gate evidence, and are not recomputed.
- Two fixtures get honest repairs; the express task becomes a sharper
  hallucination trap.
- A formal run below sample minimums now self-labels PRELIMINARY — the
  ADR-0017 decision can only be fed by a verdict that isn't.

## Implementation Notes

*(Phase 3 — appended during engineering, 2026-07-03.)*

- Implemented exactly as decided; no deviations from the Decision section.
  Audit was two-pass: a direct read of the scoring core plus an independent
  mechanical subagent pass over fixtures/rewards/gates; the two reconciled
  into the findings above (the subagent additionally surfaced the collapsed
  -baseline vacuity and the Overall-comparability caveat, both adopted).
- `Task.Validate` now enforces leakage/blank rules at load time — the six
  shipped fixtures pass after the two repairs, and
  `TestValidateRejectsLeakedChecks` pins six rejection cases plus the
  discoverable-checks acceptance ("compose" vs "composition" is the
  deliberate near-miss case).
- Word-boundary matching is applied to symbols only; expected files and
  claims keep substring semantics per the Decision (leakage rule is their
  guard). `TestSymbolWordBoundary` pins the parrot vs genuine split.
- `citesEvidence` accepts a path token or `:<line>` reference. Known noise:
  time-like strings ("12:30") technically match the line-ref pattern;
  accepted — false citations of that shape don't occur in agent evidence
  at observable rates and the alternative (stricter parsing) risks
  rejecting honest citation styles.
- Verdict self-awareness: `Verdict.DataSufficient` + PRELIMINARY labeling
  + four data-quality warnings, pinned by six new gate tests including a
  synthetic full gate-run sample (6 tasks × 5 trials × 3 profiles) that
  must NOT be labeled preliminary.
- `TestTaskGroundTruth` (agent_e2e tag) verified live 2026-07-03: all 12
  expected files across the 6 repos exist on their default branches
  (2.3s, network only).
- The committed smoke snapshots are unaffected (historical artifacts);
  the next live run will score under the hardened rules.
