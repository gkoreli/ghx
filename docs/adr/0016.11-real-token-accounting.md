# 0016.11. Real-Token Accounting — Promoting Provider Usage from Inert to Reported

## Status

Accepted on merge. Pre-registers the reporting change that narrows TRUST.md
hole **H5** ("token accounting is a chars/4 proxy"). Per the Visibility and
Truthfulness tenet, the real-token SPT variant and the run-economics line
are registered here **before** any run is reported under them. No gate, no
threshold, and no existing SPT number changes: this ADR adds a second,
provider-grounded view alongside the chars/4 view and pre-registers the
criterion under which a future ADR may flip which one is primary.

## Problem

Every SPT number quoted so far (ADR-0016.6) estimates tokens as `chars/4`.
That proxy is honest about ratios but approximate in absolute terms, and
TRUST.md H5 names it as an open hole. ADR-0016.10 D6 closed the data gap:
eval episodes now persist provider-reported usage per turn
(`TurnRecord.RawSDK.Usage` — `inputTokens`, `outputTokens`,
`cacheReadInputTokens`, `cacheCreationInputTokens`, `costUsd`, `source`),
captured from the adapter's `_claude/sdkMessage` stream. The field is
deliberately inert — no scorer reads it. The first instrumented spot check
(`docs/evals/spot-instrumented-2026-07-06/`, 5 episodes) proved the field
populates live, including per-turn `costUsd` on every terminal result.
What is missing is the promotion: computing SPT from the persisted usage
and reporting it, without breaking comparability with every committed run
that lacks the field.

## Decisions

### D1. Real-token SPT: session-level, all-processed-tokens denominator

A parallel SPT variant, `signal / (realTokens / 1000)`, computed per
episode and aggregated per profile:

- **Signal is unchanged:** `correctness × evidence`, exactly as registered
  in ADR-0016.6. Same per-1,000-token scaling.
- **Episode real tokens** = sum over the episode's turns of
  `inputTokens + cacheReadInputTokens + cacheCreationInputTokens +
  outputTokens` from `TurnRecord.RawSDK.Usage`. This is the
  *all-processed-tokens* view: every token the provider attended to on
  behalf of the episode counts once, with no favorable weighting of cached
  context. Cache economics (cache reads are cheaper, not free) is captured
  separately and honestly by the `costUsd` line (D4), not by discounting
  the denominator.
- **One level, not three.** Provider usage is reported per subject-agent
  session and cannot be attributed across the main-agent/sidecar boundary
  the way chars can (ADR-0016.6's three levels read
  `mainAgentChars`/`sidecarInternalChars`/`totalWorkflowChars`, which the
  harness measures at the boundary). The real-token variant is therefore a
  **session-level** measure: for direct profiles it covers the whole
  workflow; for the sidecar profile it covers the sidecar session
  (exploration + report). Cross-profile comparison stays meaningful as
  "signal per provider token spent on the episode". The three-level split
  remains chars-based only.
- **Aggregation matches the chars variant:** per profile, over the same
  gate-filtered episode set (`validateEpisodesForVerdict` exclusions),
  summing signal and summing real tokens before dividing — never averaging
  per-episode ratios (ADR-0016.6 implementation note).
- Both usage sources (`result` and `assistant_sum`) are accepted as token
  evidence: both are provider-reported; `assistant_sum` merely means the
  turn ended without a terminal result message.

### D2. Coverage rule: all-or-UNAVAILABLE, never a silent partial mean

An episode **has usage** iff it has at least one turn and *every* turn
carries a non-nil `RawSDK.Usage`. A profile's real-token SPT is reported
**only when every episode in that profile's aggregate has usage**;
otherwise the value is labeled `UNAVAILABLE` together with the coverage
count (`k/n episodes carry usage`). There is no partial mean: a mean over
the covered subset would silently compare different episode sets across
the two variants and bias whichever direction the uncovered episodes lean.
Zero-episode profiles are UNAVAILABLE (0/0). Merged corrective-retry and
wrap-up attempts already fold their usage into the primary turn
(`RawSDKAudit.Merge`, ADR-0016.10), so the per-turn rule needs no special
casing for them.

### D3. Dual reporting: both variants always shown, chars/4 stays primary

- The verdict (JSON + markdown) and `evalreport` gain a
  "Signal per token" section that always shows **both** variants: the
  ADR-0016.6 chars/4 table (three levels, unchanged math) and the
  real-token session-level table (or its UNAVAILABLE label). Neither
  replaces the other: chars/4 remains the primary, citable SPT because it
  is the only variant computable on **every committed run** — all
  artifacts produced before ADR-0016.10 lack usage and would read
  UNAVAILABLE forever.
- This also performs the verdict embedding ADR-0016.6 deferred ("verdict
  artifacts include an informational SPT table"): `Verdict` gains
  informational fields (`signalPerToken`, `realTokenSpt`, `economics`,
  all optional in JSON), populated by `EvaluateGates` and rendered by
  `FormatVerdict`. Committed verdict.json files are untouched; regenerated
  verdicts gain the sections.
- **Gates and thresholds are unchanged.** No gate consumes SPT
  (ADR-0016.6: observational, not a gate); `ThesisSupported`,
  G1–G5 math, and sample-sufficiency rules do not read either variant.

### D4. Run economics: costUsd totals, always coverage-labeled

The verdict reports run economics from the persisted per-turn `costUsd`:

- **Total run cost and per-profile cost**, summed over **all loaded
  episodes — including gate-excluded ones**. This is a deliberate,
  registered asymmetry with SPT: SPT measures the subject over the
  gate-comparable set; economics measures what the run cost, and excluded
  episodes still spent money.
- An episode **has cost data** iff every turn's usage has
  `source == "result"` (only terminal result messages carry
  `total_cost_usd`; an `assistant_sum` turn has tokens but no price).
- Totals are always labeled with coverage (`k/n episodes carry cost
  data`); when `k < n` the printed total is explicitly a **lower bound**,
  and when `k == 0` the line reads UNAVAILABLE. No silent partials here
  either.

### D5. Pre-registered switch criterion (the future primary flip)

A future ADR may flip the primary SPT from chars/4 to real tokens only
after **3 citable runs** (full-rigor or baseline-reused gate runs, not
spot checks) have reported both variants with **100% usage coverage on
every profile**. That ADR must: (a) compute the chars/4 ↔ real-token
relationship over those runs' committed artifacts (per-episode ratio
distribution, per-profile), (b) restate any externally quoted SPT claims
under the new primary, and (c) keep the chars/4 variant reported alongside
for historical continuity. Until that ADR exists, chars/4 is primary and
the real-token variant is informational.

## Considered and rejected

- **Fresh-tokens-only denominator** (`input + cacheCreation + output`,
  excluding cache reads): rejected — cache-read tokens are context the
  model attended to; excluding them would make SPT look better under
  heavy caching without any change in signal density. Price-weighted
  reality lives in `costUsd` (D4).
- **Splitting real tokens across the three chars levels:** impossible from
  provider usage — it is one session-level number; any split would be an
  invented allocation. Rejected (D1).
- **Replacing chars/4 now:** breaks comparability with every committed
  run; rejected (D3).
- **Partial-coverage means:** silently compares different episode sets and
  biases the number; rejected (D2) — UNAVAILABLE with counts instead.
- **Restricting economics to the gate-filtered set:** hides real spend;
  rejected (D4).
- **Emitting new OTel metrics for real-token SPT:** no chars/4 SPT metric
  exists today (SPT is a report-time computation over artifacts); adding a
  metrics stream is a separate observability decision, not smuggled in
  here.

## Verification plan

- Unit: parity fixture (known usage → known real-token SPT, exact values);
  coverage rule (one turn missing usage → episode lacks usage → profile
  UNAVAILABLE with correct counts; zero-turn episode lacks usage);
  economics (result vs assistant_sum coverage, lower-bound labeling,
  exclusion-inclusive totals); rendering (`FormatVerdict` shows both SPT
  blocks and the economics line; a usage-less fixture renders UNAVAILABLE).
- `go vet ./...`, `go test ./...` (real exit codes), `-race` on
  `internal/sidecar/evals`.
- Golden check over committed artifacts: recompute real-token SPT and
  economics on `docs/evals/spot-instrumented-2026-07-06/` (episodes carry
  usage) and record the numbers in the implementation notes; recompute on
  a pre-0016.10 committed run (no usage) and confirm the verdict says
  UNAVAILABLE.

## Implementation notes (2026-07-06, same day)

Implemented exactly as registered; no formula, coverage, or economics rule
changed while building. Shape decisions:

- `internal/sidecar/evals/spt.go` gains the parallel computation only —
  `episodeRealTokenUsage` (per-episode token/cost/coverage fold),
  `ProfileRealTokenSPT`, `AggregateRealTokenSPT`, `RunEconomics` /
  `ProfileEconomics`, `ComputeRunEconomics`. The existing chars/4
  functions are byte-identical to before this ADR.
- `Verdict` gains `signalPerToken` / `realTokenSpt` / `economics`
  (omitempty), populated in `EvaluateGates` after gate math; rendering in
  `FormatVerdict` as "## Signal per token (informational, not a gate)"
  with both blocks plus "## Run economics". `evalreport` prints the same
  real-token block and economics lines after its existing chars/4 table.
- Per D2/D4 the JSON always carries per-profile coverage counts
  (`episodesWithUsage`, `episodesWithCost`), so UNAVAILABLE labels are
  recomputable from verdict.json alone.

Golden recompute (commands: `go run ./internal/sidecar/evals/cmd/evalreport
docs/evals/spot-instrumented-2026-07-06/episodes` and `.../discovery`;
deterministic, re-runnable):

- `spot-instrumented-2026-07-06/episodes` (2 ghx-sidecar episodes, both
  with usage): real-token SPT (session) **0.005416** per 1k tokens over
  287,193 provider tokens, signal sum 1.556 (episode tokens: flask-routing
  122,936; gin-routing 164,257 across 2 turns). Chars/4 workflow SPT on
  the same episodes is 0.079 — the ~15× gap is expected: provider tokens
  re-count cached context on every API call, chars count content once.
  Economics: **$0.3694 total** (2/2 episodes with cost data) — flask
  $0.1470, gin $0.2224.
- `spot-instrumented-2026-07-06/discovery` (3 episodes, one per profile,
  all with usage): signal = 0 everywhere (verifiedRecall 0 spot, deterministic
  corr 0), so real-token SPT is a defined 0.000; economics **$0.9940
  total** (3/3) — plain $0.3857, ghx $0.4462, ghx-sidecar $0.1621. The
  sidecar episode cost 2.4–2.8× less than the direct profiles on the same
  task.
- Pre-0016.10 committed run `gate-run-2026-07-06-fixbatch` (100 episodes,
  no rawSDK usage): verdict renders real-token SPT **UNAVAILABLE (0/…
  episodes carry usage)** for every profile and economics UNAVAILABLE
  (0/100) — proven by re-running evalreport and pinned by unit test over a
  usage-less fixture.
