# 0015.1. Sidecar Evidence Ledger — Persistent Session Memory

## Status

Proposed 2026-07-04. This is the product fix for the only consistent gate
failure in the eval smokes (G4 repeat-read, ADR-0016.1), and the
implementation of the "evidence-shaped memory" that ADR-0014.1 made part of
the sidecar product contract. G4 failure blocks ADR-0017.

## Context (grounded in reconnaissance, 2026-07-04)

What exists today (file:line refs from read-only recon):

- Sessions persist `meta.json` (`name`, `repo`, `scope`, `turnCount`,
  `acpSessionId`, timestamps) and per-turn `report-<ms>.json` files with the
  full structured report (`internal/sidecar/session.go:12,101`,
  `report.go:34`).
- `BuildPrompt` rebuilds the prompt from scratch each turn and, on
  follow-ups, injects only repo, turns-completed, and scope
  (`prompt.go:60`). It never reads prior reports back (`ListReports` is
  unused by the prompt path).
- Resume is an opaque ACP `LoadSession` handoff (`acp.go:421`); whether the
  agent remembers prior tool use depends entirely on the external agent's
  loaded context.
- Since ADR-0016.3, `TurnResult.ToolTraces` gives ghx first-party knowledge
  of every command the sidecar ran and every file it touched.

Consequence, observed live in both V1 smokes (ADR-0016.3 notes): the sidecar
re-reads files across turns — repeat-read ratio 1.0 and 0.5 versus the
direct profile's 0.25 and 0.0 — failing G4. The sidecar has the memory on
disk; it just never uses it.

Metric honesty note: the eval's repeat-read detector is path-token overlap
over tool-call strings (`evals/rewards.go:268,298`) — it counts repeated
*mentions* of a path, not only literal re-reads, so a legitimate follow-up
`--grep` on an already-read file counts against memory. The metric stays
**unchanged** in this ADR: weakening it after watching it fail would be
exactly the self-deception ADR-0016.2 exists to prevent. If post-ledger spot
checks show the metric punishing legitimate references, refining it becomes
its own pre-registered change landed *before* any gate run — never after.

## Decision

1. **ghx-owned ledger, derived, not self-reported.** Each session gains
   `<sessionsDir>/<name>/ledger.json`, updated by the runtime after every
   turn, derived exclusively from data ghx already owns: the parsed
   `<ghx-report>` (relevant files, backends, commands run, uncertainty,
   next reads) and `TurnResult.ToolTraces` (actual commands, actual files
   touched). The model is never asked to maintain its own memory record.
   Fields follow the ADR-0014.1 schema: `repo`, `scope`, `commands_run`,
   `inspected_paths`, `mapped_globs`, `grep_patterns`, `relevant_files`
   (with reasons), `rejected_paths`, `backends`, `open_questions`, plus
   turn provenance and `updatedAt`.

2. **Ledger injection on resumed turns.** `BuildPrompt` includes a compact
   "Evidence ledger" block when `turnCount > 0`: inspected paths, relevant
   files with one-line reasons, rejected paths, open questions, and recent
   commands — with the explicit instruction that already-inspected files
   must not be re-read unless the new question requires different lines;
   the agent should cite ledger evidence instead. The block is bounded
   (target ≤ ~1,500 chars, newest-first trimming) so session memory never
   erodes the sidecar's own compression discipline (the ~2,000-char report
   contract from ADR-0016.1 remains untouched).

3. **ACP resume stays, as transport not memory.** `LoadSession` continues
   to provide conversational continuity when the adapter supports it, but
   correctness of memory no longer depends on it: the ledger travels in the
   prompt, so even a `NewSession` fallback (adapter without `loadSession`)
   retains evidence memory. This decouples the product contract from
   adapter capabilities.

4. **Ledger is part of the auditable surface.** `ghx sidecar` sessions can
   print their ledger (exact command surface decided at implementation);
   the eval's episode artifacts capture the injected block via the prompt,
   so V2 spot checks can verify what memory the agent actually received.

## Non-Goals

- No change to the repeat-read metric or any reward/threshold (see metric
  honesty note).
- No cross-session or cross-repo memory sharing.
- No compaction/expiration lifecycle yet (ADR-0014.1 lists it as a known
  negative; revisit when ledgers grow past the injection budget in
  practice).
- No Codemap/backend escalation state beyond recording `backends` used.

## Verification Plan (ADR-0016.3 economics ladder)

- **V0 (0 tokens)**: unit tests — ledger derivation from fake reports +
  tool traces; prompt injection bounded and formatted; `NewSession`
  fallback carries the ledger; existing prompt tests updated deliberately
  (they currently assert the absence of prior context).
- **V2 spot check (~2–3 episodes)**: rerun the `hono-middleware` sidecar
  profile; expect the turn-2 trace to show grep/read only on new
  lines/files, repeat-read ratio at or below the direct profile's, and G4
  resume still 1.0. Direct profiles are untouched by this change.

## Consequences

- The sidecar's memory claim becomes a product feature backed by disk
  state, not a hope about adapter session internals — this is the
  "persistent, addressable specialist with evidence-shaped memory" from
  ADR-0014.1, and the north-star P2 capability that makes follow-up turns
  cheaper than first turns.
- Prompt grows by up to ~1.5 KB on resumed turns (sidecar-internal, not
  main-agent context; G3 is unaffected by construction).
- `ledger.json` adds a session artifact; sessions remain local-first.

## Implementation Notes

Implemented 2026-07-04.

- Added `internal/sidecar/ledger.go` as the production ledger model and
  persistence boundary. The on-disk artifact is
  `<sessionsDir>/<name>/ledger.json`, written via temp-file-plus-rename after
  each completed turn. Entries store first-contributing turn provenance rather
  than duplicating repeated observations.
- The ledger schema follows ADR-0014.1's evidence-memory fields: repo, scope,
  commands run, inspected paths, mapped globs, grep patterns, relevant files
  with reasons, rejected paths, backends, open questions, and `updatedAt`.
  Rejected paths are represented but not yet populated because the current
  `<ghx-report>` contract has no rejected-path field; this remains a report
  schema follow-up rather than a derivation guess.
- Runtime wiring loads the ledger before `BuildPrompt`, injects it on
  follow-up turns, extracts the structured report, then derives and persists
  ledger updates from both the report and `TurnResult.ToolTraces`. This keeps
  memory ghx-owned instead of model-maintained.
- Command derivation is intentionally conservative: it recognizes direct
  `ghx read`, `ghx tree`, and `ghx search` shapes, including `--grep`,
  `--map`, quoted args, and backend flags. Unknown shell wrappers or unrelated
  commands are ignored rather than guessed.
- ACP resume remains transport, not memory. `RunTurnWithOptions` now checks
  `initResp.AgentCapabilities.LoadSession`; adapters without `loadSession`
  get a fresh `NewSession`, while the same ledger block still travels in the
  prompt.
- The public audit surface chosen was `ghx sidecar sessions ledger <name>`.
  This is the smallest consistent extension next to existing `sessions list`
  and `sessions show`, and it prints the persisted JSON directly for local
  inspection and eval artifact comparison.
- Prompt injection is bounded around 1,500 characters by rendering newest
  evidence first and trimming oldest commands before oldest inspected paths.
  Open questions are never dropped; if future ledgers accumulate very large
  open-question or relevant-file sections, compaction should be handled by a
  separate pre-registered ADR rather than silently weakening this contract.
- Verification added V0 tests for command-shape parsing, ledger derivation,
  persistence round-trip, prompt formatting/bounds, and the NewSession fallback
  prompt-memory path. No eval reward math, thresholds, or repeat-read metrics
  were changed.
