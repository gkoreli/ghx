# 0016.10. Trace-Capture Completeness

## Status

Accepted on merge. Pre-registers the measurement-stack change that closes
TRUST.md hole **H3** ("toolTraces come from ACP notifications; drops would
be silent"). Per the Visibility and Truthfulness tenet, this detector is
registered here **before** any run is scored under it; it applies **only to
runs whose episodes carry the raw-SDK audit field introduced here**. Past
artifacts are untouched: they lack the field, so the detector no-ops on
them and no historical episode is rescored.

## Problem

Every trajectory metric we quote (tool-call counts, trajectory reward,
tool-output char accounting, OTel `tool.*` spans) derives from
`ToolTraces`, which are captured from ACP `tool_call` /
`tool_call_update` notifications in `denyClient.SessionUpdate`
(`internal/sidecar/acp.go`) and `evalClient` (`internal/sidecar/evals/
client.go`). The 2026-07-06 fixbatch audit (codex, read-only; 100
episodes, 1,355 tool traces) found zero *internal* inconsistencies —
episode JSON, OTel spans, and sidecar-reported commands all agree — but
could only prove consistency of artifacts **derived from the same
ToolTraces source**. Whether the ACP notification path itself dropped or
mangled tool-use blocks before capture was unverifiable, because no raw
SDK firehose artifact existed to diff against. That is H3: a silent drop
would undercount trajectories with no detectable signal.

The audit channel already exists: eval-mode sessions set
`_meta.claudeCode.emitRawSDKMessages: true` (ADR-0020.1 D2.5/D5), and
`claude-agent-acp@0.55.0` then forwards every SDK message as the ACP
extension notification `_claude/sdkMessage` (`acp-agent.js:885-891`,
verified in the shipped adapter). ghx has never handled that
notification — the messages were emitted and discarded.

## Decisions

### D1. Raw-SDK audit persistence: normalized, bounded, per turn, inside the episode artifact

`denyClient` (sidecar profile) and `evalClient` (direct profiles)
implement `acp.ExtensionMethodHandler` and record `_claude/sdkMessage`
notifications into a new per-turn record:

- **Where stored:** `TurnRecord.RawSDK *sidecar.RawSDKAudit`, serialized
  as `rawSDK` inside the canonical episode JSON (following the existing
  `Report *sidecar.Report` precedent). NOT a sibling JSONL file. The
  original comparator sketch proposed `raw-sdk-messages.jsonl`; that is
  rejected because `DetectAnomalies(*Episode)` is pure over the single
  artifact and `SaveEpisode` re-derivation (ADR-0016.8 D6: stored
  anomalies == re-derived anomalies for any saved artifact) must keep
  holding — a second file would break both the purity and the
  "every score recomputable from committed artifacts" rule unless every
  consumer learned to thread it.
- **What is stored (normalized, not the verbatim firehose):** per turn —
  a live raw-message count (the audit denominator), the tool-use blocks
  from assistant messages (`{index, id, name, inputDigest, inputExcerpt,
  parentToolUseId}`), the tool-result blocks from user messages
  (`{toolUseId, isError, outputSize}`), provider-reported token usage
  (D4), and truncation markers. Text/thinking content is deliberately
  NOT persisted — it already lives in `TurnRecord.Text`/`Thinking`, and
  duplicating it would roughly double artifact size for zero comparator
  value. `stream_event` partial messages are counted but contribute no
  tool events (tool_use blocks arrive complete on the consolidated
  assistant message; counting both would double-count). Honest label:
  this is a *normalized bounded audit*, not a verbatim dump; if a
  detected gap ever needs the verbatim stream, a debug-only full dump is
  a follow-up, not part of this registration.
- **Size bounds (pre-registered):**
  - `rawSDKInputExcerptMax = 2048` bytes per tool-use input excerpt
    (matches the existing `OutputExcerpt` bound in `appendExcerpt`);
  - `rawSDKEventCapPerTurn = 1024` tool-use + tool-result events per
    turn; events beyond the cap are dropped, `truncated: true` and a
    dropped-event count are recorded, and the comparator then only
    reasons about the events present (never infers gaps from absence).
  - Worst case ≈ 2.2 MB/turn; observed episodes peak at 21 tool calls
    per turn, so the typical cost is a few KB.
- **Input digest:** `sha256` hex of `encoding/json.Marshal` of the
  decoded `any` value. Both sides of the later comparison (raw SDK
  input, captured `RawInput`) pass through the same
  JSON-decode→`json.Marshal` round trip, and Go marshals `map[string]any`
  with sorted keys, so digest equality is canonical without a custom
  canonicalizer.
- **Replay safety:** the adapter's `replaySessionHistory`
  (`acp-agent.js:2080-2115`) emits only `sessionUpdate` notifications,
  never `_claude/sdkMessage` — replayed history cannot pollute the raw
  audit. Defensively, any raw message that does arrive before the
  prompt is sent is dropped and counted (`replayedMessages`), mirroring
  the replayed-vs-live split used for tool traces (ADR-0016.5).

### D2. Raw channel on resumed turns (LoadSession meta)

Verified in the shipped adapter: `loadSession` →
`getOrCreateSession` forwards `params._meta` into `createSession`
(`acp-agent.js:2647-2670`), and the session fingerprint excludes
`_meta` (`acp-agent.js:55-58`), so a LoadSession request may carry the
audit flag. Since every `RunTurn` spawns a fresh adapter process, a
resumed turn's adapter otherwise defaults `emitRawSDKMessages` to false
(`acp-agent.js:3054`) and the raw channel would silently vanish on turn
1+, corrective retries, and wrap-up turns.

Decision: `RunTurnWithOptions` forwards a **raw-channel-only** meta on
LoadSession — `{"claudeCode":{"emitRawSDKMessages":true}}`, extracted
from `RunTurnOptions.SessionMeta` when and only when eval mode set the
flag at session creation. Production (`EvalMode:false`) builds no such
key, so LoadSession behavior is unchanged there. The full steering meta
(persona system prompt, tools allowlist, budgets, model pin) is
deliberately NOT forwarded on LoadSession by this ADR: that would change
subject-agent behavior on resumed turns and is a separate
measurement-conditions decision. **Discovered issue logged here for that
separate thread:** because each turn is a fresh adapter process and
LoadSession currently carries no meta at all, resumed sidecar turns run
without the ADR-0020.1 D2 steering (persona, tools allowlist, budgets,
model pin) today. This ADR does not fix or paper over that; it only
restores the audit channel, which does not alter model behavior.

The corrective-retry and wrap-up `RunTurnOptions` gain `SessionMeta` so
their LoadSession calls keep the audit channel; their results already
merge into the primary turn (`mergeRetryTurn`/`mergeWrapUpTurn` append
`ToolTraces`), and the raw audit merges the same way (append events,
sum message counts, prefer the latest terminal usage).

Direct profiles: `runDirectEpisode` sets the same eval-only
`emitRawSDKMessages` meta on its `NewSession` (a direct episode keeps
one live session for all turns, so no LoadSession concern). This adds
only audit notifications; it does not steer the subject agent, so
baseline conditions are unchanged.

### D3. The comparator: pure, artifact-only, pre-registered gap conditions

New `internal/sidecar/evals/trace_capture.go`:

```go
func CompareTraceCapture(raw *sidecar.RawSDKAudit, captured []ToolCallTrace) []TraceCaptureGap
```

Pure over episode-artifact fields only — no agent, no network, no live
SDK path — so any saved episode can be re-analyzed offline
(anomaly-taxonomy rule, ADR-0016.7). Matching is by tool-use ID: the
adapter sets ACP `toolCallId` to the SDK `tool_use` block id verbatim
(`toolCallNotification`, `acp-agent.js:3803-3826`), so `(id)` equality
is exact, with no digest-ordinal fallback needed for this adapter.

Gap conditions (exactly these four; a run scored under this ADR may not
add or remove conditions without a superseding registration):

1. `missing_tool_call` — a raw tool_use block has no captured
   `ToolCallTrace` with the same ID.
2. `missing_terminal_status` — a raw tool_result exists for an ID whose
   captured trace never recorded a terminal status
   (`completed`/`failed`) transition.
3. `input_mismatch` — both sides carry a non-empty input and the
   captured `RawInput` digest differs from the raw `inputDigest`.
4. `missing_output` — a raw tool_result carries non-empty output
   (`outputSize > 0`) but the captured trace has `OutputSize == 0` and
   no output excerpt.

Pre-registered exemptions and skip rules:

- **Adapter-by-design suppressions:** tool names `TodoWrite`,
  `TaskCreate`, `TaskUpdate`, `TaskList`, `TaskGet` never produce an ACP
  `tool_call` (`shouldEmitToolCall`/`isTaskTool`,
  `acp-agent.js:3782-3795` — TodoWrite renders as a `plan` update, Task*
  is suppressed until tool_result). Raw tool_uses with these names are
  exempt from condition 1; flagging them would be a false alarm about
  behavior the adapter documents.
- **Raw channel absent ⇒ no comparison.** When `RawSDK` is nil or
  recorded zero live messages, the comparator returns nothing. This
  covers pre-ADR artifacts, adapters without the feature, and any turn
  where the channel did not open. Absence of the audit stream is never
  evidence of a gap.
- **Truncated raw audit ⇒ compare only what is present.**
- **No overcount direction.** Captured-trace IDs absent from the raw
  audit are NOT a gap condition: H3 is about *undercounting*, and merged
  retry/wrap-up traces plus any partial raw coverage would make the
  overcount direction structurally noisy. If phantom captured traces
  ever become a suspected failure mode, that is a new registration.

### D4. Anomaly: `trace_capture_gap`, severity soft

`AnomalyTraceCaptureGap = "trace_capture_gap"` joins the declarative
taxonomy (`anomalies.go`). `DetectAnomalies` runs the comparator per
turn over **live** tool traces (replayed traces were accounted on the
turn that originally ran them, ADR-0016.5) and emits at most one anomaly
per turn, whose detail summarizes gap kinds, counts, and the first few
tool-use IDs (bounded). `CountAnomalies` gains the kind at the end of
the stable order.

**Why soft, not breaking (required justification):** the severity
taxonomy reserves `breaking` for episodes whose *product contract* was
violated — no usable report despite a verified environment
(`AnomalySeverity` doc, `anomalies.go`). A trace-capture gap violates no
product contract: the answer was produced, the report parsed, and the
correctness/evidence scores — which read answer text and report fields,
never `ToolTraces` — are untouched. What a gap flags is **measurement
undercounting**: trajectory reward, tool-call counts, tool-output char
accounting, and OTel tool spans may understate what the agent actually
did. That is an integrity signal about *our metrology*, not about the
episode, and the biased metrics err toward making the subject look
*less* active, never better. Soft severity keeps the count loudly
visible in every anomaly table (Visibility and Truthfulness) while
leaving the exclusion decision to a human reading the run — the same
posture as `eval_parallel_rate_limited` and the other
measurement-integrity soft kinds. If instrumented runs ever show gaps
correlated with score-bearing differences, upgrading severity (or
excluding flagged episodes from gates the way contamination does) is a
new pre-registered decision.

### D5. Scope: applies only to runs registered under this ADR

The detector activates purely on the presence of the `rawSDK` field in
a turn record. Every artifact produced before this ADR lacks the field:
zero anomalies, zero rescoring, zero change to any existing verdict.
The first run whose episodes carry the field is the first run whose
anomaly table may contain `trace_capture_gap`, and TRUST.md H3 moves to
"comparator built, pending first instrumented run" until that run
exists.

### D6. Bonus hook: provider-reported token usage persisted per turn (TRUST H5 groundwork)

The raw SDK channel carries what the chars/4 proxy (ADR-0016.6, TRUST
H5) has been missing: provider-reported token usage. Assistant messages
carry per-API-call `usage`
(`input_tokens`/`output_tokens`/`cache_read_input_tokens`/
`cache_creation_input_tokens`) and the terminal `result` message carries
the query-cumulative usage plus `total_cost_usd`. `RawSDKAudit.Usage`
persists these per turn: assistant usages are summed as they stream and
the terminal result usage overwrites the sum when it arrives
(`usageSource: "result"` vs `"assistant_sum"` records which one the
artifact holds). **No scorer changes**: SPT and compression math remain
chars-based exactly as registered in ADR-0016.6; this field is inert
persistence that a future H5 ADR can promote to the real-token source
after validating it against the proxy on committed artifacts.

## Considered and rejected

- **Sibling `raw-sdk-messages.jsonl` per episode** (the original
  sketch): breaks `DetectAnomalies` purity and the SaveEpisode
  re-derivation invariant; rejected in favor of the bounded in-artifact
  record (D1).
- **Persisting the verbatim firehose:** duplicates text/thinking already
  on the turn, roughly doubles artifact size, and adds nothing the four
  gap conditions read. Rejected; a debug dump knob is possible later.
- **`breaking` severity for missing raw tool_uses** (the sketch's
  suggestion): conflicts with the taxonomy's definition of breaking
  (product-contract violation) and would auto-invalidate episodes whose
  scores are unaffected. Rejected — soft with human-decided exclusion
  (D4).
- **Digest+ordinal fallback matching:** unnecessary for this adapter
  (toolCallId == tool_use id verbatim); adding an unused fallback path
  is speculative complexity. Rejected; revisit only if a future adapter
  breaks ID identity.
- **Forwarding full steering meta on LoadSession:** changes subject
  behavior on resumed turns — a product/measurement decision this ADR
  must not smuggle in. Logged as a discovered issue (D2), not fixed
  here.

## Verification plan

- Unit: comparator matrix (complete / missing call / missing terminal /
  input mismatch / missing output / suppressed-tool exemption / nil and
  truncated skips), anomaly derivation from a synthetic episode, raw
  persistence JSON round-trip, size bounds (excerpt cap, event cap +
  truncation marker), raw-message parsing (assistant tool_use, user
  tool_result, result usage, stream_event ignored), LoadSession meta
  extraction (eval vs production).
- `go vet ./...`, `go test ./...`, `-race` on `internal/sidecar` and
  `internal/sidecar/evals`.
- First instrumented run: read `trace_capture_gap` in the anomaly table
  and update TRUST.md H3 with the result (either direction — a zero is
  committed evidence too).
