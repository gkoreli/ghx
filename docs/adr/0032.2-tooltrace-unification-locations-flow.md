# 0032.2. Unify `ToolCallTrace` + fix the `Locations` capture flow

## Status

**Accepted** (Goga, 2026-07-07) at **full scope** — Layer A (type unification +
drop-fix, D1–D3) *and* Layer B (argv-derived path-scope, D4 below). It began as a
**pre-registration** of a measurement-touching change, per the frozen-measurement-stack
rule (AGENTS.md Visibility & Truthfulness): it changes what the eval layer captures for
one profile, so it was registered before implementation, not applied as a drive-by.
Found and verified by architecture audit **AA-0002**
(`docs/audits/AA-0002-reusable-core/`); Layer B was surfaced by the v2.8.0 dogfood
(`docs/dogfood/FRICTION.md`, the 2026-07-07 Locations item, finding (2)) — D2 alone
leaves `Locations` empty at the *source* for the sidecar's execute-driven recon. It
closes **TRUST hole H9**. Implementation must still measure the artifact delta on
committed fixtures before landing.

## Context

`ToolCallTrace` (and `ToolStatusTransition`) are defined **byte-for-byte twice** —
in the SAF runtime (`internal/sidecar/turnresult.go:81`) and in SAFE
(`internal/sidecar/evals/episode.go:184`) — with identical fields, JSON tags, and
doc comments (both cite ADR-0032.1 S2). The two copies are bridged by hand-written
converters, and they have **already drifted**:

- `convertSidecarTrace` (`internal/sidecar/evals/trace.go:12`) copies `ID/Kind/
  Title/RawInput/OutputSize/OutputExcerpt` + `StatusTransitions` but **omits
  `Locations`** — verified by re-reading the function body and by git-blame
  (`trace.go` last touched `afd6e99`, *before* `Locations` was added to the types).
- The reverse/host path (`host_episode.go:305`) and the plain/direct path
  (`evals/client.go:155`) **do** carry `Locations`.

Net effect: **ghx-sidecar-profile recon episodes silently persist empty
`Locations`**, while plain/direct/host profiles keep it. `Locations` is the field
ADR-0032.1 S2 added for the host-task R6 path-scope detector, so that detector runs
on silently-empty data for the sidecar profile — an **unregistered Visibility/
Truthfulness asymmetry** in committed artifacts. It also quietly falsifies ADR-0036's
"the eval stack reads the plain `ToolCallTrace` struct" claim (it reads a lossy copy).

AA-0002's five personas independently converged on this as the *only* genuine
finding; the SAF↔SAFE core is otherwise a correctly-sized shared kernel (`telemetry`
is a real leaf both halves emit through) — **no framework extraction is warranted**
(north-star filter; one product, no second consumer). This ADR is therefore narrow.

## Decision

- **D1 — Unify the type (depend-not-copy), serialization byte-identical.** Delete the
  `evals` copy of `ToolCallTrace`/`ToolStatusTransition`; `evals` uses
  `sidecar.ToolCallTrace` directly (it already imports `internal/sidecar` and already
  does exactly this for `sidecar.Report`). JSON tags are identical, so **committed
  artifacts are byte-identical from the dedup alone** — this half is non-measurement.
- **D2 — Fix the `Locations` capture flow (the measurement-touching half).** Ensure
  the sidecar-profile path captures `Locations` (remove the drop; with D1 there is no
  converter to drop it). This **changes committed artifacts for the sidecar profile**
  (`Locations` becomes populated where it was empty) — the reason for pre-registration.
- **D3 — Bound the blast radius + measure.** No scorer/gate/reward/anomaly-detector
  math changes. The only downstream consumer of `Locations` is the host-task R6
  path-scope detector (ADR-0032.1); it currently sees silently-empty data for the
  sidecar profile and will see real data after the fix — a **correctness improvement,
  not a scoring redefinition**. Implementation must show, on committed fixtures, that
  no host-task grader verdict changes except where `Locations` was legitimately
  missing, and note the (small) expected delta.

- **D4 — Derive path-scope from the `ghx` argv (the source-is-dry fix).** The sidecar's
  real recon is ~100% `kind=execute` tool calls (the agent shells out to `ghx
  read/search/inspect` via the ACP execute tool); ACP execute notifications do not carry
  file `locations`, so D2 alone leaves `Locations` empty at the *source* for the sidecar
  profile and R6 path-scope would still see nothing (dogfood FRICTION.md 2026-07-07,
  finding (2)). When an ACP notification carries no `locations`, parse the `ghx` argv
  already present in `tr.Title`/`RawInput` (e.g. `ghx read owner/repo path --lines A-B`,
  `ghx inspect owner/repo path`) and synthesize `Locations{Path, Line?}` from it, so R6
  path-scope has real data for execute-driven recon. This is **additive** (fires only
  when ACP carries none, so it never overrides real ACP locations) and is the half that
  actually closes H9; it is measurement-touching for the same reason as D2 and covered by
  the same pre-registration + delta measurement.

Also reconcile the double capture path (`denyClient.SessionUpdate` unions locations
vs `evalClient.SessionUpdate` replaces them — failure-class inventory B4 territory) as
part of D2 so the two agree; if that reconciliation proves to shift any anomaly
derivation, it stays in this same pre-registration.

## Consequences

- Closes TRUST H9; removes a duplicated type and its two-mapper drift class
  (agent-legibility win — one canonical owner).
- `Locations` becomes profile-consistent in eval artifacts; the R6 detector becomes
  trustworthy for the sidecar profile.
- Measurement change is isolated, registered, and measured — the frozen-stack
  discipline is honored.

## Implementation (as built)

**Implemented** and landed (worker `a3ae99b` → mainline `3a61b63`), verified by Fable
before merge:

- **D1** deletes the `evals` copy of `ToolCallTrace`/`ToolStatusTransition`; SAFE uses
  `sidecar.ToolCallTrace` directly (as it already did for `sidecar.Report`).
- **D2** removes `convertSidecarTrace` (it copied 6 fields + `StatusTransitions` and
  omitted `Locations`); `populateTurnRecord` now carries the runtime trace straight
  through. The flagship recompute `awk '/func convertSidecarTrace/,/^}/'
  internal/sidecar/evals/trace.go` now returns empty.
- **D4** adds a quote-aware argv parser (`internal/sidecar/evals/argvlocations.go`) that
  fills path-scope `Locations` from the `ghx` command line **only when ACP reports
  none** (additive; never overrides real ACP locations), applied at turn finalization.
- **Double-capture** reconciled by exporting `sidecar.MergeLocations` and having
  `evalClient` **union** rather than replace (matching `denyClient`).

Proofs committed and re-verified on mainline: **D1 byte-identical** trace round-trip
(`TestToolTraceSerializationByteIdentical`, 0 drift across 5 committed fixtures);
**corpus delta** 1682 execute traces empty→populated, **0** ACP-location overrides,
**0** host-task grader-verdict changes; the no-verdict-change guarantee is **structural,
not just empirical** (`TestArgvLocationsCannotChangeExecuteClassification`: derived
`Locations` land only on `execute`-kind traces; R6 `classifyLocations` runs only on
read/edit/delete/move/search kinds — the sets cannot intersect).

**Scoped decisions / honest caveats:**
- `Locations` stays `[]string` (paths only). The ADR's "`{Path, Line?}`" line half is
  **not** stored — storing it would change the type/serialization and break D1
  byte-identity, and R6 needs only paths; `--lines` is parsed and skipped.
- Derivation runs in the eval runner (measurement layer), **not** in production
  `denyClient` — the measurement change stays confined to the measurement layer.
- The D1 byte-identical proof is scoped to the **trace arrays**; a whole-`Episode`
  round-trip surfaces *pre-existing, unrelated* schema no-ops (empty `checks:{}`,
  older fixtures lacking `context.sidecarInternalChars`/`rewards.memory`) that D1 does
  not touch — confirmed by structural deep-diff.
- No live sidecar eval smoke ran in the worker (no ACP agent available there); the
  fixture-driven tests exercise the exact real captured command shapes from
  `episode_sidecar.json`/`episode_ghx.json`. Command-substitution shapes (`$(ghx …)`,
  backticks) are intentionally not attributed (conservative under-extraction).
