# 0019.1. Discovery Tier

## Status

Accepted 2026-07-06 (founder: "I don't like that repo is a hard
requirement for sidecar — that's an arbitrary limitation"). Supersedes
the single clause in ADR-0019 D3 that made `--repo` required; everything
else in ADR-0019 stands.

## Context

The requirement was born as "the question's anchor" but the dogfood week
falsified it as a product boundary: the first real reconnaissance task of
the week ("find open-source prior art similar to our framework") could
not reach the sidecar at all — the candidate list had to come from the
operator's own knowledge first (FRICTION.md 2026-07-05 "cross-repo
discovery gap", tagged tier2-demand). Reconnaissance starts one step
before "how does X work in repo Y": at "which repos do X". A
code-reconnaissance sidecar that requires the caller to have already done
the discovery is delegating the easy half. ghx itself already has the
cross-GitHub tools (search, repos); only the sidecar surface forbids the
question shape.

## Decisions

### D1. `--repo` becomes optional scope

With `--repo`: behavior unchanged — repo-scoped reconnaissance, repo-slug
session default. Without it: **discovery reconnaissance** — the sidecar
answers "which repos/libraries/frameworks do X", using ghx's cross-GitHub
search and repo tools to build a candidate set, then reading into the top
candidates enough to verify what it claims about them. Same command, same
report contract, same evidence bar; the scope is simply as wide as the
question. The `internal/cli/sidecar.go:39` hard error is deleted; the MCP
recon tool's `repo` parameter and the recon skill text become optional to
match (ADR-0019 D2 surface stays one tool).

### D2. Session naming without a repo

`--session` wins when given (unchanged). With `--repo`, the repo slug
default stands (unchanged). With neither, the session slug derives from
the question: kebab-cased leading words truncated to ~40 chars plus a
short content hash for uniqueness; the CLI prints the chosen session name
so the caller can resume it. Discovery sessions are ordinary sessions —
same `~/.ghx/sessions/<slug>/` layout, ledger, reports, traces.

### D3. Evidence rules for repo-level claims

The report schema does not change. Discovery citations use
`owner/repo` or `owner/repo:path` in relevant-file paths and evidence
sources. The evidence contract applies with one sharpening: a repo the
agent only saw in search results is an **inferred** candidate; only repos
it actually read into (files fetched, code inspected) may back
**verified** claims. Comparative statements ("X is the most complete")
must carry the uncertainty note when the candidate sweep was bounded.
ADR-0027 D4's evidence-required validation applies as-is — a discovery
report still needs verified claims with evidence, relevant paths, and
commands.

### D4. Persona: discovery doctrine

The persona gains a discovery section, active when no repo scope is
given: sweep broadly first (ghx search across code/repos, multiple query
formulations), triangulate candidates by signals worth trusting (real
usage in code, activity, docs), then verify the top candidates by
reading before claiming, and report a ranked comparison with explicit
unverified-tail honesty. Depth budgets (cheap/normal/deep) bound the
sweep exactly as they bound repo-scoped exploration — discovery at
`--depth deep` is the expensive shape, and that is the caller's dial.

### D5. Evals follow separately, pre-registered

Discovery-class eval tasks (ground truth for "which repos do X" — target
sets, acceptable-answer design, contamination rules for famous repos) are
a separate pre-registered eval ADR before any discovery number is
quoted. This ADR changes the product surface only; the measurement stack
is untouched. Until then, discovery quality evidence = dogfood sessions
under `~/.ghx` (visible, auditable, not citable).

## Considered and rejected

- **A separate `sidecar discover` command** — two commands for one
  mental act ("ask the recon sidecar") violates ADR-0019's zero-surface
  direction; scope should be inferred from what the caller provides.
- **Repo required but multi-valued (`--repo a --repo b`)** — still
  requires the caller to have done the discovery; solves the wrong half.
- **Web-search integration in the sidecar brain** — the sidecar's domain
  is the GitHub open-source world through ghx tools (NORTH_STAR); general
  web search dilutes the competence-domain boundary. Revisit only with
  demand evidence.
