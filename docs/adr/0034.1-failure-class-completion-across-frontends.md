# ADR-0034.1. Failure-Class Completion Across Frontends

## Status

Accepted on merge (2026-08-21; D1/D2/D3 landed, D4 deferred — see Implementation Notes). Research grounding: `docs/research/a4-error-affordances.md`
(§1 gap inventory G1–G6, §2 live command battery, §8 evidence appendix).
Advances NORTH_STAR workstream **A4** ("Error messages as agent affordances",
`docs/NORTH_STAR.md:304`) by completing ADR-0034's deferred phases.

## Context

ADR-0034 landed the unified FailureClass taxonomy for core CLI frontends
(phases 1–2). Four failure-class gaps remain open in dogfood evidence
(`docs/dogfood/FRICTION.md`) and were re-verified live at HEAD `719cb29`:

- **G1** — `ghx sidecar ask` always exits 0: a BLOCKED-because-invalid-slug
  ask returns a well-reasoned report with `$?`=0; only `--depth bogus`
  validation maps to exit 2 today (`internal/cli/sidecar.go:110-135`,
  `sidecar.go:76-83`).
- **G2** — sidecar reports narrate exit codes that differ from the tool's real
  codes ("explore badslug → exit 3" when the actual code is 2): plausible but
  fabricated evidence violates the visibility/truthfulness tenet.
- **G3** — `inspect` degrades a repo-404 to exit 1 (no-results) while
  `explore`/`read` exit 3 on the same slug; GitHub code search on a nonexistent
  repo returns empty instead of an error (`internal/ghx/inspect.go:255-259`),
  so the upstream 404 never reaches `ClassifyUpstream`.
- **G4** — MCP frontend flattens structured errors to strings (19 sites),
  leaving ADR-0034 phase 3 unexecuted.
- Secondary (CLI-ergonomics family, not failure-class): cobra-surface errors
  lack next-invocation hints (G5); source builds self-report version "dev"
  while doctor reports a stale PATH binary (G6).

## Decision

- **D1 — Sidecar frontend maps outcome class → exit code.** Reuse
  `CodeForError` so the sidecar command shares the core mapping:
  BLOCKED-because-bad-input → 2, no-evidence/upstream-failure → 3 or 1 per
  class, answered → 0.
- **D2 — Capture observed tool exit codes at the harness boundary.** Reports
  cite captured values only; uncaptured stays uncited. No model-narrated codes.
- **D3 — Close the inspect 404 divergence.** Classify upstream before
  rendering no-results; empty-repo (real repo, zero files) stays exit 1.
- **D4 — Structure MCP error payloads with class+hint.** Execute ADR-0034
  phase 3 verbatim; replace the flatten sites.
- **D5 (secondary scope) — cobra affordances + version provenance**
  (`-ldflags -X` stamping; doctor reconciles PATH binary vs running
  executable), or explicit deferral to a future ADR-0028.3.

## Consequences

- Scripting agents get machine-parsable outcomes from every frontend; report
  evidence becomes citable ground truth.
- Byte-identical diffs required for unchanged classes (ADR-0034 phase-2
  method); golden hint tests + per-frontend exit-code table tests; re-run the
  research §8 command battery as the acceptance script.
- Eval-stack independence: no scorer/detector changes; frozen-stack rule
  untouched.

## Implementation Notes (as-built, 2026-08-21)

- **D1 landed** (`internal/cli/sidecar.go` `askExitCode`, commit c3bd0fe):
  outcome→exit mapping at the ask frontend — bad-input BLOCKED → 2
  (invalid/unknown/unrecognized fragments), upstream BLOCKED → 3
  (unavailable/auth/daemon/network/rate-limit), evidence-free answer → 1,
  answered → 0, nil report → 3. Table test `TestAskExitCode` covers all
  classes through `CodeForError`.
- **D3 landed** (`internal/ghx/inspect.go`, commit b2d6de2): on zero search
  candidates Inspect probes the repo with a depth-1 `Tree`; a not-found
  upstream error now propagates (exit 3) while a real repo with zero hits
  still returns the no-results result (exit 1). Classification reuses the
  frozen `ClassifyUpstream` + `notFoundSignatures` — no taxonomy change.
- **D2 landed as steering** (commit 8bb8498): the persona now requires cited
  exit codes to be trace-captured, never reconstructed from memory. Full
  harness capture of tool exit codes is deferred — it needs a raw-SDK-side
  hook (ADR-0016.10 pattern) and should land as its own slice; the steering
  line plus D1's deterministic frontend mapping close the practical gap.
- **Golden-hash discipline**: the persona byte-stability test was updated
  deliberately (commit 6f304fb, new sha256 recorded in-test), per its own
  "if the change is intentional" contract.
- **D4 (MCP structured payloads) NOT landed** — deferred: the flatten-site
  inventory needs a dedicated pass and MCP surface tests; tracked as the open
  remainder of ADR-0034 phase 3.
- **Correction (2026-08-21 audit)**: G6's version-stamping gap is narrower
  than first stated — release builds DO stamp version via goreleaser
  `ldflags` (`.goreleaser.yml:7`). The residual gap is source builds only
  (`go build` self-reports "dev") plus doctor not reconciling the PATH binary
  vs the running executable.
- **Verification**: go build ✅; full `go test ./...` exit 0.
