# 0032.1. Combined-Objective Host-Task Evals — Decision

## Status

Accepted (orchestrator, 2026-07-06). Registers the design, gates, corpus
rules, and build order over ADR-0032's research. Nothing runs until the
build slices land and Goga triggers the first registered run (full-rigor
runs are event-driven; ~60 episodes is far past spot-check scale).

## D1 — Two arms, structural boundary, as researched

Adopted verbatim from ADR-0032: control = host with native exploration
(shell, `gh`, web-off); sidecar = same host with one recon MCP tool and
the concise recon skill, external exploration discouraged by prompt
contract + compliance detector (flag, never block). Exploration ≡
reconnaissance outside the local checkout — structural (tool identity +
path scope), unit-tested, frozen with the stack. No third arm.

## D2 — Registered gates (vector verdict, never a blend)

Rendered as three separate conclusions; SUPPORTED requires all three.

| Gate | Claim | Registered form |
|------|-------|-----------------|
| **GH1-success** | Non-inferiority on task success | Paired per-task: for each task, mean fail-to-pass×pass-to-pass grade per arm; sidecar-arm task mean ≥ control task mean − **δ = 0.10** in ≥ **5 of 6** tasks (at_least(n) form per ADR-0025.2; FRAGILE annotation applies). Never quoted as a success *win*. |
| **GH1-efficiency** | Superiority on context economics | Paired per-task: sidecar arm wins BOTH dead-weight fraction (lower) AND host-task SPT (higher) in ≥ **5 of 6** tasks. Wall time informational only (ADR-0025 D3 rule). |
| **GH2-recon** | Deferred exploration answers are good | Deterministic half only in v1: sidecar-arm reports scored against pre-registered sub-question ground truth, mean correctness ≥ **0.70** per run. Cross-arm judge comparison **deferred** until judge calibration (TRUST H1 κ unlock) AND an arm-blind bundle transform exists (report JSON is recognizably shaped — open problem, ADR-0032 §machinery); the v1 verdict template states this limitation verbatim. |

Minimum sample: 6 tasks × 2 arms × 5 trials; ADR-0025 D1 sequential
stopping applies per gate; ADR-0016.8 sufficiency/exclusion rules apply
(a cell below 5 valid trials ⇒ PRELIMINARY). Token attribution must use
real `gen_ai.usage.*` counts (H5 machinery, ADR-0016.11); chars/4 may be
shown alongside but cannot carry GH1-efficiency by itself.

## D3 — Corpus rules

Six hand-authored tasks, never upstreamed as issues: ≥2
dependency-behavior bugfixes, ≥2 API-migration slices, ≥1 conformance
feature (ADR-0032 families), ≥3 distinct workspace repos, mid-size
non-celebrity repos only. Exploration targets are *other* repos at
versions matching the pinned dependency manifest (ref-skew dodge (a);
ref-carrying recon questions tracked as a product feature, not built
here). Every task passes the **memorization canary** at authoring time:
subject model, issue text only, no repo access — a from-weights fix
disqualifies the task. Grader: pinned SHA + containerized env +
fail-to-pass/pass-to-pass, 2× re-run on failure, any flip disqualifies
the task. Host workspaces re-provisioned per trial; sidecar sessions get
fresh namespaces per episode (ADR-0016.5 extension).

## D4 — Host subject and credentials

Host = sonnet-class, matching the recon suite (a cheaper-host arm is its
own follow-up ADR — the P4 thesis, not smuggled in here). v1 runs on the
one subscription with anomaly-and-exclude: new BLOCKED anomalies
`host_rate_limited` and `recon_tool_unavailable`; wall-time claims
excluded whenever rate-limit anomalies fire. Credential separation
revisited only if exclusion rates make runs uneconomic.

## D5 — Build order (slices, each independently mergeable)

1. **S1 provisioner + grader**: pinned-SHA workspace clone, thin
   task-container convention (pinned image + setup/test commands in the
   task fixture — SWE-bench's *pattern*, not its harness; 6 hand-authored
   tasks do not justify adopting its full format), fail-to-pass /
   pass-to-pass runner. Deterministic, no LLM.
2. **S2 host client policy + attribution**: third ACP client policy
   (workspace-scoped writes allowed, outside denied; sidecar keeps its
   read-only contract — a sidecar write attempt stays run-invalidating),
   plus the structural exploration/engineering token classifier with
   per-episode attribution tables (visibility tenet).
3. **S3 arm-B wiring**: drive the sidecar as an MCP tool inside the host
   (first end-to-end exercise of the ADR-0019/0020.1 consumption
   surface), compliance detector, new anomaly rows, frozen-identity
   manifest extension (host prompt hash, skill hash, MCP schema hash).
4. **S4 corpus authoring**: 6 tasks + canaries + sub-question ground
   truth, committed as fixtures with authoring provenance.

Plumbing tests use scripted mock hosts (ADR-0016.1 pattern); mock runs
are never scored. After S1–S4: one ≤5-episode smoke of the full pipeline
(eval-cadence cap), then the run waits for Goga's trigger.

## Rejected here (beyond ADR-0032's rejections)

- Registering the judge half of GH2 now — would create a gate that
  cannot be evaluated until κ lands; gates must be computable when
  registered.
- Adopting the SWE-bench container harness wholesale (open question 5)
  — settled against: the leverage tenet cuts both ways, and importing a
  harness built for thousands of generated instances to serve 6
  hand-authored fixtures adds a dependency surface with no measurement
  value. Steal the invariants (pinning, hidden test patch, F2P/P2P),
  not the machinery.

## Cross-references

ADR-0032 (research this decides over); ADR-0016.6 (SPT levels,
dead-weight fraction); ADR-0016.8 (sufficiency/exclusions); ADR-0025
(stopping, economics), ADR-0025.2 (at_least(n) forms used by both H1
gates); ADR-0023.1 (judge layer, deferred half); ADR-0016.11 (real-token
usage that GH1-efficiency depends on); NORTH_STAR "Why" (the claim under
test).

## Implementation note (S1 landed, 2026-07-06)

Slice S1 (D5.1) is built: `internal/sidecar/evals/hosttask` — a
self-contained package holding the workspace provisioner and the
deterministic outcome grader. No LLM anywhere; the eval runner,
profiles, gates, and persona are untouched.

- **Fixture schema** lives in `hosttask/fixture.go` (types + JSON,
  documented in the package godoc, `hosttask/doc.go`) with a canonical
  example at `hosttask/testdata/fixtures/chi-middleware-order.json`.
  The thin task-container convention decided above is the schema: id,
  workspaceRepo, pinnedSha, image (env pin), network (default "none"),
  setupCmds, failToPassCmds, passToPassCmds, explorationSubQuestions
  (question/groundTruth/verifiedAt), memorizationCanary
  (checkedAt/result). `Validate` rejects a failed canary outright — a
  from-weights fix disqualifies the task at authoring time (D3).
- **Provisioner** (`hosttask/provision.go`) reuses tier2's pinned-SHA
  materialization plan — `tier2.SHAFetchPlan`, exported for this in
  `tier2/clone.go` — but with full blobs (no `blob:none`): host
  workspaces must work offline since grader containers default to
  network "none". Per-trial reset (ADR-0032 trap 5) holds by
  construction: every trial gets a brand-new HEAD-verified directory.
- **Grader** (`hosttask/grader.go`, `hosttask/container.go`): one
  container per attempt (`docker run` idle + `docker exec` per command
  over the bind-mounted workspace, so setup effects persist across the
  attempt's commands), grade = failToPass fraction × passToPass
  preservation (GH1), flake rule per trap 7 (any command failure ⇒
  exactly two re-runs; any per-command flip ⇒ `Flaky`, task
  disqualified, never scored). Docker absent is the typed
  `ErrDockerUnavailable`, ready for the S2+ BLOCKED anomaly mapping.
- **Tests** are hermetic via injected `GitRunner`/`ContainerRuntime`
  (grade math, flake rule, ordering, setup-abort, per-trial reset), plus
  a real-git `file://` provisioner test and a docker integration test
  gated behind `GHX_HOSTTASK_DOCKER=1`.

Remaining slices: S2 (host ACP client policy + token attribution), S3
(arm-B MCP wiring, compliance detector, anomaly rows, frozen-identity
extension), S4 (corpus authoring: 6 fixtures + canaries + sub-question
ground truth). Nothing runs until those land and Goga triggers the
registered run.

## Implementation note (S2 landed, 2026-07-06)

Slice S2 (D5.2) is built: the host ACP client write policy and the
structural exploration/engineering token-attribution layer. The eval
runner, profiles, gates, persona, and the production sidecar client's
deny-all behavior are untouched.

- **Write policy** (`internal/sidecar/evals/write_policy.go`): the eval
  client (`evals/client.go`) gains a composable `WritePolicy` interface —
  `AllowWrite(path) (resolved, error)`. A nil policy is the recon
  suite's deny-all contract, unchanged byte-for-byte (same violation
  strings), so every recon profile and the sidecar inside arm B keep
  write attempts run-invalidating. The host arm injects
  **`WorkspaceWritePolicy`**: writes whose resolved target lies inside
  the provisioned trial workspace are allowed; everything else is denied
  and recorded as an episode violation (the existing
  `evalClient.violations` → `Episode.Violations` path). Containment is
  owned by **`hosttask.WorkspaceScope`** (`hosttask/scope.go`): absolute
  paths only (an agent's cwd is not part of the recorded contract),
  `..` removed by cleaning, symlinks resolved via `filepath.EvalSymlinks`
  on the deepest existing ancestor with the non-existing remainder
  re-joined (new-file writes resolve; dangling symlinks and loops are
  refused, fail closed). TOCTOU limit stated in the godoc: containment
  is decided at call time, so a symlink swapped in afterwards can still
  redirect the operation — the scope is an eval-integrity guard, not a
  security sandbox; container/network isolation stays the security
  boundary. A write-kind permission request that reports no locations is
  denied and recorded (cannot be checked ⇒ never guessed). Allowed
  client-side fs writes target the policy-resolved path. To make path
  scope observable at all, `ToolCallTrace` (both the `sidecar` and the
  `evals` episode shape) gains a `Locations` field captured from ACP
  tool_call/tool_call_update events.
- **Token attribution** (`hosttask/attribution.go`):
  `hosttask.Classifier` — explicit fields only (workspace scope, exact
  recon MCP tool names, exploration command prefixes; no config or env
  reads, frozen-measurement-stack requirement). Classification is by
  tool identity + path scope only (trap 6), rules evaluated in order,
  first match wins:

  | # | Rule | Class |
  |---|------|-------|
  | R1 | title equals one of ReconToolNames | exploration |
  | R2 | kind `fetch` (network by definition) | exploration |
  | R3 | kind `execute`, compound command (contains `&&`, `\|\|`, `;`, `\|`, `$(`, backtick, or a newline) or empty command | unclassified |
  | R4 | kind `execute`, leading tokens match an ExplorationCommands entry (default frozen list: `gh`, `curl`, `wget`, `git clone`, `git fetch`, `git pull`, `git ls-remote`) | exploration |
  | R5 | kind `execute`, any other simple command | engineering |
  | R6 | kinds `read`/`edit`/`delete`/`move`/`search`: no recorded locations → unclassified; all locations inside workspace → engineering; all outside → exploration; mixed or unresolvable → unclassified | (as stated) |
  | R7 | kind `think` (the host planning its own work) | engineering |
  | R8 | anything else (unknown or empty kind) | unclassified |

  `Attribute` produces the per-episode **`AttributionTable`** — one row
  per tool call `{id, title, kind, class, chars}` plus
  `explorationChars`, `engineeringChars`, and `unclassified` (a NAMED
  id list; its chars count toward totals but toward neither class —
  never silently folded, visibility tenet). `DeadWeightFraction()` =
  exploration chars ÷ total chars, documented as the fallback
  accounting: real `gen_ai.usage.*` token counts are the registered
  GH1-efficiency metric (D2); chars may be shown alongside but cannot
  carry the gate.
- **Tests** are hermetic and table-driven (`t.TempDir`, no docker, no
  network, no live `~/.ghx`): scope containment
  (inside/outside/traversal/symlink escape/dangling/relative/zero
  value), policy decisions, client permission + fs-write behavior under
  nil and workspace policies, every classifier rule, attribution totals
  and the unclassified bucket, empty traces.
- **Known limits, stated honestly**: (1) path scope for permission
  decisions and R6 depends on the adapter reporting ACP tool-call
  locations — adapters that omit them fail closed on writes and land in
  `unclassified` for attribution, so S3 must verify the chosen host
  adapter emits locations; (2) execute-kind identity comes from the
  recorded title being the command line (the ACP terminal-title
  contract); compound commands are deliberately unclassified rather
  than half-guessed.

Remaining slices: S3 (arm-B MCP wiring, compliance detector, anomaly
rows `host_rate_limited`/`recon_tool_unavailable`, frozen-identity
extension), S4 (corpus authoring: 6 fixtures + canaries + sub-question
ground truth). Nothing runs until those land and Goga triggers the
registered run.

## Implementation note (S3 landed, 2026-07-06)

Slice S3 (D5.3) is built: the host episode runner, arm-B recon MCP
wiring, the compliance detector plus the D4 BLOCKED rows, and the
frozen-identity manifest extension. Recon episode behavior, profiles,
gates, and the persona are untouched; host episodes run on their own
profile labels (`host-control`, `host-sidecar`) and their own entry
point.

- **Host trial runner** (`internal/sidecar/evals/host_episode.go`):
  `RunHostTrial` drives one fixture × arm × trial end-to-end — S1
  provision (per-trial pinned workspace, `file://`-injectable for
  tests) → live host episode over ACP → S2 attribution → S1 grading.
  The ACP spawn is the existing direct-episode machinery in
  `runner.go`, extracted into one parameterized `runLiveAgentEpisode`
  (client/write-policy, advertised fs capabilities, MCP servers,
  prompts) used by both paths — shared, not forked; the recon
  profiles keep their exact prior wiring as the spec's zero values.
  Host episodes install the S2 `WorkspaceWritePolicy`, advertise
  `fs.writeTextFile: true` (S2 risk 4 — flipped ONLY on this path;
  recon episodes still advertise false), and use the workspace as the
  session cwd. Arm B registers one session-scoped stdio MCP server
  (the `reportSinkMcpServers` pattern): name `ghx-recon`, command
  `<ReconExe> serve --recon`, where `ReconExe` is an explicit config
  field for the same reason as `GHX_REPORT_SINK_EXE`. The recon tool
  definition moved from `internal/cli/serve.go` into
  `sidecar.ReconMCPTool` so the served schema and the hashed identity
  share one authority. The issue text rides `HostTrial.Objective`;
  its committed fixture home is an S4 decision. Host episodes are
  never scored with recon rewards; the outcome grade lives in the
  episode's persisted `hostTask` record next to the attribution table
  (which must be persisted: the workspace scope is gone by offline
  re-analysis time).
- **Live-adapter sighting, CONFIRMED constraint (2026-07-06)**: a real
  claude-agent-acp turn emitted
  `{"event":"tool.call","id":"toolu_01EQ...","title":"Terminal","kind":"execute","status":"pending"}`
  — execute tool calls carry the title "Terminal", NOT the command
  line. This settles the S2 note's execute-title assumption
  negatively. The classifier's execute identity (rules R3–R5) now
  reads the recorded `rawInput.command` (one exported extraction
  authority, `hosttask.ExecuteCommandLine`, title as fallback for
  command-line-titled adapters); a bare "Terminal" title with no
  rawInput command is the empty command ⇒ unclassified, never
  guessed.
- **Compliance detector + anomaly rows**
  (`internal/sidecar/evals/host_anomalies.go`, wired into
  `DetectAnomalies`/`CountAnomalies`): `host_external_exploration`
  (soft — D1 is flag-and-report, never block): any
  exploration-classified attribution row on an arm-B episode whose
  title is not the recon MCP tool; the recon titles are snapshotted
  per episode so detection recomputes offline. `host_rate_limited`
  (breaking, D4): rate-limit-shaped turn errors on host episodes,
  reusing the frozen `rateLimitSignals`. `recon_tool_unavailable`
  (breaking, D4): declarative markers ("no such tool", "not
  connected", "connection closed", …) scanned only over arm-B turn
  errors and recon-titled tool outputs — best-effort "where
  detectable", refinable before (never during) a run.
- **Registered limitation — execute is unpoliced by
  `WorkspaceWritePolicy`**: the ACP write policy sees only write-kind
  permission requests (edit/delete/move) and client fs writes; a
  shell command running agent-side can write anywhere the host user
  can. Full shell sandboxing is out of scope — container isolation
  plus per-trial fresh workspaces are the boundary, and the S1 grader
  re-verifies HEAD per trial. The visibility layer over the gap is
  the new `host_execute_outside_workspace` row (soft,
  flag-and-report, both arms): declarative absolute-path extraction
  from recorded execute commands, workspace-prefix checked, with a
  frozen benign-prefix list (system binaries/devices). Documented
  evasions: relative/computed paths, symlinked path forms.
- **Grader equal footing** (audit finding, fixed here): grade
  attempts previously re-ran against the same mutated workspace, so a
  tree-mutating test (cache/marker) could flip a re-run and falsely
  disqualify a deterministic failure as Flaky. `NewGrader` now wires
  `CopyWorkspacePerAttempt`: every attempt — first pass and trap-7
  re-runs alike — runs against a pristine copy of the host's fixed
  tree, and grading never mutates the graded workspace (pinned by
  test, including symlink fidelity). The package doc contract is
  updated accordingly.
- **Frozen-identity manifest extension** (`store.go`,
  `host_identity.go`): additive `manifest.hostTaskIdentityHashes`
  with three sha256 records — `hostPromptContract` (the frozen arm-A
  template, placeholders included), `armBPromptContract` (the arm-B
  template with the recon skill/prompt contract), `reconToolSchema`
  (canonical JSON of `sidecar.ReconMCPTool`). Kept out of
  `identityHashes` so recon baseline-reuse comparisons never see it;
  existing manifests are unaffected.
- **Tests** (hermetic; no docker — grading stubbed via
  `ContainerRuntime`; no network — provisioning from a `t.TempDir`
  git repo over `file://`): a full mock arm-B trial (workspace write
  allowed, outside write denied+recorded and never on disk,
  `writeTextFile=true` advertised, exact MCP registration asserted,
  attribution classes per call, exactly one compliance flag, manifest
  hashes recomputable, artifact-roundtrip re-detection), a control-arm
  trial (no MCP servers, native exploration attributed but never
  flagged), detector unit tables, prompt/identity determinism, grader
  fresh-copy pinning, and the S2 obligations: (a) tool-call locations
  flow to `ToolCallTrace.Locations` on the eval client path, (b)
  execute identity resolves from `rawInput.command` under
  adapter-shaped "Terminal" titles (mockagent now emits the real
  adapter shape via `richToolCalls`/`writeFiles`).

Live-adapter sightings still owed before the first registered run:
(1) the ACP title/kind shape of MCP tool calls — the frozen recon
title set (`mcp__ghx-recon__recon`, `recon`) follows the documented
SDK convention (`sidecar.SubmitReportToolID`) but has not been sighted
on a live host session; (2) whether the live adapter emits tool-call
locations for file tools (S2 known limit 1 — without them R6 lands in
`unclassified` and unlocated writes fail closed); (3) one live
end-to-end arm-B session actually spawning `ghx serve --recon` — the
first real exercise of the ADR-0019/0020.1 consumption surface.
Remaining: S4 (corpus authoring: 6 fixtures + canaries + sub-question
ground truth, plus the fixture home for the issue text), then the
one ≤5-episode smoke of the full pipeline (eval-cadence cap). Nothing
runs until Goga triggers the registered run.
