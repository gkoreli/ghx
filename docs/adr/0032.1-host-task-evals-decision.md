# 0032.1. Combined-Objective Host-Task Evals — Decision

## Status

Accepted (orchestrator, 2026-07-06). Registers the design, gates, corpus
rules, and build order over ADR-0032's research. Nothing runs until the
build slices land and Goga triggers the first registered run (full-rigor
runs are event-driven; ~60 episodes is far past spot-check scale).

## D1 — Two arms, structural boundary, as researched

Adopted verbatim from ADR-0032: control = host with native exploration
(shell, `gh`, web-off); sidecar = same host with one recon MCP tool and
the concise recon skill, external exploration discouraged by prompt
contract + compliance detector (flag, never block). Exploration ≡
reconnaissance outside the local checkout — structural (tool identity +
path scope), unit-tested, frozen with the stack. No third arm.

## D2 — Registered gates (vector verdict, never a blend)

Rendered as three separate conclusions; SUPPORTED requires all three.

| Gate | Claim | Registered form |
|------|-------|-----------------|
| **GH1-success** | Non-inferiority on task success | Paired per-task: for each task, mean fail-to-pass×pass-to-pass grade per arm; sidecar-arm task mean ≥ control task mean − **δ = 0.10** in ≥ **5 of 6** tasks (at_least(n) form per ADR-0025.2; FRAGILE annotation applies). Never quoted as a success *win*. |
| **GH1-efficiency** | Superiority on context economics | Paired per-task: sidecar arm wins BOTH dead-weight fraction (lower) AND host-task SPT (higher) in ≥ **5 of 6** tasks. Wall time informational only (ADR-0025 D3 rule). |
| **GH2-recon** | Deferred exploration answers are good | Deterministic half only in v1: sidecar-arm reports scored against pre-registered sub-question ground truth, mean correctness ≥ **0.70** per run. Cross-arm judge comparison **deferred** until judge calibration (TRUST H1 κ unlock) AND an arm-blind bundle transform exists (report JSON is recognizably shaped — open problem, ADR-0032 §machinery); the v1 verdict template states this limitation verbatim. |

Minimum sample: 6 tasks × 2 arms × 5 trials; ADR-0025 D1 sequential
stopping applies per gate; ADR-0016.8 sufficiency/exclusion rules apply
(a cell below 5 valid trials ⇒ PRELIMINARY). Token attribution must use
real `gen_ai.usage.*` counts (H5 machinery, ADR-0016.11); chars/4 may be
shown alongside but cannot carry GH1-efficiency by itself.

## D3 — Corpus rules

Six hand-authored tasks, never upstreamed as issues: ≥2
dependency-behavior bugfixes, ≥2 API-migration slices, ≥1 conformance
feature (ADR-0032 families), ≥3 distinct workspace repos, mid-size
non-celebrity repos only. Exploration targets are *other* repos at
versions matching the pinned dependency manifest (ref-skew dodge (a);
ref-carrying recon questions tracked as a product feature, not built
here). Every task passes the **memorization canary** at authoring time:
subject model, issue text only, no repo access — a from-weights fix
disqualifies the task. Grader: pinned SHA + containerized env +
fail-to-pass/pass-to-pass, 2× re-run on failure, any flip disqualifies
the task. Host workspaces re-provisioned per trial; sidecar sessions get
fresh namespaces per episode (ADR-0016.5 extension).

## D4 — Host subject and credentials

Host = sonnet-class, matching the recon suite (a cheaper-host arm is its
own follow-up ADR — the P4 thesis, not smuggled in here). v1 runs on the
one subscription with anomaly-and-exclude: new BLOCKED anomalies
`host_rate_limited` and `recon_tool_unavailable`; wall-time claims
excluded whenever rate-limit anomalies fire. Credential separation
revisited only if exclusion rates make runs uneconomic.

## D5 — Build order (slices, each independently mergeable)

1. **S1 provisioner + grader**: pinned-SHA workspace clone, thin
   task-container convention (pinned image + setup/test commands in the
   task fixture — SWE-bench's *pattern*, not its harness; 6 hand-authored
   tasks do not justify adopting its full format), fail-to-pass /
   pass-to-pass runner. Deterministic, no LLM.
2. **S2 host client policy + attribution**: third ACP client policy
   (workspace-scoped writes allowed, outside denied; sidecar keeps its
   read-only contract — a sidecar write attempt stays run-invalidating),
   plus the structural exploration/engineering token classifier with
   per-episode attribution tables (visibility tenet).
3. **S3 arm-B wiring**: drive the sidecar as an MCP tool inside the host
   (first end-to-end exercise of the ADR-0019/0020.1 consumption
   surface), compliance detector, new anomaly rows, frozen-identity
   manifest extension (host prompt hash, skill hash, MCP schema hash).
4. **S4 corpus authoring**: 6 tasks + canaries + sub-question ground
   truth, committed as fixtures with authoring provenance.

Plumbing tests use scripted mock hosts (ADR-0016.1 pattern); mock runs
are never scored. After S1–S4: one ≤5-episode smoke of the full pipeline
(eval-cadence cap), then the run waits for Goga's trigger.

## Rejected here (beyond ADR-0032's rejections)

- Registering the judge half of GH2 now — would create a gate that
  cannot be evaluated until κ lands; gates must be computable when
  registered.
- Adopting the SWE-bench container harness wholesale (open question 5)
  — settled against: the leverage tenet cuts both ways, and importing a
  harness built for thousands of generated instances to serve 6
  hand-authored fixtures adds a dependency surface with no measurement
  value. Steal the invariants (pinning, hidden test patch, F2P/P2P),
  not the machinery.

## Implementation note (S1 landed, 2026-07-06)

Slice S1 (D5.1) is built: `internal/sidecar/evals/hosttask` — a
self-contained package holding the workspace provisioner and the
deterministic outcome grader. No LLM anywhere; the eval runner,
profiles, gates, and persona are untouched.

- **Fixture schema** lives in `hosttask/fixture.go` (types + JSON,
  documented in the package godoc, `hosttask/doc.go`) with a canonical
  example at `hosttask/testdata/fixtures/chi-middleware-order.json`.
  The thin task-container convention decided above is the schema: id,
  workspaceRepo, pinnedSha, image (env pin), network (default "none"),
  setupCmds, failToPassCmds, passToPassCmds, explorationSubQuestions
  (question/groundTruth/verifiedAt), memorizationCanary
  (checkedAt/result). `Validate` rejects a failed canary outright — a
  from-weights fix disqualifies the task at authoring time (D3).
- **Provisioner** (`hosttask/provision.go`) reuses tier2's pinned-SHA
  materialization plan — `tier2.SHAFetchPlan`, exported for this in
  `tier2/clone.go` — but with full blobs (no `blob:none`): host
  workspaces must work offline since grader containers default to
  network "none". Per-trial reset (ADR-0032 trap 5) holds by
  construction: every trial gets a brand-new HEAD-verified directory.
- **Grader** (`hosttask/grader.go`, `hosttask/container.go`): one
  container per attempt (`docker run` idle + `docker exec` per command
  over the bind-mounted workspace, so setup effects persist across the
  attempt's commands), grade = failToPass fraction × passToPass
  preservation (GH1), flake rule per trap 7 (any command failure ⇒
  exactly two re-runs; any per-command flip ⇒ `Flaky`, task
  disqualified, never scored). Docker absent is the typed
  `ErrDockerUnavailable`, ready for the S2+ BLOCKED anomaly mapping.
- **Tests** are hermetic via injected `GitRunner`/`ContainerRuntime`
  (grade math, flake rule, ordering, setup-abort, per-trial reset), plus
  a real-git `file://` provisioner test and a docker integration test
  gated behind `GHX_HOSTTASK_DOCKER=1`.

Remaining slices: S2 (host ACP client policy + token attribution), S3
(arm-B MCP wiring, compliance detector, anomaly rows, frozen-identity
extension), S4 (corpus authoring: 6 fixtures + canaries + sub-question
ground truth). Nothing runs until those land and Goga triggers the
registered run.
