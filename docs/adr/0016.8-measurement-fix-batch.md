# 0016.8. Measurement Fix Batch

## Status

Accepted 2026-07-05, pre-registered **before** implementation and before
any run is scored under these rules (AGENTS.md "the measurement stack is
frozen during a run"; precedent: the compliance-detector fix, `afd6e99`).
Binds the next full-rigor run and all runs after it. No committed verdict
is rescored retroactively — the 2026-07-05 partial run's README already
carries the projected deltas as PRELIMINARY, and they stay projections
until the next run measures them.

Sources: the independent cross-family audit
(`docs/evals/audit-2026-07-05-independent/REPORT.md` — 90/90 exact
recomputation, 4 majors, 3 minors) and the insight-mining report
(`docs/evals/gate-run-2026-07-05-d2-0021-0022-partial/INSIGHTS.md`).
Every fix below cites its evidence.

## Decisions

### D1. Union-of-all-turn-reports scoring (the instrument defect)

`answerText` and the evidence/relevant-files scorers read only the final
`ep.Report` (rewards.go:42,123,154,194). Checks span the whole task, but a
well-behaved multi-turn sidecar **delta-reports** — the final turn carries
only what is new (gin-routing final turn: tree.go only, 70 chars). The
scorer therefore penalizes exactly the compression the product exists to
provide. Measured on the 2026-07-05 partial run: union rescoring moves
multi-turn sidecar correctness +0.278, evidence +0.226 (n=6); the cleanest
exhibit is `hono-middleware_ghx-sidecar_1783310129190`, scored evidence
0.00 on an episode whose turn-0 report had two verified claims with code
evidence. Projected profile effect: correctness 0.866→0.958, G1 ratio
0.921→1.020 (INSIGHTS.md P2 — projection, not citable until measured).

Fix: every scorer that reads `ep.Report` folds in the union of all
accepted per-turn reports (`TurnRecord.Report`, episode.go:112) — answer
text, verified/inferred claims, relevant files, evidence, commandsRun.
Final `ep.Report` remains the *contract* artifact (what the consumer got);
the union is the *scoring* input. Single-turn episodes are unchanged
(union of one). Duplicate claims/files across turns dedupe by content so
repetition is not rewarded. The judge scorer (ADR-0023.1) remains the
durable fix for trajectory quality; this is the deterministic interim.

### D2. Contamination guard for self-referential tasks (audit major 1)

Three ghx-mapengine plain episodes read `docs/adr/0013-ghx-map-command.md`
inside the target repo — an answer-bearing design doc for the task
(audit §3). When the subject repo is ghx itself, its own ADRs can leak
pre-registered answers into any profile.

Fix: task files gain an optional `checks.contaminationPaths` list
(path prefixes, e.g. `docs/adr/`). The anomaly detector flags any episode
whose tool calls read a matching path with a new soft anomaly
`answer_doc_contamination` (declarative substring detector, same pattern
as the existing taxonomy). Contaminated episodes are excluded from gate
aggregates and listed in the verdict, same as BLOCKED. The ghx-mapengine
task registers `docs/adr/` and `docs/evals/`. Guard applies to all
profiles equally — it protected the *baseline* this time; next time it
could inflate the sidecar.

### D3. `thesisSupported` requires `DataSufficient` (audit major 2)

`EvaluateGates` sets `ThesisSupported = valid && G1..G5` without
`DataSufficient` (gates.go:230), so verdict.json can read
`thesisSupported: true` on a below-contract sample while only the
markdown self-labels PRELIMINARY. ADR-0016.2 requires below-minimum
verdicts be PRELIMINARY everywhere. Fix: JSON gains an explicit
`preliminary: bool` and `thesisSupported` stays true only when
`DataSufficient` also holds; the markdown renderer keeps its existing
labeling, now guaranteed consistent with the JSON.

### D4. Sufficiency counts repos (audit minor)

`sampleSufficiency` omits ADR-0016.1's "≥ 3 repos" condition
(gates.go:325). Fix: count distinct task repos; < 3 repos →
insufficient. Add the missing condition to the rendered sufficiency
explanation.

### D5. Manifest carries the full planned matrix (audit major 4)

`expectedEpisodes: 18` against a 90-episode run is a provenance defect
(audit §6) and the root of the `GHX_EVAL_EXPECTED_EPISODES` limitation in
ADR-0025 D1 (stopping math needs the true planned total). Fix: the
manifest records tasks × profiles × trials and the derived
`expectedEpisodes` for the whole planned run; multi-round accumulation
appends rounds to the manifest instead of overwriting; the env override
remains only as an explicit manual escape hatch, recorded in the manifest
when used.

### D6. Episode JSON persists its own anomalies (audit major 3)

Two episodes carried detector-derivable anomalies not stored in their
`anomalies` field (run-level counts were correct only because
`CountAnomalies` recomputes). Fix: detectors run before episode
persistence, so the stored record is complete; add a regression test that
re-deriving anomalies from any persisted episode equals its stored field.

### D7. Unacceptable-claim zeroing needs word-boundary honesty (insight #9)

`express-router-location` correctness is bimodal 0.5/1.0 from the
unacceptable-claim substring zeroing (`lib/router/index.js` matched inside
honest text about the historical location, e.g. "moved from
lib/router/index.js"). A negation-adjacent mention is not the wrong
claim. Fix (deterministic, no cleverness): an unacceptable claim only
zeroes when it appears **outside** an explicit negation/history context —
implemented as a pre-registered exclusion list per task
(`checks.unacceptableClaimExceptions`, exact substrings such as "moved
from" / "previously at" within N chars before the match). If an exception
list feels like it is growing per-run, that is the judge scorer's job and
the task's check should be simplified instead.

### D8. Direct-profile evidence floor documented, not changed (audit minor)

The direct-profile fallback (tool usage + path token when
`ep.Report == nil`, rewards.go:133) is intentional but undocumented in
ADR-0016.1's table. This ADR is now the documentation of record: the
fallback exists so profiles without a report contract are scored on
observable evidence behavior, floor 0.5 when tools were used and paths
cited. No code change; the insight-miner's "0.5 floor" observation is the
fallback working as designed on report-less episodes.

### D9. Curated runs commit their traces (audit note)

READMEs that cite a replayable `traces.jsonl` must commit it (or state
why not) when the run is curated into `docs/evals/`. Policy, not code.

## Considered and rejected

- **Rescoring committed verdicts under the new rules** — changing rules
  after seeing data is the validity hole; committed verdicts stay as
  floors with their known defects documented (README notes already do).
- **Scoring the raw transcript instead of report union** — dissolves the
  report contract; the product claim is that the *report* carries the
  signal, so the scorer must read reports, all of them.
- **LLM-based unacceptable-claim disambiguation** — nondeterminism inside
  the frozen gate layer; that is the judge's layer (ADR-0023.1 D1).
- **Mean-of-cells reweighting** (audit minor on unbalanced cells) —
  deferred; current runs are balanced by construction and D5 makes
  imbalance visible. Pre-register separately if unbalanced runs become
  normal.

## Verification plan

Unit tests per fix (union dedupe; contamination flag + exclusion;
sufficiency repos; preliminary JSON; manifest round accumulation; anomaly
persistence equality; exception-list zeroing). Golden: re-run the scorer
over the committed 2026-07-05 partial episodes in a test and assert the
union deltas match INSIGHTS.md's table (+0.278/+0.226 aggregate) — the
projection becomes a pinned regression fixture without touching the
committed verdict.

## Implementation Notes (2026-07-05)

Implemented as pre-registered; on-the-fly decisions recorded per AGENTS.md.
All in `internal/sidecar/evals` unless noted.

**D1 — union mechanics (`scoringReport`, rewards.go).** The union of *one*
distinct report returns that report verbatim, so single-turn scoring is
bit-identical to the pre-D1 scorer — including within-report duplicates,
whose fractions would otherwise shift under content dedupe ([A✓, A✓, B✗]
is 2/3 with duplicates, 1/2 deduped). Content dedupe therefore applies only
when two or more distinct reports merge. Dedupe keys: claims by
summary+evidence, relevant files by path+reason, evidence by source+summary,
commands/backends/uncertainty/nextReads by exact string; the union answer is
the newline-join of distinct turn answers. Whole-report dedupe (JSON
equality) also collapses the old build's "repeat everything each turn"
pattern to a single report, which keeps its scores unchanged — matching
INSIGHTS' finding that OLD union deltas were ~0. The trajectory scorer's
commandsRun *fallback* (rewards.go, formerly :194) unions too; it is inert
on episodes that record tool calls. `ep.Report` is untouched everywhere —
contract artifact vs scoring input, exactly as decided.

**D1 side effect — trace explanations.** `otel_reward_events.go` explained
checks from `ep.Report` and would have contradicted union scores, so its
correctness/evidence/trajectory events now read `scoringReport` and the D7
predicate. Unacceptable-claim events carry both `check.matched` (substring
present) and `penalty.applied` (asserted outside exception contexts), so an
excused historical mention stays visible in traces without implying a
zeroing.

**D2 — detector and exclusion shape.** Declarative substring match of each
`contaminationPaths` prefix over **live** `ToolCalls` only — replayed traces
are audit-only (ADR-0016.5) and were accounted on the turn that originally
ran them. One anomaly per turn × prefix bounds the list on doc-heavy
trajectories. Exclusion happens in `validateEpisodesForVerdict` by
re-running `DetectAnomalies` on the episode (checks are snapshotted onto
`ep.Checks`, so the exclusion recomputes offline from the artifact alone).
Contamination does **not** set `Valid=false`: like BLOCKED it is listed
(verdict note + anomaly table) and its episodes are dropped from aggregates,
but the rest of the run still measures exploration.

**D3 — markdown gained a third verdict line.** With `thesisSupported` now
requiring `DataSufficient`, the old "THESIS NOT SUPPORTED — see failed gates
above" line would lie on a preliminary all-gates-pass run. FormatVerdict
renders that case as "thesis gates pass, but the sample is below the
pre-registered gate-run minimums", plus a matching JSON note. Gate tests
that asserted thesis support on one-task fixtures moved to contract-size
fixtures (`gateRunEpisodes`).

**D4.** Repos counted from `ep.Repo` (empty strings not counted). Synthetic
gate-test fixtures gained distinct repos; the shipped task set spans 6.

**D5 — rounds instead of a trials knob.** The harness cannot see `-count`,
so each `TestEpisodes` invocation appends one `PlannedRound{tasks, profiles,
trials: 1}` via `RecordManifestRound`; a 5-round gate run accumulates five
rounds summing to the true 90. `ExpectedEpisodes` = sum of rounds unless
`GHX_EVAL_EXPECTED_EPISODES` is set, which wins **and** is recorded as
`expectedEpisodesOverride` so provenance shows a human asserted the total.
`UpdateManifestIdentity` refreshes identity post-run without touching
rounds; `SaveRunManifest` survives for the mock-run path.

**D6 — invariant by construction.** Rather than trusting every caller to
run detectors, `SaveEpisode` itself re-derives `ep.Anomalies` immediately
before marshaling (overwriting stale caller-set values). The regression
test saves WARN/unparsed, stale-anomalies, contamination, and clean
episodes and asserts `DetectAnomalies(loaded)` deep-equals the stored
field. `RunEpisode` still sets anomalies for in-process consumers; the
harness sets `ep.Parallel` before saving so the rate-limit detector sees it.

**D7 — exception list is evidence-grounded, window pinned at 64.** None of
the three committed false zeros literally said "moved from": the actual
contexts are "Express 4.x had the router inlined at \`lib/router/index.js\`"
(NEW plain 1783310655275) and two "…change from express 4.x, where the
router (\`lib/router/index.js\`)…" (OLD 1783293764685, 1783298460843). The
fixture registers `["moved from", "previously at", "express 4"]` — the two
ADR-example phrasings plus the marker that actually covers all three
committed contexts (~40 chars before each match; window constant
`unacceptableClaimExceptionWindow = 64`). Zeroing is suppressed only when
*every* occurrence is excused; one bare assertion still zeroes. Validation
rejects blank entries and exceptions without a corresponding
unacceptableClaims list.

**Golden regression** (`union_scoring_test.go`,
`TestUnionScoringGoldenPartialRun`): rescoring the six committed multi-turn
sidecar episodes with the union scorer reproduced the INSIGHTS P2 table on
the first run — aggregate Δcorrectness +0.278, Δevidence +0.226 (asserted
within 0.001; per-episode within 0.005 of the 2-dp table). The projection
is now a pinned fixture; the committed verdict was not rescored.
