# 0029.2. Sidecar Persona Revision 3 — Policy-Gated Tier-2 Escalation

## Status

Proposed — **pre-registered with exact text, deliberately NOT applied yet.**

The escalation policy engine and decision recording (ADR-0024.2) land first,
so the measurement surface exists before the behavior change. This revision
is applied by the orchestrator in its own commit, between runs, never
mid-run, per the ADR-0029/0029.1 persona rules: persona wording changes the
subject under measurement; it must never be introduced while a gate run is in
progress and must never rescore existing episodes. The application commit
must also update the persona golden hash in `internal/sidecar/prompt_test.go`
in the same commit.

This ADR does **not** change eval scoring, detectors, rewards, gates,
thresholds, episode definitions, or ground truth. It changes only sidecar
persona doctrine in `internal/sidecar/prompt.go` (when applied).

## Context

M7 slices 1–2 absorbed codemap, ast-grep, and repomap ranking under
`ghx tier2 ...` (ADR-0024.1 implementation notes). ADR-0024.2 records a
declarative escalation decision for every sidecar turn. But the persona
predates Tier 2: `BuildPersonaSystemPrompt` teaches inspect/explore/read/
search only, and a command absent from the persona's example list effectively
does not exist for the sidecar (ADR-0029.1 D1 rationale). Until this revision
lands, live `escalationUsed` in `tier-decisions.jsonl` stays false by
construction.

The persona doctrine below mirrors the pre-registered policy exactly
(ADR-0024.1 "Escalation Policy"; ADR-0024.2 D1/D2): hard question shapes or
two remote-insufficiency strikes, always gated on the `local` backend grant.

## Decision

Three surgical persona edits. Everything else in the persona is untouched.

### D1. Add the `ghx tier2` commands to the "How to run ghx" example list

Current persona text being changed (rendered persona bytes):

```text
  ghx search "repo:owner/repo symbolName"
  ghx search "repo:owner/repo exact phrase"
```

Replacement text:

```text
  ghx search "repo:owner/repo symbolName"
  ghx search "repo:owner/repo exact phrase"
  ghx tier2 codemap owner/repo --importers path/to/file.ts
  ghx tier2 astgrep owner/repo --pattern 'compose($$$ARGS)' --lang ts
  ghx tier2 repomap owner/repo --query "concern phrase"
```

### D2. Replace the deeper-backend step with policy-mirrored escalation doctrine

Current persona text being changed (operating loop step 7):

```text
7. If remote evidence is insufficient, name the deeper backend needed but do not
   perform it unless allowed.
```

Replacement text:

```text
7. Tier-2 escalation (local structural analysis) is policy-gated. Only when
   "local" is in your allowed backends AND either (a) the question asks about
   cross-file structure — what imports/depends on something, blast radius,
   what breaks, call relationships, implementors, definition/reference — or
   (b) after two remote attempts you still cannot rank candidates with
   evidence, run ONE targeted `ghx tier2` command: `codemap --importers
   <file>` or `codemap --deps` for import/dependency structure, `astgrep
   --pattern <p> --lang <l>` for structural pattern matches, `repomap
   --query "<concern>"` for ranked entry points over the whole repo. Cite
   the exact command as evidence and include the matching backend
   (`local:codemap`, `local:ast-grep`, `local:repomap`) in `backendsUsed`.
8. If remote evidence is insufficient and "local" is NOT in your allowed
   backends, name the blocked backend in `uncertainty` and `nextReads`. Never
   fabricate structural claims (importers, blast radius, call paths) from
   remote evidence alone.
```

### D3. Teach `tierUsed` in the submit_report contract

Current persona text being changed (report example object):

```text
  "backendsUsed": ["remote"],
```

Replacement text:

```text
  "tierUsed": "tier1",
  "backendsUsed": ["remote"],
```

And immediately after the "Your turn is complete only after submit_report
returns \"report accepted\"." paragraph, insert:

```text
Set "tierUsed" to the highest tier that produced evidence for this report:
"tier0" (session memory only, no commands), "tier1" (remote ghx commands),
"tier2" (any ghx tier2 command). Reports that claim tier2 must list the
local:* backend(s) in "backendsUsed".
```

## Eval-measurement rule

- Pre-registered here before the next run; never lands or changes mid-run.
- After application, verification is a sidecar-only spot check for direction:
  live asks with `local` in allowed backends on cross-file questions (e.g.
  the ADR-0024.1 smoke questions), then read `tier-decisions.jsonl` and the
  session traces for `ghx.tier.decision` / `ghx tier2` usage. An agent that
  ignores the escalation doctrine is a negative finding and gets committed
  as such.
- Citable numbers come only from a later pre-registered run after the policy
  and persona are frozen (ADR-0024.1 verification plan).

## Verification plan (for the application commit)

- Persona golden-hash update in `prompt_test.go` in the same commit.
- `TestBuildPersonaSystemPromptContract` gains assertions for the tier2
  doctrine and the `tierUsed` field.
- `go vet ./...`, `go test ./...` with real exit codes.
- Live spot check per the eval-measurement rule above.

## Considered and rejected

- **Applying this together with ADR-0024.2's engine slice**: rejected —
  persona changes are sequenced by the orchestrator between runs, and landing
  the recorder first gives a clean before/after in `tier-decisions.jsonl`.
- **Teaching tier2 unconditionally (no `local` gate in the text)**: rejected;
  the policy's hard gate is `AllowedBackends`, and the persona must mirror
  the pre-registered rule, not loosen it.
- **Letting the agent choose tiers freely ("use tier2 whenever useful")**:
  rejected — ADR-0024.1 rejected implicit LLM escalation; the doctrine must
  state the same observable triggers the policy evaluates.
- **Also teaching `--sparse`/`--ref` tuning flags**: rejected for revision 3;
  keep the surface minimal until dogfooding shows the need.
