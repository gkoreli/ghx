# 0019.3. Adoption Surface Flip — Recon-First Serve Default, Contract Purity, Install Rails

## Status

Proposed. Continues the `sidecar-adoption` thread (ADR-0019 zero-CLI surface,
0019.1 discovery tier, 0019.2 discovery eval tasks). This ADR records the
post-dogfood decision ADR-0019 D2 explicitly reserved: *"flipping recon-only
to the default is an explicit post-dogfood decision recorded here when made."*
Dogfood week ran (FRICTION.md, 2026-07-05 → 2026-07-07); the happy path held
across three languages, three depths, and the daemon. The evidence for flipping
is in `docs/research/saf-adoption-wedge.md`.

## Context: why the flagship surface is not the flagship

The product sentence is *"ask ghx repo questions in English; get schema-
validated evidence reports back."* Yet every default surface teaches tools,
not the sentence:

- `ghx serve` with no flags registers **seven direct tools**
  (`internal/cli/serve.go:146–152`: explore, repos, search, read, tree,
  search_tools, code); the recon sidecar is opt-in behind `--recon`
  (`serve.go:416`, default false). A main agent whose owner read no docs gets
  the step-driving surface — the exact anti-pattern the north star names.
- The recon MCP tool returns the report JSON **with prose concatenated onto
  the string** (`serve.go:208–221`: route line + artifacts footer appended to
  `json.Marshal(report)` output). For the programmatic consumer this is a
  broken contract: the payload is not parseable JSON. Route provenance and
  artifact pointers are valuable — they belong *inside* the structured
  payload, not glued to it.
- `skills/ghx-recon/SKILL.md` has drifted to **36 non-empty lines** against
  its own ≤30 budget (ADR-0019 D1; enforced at introduction by
  `skills/doc_test.go`). Doctrine is creeping back outside the boundary.
- Install rails stop at npx/brew/npm/go (README quickstart). The surfaces
  where agent owners actually install — MCP registries/plugin manifests and
  the skills ecosystem — have no one-line ghx entry
  (`docs/research/saf-adoption-wedge.md`, wedges A/B).

Meanwhile host-native subagents commoditized context isolation; what remains
defensible is remote/discovery + persistent session memory + auditable
evidence contracts (prior-art re-check in the wedge research). Every default
must therefore showcase the evidence contract, and the distance from install
to first useful answer must approach zero.

## Decision

### D1. Recon-first is the default `ghx serve` mode

Bare `ghx serve` serves exactly one tool: `recon(question, repo?, session?,
depth?)`. The seven direct tools move behind an explicit `--direct` flag
(inverse of today's `--recon`). Rationale: the default path a consumer gets
with zero documentation must be the product sentence. Direct tools remain
first-class — they are the P1 standalone product and the eval baseline
profile — they just stop being the silent default. `--recon` remains accepted
as a no-op synonym for one release cycle with a deprecation note in `--help`,
so existing configs do not break silently.

### D2. Contract purity: the recon result is machine-parseable JSON, always

The recon tool returns a single JSON object. Provenance moves inside it:

```json
{
  "report": { ...existing report fields... },
  "route":   { "session": "...", "source": "...", "rule": "..." },
  "artifacts": { "sessionDir": "~/.ghx/sessions/<name>", "traceId": "..." }
}
```

Humans keep rich text via `ghx sidecar ask`; agents get bytes. No prose may
be appended to any MCP tool result — pinned by a test asserting
`json.Unmarshal` succeeds on every recon result shape (success, BLOCKED,
error-result paths).

### D3. Skill back under budget; one-sentence description everywhere

`skills/ghx-recon/SKILL.md` returns to ≤30 non-empty lines (budget re-pinned
in `skills/doc_test.go`). The MCP tool description carries the same one
sentence. Nothing CLI-shaped enters either surface.

### D4. Install rails: registry-grade one-liners

Ship alongside the binary (no hosted service, local-first holds):

1. **MCP config snippets** in README + `ghx serve --print-mcp-config`
   emitting a ready-to-paste `mcpServers` block for Claude Code / Cursor /
   generic MCP clients (command form: `npx -y @gkoreli/ghx serve`).
2. **Skills-ecosystem rail**: publish the recon skill so
   `npx skills add @gkoreli/ghx` (or equivalent) installs it; document the
   manual fallback (one `ghx skill --recon >` redirect) as ground truth.
3. **Doctor stays the front door**: every rail's docs end at
   `ghx sidecar doctor` so auth/env failures surface with remediation on
   first contact (the wedge research's core finding: wiring, not install,
   is the tax).

### D5. Verification bar

- Full `go test ./...` green; new tests pin D1 (default mode registers only
  `recon`) and D2 (parseable JSON in all shapes).
- One live dogfood pass: fresh-session `ghx serve` wired into a real agent
  client, first question answered, result parses as JSON, artifacts dir
  exists. Logged in FRICTION.md.
- Breaking-change note in CHANGELOG (direct-tools users add `--direct`);
  version bump via `node scripts/bump.js` per repo rules.

## Considered and rejected

- **Removing direct tools entirely**: rejected — P1 is a shipped standalone
  product, the eval baseline depends on it, and deprecation is an M7/P3
  question (ADR-0019 already ruled; nothing changed).
- **Keeping prose suffix but also adding a `--json` flag on the tool**:
  rejected — a tool contract that requires a flag to be parseable is still a
  broken default; agents don't read flags, they read schemas.
- **Auto-config injection into detected clients** (writing user MCP configs
  directly): rejected for now — surprising global side effects on install
  violate least-astonishment; print/paste keeps the user in control. Revisit
  if dogfooding shows paste friction dominates.
- **Hosting a managed endpoint**: violates local-first (ADR-0019).

## Risks

- Existing consumers of bare `ghx serve` see different tools after upgrade.
  Mitigation: CHANGELOG call-out, `--direct` escape hatch, `--recon`
  accepted as no-op through one release.
- Skills-ecosystem publishing may have external review latency; D4(2) ships
  with the manual redirect documented so the rail is never blocked on it.

## Implementation Notes (2026-08-21, shipped)

- **D1** landed in `internal/cli/serve.go` via `newServeServer(direct)` /
  `registerDirectTools` / `registerReconTool`: bare `serve` registers exactly
  the recon tool; `--direct` restores the seven direct tools + `code`;
  `--recon` is parsed and ignored (deprecated synonym, no warning emission —
  verified by registration-path test rather than output assertion). Long help
  rewritten; eval harnesses invoking `serve --recon` keep working.
- **D2** landed as `sidecar.ReconResult{report, route, artifacts}`
  (`internal/sidecar/reconresult.go`, core-side boundary type per the
  module rules); the MCP handler returns only
  `json.Marshal(NewReconResult(report, turn))`. Deviation from the ADR's
  sketch: hard failures stay MCP **tool errors** (no envelope), so a nil-turn
  error shape parses as `{"report":{...},"route":null,"artifacts":null}` on
  the success/BLOCKED paths and as an error result otherwise. Contract pinned
  by unmarshal tests across success / BLOCKED / error shapes with zero bytes
  outside JSON (`internal/cli/serve_test.go`, `internal/sidecar/reconresult_test.go`,
  updated `internal/cli/sidecar_test.go`). The frozen eval-identity schema of
  `ReconMCPTool()` was deliberately untouched.
- **D3** landed as a trim of `skills/ghx-recon/SKILL.md` to 25 non-empty body
  lines (budget re-pinned by `TestReconSkillBodyLineBudget`) with verbatim
  sentence parity between the skill and the recon tool description.
- **D4** landed as `ghx serve --print-mcp-config` (emits the `mcpServers`
  block, validated by round-trip parse) plus README install rails ending at
  `ghx sidecar doctor`; CHANGELOG carries the breaking-change note.
- Verification: `go build ./...`, `go vet` clean; full `go test ./...` green;
  live stdio smoke: default → `[recon]`, `--direct` → 7+code, `--recon` →
  `[recon]`.
- Open follow-up: one live dogfood pass wiring bare `ghx serve` into a real
  agent client, logged in FRICTION.md — the ADR's D5 bar before release.
