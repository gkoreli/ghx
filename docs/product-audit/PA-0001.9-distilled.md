### R1 — Flip the default adoption surface to recon (H1). Workstream **B2** (= M5 frontier). One-file edit.

The product's terminal goal is *"a main agent … needs zero knowledge of the ghx
CLI — it never loads the ghx skill file at all"* (`NORTH_STAR.md:24`). The
default install ships that exact file.

```
$ cat .claude-plugin/plugin.json
{ "name": "skills", "skills": [ "./skills/ghx", "./skills/ghx-mcp" ] }
$ grep -c recon .claude-plugin/plugin.json      → 0
$ ghx skill        | wc -l  → 232      # the heavy CLI skill is the default
$ ghx skill --recon | wc -l  → 47      # the north-star surface, opt-in behind a flag
```

**CONFIRMED.** The recon skill is not in the manifest; the default `ghx skill`
and `ghx serve` both land on the heavy surface. **Two honest mitigations I
verified** (adopt them, don't hide them): both heavy skills *self-redirect* in
their first blockquote — `skills/ghx/SKILL.md:13-19`: *"This is the
power-user/tool layer… delegate the whole question to the recon service
instead… You then need zero knowledge of the commands below."* And this is the
openly sign-posted **M5/B2** frontier (`NORTH_STAR.md:280`), not a hidden lie.

- **North-star:** fails the filter's first clause (*remove tokens/knowledge
  from the main agent's context*) at the point of adoption.
- **Leverage caveat (size before acting):** H1 assumes the plugin is the
  dominant install channel. A `brew`/`go install` binary ships **no** skills at
  all, and an agent may be handed `ghx skill --recon` directly. Impact is
  channel-dependent; the synthesis (via `.6`) already flags this and it is
  correct. Still the highest-leverage move because the fix is a config line and
  has zero measurement dependency.
- **Do:** add `./skills/ghx-recon` to `plugin.json` (or make it primary); demote
  the heavy skills to opt-in; surface `inspect` on the recommended surface (R6).

## Bones thrown away (and why)

**These are the fish's bones — a *true underlying fact* wrapped in an
*over-reaching frame*. I keep the fact, discard the frame.**

1. **"Native `Explore` is ghx's *exact* Benefit / the true alternative" (H3 sub) —
   REFUTED for the measured domain.** Explore is read-only *local-filesystem*
   search (confirmed by its own tooling: it sweeps files/directories, it has no
   GitHub-fetch). It **cannot** fetch an un-cloned GitHub repo or sweep the
   open-source world — which is *every task ghx's evals measure* (express, gin,
   hono, flask, openai-node, all remote no-clone) plus the discovery tier.
   Explore competes only on the **local-repo context-protection benefit**, never
   on ghx's **capability**. The audit conflated benefit-overlap with
   capability-overlap; that conflation *understates* ghx's position. Keep: "brain
   not tools is advantage-not-Power" (true). Discard: "Explore commoditizes ghx"
   for anything but the local tree.

2. **"SPT is a compression meter, NOT a quality meter / value-free label" (`.5`
   F1) — over-reach.** The numerator *is* signal = correctness × evidence, a
   quality proxy; a terser report that drops correctness drops SPT. SPT is a
   **context-efficiency** meter *by design* — which is precisely the north star
   ("the main agent's context is sacred"). Its gameability is real but is
   **downstream of the H1 hole** (substring gates score recall, not quality), not
   intrinsic to SPT. Keep: "the advantage is the denominator" and the 24×≈25×
   identity (→ R2). Discard: the "wearing a quality label / directly moveable
   proxy nobody agreed to" framing.

3. **"The named NSM (SPT) is non-load-bearing while G1 actually gates" (`.5`
   F4) — a wording nit, not a defect.** The zealot filed it himself as his
   least-confident call, and the underlying design — *"SPT is deliberately not a
   gate"* (ADR-0016.6:99) — is **good hygiene** (the most obvious Goodhart for a
   compression product was explicitly refused). Discard the "mislabeled north
   star" as a finding; keep only a one-sentence clarification in "The Moat" that
   SPT is the reported aspiration and G1/G3 are the operative gates.

4. **The synthesis's dismissal of F7's "141 lines" as "an unverified substring"
   — I REFUTE the dismissal; F7 was right.** The synthesis measured
   `wc -l prompt.go` = 350 (the *source file*) and used it to wave off F7's 141.
   But F7 measured the **rendered** `BuildPersonaSystemPrompt()` output. I
   extracted and measured the rendered string independently:

   ```
   BuildPersonaSystemPrompt: rendered_bytes=6583  rendered_lines=137  approx_tokens=1645
   ```

   That corroborates F7's 141 / 6858 / ~1714 (my regex under-captured a few
   concatenated tokens). So the load-bearing point stands and is *stronger* than
   the synthesis allowed: NORTH_STAR's "~400 lines" (`:96`) is ~3× the rendered
   doctrine, and `prompt.go:32`'s own comment says *"~400 **tokens**"* per turn —
   a different unit conflated with lines. This is a real bone in the *synthesis*,
   not the persona. → tenet-evolution #2.

5. **"M8 anticipation reads as working" (L2) — keep, but it's nearly cold.** The
   D1 gate FAILED, the build was correctly halted, and `docs/adr/0031.2-nextreads-
   contract-revision.md` exists (verified). Purely a one-line inline caveat in
   NORTH_STAR §cap-2. Not worth escalation.

6. **README "≤ 30 lines" for the recon skill (`.1` F6) — CONFIRMED trivial.**
   `README.md:337` says ≤30; `wc -l skills/ghx-recon/SKILL.md` = 47. Real, tiny,
   fold into the R1 doc pass.

## North-star / tenet evolution proposals

Where the yardstick itself has fallen behind ghx's velocity — proposed
deliberately, with evidence.

1. **The flagship narrative has fallen behind ghx's own honesty machinery —
   invert the drift.** The connective theme of the entire audit, which I confirm
   under independent recompute: **`TRUST.md`, `corpus-discrimination`, the kept
   honest-negative, and the contamination guard are all *more truthful* than the
   NORTH_STAR banner.** The eval discipline outran the narrative. Propose a
   standing rule: *the NORTH_STAR milestone banners may never read cleaner than
   the committed ledger they cite.* Concretely, re-anchor M4's line to the
   citable fixbatch run (16.6×, 2/6 discriminating, quality-half-pending) and
   mark the confirmatory run superseded-as-conservative-floor **in NORTH_STAR
   itself**, not only in the fixbatch README.

2. **Re-anchor P4 exit-trigger #2 on the measured, cache-stable token cost.** The
   trigger fires on *"a measured SPT plateau attributable to … the ~400-line
   persona doctrine paid every session"* (`NORTH_STAR.md:223`). Measured: the
   rendered persona is **~137–141 lines / ~1.7k tokens**, and ADR-0020.1 already
   moved it to the cache-stable session system prompt (so "paid every session"
   overstates the per-inference cost that prompt-caching removes). A
   pre-registered exit trigger must be as accurate as any eval gate (the project's
   own Visibility/Truthfulness discipline applied to itself). Fix the figure and
   re-derive whether the trigger is anywhere near firing.

3. **Promote "publish the SAFE benchmark" from Consequence Product to a dated
   frontier item.** The generative-competition tenet (AGENTS.md, 2026-07-07) is
   **sound and I validated it in the act** — the strongest competitor
   (codebase-memory-mcp) is simultaneously the strongest absorption candidate,
   and one `ghx sidecar ask` beat raw `ghx repos` at competitive recon (the moat
   thesis proven under the auditor's hands). No tenet change. But the tenet's
   *timing* assumption is stale: a rival already published an arXiv recon
   benchmark. "Others can run their agents against ours" (`NORTH_STAR.md:108`) is
   being contested **now**, by a tool, before ghx's version exists. The benchmark
   should get a near-term slot, not a "someday" one.

4. **Name the selection-time competitor precisely, and reposition the moat on the
   uncontested domain.** NORTH_STAR §Moat asserts *"there may be no real
   competition in code reconnaissance at all."* True for the **remote/discovery**
   domain (uncontested); false for the **local-repo** overlap (native Explore +
   local indexers commoditize it). Amend §Moat to state the defensible ground
   explicitly — remote-first, GitHub-wide discovery, and the persisted evidence
   contract — so the strategy doc stops resting the "no competition" claim on a
   selection contest it does not yet run.

## Bottom line

The audit's own headline survives a hostile, independent recompute: **ghx's
committed ledgers are more honest than its flagship banner, and the fix for most
High findings is narrative honesty plus finishing already-scoped measurement (run
C8, calibrate the judge), not new machinery.** But the *convergence* structure is
weaker than the synthesis implies — only H3 is genuine independent-persona
agreement, and its most alarming sub-claim (native Explore commoditizes ghx) is
**refuted** for ghx's measured domain, which actually *strengthens* the position.
The two truly load-bearing, cross-validated actions are near-free and orthogonal
to the eval work: **flip the default install to the recon surface (H1 — one file,
directly on the M5 frontier)** and **stop the banner over-reading the ledgers (H2
— a wording pass over a proof I reproduced)**. Nearly every discarded "bone" is
the same shape: a *true fact* dressed in an *over-reaching frame* — the discipline
here is to eat the fact and spit out the drama.
