# Engineering Feasibility / Absorption-Architect — codebase-memory-mcp (PA-0002.3)

**The question:** should ghx absorb `DeusData/codebase-memory-mcp` (hereafter **cbm**)
entirely as an internal tool/tier — and *can* it, technically? This lens answers only
the second half: **can we swallow this without it swallowing us?**, with hard evidence.

## Bottom line (decision-grade)

| Axis | Verdict |
|---|---|
| **LICENSE (hard gate)** | **MIT, Copyright (c) 2025 DeusData** — and every transitive vendored dep is permissive (BSD/MIT/PD/0BSD/Unlicense/Apache-2.0/CC0/ISC), **zero GPL/LGPL/AGPL**. **GO. Absorbable. MIT-in-MIT-out is satisfied.** |
| **Language / build** | **Pure C11** (763 `.c`, 640 `.h`, 178 vendored `grammar_*.c`), `Makefile.cbm` + `flake.nix`, single static binary for macOS/Linux/Windows. *Not* Go — `internal/`,`pkg/` are legacy dir names; `cli.h` says it is a "Port of Go cmd/codebase-memory-mcp" (**ex-Go, recently rewritten to C**, at v0.8.1). |
| **Recommended absorption mode** | **SHELL-OUT** to the released static binary as a Tier-2 backend `local:cbm` (identical mechanic to how ghx already absorbs ast-grep). **NOT vendor-source, NOT reimplement.** |
| **Effort** | **M** (≈ ast-grep adapter + a two-phase index→query lifecycle). Vendor-source = **L/XL and rejected**; Go reimplement = **L and premature**. |
| **Biggest engineering risk** | **Stateful-index / daemon mismatch.** cbm's sub-ms selling point *requires* a persisted, reused index (SQLite `.db`) and ideally a warm watcher process; ghx Tier-2 today is stateless one-shot over an immutable SHA snapshot. You either re-index per cold call (eroding the "sub-ms" pitch) or take on index-lifecycle/daemon ownership (ADR-0030 territory). |
| **Least-confident call** | Whether cbm's *measured* value actually beats ghx's existing recon on ghx's own tasks. The vendor's **own arXiv abstract reports a quality regression** (83% vs 92% for a file-explorer) at 10× tokens — that needs a bake-off, not a code read. I could not run the binary (read-only, text-only), so all speed/quality is code-plausibility, not measurement. |

North-star relationship: absorption **passes the filter** in principle (P3 "swallow the
tools" / M7; a structural graph backend removes read/grep loops from the sidecar's Tier-1
budget) **and** passes the Open-Source-Leverage gate (MIT-in-MIT-out, adopt-with-attribution).
The open question is *value*, not *feasibility* — feasibility is a clear yes.

## Evidence ledger (recompute from these)

All target-repo facts were gathered by **dogfooding ghx** (`go build -o /tmp/ghx ./cmd/ghx`).
`ghx read`/`ghx tree` use the GitHub contents/git API (core quota, 5000/h) and worked
throughout; `ghx grep` uses the code-search API (10/h) and was **rate-limited after 10 calls**
— logged as an AX finding below. `gh api` and `WebFetch` (arXiv) used as fallbacks, logged.

### E1 — LICENSE hard gate: MIT, clean transitively
- **Source:** `LICENSE:1-3` → `MIT License / Copyright (c) 2025 DeusData`.
  Recompute: `/tmp/ghx read DeusData/codebase-memory-mcp LICENSE`.
- **Transitive:** `THIRD_PARTY.md` enumerates every vendored component — SQLite (Public
  Domain), mimalloc/yyjson/Verstable (MIT), xxHash/TRE/LZ4 (BSD-2), **zstd (dual BSD-3/GPLv2 —
  BSD selected)**, simplecpp (0BSD), wyhash (Unlicense), nomic-embed-code model (Apache-2.0),
  178 tree-sitter grammars (nearly all MIT; `clojure`/`fennel` CC0-1.0, `jinja2`/`just`
  Apache-2.0, `pine` ISC). Recompute: `/tmp/ghx read DeusData/codebase-memory-mcp THIRD_PARTY.md`.
- **Finding:** **no copyleft anywhere in the effective set.** zstd's GPLv2 option is *not*
  selected. Every license is permissive; all are attribution-only.
- **Strategy tenet (quoted, `AGENTS.md:187`):** "openly, vocally, with attribution and
  stewardship (**MIT in, MIT out**)." cbm is MIT; ghx is MIT → **the hard gate passes**.

### E2 — Language & build: pure C, single static binary, ex-Go
- **Source:** file census — `/tmp/ghx tree DeusData/codebase-memory-mcp | grep -oE '\.(c|h|go|rs|py|ts)$' | sort | uniq -c` → **763 `.c`, 640 `.h`, 17 `.py`, 13 `.ts`, 1 `.go`**. Build:
  `Makefile.cbm:1` "Build system for pure C rewrite" (`-std=c11`, ASan/UBSan/TSan, `-O2`
  prod, mimalloc-bound). `README` badge "**Pure C — zero dependencies**", "**single static
  binary** (macOS arm64/amd64, Linux arm64/amd64, Windows amd64)".
- **Ex-Go heritage:** `src/cli/cli.h:5` — "**Port of Go `cmd/codebase-memory-mcp/` install/update/config logic.**"
- **Finding:** the `internal/`,`pkg/` dirs are **not** Go packages — they hold C
  (`internal/cbm/*.c`, `internal/cbm/vendored/...`). A Go program cannot import this; consuming
  the source means **cgo across ~1400 C/H files** — infeasible. The binary, by contrast, is a
  drop-in external tool. This is the technical fact that decides shell-out over vendor.

### E3 — Architecture: tree-sitter → SQLite graph, MCP + one-shot CLI
- **Entrypoint modes** (`src/main.c:4-13`): `(default)` MCP server over stdin/stdout
  (JSON-RPC 2.0); **`cli <tool> <json>` — "Run a single tool call and print result"**;
  `--version`/`--help`/`--ui`. A background **watcher** thread "polls for git changes" (incremental reindex).
- **Persistence** (`src/store/store.h:2`): "**Opaque SQLite graph store for code knowledge
  graphs**." Node types `Function/Class/Method/Module/File`; edge types `CALLS/HTTP_CALLS/IMPORTS`;
  `project`, `file_hash(sha256,mtime,size)` tables. So the "persistent knowledge graph" is
  **nodes+edges in on-disk SQLite** — a standard, absorbable design.
- **Parse + query** (`src/mcp/mcp.h:4`): "**14 graph analysis tools (search, trace, query,
  index, ...)**", JSON-RPC 2.0. `README`: tree-sitter AST across 158 languages + in-house
  "Hybrid LSP" semantic type resolution for ~9-11 languages; Cypher-like queries; RAM-first
  indexing (LZ4, in-memory SQLite, fused Aho-Corasick).
- **Commodity vs. hard:** *commodity* = tree-sitter parsing (178 vendored `grammar_*.c`,
  verified by `ghx tree | grep -cE 'grammar_.*\.c$'` → 178) + SQLite storage. *Genuinely hard*
  = cross-file **semantic resolution** — call chains, type refs, cross-service HTTP linking,
  impact/blast-radius, "Hybrid LSP". That hard core is exactly the capability ghx's Tier-2
  (codemap/ast-grep) does **not** yet have — it is the reason to absorb, if the value proves out.

### E4 — Integration path: it maps onto the existing Tier-2 subprocess pattern
- **Source (ghx side):** `internal/sidecar/tier2/astgrep.go:20-24` — ast-grep (a Rust/MIT tool)
  "**absorbed as an internal subprocess tool per ADR-0024.1 — it disappears from the user's
  operational surface, never from attribution.**" The shared body is `toolrun.go`
  `subprocessAdapter` (PATH discovery + typed not-installed error + evidence-capturing exec in
  a snapshot dir). `service.go:180` `Service` is the single owner (Codemap, AstGrep, Repomap).
- **The fit:** a new `cbm.go` `subprocessAdapter{binary:"cbm", backend:"local:cbm"}` + a
  `Service.RunCbm(...)` shelling `cbm cli <tool> ...` over a snapshot dir slots in exactly like
  `RunAstGrep`. cbm's flags→JSON arg builder (`cli.h:23`, kebab→snake, typed by input_schema)
  gives a clean CLI contract to target. Policy wiring: cbm answers precisely the `hard-signal`
  questions ADR-0024.2 already routes to Tier-2 — `imports`/`depends on`/`blast radius`/`who
  calls`/`call chain`/`references to` (`0024.2-escalation-policy.md:96-106`).
- **The gap that makes it M not S:** every existing adapter is **stateless one-shot** (`ast-grep
  run ... → JSON → done`). cbm is **two-phase and stateful** — you must `index` a project into a
  `.db` first, then query it; the sub-ms pitch only holds if the `.db` is *persisted and reused*.
  ghx's snapshot cache is **SHA-keyed and immutable** (`service.go:51` "SHA is the snapshot
  identity and cache key"), which is actually a *good* host for "index once per SHA, store `.db`
  beside the snapshot, query many". But cbm's watcher/incremental-reindex model assumes a
  *mutable* working tree and collides with immutable snapshots — so you adopt the index/query
  tools and **ignore the watcher/daemon half**, or you take on daemon lifecycle (ADR-0030).

### E5 — The claims: one real regression hidden behind cherry-picked multipliers
- **README headline** (`README.md`): badge "**99% fewer tokens**"; body "**120x fewer tokens** —
  5 structural queries: ~3,400 tokens vs ~412,000 via file-by-file search."
- **The project's OWN arXiv abstract** (arxiv.org/abs/2603.27277, fetched): "**ten times fewer
  tokens and 2.1 times fewer tool calls**", "**83% answer quality versus 92% for a
  file-exploration agent**", "matches or exceeds on 19 of 31."
- **Finding:** (a) the token multiplier is **cherry-picked best-case** — 99%/120× headline vs
  **10× measured average** in their own paper; (b) more importantly the paper reports a
  **~9-point answer-quality regression (83 vs 92)** that the README omits. This is precisely the
  best-case-vs-average, buried-comparator pattern ghx's "**Evidence, not vibes**" tenet exists to
  reject — so cbm's marketing must be **re-measured on ghx's tasks**, never quoted. Plausible
  claims (from code, not verified-by-running): 158 languages (grammars are vendored and counted),
  ms indexing / sub-ms query (SQLite indexed point-lookups warm; RAM-first LZ4/Aho-Corasick are
  real techniques). **arXiv authenticity itself is unverifiable** — the page resolves but the
  numbers are vendor self-report regardless; the sub-model's "future date" objection is moot from
  the repo's 2026-07-07 clock (28 Mar 2026 is past), but that does not make the paper peer-reviewed.

## Ranked findings

### F1 — [License] Clean MIT, transitively — the hard gate is a GO · Severity: n/a (enabling) · self-verified
- **Persona·Scope·Surface:** Absorption-Architect · Trust/license-provenance · target LICENSE + THIRD_PARTY.
- **Novelty:** NEW (no prior PA dispositioned this repo).
- **Evidence:** E1. `LICENSE` = MIT (c) 2025 DeusData; every vendored dep permissive; zstd's GPLv2
  path not selected; no GPL/LGPL/AGPL.
- **Disposition:** *Confirmed sound.* Absorbable under MIT-in-MIT-out. **The one caveat that
  survives:** if we ever **vendor source** we inherit the obligation to carry ~15 upstream
  LICENSE/NOTICE files (tree-sitter, SQLite, mimalloc, yyjson, xxHash, TRE, LZ4, zstd, simplecpp,
  Verstable, wyhash, nomic, + per-grammar). **Shell-out inherits none of that** (the binary is the
  user's separately-installed tool, like ast-grep) — a decisive, license-driven argument *for*
  shell-out over vendor.
- **North-star:** passes Open-Source-Leverage gate (`AGENTS.md:187`).
- **Verification:** self-verified from the two files; a reader re-runs the two `ghx read` commands.

### F2 — [Feasibility] Shell-out is the only sane mode; source-vendor is infeasible, reimplement is premature · Severity: High-leverage (decides the whole approach) · self-verified
- **Persona·Scope·Surface:** Absorption-Architect · Platform/scale · target language + ghx tier2.
- **Evidence:** E2 (pure C, 1400+ files, ex-Go) + E4 (existing subprocessAdapter precedent).
- **The three modes, priced:**
  - **Shell-out (`local:cbm` Tier-2 backend) — RECOMMENDED, effort M.** Mirrors `astgrep.go`
    exactly; isolates ghx from cbm's C-source churn *and* its ~15-license tail; user installs the
    static binary (an `AstGrepInstallHint`-style message). Extra work over ast-grep = the two-phase
    index→query lifecycle + `.db`-per-SHA caching (E4).
  - **Vendor source — REJECTED, effort L/XL.** cgo across ~1400 C/H files into a Go binary;
    inherit every upstream license; track a **pre-1.0, mid-Go→C-rewrite** upstream. Violates
    "no bandaids" (`AGENTS.md:224`) — it is a permanent maintenance anchor.
  - **Reimplement in Go — REJECTED for now, effort L.** ghx already walks this road (codemap,
    ast-grep, repomap ranking, ADR-0024). Rebuilding cbm's *graph + Cypher + impact-analysis +
    Hybrid-LSP* surface in Go is a large bet that only pays if shell-out first proves the value.
    Hand-roll "only when nothing existing serves the vision" (`AGENTS.md:194`) — something serves.
- **Disposition:** *Needs work → route to Workstream A (A3 "Tier-2 structural tools absorbed") and
  an ADR under the 0024 thread* before any build. This is the M7/A3 lane by construction.
- **North-star:** P3 "swallow the tools"; Remote-first/escalation-explicit (Tier-2 is the deliberate
  visible deeper layer).
- **Verification:** self-verified; **flag — same-family only.** A High approach-deciding call should
  get a cross-family (Codex) check before it is milestone-citable (Process step 5).

### F3 — [Risk] The stateful-index / daemon mismatch is the real integration cost · Severity: High (Likelihood High × Impact Medium) · self-verified
- **Persona·Scope·Surface:** Absorption-Architect (Technical-Debt Realist kin) · Platform/scale · ghx tier2 + ADR-0030.
- **Evidence:** E3 (watcher + persistent SQLite) vs `service.go:51` (immutable SHA snapshots) and the
  stateless one-shot shape of `toolrun.go`/`astgrep.go`.
- **The problem:** cbm's "sub-ms queries" presuppose a *warm, persisted* index. ghx Tier-2 is
  cold-one-shot over an immutable clone. Two honest options, each with a cost: **(a)** index per cold
  snapshot and query immediately — simplest, fits the SHA-keyed cache, but you pay indexing latency
  every cold call and lose the "warm sub-ms" pitch (mitigant: cbm indexes an average repo in "ms", so
  a cold index-then-query may still be acceptable — **must be measured**); **(b)** persist the `.db`
  per SHA and keep a warm cbm process across queries — recovers sub-ms but pulls in process/daemon
  lifecycle, which ghx has deferred to B6/ADR-0030. cbm's git-watcher incremental-reindex is
  **unusable** against immutable snapshots and must be disabled.
- **Disposition:** *Needs work → the ADR must pre-register which option, and a latency bake-off gate.*
- **North-star:** bears on "sub-second answers" (M8) and "always-on runtime" (B6) — do not let cbm
  smuggle in a daemon requirement ahead of that milestone.

### F4 — [Trust] cbm's marketing hides a measured quality regression — re-measure, never quote · Severity: Medium (Likelihood High × Impact Low-Med) · self-verified
- **Persona·Scope·Surface:** Absorption-Architect (AI-PM-Pragmatist kin) · Trust/evals-as-research · README vs arXiv.
- **Evidence:** E5. README "99% / 120× fewer tokens" vs the vendor's own paper "10× tokens, **83%
  vs 92% answer quality**".
- **Disposition:** *Confirmed sound (as a caution).* If ghx absorbs cbm, the go/no-go is a
  **ghx-eval bake-off** on discovery/localization tasks (C5 discovery fixtures; codemap/ast-grep as
  the incumbent baseline) — **not** the vendor's numbers. A 9-point quality drop for 10× tokens may or
  may not beat ghx's current Tier-1 recon; the sidecar's whole thesis is *signals per token*, and that
  tradeoff is exactly what our own gates measure.
- **North-star:** "Evals and benchmarking are how we know" — absorption is gated on our measurement,
  not theirs.
- **Verification:** self-verified; the arXiv page is a fallback source (logged), authenticity unverified.

### F5 — [AX, ghx self-finding] ghx grep dies at 10 code-searches/hour; recon leaned on read/tree · Severity: Low (Likelihood High × Impact Low) · self-verified
- **Evidence:** `ghx grep DeusData/... "\.db"` → `HTTP 403: API rate limit exceeded ... code_search`
  after 10 calls (`gh api rate_limit` → `code_search: {limit:10, remaining:0}`). `ghx read`/`ghx tree`
  (core quota 5000/h) never flinched — the whole architecture read was done through them.
- **Disposition:** *Needs work → route to Workstream A (A2 usage-mining / A4 error-as-affordance).*
  For an *absorption-scouting* job (this audit's exact use case), 10 greps/hour is a hard ceiling; the
  error is honest but the affordance is weak — it names `gh auth login` but a sidecar doing GitHub-wide
  discovery will hit this constantly. Cross-ref PA-0001.1 (AX) if it raised a token/quota class.
- **North-star:** discovery tier (B5) is the surface most exposed to this; a real gap for the
  "sweep the GitHub open-source world" capability.

## What is actually fine (checked, sound)

- **The license is not a trap.** I specifically hunted for hidden copyleft (the common vendor-repo
  gotcha): zstd is the usual suspect (dual BSD/GPLv2) — `THIRD_PARTY.md` explicitly selects BSD-3. No
  GPL/LGPL/AGPL in grammars, C libs, or the model. Clean.
- **The design is not exotic.** SQLite-backed nodes/edges + tree-sitter parse is a boring,
  well-understood, absorbable stack — no bespoke storage engine, no proprietary format, no network
  service. The "knowledge graph" is a graph-over-SQLite, not a Neo4j dependency.
- **The CLI surface exists and is clean.** `cli <tool> <json>` with a typed flags→JSON builder means
  we do **not** have to speak MCP JSON-RPC to absorb it (though we could — ghx already has an MCP
  server). One-shot shell-out is available today.
- **Attribution is honored upstream.** `THIRD_PARTY.md` is thorough and per-component — a good
  stewardship model to mirror if we absorb (we would add a `local:cbm` attribution exactly like the
  `astgrep.go:20` ast-grep credit).

## Absorption candidate summary (for the synthesis)

- **What to take:** the cross-file **semantic graph** capability (call chains, importers/dependents,
  blast-radius, cross-service HTTP linking) that ghx Tier-2 lacks — via **shell-out to the `cbm`
  static binary** as backend `local:cbm`.
- **Where it plugs in:** `internal/sidecar/tier2/cbm.go` (new `subprocessAdapter`) + `Service.RunCbm`
  + ADR-0024.2 `hard-signal` routing; ADR under the 0024 thread; Workstream A3.
- **North-star filter:** PASS in principle (removes read/grep loops from the sidecar's budget;
  visible tier, remote-first-then-explicit-escalation) — **conditioned on** a ghx-eval bake-off (F4)
  proving it beats the incumbent codemap/ast-grep + Tier-1 recon on our own tasks.

## What was not audited
- Runtime behavior — I could not execute the binary (read-only, text-only): speed/quality claims are
  code-plausibility, not measurement (that is the bake-off, F4).
- Full ghx architecture fit beyond `internal/sidecar/tier2` (defer to arch-audit).
- Security posture of shelling out to a third-party binary that reads the whole tree (defer to
  `security-review`; flagged here only as an ADR must-cover).
- Binary size / distribution weight of 178 grammars + embedded nomic model + graph-UI assets (a
  real distribution-tail concern *if* bundled; a non-issue if user-installed like ast-grep).
