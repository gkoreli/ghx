open-source world that the audit's competitive and absorption findings point to.

Governing frame (binding, not decorative): **competition is generative, not
defensive** (`AGENTS.md`: *"the question a competitor raises is never 'do we

sharpen*, gated only on the **north-star filter** (removes tokens/knowledge from
the main agent's context · cheaper-or-more-proficient recon · more auditable
evidence · better training trajectories) plus the **Picasso rule** (adopt
openly, with attribution).

**Every link was verified to resolve** (`gh api repos/…` for maturity, `gh api

URLs). Maturity is a 2026-07-07 snapshot. Load-bearing in-repo facts were
**dogfooded through ghx** (`ghx read`/`ghx grep` against `go build -o /tmp/ghx`,

## Section A — Competitors / category (the threat surface, deep-linked)

### A1 · `DeusData/codebase-memory-mcp` — the benchmark-backed, auto-distributing MCP recon server
**Verified:** 27,876★ · C · `pushed 2026-07-07` (daily-active) · not archived.
- Repo: <https://github.com/DeusData/codebase-memory-mcp>
- README (auto-install + benchmark claims): <https://github.com/DeusData/codebase-memory-mcp/blob/main/README.md>
- The distribution mechanic in code: <https://github.com/DeusData/codebase-memory-mcp/blob/main/src/cli/hook_augment.c> (a *"non-blocking Claude Code PreToolUse augmenter … for Grep/Glob calls injects matching graph symbols"*)
- arXiv preprint: <https://arxiv.org/abs/2603.27277> — *"Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP"* (curl 200; title matches)

**WHY IT MATTERS:** the single closest thing to a category rival — it ships
ghx's exact *signals-per-token* pitch, an *arXiv benchmark* (the "consequence
product" ghx planned), **and** the distribution Power ghx lacks, all at once.

**Claims verified verbatim (dogfooded):** README — *"**11 agents, one command**
— `install` auto-detects Claude Code, Codex CLI, Gemini CLI, Zed, OpenCode,
Antigravity, Aider, KiloCode, VS Code, OpenClaw, and Kiro — configures MCP
entries, instruction files, and pre-tool hooks for each."* · *"159 languages —
vendored tree-sitter"* · Linux kernel (28M LOC) indexed in 3 min · README
"Research" line links arXiv:2603.27277. It is a **local index** (indexing pass
required, *"your code never leaves your machine"*) with **no GitHub-wide
discovery and no persisted audit-designed report**.

**WHAT WE'D TAKE / WHERE IT PLUGS IN** (this is also absorption-candidate **A1**):
- *Utility → feature:* its persistent **tree-sitter + LSP knowledge graph**
  (functions, classes, call chains, HTTP routes, cross-service links) →
  a new `ghx tier2 graph` backend beside the existing codemap/ast-grep/repomap
  set — a **local escalation tier** (P3/M7), never the default (remote-first
  stays ghx's line).
- *Mechanic → onboarding:* its one-command **auto-install into host agents** →
  give `ghx serve` the same plug-and-play host wiring (contests the
  distribution lever, does not cede it).
- *"Why now":* it published an arXiv recon benchmark before ghx's SAFE
  benchmark exists — the category's numbers are being set by someone else;
  publish SAFE (Consequence Products) on the axes their local indexer can't
  score: remote-first, GitHub-wide discovery, persisted evidence.

**NORTH-STAR FILTER:** **passes** — deeper structural signal per token (swallow
the tools) and removes an operator indexing/setup tax. Absorb the graph as an
escalation tier; win on discovery + evidence.

### A2 · Claude Code `Explore` — the **native alternative** (Dunford true-alternative), deep-linked
**Verified:** docs page `curl -sI` → HTTP 200.
- Sub-agents doc (primary): <https://code.claude.com/docs/en/sub-agents>
- Anthropic framing (blog): <https://claude.com/blog/subagents-in-claude-code>

**WHY IT MATTERS:** the true alternative to ghx is **not** "the agent greps
files" — it is the host's *native* recon subagent. `Explore` delivers ghx's
context-subtraction Benefit for free, inside ghx's primary host.

**Precisely what it CAN do (verified from the live doc):** *"A fast, **read-only**
agent optimized for searching and analyzing codebases … Tools: read-only tools;
Write and Edit are denied … Purpose: **file discovery, code search, codebase
exploration**."* It preserves the main context by keeping exploration out of the
main conversation, and *"Explore and Plan skip your CLAUDE.md files and the
parent session's git status to keep research fast and inexpensive."*

**Precisely what it CANNOT do (the ghx-defensible residue):** it operates on the
**local checked-out codebase** — file discovery / code search over the working
tree. It has **no GitHub-wide fetch or discovery** ("which repos do X" is
outside it), **no un-cloned remote repo access**, and **emits no persisted,
audit-designed evidence artifact**. This is exactly PA-0001.9's refutation of
the "Explore commoditizes ghx" over-claim: Explore overlaps ghx's *local-repo
context-protection benefit* only, never ghx's *remote/no-clone/discovery
capability* — which is every task ghx's evals measure. Do **not** fight Explore
on the local tree; position ghx as the recon service the main agent (or Explore
itself, via MCP) reaches for the moment the job leaves the local repo.

**[UPDATED] cost-routing correction:** PA-0001.4 states *"Explore runs Haiku by
default."* The live doc now says *"As of **v2.1.198**, Explore **inherits the
main conversation's model instead of always running on Haiku**. On the Claude
API, the inherited model is capped at Opus."* The generic built-in-subagents
page still lists *"Control costs by routing tasks to faster, cheaper models like
Haiku"* as a benefit, but **Explore specifically moved off forced-Haiku**. This
weakens (does not void) the A4 "Haiku validates the P4 cheap-model bet"
argument — see B4.

**WHAT WE'D TAKE / WHERE IT PLUGS IN:** *vision validation, not code.* Explore
proves the host itself treats "read-only, context-isolated recon as a separate
cheap agent" as a first-class primitive — that is the Sidecar Framework mental
model shipping at platform scale. Absorb it as **evidence for the boundary**,
and as a **positioning input**: the recon skill's "when to use" must name what
Explore can't do (GitHub-wide discovery + persisted evidence + backends).

**NORTH-STAR FILTER:** **passes as positioning/validation**, not as a feature —
it sharpens where the differentiator must be (downstream of the local tree).

### B2 · `yamadashy/repomix` — tree-sitter `--compress`
**Verified:** 26,938★ · TypeScript · compress guide exists.
- <https://github.com/yamadashy/repomix/blob/main/website/client/src/en/guide/code-compress.md>

**Dogfooded facts (ghx read):** `--compress` uses tree-sitter to *"extract
essential code structures while removing implementation details"* — **preserves**
function/method signatures, interface/type definitions, class structures;
**removes** implementations, loop/conditional logic, internal declarations
(README elsewhere claims ~70% token reduction).
**WHY IT MATTERS:** turns raw file dumps into signature-level maps — the exact
fix for the "raw README/markup" signal-per-token tax PA-0001.4 F6 flagged.
**WHAT WE'D TAKE / WHERE IT PLUGS IN:** *feature.* A `--compress`-style
signature-only pass on `ghx read` and tier-2 map output — strips bodies, keeps
the structural skeleton an agent actually needs.
**NORTH-STAR FILTER:** **passes** — directly raises signals per token and
shrinks what enters the main agent's context.

## North-star-filter roll-up

(deeper structural signal, compression, better ranking) or the **auditable
evidence** clause (AX/attack taxonomies) — none requires forking an official

strategy doc's competitor-naming (remote/discovery is uncontested; the local
tree is not). The generative posture holds under deep-linking: **the strongest
rival is also the strongest absorption target**, and the native alternative is a
capability-boundary marker, not a kill-shot.
