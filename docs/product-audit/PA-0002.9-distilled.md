# PA-0002 — convergence & decision-grade ledger

**The question:** should ghx absorb `DeusData/codebase-memory-mcp` (**cbm**)
entirely as an internal tool/tier?

I produced none of the five persona findings. I re-derived every load-bearing
fact myself (LICENSE, arXiv, ghx tier-2 code, target CLI mode) before trusting
any of them, mapped where the five lenses *genuinely* converge versus where they
merely re-read the same prior, and reduced the result to one decision-grade
recommendation with the over-reaching bones cut out.

---

## Distilled recommendation

**ABSORB-ENGINE-GATED — engine only, shell-out only, behind a measured gate that
has not yet run.** Concretely:

- **Take** the cbm *engine* (tree-sitter + Hybrid-LSP knowledge graph: precise
  reference/call-path resolution, Cypher-queryable persistent call-graph,
  cross-service HTTP/gRPC linking, impact/blast-radius) as **one optional Tier-2
  subprocess backend `local:cbm`**, invoked via its one-shot `cli <tool> <json>`
  mode exactly the way ghx already absorbs ast-grep — **no source-vendor, no
  reimplement**.
- **Gate it** on a pre-registered ghx tier-2 bake-off (correctness
  non-inferiority **and** signals-per-token superiority on the cross-file /
  reference / call-path / discovery question class only), forced stateless at
  the boundary (`CBM_CACHE_DIR`→`~/.ghx/cache/tier2/cbm`, watcher + auto-index
  **off**), governed by a new **ADR-0024.x**.
- **Refuse** the literal prompt ("absorb *entirely*"): its persistent
  local-index-by-default posture, background watcher, always-on MCP server, 3D
  UI, team-graph artifact, and 11-agent auto-installer are the antithesis of
  ghx's remote-first tenet and its zero-CLI Non-Goal. Also refuse the
  PreToolUse **injection hook** and the installer's **instruction-file / hook**
  half, and refuse citing cbm's own numbers.

**Timing caveat (the honest core):** the gate is currently **unmet** — no ghx
tier-2 eval has run, and cbm's own paper leans mildly *against* the value (83% <
92% answer quality; graph parity on only 19/31 even for graph-native queries).
So today's action is **the eval, not the integration**. "Absorb-engine-gated"
and the veto persona's "absorb-idea-only, deferred and narrow" are the **same
operational place**: a pre-registered watchlist item under ADR-0024, not this
loop's build. There is no genuine dissent among the five on the *shape*; the only
spread is *urgency*.

This passes both filters as scoped: the north-star filter (P3 "swallow the
tools", removes read/grep loops from the sidecar's Tier-1 budget, stays visible
and remote-first-then-explicit) and Open-Source Leverage (MIT-in-MIT-out,
adopt-with-attribution). It fails both if read as "adopt the whole product."

## Bones discarded (over-reaching or contradicted, with reason)

1. **"cbm is the deepest structural signal per token" / "beyond codemap+aider, the #1 candidate"** (PA-0002.1) — cut the superlative. Contradicted by cbm's own paper (83% < 92%, 19/31). Keep only: *deeper on the precise reference/call-path class ghx's heuristic codemap under-serves — if a ghx bake-off proves it.*
2. **The precise "~80% overlap / 20% additive" fraction** (PA-0002.4) — cut the number, keep the direction. Unmeasured and self-flagged. The defensible statement: *the commodity structural classes (parse, structural search, import/dep graph, ranking) are already absorbed; the genuinely additive classes are LSP-grade reference resolution, a Cypher-queryable persistent call-graph, cross-service linking, and semantic search.*
3. **"158 languages" as a capability claim** (README, echoed loosely) — cut. It is a parse-grammar count; the capability number is 9–11 (semantic resolution). The "178 grammar_*.c" outlier (PA-0002.3) is likewise not a capability figure.
4. **"Persistent index to serve the B6 daemon / M8 anticipation" as a present reason to absorb** (PA-0002.2 F4; PA-0002.5 steelman-3) — cut from the *now* case; it inverts remote-first to serve an unbuilt milestone. Retain strictly as a phase-2 ADR open item, gated on B6 existing and demanding it with evidence.
5. **Any implication that absorbing closes the distribution/marketing gap now** (the "distribution Power ghx lacks", arXiv-benchmark, 11-agent installer framing in PA-0002.1 §2) — cut from the absorption decision. The benchmark is a "why now to publish SAFE" (positioning); the installer's *aligned* half (MCP-registration for `ghx serve`) routes to B2 setup work, not to this absorption.
6. **Novelty overclaim on the Hybrid-LSP core** ("from-scratch … the hard, novel core", PA-0002.1 E5) — soften. cbm is an ex-Go→C port whose Hybrid-LSP is, per its own README, "structurally inspired by gopls/pyright/tsserver/rust-analyzer" — inspired-by, not wholly novel.

## Least-confident call

**Whether the cbm engine would move ghx's signals-per-token *net positive* on
ghx's own task distribution — i.e. whether `local:cbm` clears the pre-registered
gate at all — is genuinely unresolved, and the available evidence leans mildly
*discouraging*.** Feasibility is a clear yes (PA-0002.3, and I re-confirmed the
seam and the CLI mode). Value is a maybe that only a ghx bake-off can settle: the
paper cbm ships shows a 9-point answer-quality regression and parity on only
19/31 even for graph-native queries; the win, if any, lives in one narrow
question class (precise reference / call-path resolution) that ghx's admittedly
heuristic codemap under-serves (ADR-0024.1 concedes the gap). This is exactly
where PA-0002.4 and PA-0002.5 land their own least-confident calls, and I share
it. **The strongest, load-bearing external fact (83% vs 92%) is also SHARED-PRIOR
— a single arXiv abstract, vendor-run, uncalibrated same-family judge — so it can
bound the decision but must not settle it.** Only a ghx-native, judge-calibrated
(κ ≥ 0.6, ADR-0023.1) tier-2 ablation can, and that ablation has not run.
Recommendation stands as **absorb-engine-gated**, with the gate explicitly unmet
today: the next artifact is the pre-registered ADR-0024.x eval, not the
integration diff.
