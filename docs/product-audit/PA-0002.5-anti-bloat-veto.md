# The case against absorbing `codebase-memory-mcp` *entirely*

**Scope of this artifact.** One persona (#8, Simplicity/Anti-Bloat Minimalist),
one question: *should ghx absorb `DeusData/codebase-memory-mcp` in its entirety?*
I am the deliberate veto voice, so the orchestrator hears the counter-thesis and
"absorb it" is not a foregone conclusion. Read-only; the only thing I wrote is
this file. All GitHub evidence was gathered by **dogfooding ghx** (`explore`,
`tree`, `read`) with `gh` only for release-asset sizes and repo metadata ghx does
not yet surface (logged as gap **G1** below).

## Verdict

**DON'T ABSORB THE WHOLE TOOL.** On the three-way scale
(absorb-whole / absorb-idea-only / **don't-absorb-whole**):

- **Absorb-whole: rejected, hard.** Vendoring or hosting the entire engine imports
  a rival product built on the *opposite* architectural bet to ghx's founding
  tenet, plus a foreign-language build tail, a persistent-index storage model, a
  background watcher daemon, a 14-tool MCP surface, an 11-agent auto-installer, and
  a 3D UI. None of that is load-bearing for ghx; almost all of it is anti-thetical.
- **Absorb-idea-only: conditionally allowed, but DEFERRED and NARROW.** *If* a
  citable tier-2 eval later proves ghx's existing `codemap + ast-grep + repomap`
  stack fails on a recurring, nameable class of precise cross-file questions, then
  the *right* move is to add **one optional subprocess backend** (`local:cbm`),
  exactly the pattern ADR-0024.1 already uses for codemap/ast-grep — not to swallow
  the product. That is a watchlist item, not a "yes" today.

The literal question — *absorb it entirely?* — gets an emphatic **no**. The
one-line reason: **codebase-memory-mcp is not a component ghx is missing; it is a
whole competing product whose center of gravity is the exact thing ghx's north
star refuses to become — a persistent local index, on by default.**

This is not a lone hunch. **PA-0001.4 (Competitive-Paranoid) already reached the
same architectural line** — "absorb the graph as a tier-2 internal tool… Remote-first
stays ghx's line — absorb the graph as a *local escalation tier*, not the default"
(`docs/product-audit/PA-0001.4-competitive-paranoid.md:165`). My delta: I pressure-test
whether even *that* narrow absorption earns its place now, and I supply the veto
evidence for why "entirely" must be ruled out explicitly, not left implicit.

## The single strongest argument (read this if you read nothing else)

**Absorbing the whole tool inverts ghx's founding architectural bet, and a product
is defined by what it refuses to become.**

- ghx's tenet, verbatim: *"**Remote-first, escalation explicit.** No clone, no local
  index by default. Pulling code locally and codemapping it is a deliberate, visible
  deeper layer (P3), never silent magic."*
  (`docs/NORTH_STAR.md:207-209`).
- codebase-memory-mcp's identity, verbatim from its own README (via
  `ghx read DeusData/codebase-memory-mcp README.md`): *"**Single static binary,
  zero infrastructure**: SQLite-backed, **persists to `~/.cache/codebase-memory-mcp/`**"*;
  *"**Auto-sync**: Background watcher detects file changes and re-indexes automatically"*;
  and an opt-in `config set auto_index true` that *"indexes automatically on first
  connection"* and registers a *"background watcher for ongoing git-based change detection."*

These two sentences cannot both be a product's center of gravity. codebase-memory-mcp
*is* "a persistent local index, on by default, kept warm by a daemon." ghx *is* "no
local index by default; escalation is the rare, explicit, visible exception." You can
gate a subprocess behind tier-2 (sanctioned). You cannot gate a *product's soul* behind
tier-2. Whole absorption doesn't add a tier-2 tool — it drags ghx's center of gravity
across the exact line its north star draws, and hands every future contributor a second,
louder answer to "what is ghx?"

Des Traynor's rule (the persona's source grounding, "Product strategy means saying no,"
[intercom.com/blog/product-strategy-means-saying-no](https://www.intercom.com/blog/product-strategy-means-saying-no/)):
*"delivering a cohesive product with well defined parameters."* The parameter here is
literally written down as tenet #`207`. Absorbing the whole tool erases it.

## Ranked findings (the veto brief)

Severity = Likelihood × Impact (3×3 per the skill). Ordered by leverage.

### V1 — Whole absorption inverts the remote-first tenet (the line between tier-2 and Non-Goal)

- **Persona · Scope · Surface:** #8 · North-Star Alignment / Positioning · strategy docs + their README.
- **Novelty:** `KNOWN-CONFIRMED` ⟨`PA-0001.4:111,165`⟩. Delta: PA-0001.4 named the
  tension and pre-approved the *narrow* graph-as-tier-2 idea; I add the explicit
  **veto on "entirely"** and locate *where the line is*.
- **SOURCE (their-repo):** README §"Distribution & operation": *"SQLite-backed,
  persists to `~/.cache/codebase-memory-mcp/`"* + §"Auto-Index": background watcher,
  auto-sync. Recompute: `/tmp/ghx read DeusData/codebase-memory-mcp README.md --lines 90-240`.
- **SOURCE (ghx-repo):** `docs/NORTH_STAR.md:207` ("No clone, no local index by
  default"); the Non-Goals list `docs/NORTH_STAR.md:264-270`. Recompute:
  `sed -n '207,209p;264,270p' docs/NORTH_STAR.md`.
- **STRATEGY:** Tenet "Remote-first, escalation explicit" (quoted above). **The line:**
  tier-2 escalation is sanctioned when it is (a) *rare*, (b) *explicit/visible in the
  report + traces*, (c) *ephemeral* (ADR-0024.1's shallow, LRU-evicted snapshots, not a
  standing index), and (d) *decided by the sidecar brain per question*. codebase-memory-mcp
  as a *product* is none of those: it is a standing, auto-refreshing, persistent index —
  the definition of the Non-Goal, not the definition of an escalation.
- **EXTERNAL:** [codebase-memory-mcp README "Distribution & operation"](https://github.com/DeusData/codebase-memory-mcp/blob/main/README.md)
  — why it matters: the tool advertises persistence + a background watcher as headline
  features; those are precisely the properties ghx's tenet exists to exclude by default.
- **Severity:** Likelihood High × Impact High → **Stop & resolve before proceeding.**
  This is the finding that turns "absorb it" from obvious into contested.
- **Disposition:** *Confirmed sound* → the counter-thesis; routes to any PA-0002 synthesis.
- **North-star relationship:** A whole-tool absorption **fails the north-star filter's
  spirit** — it does not "remove tokens from the main agent's context" so much as import a
  parallel product; and it directly contradicts the remote-first tenet.
- **Verification state:** `self-verified` (tenet + README quotes are directly recomputable;
  the *architectural-inversion* judgment is mine and should get a cross-family check before
  any PA-0002 synthesis cites it as thesis-bearing, per skill directive 5).

### V3 — Absorb the IDEA, not the TOOL: the minimum ghx needs is already built

- **Persona · Scope · Surface:** #8 · Adjacent-opportunity / YAGNI · their-repo + ghx ADRs.
- **Novelty:** `KNOWN-CONFIRMED` ⟨ADR-0024.1 "Absorb vs Steal"⟩. Delta: apply that existing
  doctrine to *this* tool and show the "whole tool" is 90% not-needed.
- **SOURCE (their-repo footprint):** By dogfooding + `gh`:
  - **Language:** pure **C** — `763 .c` + `640 .h` files. Recompute:
    `/tmp/ghx tree DeusData/codebase-memory-mcp | grep -oE '\.[a-z]+$' | sort | uniq -c | sort -rn`.
  - **158 vendored tree-sitter grammars** compiled into the binary, **bundled Nomic
    `nomic-embed-code` embeddings** (README §"Search"), a **C Hybrid-LSP** (README §"Indexing
    pipeline"), a **Cypher-like query language**, a **3D UI** (`graph-ui/`, 35 `.tsx`).
  - **Binary size:** ~35 MB *compressed* per platform (`gh api …/releases/latest`;
    darwin-arm64 = 36 MB). ghx's own binary is **61 MB** (`ls -la /tmp/ghx`). A subprocess
    dependency ≈ doubles on-disk footprint; vendoring the C source into a Go binary is a
    non-starter.
  - **Maturity/velocity:** created **2026-02-24**, latest tag **v0.8.1** (pre-1.0), **pushed
    the day of this audit** (`pushed 2026-07-07`), and it *"checks for updates on startup."*
    Recompute: `gh api repos/DeusData/codebase-memory-mcp --jq '.created_at,.pushed_at,.license.spdx_id'`.
    A fast-moving pre-1.0 C engine is a versioning tail ghx would chase forever.
- **STRATEGY:** ADR-0024.1 "Absorb vs Steal," verbatim: aider repomap → *"Steal algorithm,
  not dependency… ghx should own the model over its own artifacts"*; and the rejected option
  *"**Vendor upstream code immediately**: rejected. Shell out… Absorption under ghx does not
  require source vendoring"* (`docs/adr/0024.1-escalation-tiers-decision.md:323,388-390`).
  The *minimum ghx actually needs* from tier-2 — cross-file import/call/blast-radius
  structure — is **already covered** by codemap+ast-grep+repomap (ADR-0024.1 Implementation
  Notes verify `--importers`/`--deps` return real fan-in live, `:604-608`). No named gap
  requires the *whole* engine.
- **EXTERNAL:** [nomic-embed-code](https://github.com/DeusData/codebase-memory-mcp/blob/main/README.md#search)
  bundled embeddings + [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammars —
  why it matters: these are the *heavy, foreign* parts of "the whole tool" that ghx would
  inherit and never use if all it wanted was better reference precision.
- **Severity:** Likelihood High × Impact Medium → **Scoped fix.**
- **Disposition:** *Confirmed sound* — the "idea vs tool" answer is: the idea (precise graph
  edges) is worth watching; the tool (a C persistent-index product) is not worth hosting.
- **North-star relationship:** Passes the *idea* filter (deeper signal/token), fails on the
  *tool* (imports cost with no proven marginal reconnaissance gain over what ships today).
- **Verification state:** `self-verified`.

### V4 — The cost of "yes" lands on every user who never triggers tier-2

- **Persona · Scope · Surface:** #8 · Token-economics / Simplicity · their-repo + NORTH_STAR §3.
- **Novelty:** `NEW`.
- **The tax, itemized** (each a permanent cost even for the majority of asks that stay
  remote Tier-0/1):
  1. **Storage-model collision.** NORTH_STAR §3: *"`~/.ghx` is the product's root storage
     (sessions, ledgers, reports, traces, caches, config)"* (`docs/NORTH_STAR.md:148`). The
     tool persists to a *second* root, `~/.cache/codebase-memory-mcp/`, plus an in-repo
     `.codebase-memory/graph.db.zst` team artifact. Two storage roots is exactly the "one
     authoritative owner" tenet failing.
  2. **A second daemon.** ghx's own always-on runtime is milestone **B6** (`NORTH_STAR:315`).
     The tool ships its own background watcher/re-indexer. Two resident processes contend for
     the same "keep the code model warm" job.
  3. **Distribution anti-pattern.** The tool's installer *"auto-detects Claude Code, Codex
     CLI, Gemini CLI, Zed… configures MCP entries, **instruction files**, skills, and
     **pre-tool hooks** for each"* and exposes **14 MCP tools** (README §"Quick Start" +
     §"Features"). This is the literal inverse of ghx's Non-Goal *"Teaching every main agent
     the ghx CLI (the opposite of the goal)"* (`NORTH_STAR:268`) and of the north star's
     "one concise skill, zero CLI knowledge" (`:24-28`). Absorbing "the tool" means either
     discarding its entire distribution layer (so you absorbed the *engine*, not the *tool* —
     back to V3) or importing an anti-goal.
  4. **Binary + build tax.** +35 MB subprocess or a C toolchain in ghx's Go build.
  5. **Doctrine tax.** The sidecar persona (~400 lines already, `NORTH_STAR:95`) would grow a
     fourth-backend decision branch and 14-tool vocabulary — the very context weight the Moat
     wants to *drive down*.
- **STRATEGY:** the Simplicity persona's own question (`research/02-pm-personalities.md:298`):
  *"What does this feature cost every other user, even the ones who never touch it?"* Here the
  answer is: two storage roots, a second daemon, an anti-goal installer, 35 MB, and doctrine —
  paid by 100% of users to serve the minority of asks that escalate.
- **EXTERNAL:** [codebase-memory-mcp install.sh](https://github.com/DeusData/codebase-memory-mcp/blob/main/install.sh)
  — why it matters: the auto-config-into-11-agents mechanism is a product-shaping choice ghx
  would have to accept or amputate.
- **Severity:** Likelihood Medium × Impact High → **Escalate now.**
- **Disposition:** *Confirmed sound*.
- **North-star relationship:** Fails the filter — adds context/config/storage tax without a
  measured reconnaissance gain for the common path.
- **Verification state:** `self-verified` (README + NORTH_STAR quotes recomputable).

## What would make absorption WORTH the tax anyway (steelman — not crying wolf)

The honest other side. There is a real, non-trivial case, and I'll state it at full strength:

1. **ghx's own ADR admits the precision gap this tool fills.** ADR-0024.1 concedes ghx's
   tier-2 is heuristic: *"Import extraction is deliberately heuristic… Precise resolution is
   stack-graphs territory, which stays out of this build by decision"* (`:619-622`), and it
   keeps an **open watchlist slot** for exactly this: *"repeated Tier-2 uncertainty on
   implementor/reference/call-path questions where codemap and ast-grep found files but could
   not prove symbol relations"* (`:448-450`). codebase-memory-mcp's **Hybrid-LSP semantic type
   resolution** (11 languages, tsserver/pyright/gopls-compatible) + **semantic vector search**
   is a genuinely more precise engine than ghx's import heuristics. If the gap bites in a
   measured run, this tool is a **stronger stack-graphs replacement than stack-graphs**: single
   static binary, 158 languages, MIT, sub-ms queries, **no build/typecheck step** (the exact
   reason SCIP was rejected). It slots into the watchlist slot ADR-0024.1 already left open.

2. **MIT license makes it legally clean to absorb** (`gh api … .license.spdx_id → MIT`,
   confirmed by reading `LICENSE`). No copyleft trap. The Picasso rule's "MIT in, MIT out"
   (AGENTS.md:187) is satisfied. This removes a common false objection — I will not pretend
   licensing blocks it; it doesn't.

3. **A persistent index could serve the always-on daemon (B6) and cross-session memory.**
   ghx's ephemeral LRU snapshots re-clone; a warm persistent graph is faster on repeat visits.
   *If* ghx ever decides the daemon's job is "keep a local model of frequently-visited repos
   warm," a persistent graph store is the natural substrate.

**But even the steelman lands on "not whole, not now":**

- Each point above justifies **one optional subprocess backend** (`local:cbm`), invoked only
  under an explicit tier-2 escalation, ghx owning clone/cache/provenance, install **optional**
  and degrading to remote (exactly how codemap/ast-grep already behave —
  ADR-0024.1:669-681). It does **not** justify hosting the watcher, the 14-tool MCP surface,
  the 11-agent installer, the UI, the Cypher language, or the persistent-index-by-default posture.
- Point 3 is the tail wagging the dog: adopting a persistent local index *to serve the daemon*
  would flip the remote-first tenet to serve an unbuilt milestone. Reject until B6 exists and
  demands it with evidence.
- And it is **premature**: the gate is a *measured* failure class, and no such tier-2 eval has
  run (M7 is P3; the citable verdict is pre-registered but unrun — ADR-0024.1:435-436). YAGNI
  applies: absorb on measured need, not on a 28k★ star count.

Net: the steelman upgrades the ceiling from "never" to "maybe one optional subprocess backend,
after a measured gap." It never reaches "absorb entirely."

## What is actually fine (equal rigor)

- **The tool is excellent, and studying it was worth it.** Fast, MIT, single-binary, 158
  languages, genuinely stronger reference precision than ghx has today. Naming it a veto target
  is *not* dismissing it — it's the right way to treat a peer (AGENTS.md:201-212: competitive
  analysis is generative). The *idea* absorption channel is legitimately open.
- **The narrow "graph as tier-2" idea PA-0001.4 proposed is not wrong** — it's just (a) already
  covered for the common cases by codemap/repomap, and (b) correctly gated behind a measured gap.
  I am not vetoing the *idea*; I am vetoing *"entirely,"* and flagging that even the idea is a
  deferred watchlist item, not this loop's work.
- **ghx's existing tier-2 doctrine is sound and load-bearing.** ADR-0024.1's "Absorb vs Steal"
  table, subprocess-not-vendor rule, and remote-first tier boundaries are exactly the machinery
  that makes this an easy veto. The framework works; use it.
- **Nothing here says "fear the competitor."** The right response is contest-on-the-axis-they-
  can't-hold (remote-first, GitHub-wide discovery, the evidence contract, the SAFE benchmark) —
  which PA-0001.4 already routed. This artifact only removes "swallow the whole thing" from the menu.

## Least-confident call

**Whether even the narrow, subprocess-only `local:cbm` backend should be pursued at all —
versus finishing ghx's own repomap/stack-graphs path.** My veto against *whole* absorption is
high-confidence and multiply-sourced. But the semantic-vector + Hybrid-LSP precision is a real
capability ghx lacks and its own ADR admits is a gap; I am *not* certain the narrow backend
should be rejected too. My honest position: it should be a **pre-registered watchlist item
measured against a real tier-2 eval**, not a "yes" and not a hard "no." If a run proves
codemap+ast-grep+repomap repeatedly fail the reference/call-path class ADR-0024.1 named, then
`local:cbm` as an optional subprocess backend is defensible — and stronger than stack-graphs.
That single decision is where I'd want a cross-family (Codex/gpt-5.5) adjudication before any
PA-0002 synthesis commits.
