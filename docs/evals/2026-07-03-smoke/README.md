# Live smoke snapshot — 2026-07-03

**Scope: smoke run, NOT the ADR-0016.1 gate run.** One task
(`hono-middleware`, 2 turns), one trial per profile, agent =
`@agentclientprotocol/claude-agent-acp` v0.55.0 (Claude Code backend),
episodes produced by `go test ./internal/sidecar/evals -tags=agent_e2e`.
The formal gate run requires ≥ 6 tasks × 5 trials per profile.

## What this run established

1. **The live pipeline works end-to-end**: real agent, real ACP handshake,
   real `ghx` commands against GitHub, report extraction, session
   resumption on the follow-up turn (`resume rate 1.00`), rewards, verdict.
2. **It caught a real production bug first**: the original deny-all
   permission client rejected the agent's request to run `ghx` itself; the
   sidecar could only answer `BLOCKED`. Fixed in `internal/sidecar/acp.go`
   (kind-based read-only policy) in the same change that adds this snapshot.
3. **G1/G2/G4/G5 pass; G3 fails on this snapshot.** The sidecar's report
   JSON across 2 turns (7,668 chars) was almost as large as the ghx
   profile's entire produced transcript (8,017 chars) — far above the
   0.35× threshold.

## Why G3 here is signal but not verdict

- n=1 on an easy calibration task; the gate run decides, not this.
- Known accounting bias **against** the direct profiles: main-agent chars
  count only agent-produced text. Tool *outputs* (file contents, search
  results) that a real main agent carries in context are not captured yet,
  which undercounts direct-profile context — possibly severely. Capturing
  tool-output sizes from ACP `tool_call_update` events is the top
  accounting follow-up before the gate run.
- Independent real signal: nothing in the sidecar persona bounds report
  size. A report-compactness constraint is a legitimate product improvement
  to make before the gate run (it changes the prompt contract, so it must
  land before, not after, the measured run).
