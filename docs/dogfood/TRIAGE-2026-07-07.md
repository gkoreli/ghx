## F1 — malformed-slug exit code (`explore`/`tree`/`read`): FIXED

**Status: FIXED by ADR-0035 T1.1** (commit `9e4a10e`, changelog `fc889fe`).

That commit introduced a single `ghx.ParseRepo` value-object validator
(`internal/ghx/repo.go`), unified the three divergent owner/repo validators, and
routed `explore`/`read`/`tree` core errors through `ghxCoreError`
(`internal/cli/ghx.go`), which maps any `invalid repo` error to
`ExitBadInvocation` (exit 2). It also fixed a real crash: `ghx tree noslash`
previously panicked via an unchecked slice index in `glob.go`.

Verified on the HEAD binary (`c0381bd`):

- `ghx explore badslug` → `invalid repo "badslug": expected owner/repo, e.g. ghx explore gkoreli/ghx`, **exit 2**
- `ghx tree noslash` → same message, **exit 2** (no panic — the task's named check)
- `ghx read badslug README.md` → same message, **exit 2**

All three now agree on the bad-invocation class and carry an example
invocation. Matches the friction's expectation exactly.

**Next action:** none — close the FRICTION.md F1 entry as fixed.

## F2 — `read` of a nonexistent repo returns exit 0: OPEN, decision needed

**Status: OPEN — product/CLI-semantics decision for Fable.**

Verified still exit 0 on the HEAD binary:

- `ghx read totally/nonexistent-repo-xyz123 README.md` → `=== README.md (not found) ===`, **exit 0**

The read path returns `nil` when a requested file does not resolve, so a
scripting agent checking `$?` reads a nonexistent repo/file as success. This is
unchanged since the friction run; ADR-0035 T1.1 fixed only the *malformed-slug*
class (F1), not the *unresolved-file / 404-repo* class.

**Decision needed:** is "requested file not found" a success (today) or should a
fully-unresolved read return `ExitNoResults` (1), and a 404 repo/ref return
`ExitUpstreamFailure` (3)? This changes a public CLI exit-code contract, so it
belongs to Fable. **Next action:** Fable decides the contract; if it changes,
implement it in the read command alongside the existing 404 affordance already
present in `upstreamRules` (see F3), and add a regression test.

## F3 — live 401 on `search` has no A4 affordance: FIXED

**Status: FIXED by the A4 error-affordances work** (commit `db67a07`,
`feat(cli): errors name the fix-it invocation`).

This corrects the friction's "no affordance" observation: `db67a07` landed
**after** the friction-run binary `e8816ec`/v2.6.0
(`git merge-base --is-ancestor db67a07 e8816ec` = **no**), so the friction run
genuinely had no affordance, and the fix arrived afterward. It added an
`upstreamRules` table (`internal/cli/errors.go`) that maps 401 / `bad
credentials` / `unauthorized` (and 403/forbidden, 404, rate-limit, and network
classes) to a fix-it hint, applied uniformly through `upstreamError` for every
CLI upstream failure.

Verified on the HEAD binary with a deliberately invalid token:

```
$ GH_TOKEN=ghp_invalid… ghx search charmbracelet/bubbletea "func eventLoop"
search failed: HTTP 401: Bad credentials (…)
→ GitHub authentication failed. Run `gh auth login` (or set GH_TOKEN), then verify with `gh auth status` and retry.
exit=3
```

The A4 promise (errors name the fix) is now met on the single most common live
failure.

**Residual (NOT re-verified here; carried from the friction note):** the
friction also reported that an *empty* `GH_TOKEN=` can fall back to the `gh`
keyring token and degrade to exit-1 "0 results", i.e. missing-auth masquerading
as no-results. That is a separate auth-absent-signal gap, unrelated to the 401
affordance (no 401 is raised, so no rule fires). It could not be cleanly
reproduced in this environment (a valid keyring token is present). **Next
action:** none for the primary 401 gap (close it); keep the empty-token
masquerade as a smaller standalone open note.

## F4 — tool-call `Locations` empty (execute-kind calls carry no ACP locations): OPEN

**Status: OPEN — note for ADR-0032.1.**

Two distinct findings, both verified against code:

1. **Setup mismatch (resolved as process, not product).** The friction-run
   binary `e8816ec` predated the S2 Locations fix (`5aec071`,
   `fix(sidecar): populate ToolCallTrace.Locations from ACP tool-call
   notifications (ADR-0032.1 S2)`). That fix **is** on mainline HEAD
   (`git merge-base --is-ancestor 5aec071 HEAD` = **yes**), so the empty
   Locations the dogfood run observed are expected-for-that-binary, not a
   mainline regression. Process fix: cut dogfood worktrees from mainline HEAD,
   not a release tag.
2. **Product nuance the fix does not cover.** The sidecar's recon tool calls are
   all `kind=execute` — the agent shells out to `ghx read/search/inspect` via
   the ACP execute tool, not native ACP read/search tools — and ACP
   execute-tool notifications generally do not carry file `locations`. ADR-0032.1
   S2 populates `ToolCallTrace.Locations` from whatever the notification
   carries, so R6 path-scope classification (ADR-0032.1) likely still sees empty
   Locations in real sidecar usage. The S2 tests prove population from
   *synthetic* locations; nothing yet proves the live Claude Code adapter emits
   locations for the sidecar's execute-driven pattern.

**Next action:** record finding (2) as an explicit limitation on ADR-0032.1's R6
path-scope rule; consider deriving path-scope from the `ghx` argv in the tool
call's title/RawInput rather than relying on ACP Locations for execute-kind
calls.

## F5 — sidecar token metric undercounts a turn's real cost: OPEN

**Status: OPEN — observability gap; folds into ADR-0036 Phase D.**

The friction found that `metrics.jsonl` `gen_ai.client.token.usage` reflects only
the sidecar's own orchestration model, not the subject ACP agent
(claude-sonnet-5) that does the actual recon, so a depth level's real token cost
is not recoverable from the committed artifacts (input a flat 102 tokens across
cheap/normal/deep).

ADR-0036 Phase D (`docs/adr/0036-target-architecture-runner-port-and-boundaries.md`,
D1) is the pre-registered path: an in-process `claude-sdk` runner over
`anthropic-sdk-go` that fills `TurnResult.Usage` with **real production tokens**
and is explicitly called out as closing trust hole **H5** (today's char-proxy /
undercount). F5 folds into that work.

**Nuance to preserve (visibility tenet):** Phase D's real-token accounting is
about the *runner's own* usage; the F5-specific ask — surfacing or unambiguously
relabeling the *subject-agent* cost so a reader can recover what a depth level
cost — should be tracked explicitly under that ADR so it is not lost in the
larger runtime change. **Next action:** track F5 under ADR-0036 Phase D; as a
cheap interim, relabel the metric so it is unambiguous that it excludes
subject-agent cost.
